From `docs/architecture/build-plan.html#m2`. Access lane. Depends on contracts C2 (M0.1), C3 (M0.4) and C6 (M0.5, M0.6). Reuse: flightdex-v2 routes, `authenticate` (borrow), api-keys, `packages/mcp` (copy). Paths are in `docs/architecture/reuse.html`.

## Scope

`api_keys` table (this lane's first migration), service and tRPC router, settings page (table, create dialog, copy-once).

`/mcp` route with `createMcpHandler` per request, 1 MB body cap, `allowedHostnames` from `PUBLIC_BASE_URL`, structured log line.

Tool input schemas and bodies: `list_agents`, `send_message` (`startRun` with `origin: "mcp"`, `requestId`, optional `waitMs` up to 25 s; from a run principal it inherits the subject and is refused when the target is a busy ancestor or depth would exceed 3), `get_run`, `list_sessions`, `read_session`, `search_sessions` (LIKE over `message.*` payloads, FTS later).

Run tokens are accepted here too, so an agent can read its own sessions, scoped to its agent id.

## Check

`bun scripts/smoke-mcp.ts --key hm_key_...` against `bun run dev` with the seeded fake agent: lists tools, sends a message with `waitMs: 5000`, gets the echo back, reads the session.

`mcp.test.ts`:

- a run-token principal can read its own session and gets an empty list for another agent's;
- an api-key principal whose user left the org (fake `isOrgMember` false) gets 401;
- `send_message` from a run on behalf of user U creates a run on behalf of U with `parent_run_id` set;
- a `send_message` from B back to A while A is B's running ancestor is refused.

Manual: `claude mcp add --transport http harbourmaster http://localhost:3000/mcp --header "Authorization: Bearer hm_key_..."` then ask Claude Code to message the agent.
