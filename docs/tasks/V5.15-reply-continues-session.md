From the V5 gate review (`docs/reviews/V5-1.md`).

Scope
- `packages/services/src/mail/inbound.ts` `startInbound`: when the thread already has a `session_id` and that session is not the thread's `mail:<mailboxId>:<threadId>` session, start the reply's run in that existing session. Don't open a new mail session, and don't overwrite `mail_threads.session_id`.
- `packages/services/src/runs.ts` / `runs/types.ts`: add a trusted `StartRunOptions` field (for example `sessionId`), not part of `startRunInputSchema`. It continues a known session of the same agent and workspace and skips the ui and private actor check, which a mail trigger cannot pass.
- Keep `requestId: mail:<externalMessageId>` for idempotency.

Check
- `inbound.test.ts`: a run in a `ui` session sends mail to an outside address (allowed), and an inbound reply on that thread starts a run in the same session. `threadForTask` for the first run still returns the thread. A thread first started by inbound mail still continues its mail session, and a redelivery still starts one run.
- `bun run check && bun run test && bun run build` pass.
