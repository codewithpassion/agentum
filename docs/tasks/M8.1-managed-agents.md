From `docs/architecture/build-plan.html#m8`. On 17 Oct 2026 Dom asked for agents running on cloud machines, so the Managed Agents lane that v1 left out ("Dom first") is back in. An agent can now run on Anthropic Managed Agents instead of an enrolled machine.

## Scope

Follow the M8.1 entry in the build plan. Read Agentum's gotcha list in `docs/analysis/agentum.md` section 6 first. Agentum's source is `/home/roboto/devel/agentum`, read-only, and code can be copied from it.

- Decide between session-scoped and run-scoped tokens first, and write the decision in the review file. Managed Agents fix `mcp_servers` when the agent is registered or synced (`CreateSessionInput` has no MCP field). The plan's likely answer is a session-scoped token whose proxy lookup finds the session's active run for `on_behalf_of_user_id`, so the proxy and the run-token resolver gain a second token kind.
- Copy and adapt Agentum's `gateway.ts`, `events.ts`, `config.ts` and `workspace-keys.ts`, plus a `managed_agents` table (a schema change, so run `bun run generate`), `ManagedRuntime.dispatch`, and a `ManagedPoller` Durable Object with an alarm per active run. Add the DO to the top level, `env.staging` and `env.staging.previews` in `wrangler.jsonc`, and add a new migration tag (don't edit `v1`). The agent form gains a runtime select (machine or managed).
- Managed runs go through the same run lifecycle, events, transcript, files and Slack/inbox/trigger/routine paths as machine runs, so the Sessions and Log pages and replies work unchanged. Where Managed Agents can't support something (local files, skills sync, `[ATTACHMENT:path]`), say so in the agent form and the review file instead of failing quietly. MCP image results don't reach the model (see Agentum's notes), so use custom tool results where images matter.
- The Anthropic API key is per workspace, stored with the existing encrypted secrets (`SECRETS_KEY`), and entered in the UI. It is never an env var the app reads for every workspace. Tests and local use read a key only from `apps/web/.env.local` (`ANTHROPIC_API_KEY`), and the key is never printed or logged.

## Check

`managed.test.ts` against a fake gateway: dispatch, poll, complete, budget stop; a two-turn session where the second run is on behalf of a different user resolves the second user's credential; two concurrent managed sessions on one agent don't share a token. Live, only if `ANTHROPIC_API_KEY` is in `apps/web/.env.local`: run `cloudflared tunnel --config /dev/null --url http://localhost:<port>` with `PUBLIC_BASE_URL` set to it, create a managed agent, send "Reply with the word pelican" and get the reply, then assign the stub connector and ask it to call echo, and the Log shows `connector.call` for the managed session. If the key is missing, report the live check as a Dom step. `bun run check && bun run test && bun run build` pass, and the bundle grep for `drizzle` passes.
