Managed Agents already has the protocol: a tool with `permission_policy: always_ask` parks the session idle with `stop_reason.type = "requires_action"` and `event_ids`, and the client answers with `user.tool_confirmation` (`result: "allow" | "deny"`, `tool_use_id`, optional `deny_message`). A custom tool parks the same way until a `user.custom_tool_result` arrives. Today `gateway.ts` sets every toolset to `always_allow`, and `isAbnormalStop` in `managed/events.ts` fails a run that stops on `requires_action`.

## Scope
- `packages/services/src/managed/gateway.ts`: `toolsFor` takes the agent's rules and sets `configs: [{ name, permission_policy: { type: "always_ask" } }]` per tool with an `ask` rule on the agent toolset or the matching `mcp_toolset` (tool keys from V1.3). The rules join the agent fingerprint, so a rule change re-syncs the Anthropic agent. Add the `ask_user` custom tool from `ASK_USER_TOOL`. New gateway calls `confirmTool(sessionId, toolUseId, decision, denyMessage?)` and `sendCustomToolResult(sessionId, toolUseId, text)`.
- `packages/services/src/managed/events.ts` and `service.ts`: `requires_action` is no longer an abnormal stop. In `settle`, for each blocked event id, find the matching `agent.tool_use`, `agent.mcp_tool_use` or `agent.custom_tool_use` (keep its input in `SessionEvent.tool`) and call `requests.open` (`approval` for a tool, `question` for `ask_user`). On the next step, for each request with an outcome, send the confirmation or custom tool result once (record that it was sent, so a repeated step does not send twice; use the request's status plus a sent marker kept in the poller's DO storage, not a new column). Answers are mapped with `outcomeText`; `always_allow` sends `allow` and the next sync clears the rule from the toolset.
- The 60-minute `RUN_MAX_MS` counts only time not spent waiting: subtract the summed `answered_at - created_at` (or now for an open one) of the run's requests.
- The poller keeps polling a waiting run at a slower interval (for example 15 s) and heartbeats it; a kick from `resume` brings it back at once.

## Check
- `managed.test.ts` with the fake gateway: a `requires_action` idle opens one request and the run goes `waiting`; allow sends `user.tool_confirmation` with `allow` once even over two steps; deny sends `deny` with the note; an `ask_user` custom call gets the answer text as `user.custom_tool_result`; expiry sends deny or the expiry text; the age limit ignores waiting time; a run with no rules still registers `always_allow` toolsets.
- `gateway.test.ts`: `configs` per ruled tool and the custom tool in the agent body.
- `bun run check && bun run test && bun run build` pass.
- Live on staging (controller): a managed agent with "Ask me before" on `bash` waits, is allowed from the web card and finishes; an `ask_user` question is answered from Slack.

## Refinements (26 Oct 2026, against main)

Checked against the code before V1 started. Where these differ from the scope above, they win.

- The rules join the agent fingerprint in `managed/service.ts` (`ensureRegistered`, around line 383), not `gateway.ts`.
- `SessionEvent.tool` already holds `{ id, input, name }`; read the input from it.
