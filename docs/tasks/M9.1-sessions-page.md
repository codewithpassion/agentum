From the build plan's M9 section (docs/architecture/build-plan.html#m9), approved by Dom on 16 Oct 2026. The build plan has no numbered tasks for M9; this is its first page. The app has no sessions page yet (`apps/web/src/routes/_app/`).

## Scope

A Sessions page in the app shell, with a nav entry: a list of the sessions the signed-in user can see across agents and origins (UI, Slack thread, Slack DM, inbox, trigger, routine), newest first, with agent, origin, last activity and run status, filterable by agent and origin. Opening one shows its transcript, with tool calls as collapsed cards (tool name, input, output) and input and output files as chips, reusing the chat's transcript logic and chip component rather than copying them. Data comes through tRPC and the existing `sessions` service, whose visibility rules (private `ui` and Slack DM sessions) apply unchanged. Use existing shadcn components only.

## Check

`apps/web/e2e/sessions.ts`, a browser script that uses dev login (create the `e2e` folder and a `bun run e2e:sessions` script): it seeds or creates two sessions, sees both in the list, filters to one, opens it, and sees a tool card and a file chip. A service or router test shows another user's private session stays out of the list. `bun run build` and the bundle grep for `drizzle` pass. `bun run check && bun run test && bun run build` pass.
