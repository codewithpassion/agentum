The service half of one registry for both roles. Relay, UI and agents all go through these methods.

## Scope
- `packages/services/src/machines.ts`: `createEnrollToken` takes `role` and an optional existing `machineId`. `enroll` handles the computer role: it creates a computer-only machine or adds the role to the named machine, and writes `machine_credentials`. `authenticate(header, role)` resolves a credential for one role only, so a daemon credential never opens a computer socket and the reverse.
- `markComputerOnline(hello)` and `markComputerOffline` store capabilities from the v1 hello and write `computer.online` / `computer.offline` events. `list` returns roles and both statuses.
- `attachComputer(principal, agentId, machineId | null)`: only cloud and managed agents, only machines with the computer role in the same workspace, and one agent per computer. It writes `agent.updated`.
- `revoke` also revokes the computer credential and calls the relay port, which closes every socket.
- `apps/web/src/server/trpc/machines-router.ts`: `createEnrollToken` with role and machine, `list`, and `attachComputer`.

## Check
- `packages/services/src/machines.test.ts` covers the cases above: computer-only enrol, adding the role to an existing machine, role-scoped authenticate, attach rules (runtime, workspace, one agent per computer), and revoke closing both roles. `machines-router.test.ts` passes.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-27)

Checked against main at 26b4c58. Where these differ from the scope above, they win.

- `authenticate(authorization)` (`packages/services/src/machines.ts:195`) has no role and calls `findMachineByCredential` from `packages/db`. Add `role`, defaulting to `agent_host`, so `/connect` and the machine run routes compile unchanged and a computer credential gets nothing there. `agent_host` reads `machines.credential_hash`, `computer` reads `machine_credentials`. Both refuse a revoked machine.
- `enroll` takes V6.1's union. A code with `machine_id` adds a `machine_credentials` row to that machine. A code without one creates a computer-only machine with the unusable `credential_hash` from V6.1. The code spend stays one conditional write.
- `markComputerOnline` and `markComputerOffline` mirror `markOnline` and `markOffline` (around lines 289 and 336), including the `"revoked"` answer that makes the relay close with 4401.
- `revoke` already calls `relay.revoke(machineId)`, which closes every socket once V6.9 tags them. Revoked status covers both roles, so no extra credential update is needed.
- `attachComputer`: only `cloud` and `managed` runtimes. V6.1's unique index enforces one agent per computer; map the clash to a `conflict` error. `agent.updated` is already in `EVENT_TYPES`.
- `MachineRecord` gains roles and `computerStatus`. V3.11 reads `machines.list` for machine state, so keep the existing fields.
- tRPC: `apps/web/src/server/trpc/machines-router.ts` exists.
- Overlap: `packages/services/src/machines/types.ts` with V4.6 (worker lane, adds `announce`). No V3 to V5 task edits `machines.ts`.
- Add the attached computer (`computerMachineId` and its desktop flag) to `CloudStart` (`packages/services/src/cloud/types.ts`) and fill it in `cloud/runtime.ts`, so V6.13 (worker lane) only reads it. Same-file overlap with V4.9 in the services lane.
