From `docs/architecture/build-plan.html#m5`. Runtime lane, after M1.6. Depends on contracts C3 and C7 (M0.4). Reuse: Ariadne `signature.ts`, `events.ts`, `user-mapping.ts`; control-plane `slack-client.ts`; flightdex-v2 `readCappedBody` (copy). Paths are in `docs/architecture/reuse.html`.

## Scope

`slack_apps` and `slack_events_seen` tables.

`POST /api/slack/events`: URL verification, signature check with the app's signing secret (looked up by `api_app_id`, and the event's `team_id` must match that row), body cap.

Mention and DM to `StartRunInput` with `origin: "slack"`, `externalKey = team:channel:threadTs`, principal `{ kind: "user", via: "slack" }` from `identity_links`.

Durable admission: one atomic write stores the `slack_events_seen` row and the run, with any Slack file descriptors in `pending_files`, then the route answers 200. A `waitUntil` downloads pending files into R2 and clears `pending_files`; the sweep finishes any it did not, three attempts then `failed` with an event.

A sender with no link: the write stores the dedupe row and a `slack.unlinked_sender` event, the 200 goes out, and `waitUntil` runs the `users.info` email lookup. A match that is also an org member creates the link and a reply asking them to send again. Anything else gets "ask Dom to add you".

Slack gateway `deliver` posts in the thread with retry, and sends a Connect path as an ephemeral message to the context's `onBehalfOfUserId`. Channel watch is deferred.

## Check

`slack-events.test.ts` with recorded fixtures:

- a mention from a linked user creates a run with the right session key and `on_behalf_of_user_id` before the response is returned;
- a retry with the same body creates nothing and still answers 200;
- a bad signature is 401;
- a `team_id` that does not match the app row is 401;
- a bot's own message is ignored;
- an unlinked sender gets no run and a `slack.unlinked_sender` event;
- an email match for a Clerk user outside the org creates no link;
- a failure injected into the atomic write answers 500 so Slack retries, and no dedupe row exists;
- a message with a file creates a run with `pending_files` that the claim refuses, and after the download job the run is claimable with the file in `input_file_ids`;
- a process loss between the 200 and the download leaves `pending_files` that the sweep completes.

`bun scripts/dev/slack-replay.ts fixtures/mention.json --secret ...` signs and posts a fixture to the dev server and prints the run id.
