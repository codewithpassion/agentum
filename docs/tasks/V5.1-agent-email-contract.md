Tables, enums, ports and tool shapes for agent mail, shaped by the V5.2 decision. The only V5 task that changes the schema.

## Scope
- New `packages/db/src/schema/mail.ts`: `agent_mailboxes` (id, workspace_id, agent_id unique, address unique across the deployment, routing_rule_id, status `provisioning | active | failed | disabled`, last_error, created_at); `mail_threads` (id, workspace_id, mailbox_id, external_thread_id, session_id, task_id, subject, last_message_at; unique mailbox and external thread); `mail_messages` (id, thread_id, direction `in | out`, from, to, cc, subject, snippet, external_message_id, status `received | held | sent | rejected | expired | bounced | failed`, approval_id, run_id, created_at). Mail bodies stay in the mailbox backend; D1 keeps the index the desk and profile need.
- V3 reserves `agents.email_local`, unique per workspace. The address is `<email_local>@<domain>`. If all workspaces share one mail domain, the address must be unique across the deployment: the unique index on `agent_mailboxes.address` enforces it, and V5.3 maps a clash to the V3 "That address is taken" error. The migration creates a `provisioning` row for every active agent with an `email_local`. `bun run generate`, commit `migrations/` and `meta/`.
- `packages/db/src/shared.ts`: `TRIGGER_KINDS` gains `mail`; session origin `mail` with external key `mail:<mailboxId>:<threadId>`; `MAIL_MESSAGE_STATUSES`, `MAILBOX_STATUSES`; `EVENT_TYPES` gains `mail.received`, `mail.held`, `mail.sent`, `mail.rejected`, `mail.bounced`, `mailbox.provisioned`; the V1 approval kind for `mail_send`.
- The "outside contact" rule as a doc comment: a recipient is inside when it is a mailbox of the same workspace or a workspace member's email; everyone else is outside and needs approval unless a V1 "Always allow" covers that agent and address.
- `packages/services/src/mail/types.ts`: `MailboxPort` (the methods V5.2 names: create mailbox, list threads, read thread, send, reply) and `EmailRoutingPort` (`createRule`, `deleteRule`), and the parsed inbound message shape.
- `packages/mcp/src/ports.ts`: mail port signatures and the input schemas of `mail_list`, `mail_read`, `mail_send`, `mail_reply`.

## Check
- `packages/db/src/schema.test.ts` and `foreign-keys.test.ts` cover the tables; a migration test shows an agent with `email_local` getting a `provisioning` mailbox row.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-27)

Checked against main at c5ba505. Where these differ from the scope above, they win.

- depends_on is V4.1 and V5.2. V4.1 is the only V4 task that changes the schema. Its migration is 0018 if nothing else merges first, so this one is 0019. `agents.email_local` exists since V3.1.
- No tasks table exists, because a task is one run (V2). Drop `mail_threads.task_id`. A thread keeps `session_id` (null until its first run), and each message keeps `run_id`. `threadForTask(runId)` finds the thread through the message's run or the run's session.
- Name the columns `from_address`, `to_addresses` and `cc_addresses` (JSON arrays), not `from`, `to` and `cc`. Rename `approval_id` to `request_id`, a foreign key to `run_requests`. Foreign keys: workspace, agent, mailbox, thread, session, run and request. `foreign-keys.test.ts` inserts parents first.
- Drop the backfill. `address` is not null and needs `MAIL_DOMAIN`, which a SQL migration can't know. V5.3 provisions on demand and sweeps active agents that have an `email_local` and no mailbox. The migration test covers the new tables only.
- `agents.email_local` is already unique across the deployment (V3.1). The unique index on `agent_mailboxes.address` stays as a second guard. A clash in another workspace is V3.4's "That address is taken", nothing new here.
- `TRIGGER_KINDS` gains `mail`. Text enums exist in TypeScript only, so no SQL changes. A mail trigger row has no token and no cron. `triggers.list` filters on `kind = "http"` (`triggers.ts` around line 308) and routines filter on `routine`, so the row shows in neither. V5.3 makes one per mailbox.
- Mail approvals need no new request kind. V5.5 opens a plain `approval` with `toolName: "mail_send"`, `toolUseId: "mail:<messageId>"` and `toolKey: "mail:<address>"`. V1's card, answer and Always allow then work unchanged (Always allow writes an `allow` rule for the tool key, `requests.ts` around line 440). Drop "the V1 approval kind for `mail_send`". Add `MAIL_SEND_TOOL = "mail_send"` and `mailToolKey(address)` to `shared.ts` so V5.5 and V5.10 agree. `NEEDS_YOU_KINDS` stays as it is.
- `EVENT_TYPES`: the listed ones plus `mail.expired` and `mailbox.failed`.
- Session origin `mail` belongs in `SESSION_ORIGINS` in `packages/services/src/runs/types.ts`, not `shared.ts`. V5.4 adds it in the services lane.
- Don't touch `packages/mcp/src/ports.ts`. V4.13 (mcp lane) edits it and can run at the same time. V5.8 adds the mail ports and the four input schemas. This task keeps `packages/services/src/mail/types.ts`, a new file: `MailboxPort` with the V5.2 method list, `EmailRoutingPort` (`createRule`, `deleteRule`, `findRule`) and the parsed inbound message.
- Inside rule for the doc comment: a recipient is inside when it is a mailbox of the same workspace, or an email that `MemberDirectory` (`desk-api.ts:56`, `(email, clerkOrgId) => userId | null`) resolves. Dom's open question, plan default: a list of company domains does not count as inside.
