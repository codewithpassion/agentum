Tables, enums, ports and tool shapes for agent mail, shaped by the V5.2 decision. The only V5 task that changes the schema.

## Scope
- New `packages/db/src/schema/mail.ts`: `agent_mailboxes` (id, workspace_id, agent_id unique, address unique across the deployment, routing_rule_id, status `provisioning | active | failed | disabled`, last_error, created_at); `mail_threads` (id, workspace_id, mailbox_id, external_thread_id, session_id, task_id, subject, last_message_at; unique mailbox and external thread); `mail_messages` (id, thread_id, direction `in | out`, from, to, cc, subject, snippet, external_message_id, status `received | held | sent | rejected | expired | bounced | failed`, approval_id, run_id, created_at). Mail bodies stay in the mailbox backend; D1 keeps the index the desk and profile need.
- V3 reserves `agents.email_local`, unique per workspace. The address is `<email_local>@<domain>`. If all workspaces share one mail domain, the address must be unique across the deployment: the unique index on `agent_mailboxes.address` enforces it, and V5.3 maps a clash to the V3 "That address is taken" error. The migration creates a `provisioning` row for every active agent with an `email_local`. `bun run generate`, commit `migrations/` and `meta/`.
- `packages/db/src/shared.ts`: `TRIGGER_KINDS` gains `mail`; session origin `mail` with external key `mail:<mailboxId>:<threadId>`; `MAIL_MESSAGE_STATUSES`, `MAILBOX_STATUSES`; `EVENT_TYPES` gains `mail.received`, `mail.held`, `mail.sent`, `mail.rejected`, `mail.bounced`, `mailbox.provisioned`; the V1 approval kind for `mail_send`.
- The "outside contact" rule as a doc comment: a recipient is inside when it is a mailbox of the same workspace or a workspace member's email; everyone else is outside and needs approval unless a V1 "Always allow" covers that agent and address.
- `packages/services/src/mail/types.ts`: `MailboxPort` (the methods V5.2 names: create mailbox, list threads, read thread, send, reply) and `EmailRoutingPort` (`createRule`, `deleteRule`), and the parsed inbound message shape.
- `packages/mcp/src/ports.ts`: mail port signatures and the input schemas of `mail_list`, `mail_read`, `mail_send`, `mail_reply`.

## Check
- `packages/db/src/schema.test.ts` and `foreign-keys.test.ts` cover the tables; a migration test shows an agent with `email_local` getting a `provisioning` mailbox row.
- `bun run check && bun run test && bun run build` pass.
