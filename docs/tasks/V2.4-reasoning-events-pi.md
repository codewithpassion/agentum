Cloud runs drop Pi's `thinking` parts (`eventOfPart` in `apps/web/src/server/pi-run-events.ts` returns nothing for them). The thread's reasoning container and the action log's thoughts need them. If V1 already records reasoning for cloud runs, close this task at planning.

## Scope
- `apps/web/src/server/pi-run-events.ts` `eventOfPart`: a non-empty `ThinkingContent` part becomes `message.reasoning` with `{ text }`, in order with the text and tool calls of the same message.
- Redacted or signature-only thinking becomes nothing.
- Make sure V1's live stream publishes the new event the way it publishes `message.assistant` from `PiRun`.

## Check
- `apps/web/src/server/pi-run-events.test.ts`: an assistant message with thinking, text and a tool call gives three events in that order; empty and redacted thinking give none.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-26)

Checked against main at 4da1878. Where these differ from the scope above, they win.

- `ThinkingContent` in pi-ai 1.3.0 is `{ type: "thinking", thinking, thinkingSignature?, redacted? }`. Map `thinking` when it is non-empty and `redacted` is not true.
- Publishing needs no work here. V2.1 adds `message.reasoning` to `RUN_EVENT_TYPES` and `STREAM_EVENT_TYPES`, and PiRun's events already reach the stream through `ingestRunEvents`. `pi-run-deltas.ts` stays as is: thinking never becomes a delta frame.
- `toRunEvents` numbers the whole slice from 1, so a cloud run that spans the deploy gets shifted seqs and skips a few later events (seqs at or below `lastSeq` are dropped). Accept it and note it in the review file.
