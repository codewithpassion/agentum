Found by the local end-to-end run on 16 Oct 2026 and approved by Dom. Asked to "attach" a file it had written, a real Claude Code agent said it can't attach files. The chip only appeared after it was told to write `[ATTACHMENT:<abs path>]`. Nothing in the claim (`packages/services/src/runs/machine-claim.ts`) or the daemon (`apps/daemon/src/executor.ts`) tells the agent about the marker.

## Scope

Every run's system prompt tells the agent, in one or two short sentences, how to return a file: write it inside its work directory and put `[ATTACHMENT:<absolute path>]` on its own line in the final answer. Build the sentence from the marker definition in `@repo/protocol` so the wording and the parser can't drift. Add it in one place (the daemon, where it already appends to the system prompt, or the claim payload), for both single-user and multi-user machines, after the agent's own instructions.

## Check

A daemon test shows the system prompt passed to the SDK contains the attachment sentence, and that the path pattern in it matches what the attachment parser accepts. Live, in local dev with the compiled daemon and a real Claude Code agent whose instructions say nothing about files: "write hello.txt with the word hi and attach it" gives a reply with a working file chip. `bun run check && bun run test && bun run build` pass.
