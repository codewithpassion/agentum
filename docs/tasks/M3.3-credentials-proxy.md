From `docs/architecture/build-plan.html#m3`. Access lane. Depends on M0.5. Pattern: flightdex-v2 `acting?` resolution. The live test through Claude Code needs M1.4, which is done. The `mcpServers` builder plugs into the M1.3 claim route.

## Scope

`createCredentialsService({ db, atomic, secretsKey, clock, fetch })`. `resolve({ connectorId, agentId, onBehalfOfUserId })` with the three modes, the `not_assigned` result, and the `single_user` machine rule.

`/api/proxy/:connectorId` in the order the overview gives: token and row check, assignment row or 403, resolve (revoked counts as `needs_auth`), forward, 5 minute cap (Dom's answer to open question 9), one `connector.call` event.

Refresh ahead when `expires_at` is within two minutes; on a refresh, take the `refreshing_until` lease first, only the winner calls the token endpoint, losers poll `version` for up to 5 s.

`mcpServers` builder used by the claim route. Needs-auth error text carries the Connect path, and the Slack gateway sends it as an ephemeral message.

## Check

`credentials.test.ts` covers the mode matrix:

- on behalf of a user with and without a credential, no user, each of the three modes, never the agent's credential for a person in `user_or_agent`;
- the chain case: user without a credential starts run A, run A's token starts run B on another agent, B's resolution is `needs_auth`;
- a `single_user` machine run on behalf of a non-enrolling user resolves the agent credential and records why.

`proxy.test.ts`:

- a run token for a finished or interrupted run gets 401;
- a connector not assigned to the run's agent gets 403 before any credential lookup;
- a revoked credential gets the `needs_auth` error;
- the stub sees the real header and never the run token;
- `--fail-once` makes the next call refresh and succeed with `version = 2`;
- two concurrent calls that both see a 401 produce exactly one token-endpoint call at the stub (`--count-token-calls`) and both succeed;
- a refresh racing a revocation leaves the row `revoked` and the stale holder's write is rejected;
- a refresh racing a re-authorisation leaves the newer grant;
- a lease holder that dies leaves a lease that expires in 30 s and the next caller takes it;
- `--fail-once` with no refresh token sets `needs_auth` and appends `connector.needs_auth`;
- `--sleep 310` produces `connector.timeout`.

Live with M1.4: an agent on a machine calls the stub's `echo` through the proxy after a four-minute idle wait (so more than two leases have passed); the transcript shows `tool.call` and the log shows `connector.call`.

Staging part: blocked until O.1. A live `--sleep 240` call through the deployed Worker completes (this is where the 5 minute cap from open question 9 is proven or lowered).
