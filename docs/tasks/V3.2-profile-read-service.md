The one-page profile reads every row in one call instead of the eight tabs' separate queries. The "Ask me before it…" toggles read and write V1's approval rules for the agent.

## Scope
- New `packages/services/src/agent-profile.ts` `createAgentProfileService`, built in `compose.ts` from the existing services, not new queries where a service already answers.
- `profile(principal, agentId)` returns the header (name, slug, runtime, model, machine, status, `email_local`, a waiting run if any) and these rows:
  - Does and Voice: instructions and soul.
  - Tools: assigned connectors from `connectors.ts` assignments, plus granted secrets as hidden chips from `secrets.ts`.
  - Skills: assigned skills, marking a proposed version.
  - Hands to: `hands_to`. Receives from: the agents whose `hands_to` names this one.
  - Starts on: triggers, routines, and the Slack app mention.
  - Channels: the Slack app's status. Email shows as "reserved" until V5.
  - Library: `agents/<slug>/` as home and `libraryPaths` from runtime config, shown read and write. Enforcing access is V4's.
  - Recent tasks: `tasks.list({ agentId, limit: 5 })` from V2.9.
- Ask before: `askBefore(principal, agentId)` lists the agent's gateable actions (connector tools that aren't read-only and the built-in side-effect tools V1 gates), each with a plain label ("Xero: create bill") and its V1 rule (ask, or always allowed). `setAskBefore(principal, agentId, action, ask)` writes through V1's rule service.
- New thin `apps/web/src/server/trpc/agent-profile-router.ts`, added to `runtime-router.ts`.

## Check

## Refinements (2026-10-26)

Checked against main at ae74008. Where these differ from the scope above, they win.

- Read-only flags: `CachedTool` (`connectors/mcp.ts:3`) keeps only `name` and `description`. Keep `annotations.readOnlyHint` from `tools/list` as `readOnly` in the probe and in `toolSchema` (`connectors.ts:214`). The `tools` column is JSON text, so no migration. Old rows read as not read-only until their next refresh. V3.5's catalogue reads the same flag.
- Ask before: lift `BUILTIN_TOOL_KEYS` and `toolKeySuggestions` from `apps/web/src/components/agent/settings/ask-rules-logic.ts` into the service. Rule keys are `<serverKey>/<tool>`, with `connectorServerKeys` from `@repo/protocol/server-keys` in assignment order, so they match what V1's gates compute. Skip tools outside an assignment's `allowedTools` (X.7). Built-ins: `bash`, `write`, `edit`, `web_fetch`, `run_script`, `run_skill_script`.
- `setAskBefore(..., true)` is `requests.setRule` with mode `ask`. `false` is `removeRule`, since no row means allow. A rule in mode `allow` (from Always allow) shows as off.
- Sources: `connectors.assignments`, `secrets.grantsOf`, `skillsStore.assignments` or `forAgent`, with a proposed version from `skillsStore.proposals` (as `desk.ts` reads them), `triggers.list` and `routines.list` filtered to the agent, `slackApps.list` filtered to the agent, `libraryPathsOf` from `library/sync-paths.ts`, and `tasks.list({ agentId, limit: 5 })`. `soul`, `handsTo` and `emailLocal` come from `AgentRecord` (V3.1).
- Waiting run: one query on `runs` for the agent with status `waiting` (`runs_agent_status_idx`), newest first, so the header's "Paused on task #…" does not depend on the 5 recent tasks.
- `agents.get` returns any status, so `profile` itself answers not_found for a draft.
