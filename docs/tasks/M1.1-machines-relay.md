From `docs/architecture/build-plan.html#m1`. Builds on contracts C1, C2 and C4. Reuse: Ariadne enrolment, connect, relay and presence (copy). Paths are in `docs/architecture/reuse.html`.

## Scope

Enrol tokens (`hm_enr_`, 15 minutes, single use). Machine credentials (`hm_mach_`, hashed). `machines.enrolled_by` and `single_user` set from the enrol call. `POST /api/machines/enroll`. `GET /api/machines/connect` (upgrade, then 4401 or 1012 inside the socket).

`MachineRelay` with hibernation: `hello` and `hello_ack`, ping with last-ping in DO storage, an alarm that marks the machine offline in D1 after 90 s, machine online and offline events, revoke. On `hello` the relay reads every queued or offered run for the machine's agents and offers them oldest first. The machine adapter's dispatch and the sweep also offer through the DO stub.

Carried over from M0 reviews:

- Decide whether `hello.agents` carries slugs or ULIDs. The M0.6 fixture uses slugs, while `offer.agentId` and `claim.agent.id` are ULIDs.
- The connect route replaces the dev-only `/api/machines/ping-do` from M0.0 and M0.7. Remove it.

## Check

`bun test apps/web` covers the relay logic with a fake socket:

- `hello` gets `hello_ack`;
- a replacing connection closes the old one with 1012;
- a revoked credential closes with 4401;
- the alarm after silence marks the machine offline;
- `hello` with two queued runs produces two offers, oldest first.

Then, against `bun run dev`:

- `bun scripts/dev/enroll-token.ts` prints a code;
- `bun scripts/dev/fake-daemon.ts --code hm_enr_...` enrols, connects and prints `hello_ack`;
- `bun scripts/dev/machines.ts` lists the machine as online;
- kill the script, and within two minutes `machines.ts` lists it offline and an event exists;
- with the fake daemon stopped, start a run on a fake-runtime agent assigned to the machine, start the fake daemon, and the offer arrives.
