Found by Dom on staging on 19 Oct 2026. An agent posted to a channel with `slack_send` (M5.7) and wrote "@dominik" to tag Dom. Slack showed the plain text "@dominik" with no mention, because Slack only turns `<@U…>` (user id) into a mention. Channel mentions work the same way (`<#C…>`), as do `<!here>` and `<!channel>`.

## Scope

- `slack_destinations` returns, for each linked person, the Slack user id and the exact mention text (`<@U…>`), and for each channel the `<#C…>` form.
- `slack_send` turns `@name` into a real mention when the name matches a linked person, by Harbourmaster name, Slack display name or Slack username, case-insensitive, whole word only. It leaves `@name` alone when nothing matches or when two people match, and says so in the tool result ("@dominik matched nobody, sent as plain text"). Text the agent already wrote as `<@U…>` passes through unchanged.
- `@here` and `@channel` are not converted. Notifying a whole channel stays off unless a later task adds it.
- The tool descriptions say how to mention someone: use the mention text from `slack_destinations`, or `@name` for a linked person.
- Apply the same conversion to the automatic reply a run posts in a Slack thread (the gateway's `post` in `packages/services/src/slack/gateway.ts`), so a mention works there too.

## Check

- Tests: `@dominik` for a linked person becomes `<@U…>`; an unknown and an ambiguous name stay plain text and are reported; `<@U…>` passes through; `@here` stays plain; whole-word only (an email address such as `a@dominik.com` is untouched); the thread reply gets the same conversion.
- `bun run check && bun run test && bun run build` pass.
- Live on staging (Dom and controller): Comms-Chief posts "@dominik hello" to #new-channel and Dom gets a real mention.
