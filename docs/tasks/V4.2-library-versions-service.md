Every library write keeps the bytes it replaced, so people can compare and restore. Today `packages/services/src/library.ts` only has etag compare-and-set and no history.

## Scope
- `write`, `remove`, `move` in `packages/services/src/library.ts` add a `library_versions` row in the same `atomic` batch as the entry and the event. `write` also puts the bytes at the immutable version key (`LibraryBlobs.put` without `ifEtag`). `remove` writes a tombstone. `move` rewrites the path of the moved rows' versions, so history follows a rename.
- New methods: `versions(principal, path)`, `readVersion(principal, versionId)`, `compare(principal, a, b)` returning both texts (or a "binary" marker), `restore(principal, versionId, { ifEtag })` writing a new version with op `restore` and a `library.restore` event.
- `pruneVersions(now)`: drops versions older than `LIBRARY_VERSION_KEEP_DAYS` beyond the newest `LIBRARY_VERSION_KEEP_MIN` per path, deletes their blobs in batches, and removes tombstoned history after the window. Safe to run twice.
- An optional `notify(change: LibraryChange)` dependency of `createLibraryService`, called after each committed write, delete, move or restore. V4.6 wires it.
- tRPC: `versions`, `readVersion`, `compare`, `restore` in `apps/web/src/server/trpc/library-router.ts`.

## Check
- `packages/services/src/library-versions.test.ts`: write twice then list two versions; restore makes version 3 with the old bytes; compare returns both texts; move keeps history under the new path; delete then restore brings the file back; prune keeps the newest 20 and everything inside 30 days and deletes the blobs; `notify` fires once per committed change and not on a failed compare-and-set.
- `bun run check && bun run test && bun run build` pass.
