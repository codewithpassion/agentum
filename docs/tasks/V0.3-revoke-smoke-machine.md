Must-fix 1 from the V0 gate (`docs/reviews/V0-1.md`). V0.2's cleanup left machine `v02-smoke` enrolled and unrevoked on production, and its credential on disk. The machine is `single_user`, so a daemon started with that file gets production runs as Dom's user. The Machines UI has no revoke button, but the `machines.revoke` tRPC procedure exists (`apps/web/src/server/trpc/machines-router.ts:15`). Revoking a smoke fixture is part of the V0.2 cleanup Dom approved.

## Scope

- Sign in on production with `bun run agent-login --env production` in a fresh browser session; never print or log the URL.
- Call the `machines.revoke` tRPC mutation for `v02-smoke`, with the `machineId` from `harbourmaster-wt/tmp/V0.2-smoke/home/.harbourmaster/config.json` (read only that key) or from `machines.list`.
- Then delete `harbourmaster-wt/tmp/V0.2-smoke/home`.
- No repo changes.

## Check

- `machines.list` on production shows `v02-smoke` as revoked.
- `harbourmaster-wt/tmp/V0.2-smoke/home/.harbourmaster/config.json` no longer exists.
