From `docs/architecture/build-plan.html#m4`. Automation lane. Registers its tick with the `scheduled()` registry from M0.7 and relies on the queued-run sweep from M0.4. Reuse: bruce-next `cron.ts` (copy). Paths are in `docs/architecture/reuse.html`.

## Scope

`kind: "routine"` with cron, timezone (default from the workspace), prompt, `next_run_at`.

The tick job, for each due row, runs one atomic write: insert the run with `request_id = trigger:<id>:<occurrenceIso>` and `UPDATE triggers SET next_run_at = <next> WHERE id = ? AND next_run_at = <due>`; then dispatch. A duplicate `request_id` from an overlapping tick is caught and the existing run read back. A run left queued by a crash after the write is picked up by the sweep from M0.4.

`consecutive_errors` with auto-disable at 5. UI with a few presets that compile to cron.

## Check

`cron.test.ts` copied.

`routines.test.ts` with an injected clock:

- a `*/5` routine fires once per slot, never twice;
- two ticks for the same minute produce one run, and the second tick reads it back without inserting;
- a tick whose atomic write fails leaves `next_run_at` at the due slot so the next tick fires it;
- a crash after the write and before dispatch leaves a `queued` run that the sweep offers within 60 s of simulated time;
- a DST change in Australia/Sydney does not skip or double.

Live probe, not a gate: create a `* * * * *` routine, hit the scheduled handler URL twice a minute apart, see two runs.
