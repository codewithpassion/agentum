Editor mode writes the same config as the agent profile, so the map's mutations call the same service methods and keep the same rules (approve-first triggers, approvals, workspace authz).

## Scope
- `packages/services/src/map.ts`: `connectTrigger(principal, triggerId, agentId)`, `disconnectTrigger`, `plugTool(principal, agentId, tool)` and `unplugTool`, where a tool is a connector, the computer, the browser or a skill. Each goes through the trigger, agent and skills services the profile uses, with no direct table writes. `savePositions(principal, positions[])` upserts `map_positions`.
- One `map.edited` event per mutation, alongside the events the underlying services already write.
- tRPC procedures in `map-router.ts`.

## Check
- `map.test.ts`: each mutation leaves the same rows as the matching profile action, an agent-proposed trigger stays approve-first, invalid pairs are refused (a trigger in another workspace, computer on a machine agent), and positions upsert.
- `bun run check && bun run test && bun run build` pass.
