Asked for by Dom on 16 Oct 2026. Nothing has been deployed with the Harbourmaster schema yet, so the 16 migrations in `packages/db/migrations` (0000_notes to 0015) can become one. That leaves a single baseline for the first remote apply.

## Scope

Replace every file in `packages/db/migrations/` and `migrations/meta/` with one migration that creates the current schema, generated by drizzle-kit from `src/schema/*.ts` (`bun run generate` in `packages/db` after clearing the folder), so that `meta/_journal.json` and a single snapshot match it and the next `bun run generate` produces no diff. Name it with a new tag (for example `0000_init`), not one of the old file names. Wrangler records applied migrations by name, and the remote database may still list `0000_notes`.

Carry over everything drizzle-kit doesn't generate, appended by hand at the end of the file:
- The `events` triggers that refuse UPDATE and DELETE (`0002_foundation.sql`, re-added in `0004_*.sql`).
- Any other hand-written SQL in the old files: triggers, partial or expression indexes, backfills that still matter, and seed rows.
Diff the old files' hand-written parts against the generated output to find them. Don't carry the `notes` table or anything a later migration dropped.

Update every place that names a migration file or count: `CLAUDE.md` (the triggers rule names `0002_foundation.sql` and `0004_*.sql`), `packages/db/README.md`, `docs/HANDOVER.md`, tests that load migrations (`migrated()` and similar), and scripts. Keep the "a migration that recreates `events` must add the triggers back" rule, pointing at the new file.

Local databases created from the old files no longer match. Document the reset in `packages/db/README.md`: delete `apps/web/.wrangler/state/v3/d1` and re-apply.

## Check

- `ls packages/db/migrations` shows one `.sql` file and `meta/` with one snapshot.
- `bun run generate` right after gives "No schema changes".
- On a fresh local database, `bunx wrangler d1 migrations apply DB --local` in apps/web applies one migration with no errors.
- A schema comparison shows the same tables, columns, indexes and triggers as a database built from the old 16 files. Use `sqlite_master` from both, normalised, and diff them; record the result in the review file.
- A test shows an UPDATE and a DELETE on `events` are refused after the single migration.
- `bun run check && bun run test && bun run build` pass. Then the local dev server starts and `bun run e2e:sessions` and `bun run e2e:log` pass against it.
