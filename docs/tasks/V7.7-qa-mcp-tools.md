Agents use the board through platform MCP tools. V7.12 wires the port.

## Scope
- `packages/mcp/src/ports.ts`: a `QaPort` (ask, answer, list, get).
- `packages/mcp/src/tools/qa.ts`: `qa_ask(title, body)`, `qa_list(status?)`, `qa_read(id)` and `qa_answer(id, body)`. Descriptions say when to ask the board rather than the user (ask-user is for the person running the task).
- Register the tools for every agent.

## Check
- `packages/mcp/src/tools/qa.test.ts` with a fake port: schemas and limits, results, and failures as tool errors.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-27)

Checked against main at 24c28ad. Where these differ from the scope above, they win.

- depends_on stays V7.1.
- Follow V6.5's pattern: `McpPorts` gains an optional group `qa?: QaPort`, and `ServerOptions` in `server.ts` gains `qa?: boolean`. `harbourmasterTools` adds the tools only when both are set, so `apps/web` compiles until V7.12 wires the port.
- Annotations from `tools/define.ts`: `READ_ONLY` for `qa_list` and `qa_read`, a write annotation for `qa_ask` and `qa_answer`. V3.9's dry-run gate in `register.ts` then skips the writes, and `readOnly` servers (read-only keys) drop them.
- Input limits come from `QA_TITLE_MAX` and `QA_BODY_MAX` in `@repo/db/shared` (V7.1).
- Same-file overlaps in the mcp lane: `ports.ts`, `server.ts`, `tools/define.ts` and `tools.test.ts` with V4.13, V5.8 and V6.5.
