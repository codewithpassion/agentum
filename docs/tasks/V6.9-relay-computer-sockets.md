The relay half of agentum `modules/computer/relay.ts`, hosted inside the existing `MachineRelay` under the one-DO decision from V6.1, so a machine's daemon and its computer share one object.

## Scope
- `apps/web/src/server/computer-relay-core.ts` is ported from agentum `relay.ts`, with its pure logic testable like `relay-core.ts`. It covers the v1 hello and capability store, request and reply correlation by id, `MAX_IN_FLIGHT_EXEC` and the queue depth, staleness checks, orphaned-request cancel on reconnect, replace (4409), revoke (4401) and the desktop lease (agent and human holds with idle backstops, and the clipboard cleared on hand-back).
- `apps/web/src/server/relay.ts`: accept sockets with tags (`daemon`, `computer`). Route `webSocketMessage` and `webSocketClose` by tag, and answer the bare `ping` with `setWebSocketAutoResponse` so idle computers stay hibernated. Daemon behaviour stays the same, and `relay.test.ts` still passes.
- RPC methods on `MachineRelay`, exposed through `relay-port.ts`: `computerExec`, `filePut`, `fileGet`, `desktopScreenshot`, `desktopInput`, `clipboardGet`/`Set`, `takeHumanLease`, `releaseHumanLease` and `computerStatus`.
- `apps/web/src/server/routes/machines.ts`: `GET /api/machines/computer` authenticates with `machines.authenticate(header, "computer")` and hands the upgrade over with identity headers, refusing with 4401 the same way `/connect` does.
- Presence: the hello and the alarm call `markComputerOnline`/`Offline` from V6.4.

## Check
- `apps/web/src/server/computer-relay-core.test.ts`, ported from agentum `relay.test.ts` with fake sockets and storage: hello, exec round trip, in-flight cap, stale socket, replace, revoke, lease rules and orphans. `relay.test.ts` covers mixed tags on one object. `routes/machines.test.ts` covers the computer upgrade and a daemon credential being refused there.
- `bun run check && bun run test && bun run build` pass.
