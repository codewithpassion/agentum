The shared sync core needs to know which roots it may push, and to pull a few announced paths without walking every root. The daemon and the VM both use it.

## Scope
- `packages/library-sync/src/types.ts`: roots become `{ path, mode }[]`.
- `sync-out.ts`: a local change under a `read` root is not sent. It is reported in a new `refused` list, and the next sync in puts the library's bytes back.
- `sync-in.ts`: an `only?: string[]` option pulls just those paths (and removes them locally when the library deleted them), still never overwriting an unsent local edit.
- New `coalesce.ts`: a pure debouncer that gathers changed paths for a quiet window (default 1.5 s, at most 5 s) and hands one batch on. The daemon watcher and the VM loop use it.
- `index.ts` barrel exports the new options and the debouncer.

## Check
- `sync-out.test.ts`: an edit under a read root is refused and not written. `sync-in.test.ts`: `only` pulls one path, removes a deleted one, keeps an unsent edit. `coalesce.test.ts` with a fake clock: bursts batch, the 5 s cap flushes.
- `bun run check && bun run test && bun run build` pass.
