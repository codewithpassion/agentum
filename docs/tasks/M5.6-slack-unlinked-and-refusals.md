Asked for by Dom on 19 Oct 2026, after connecting a Slack app on staging. Two problems showed up:
- The reply to a Slack user Harbourmaster can't match names Dom: `UNLINKED_REPLY` in `packages/services/src/slack.ts:63` is "I don't know you yet. Ask Dom to add you." It also doesn't say how matching works, so the person can't fix it.
- A refused event leaves no trace. `receive` in `packages/services/src/slack.ts:415-428` returns `unauthorized` for an unknown app id, a bad signature or a team mismatch, and the route answers 401 with nothing in the Log. A wrong signing secret on staging took a log tail to find.

## Scope

- Change the unlinked reply to name no person and say what to do, in one or two sentences, for example: "I don't know you yet. Ask a Harbourmaster admin of this workspace to invite you, using the same email address as your Slack profile." Also cover the case where Slack returns no email (the user's email is hidden): say so.
- Record a refused event in the Log of the app's workspace when the app is known (bad signature or team mismatch), as a `slack.event_refused` event with the reason (`signature`, `team`) and the app id. Never include the body, the signature or any secret. An unknown app id has no workspace, so it gets only a `console.warn` line with the app id. Rate-limit the Log entry to one per app per reason per 10 minutes, so a flood of bad requests can't fill the Log.
- Show `slack.event_refused` in the Log UI with a short label and the reason, such as "Slack event refused: signature didn't match. Check the signing secret in the agent's Slack settings."

## Check

- Service tests: bad signature and team mismatch each write one event with the reason, a second one within 10 minutes writes none, an unknown app id writes none; the unlinked reply text has no person's name and the hidden-email case gets its own text.
- `bun run check && bun run test && bun run build` pass.
- Live on staging (controller): a request signed with a wrong secret shows the refusal in the Log.
