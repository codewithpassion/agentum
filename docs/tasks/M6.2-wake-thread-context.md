From M6 gate round 1 (docs/reviews/M6-1.md, finding 1), raised to a task by Dom on 16 Oct 2026. A woken agent gets only the post's text as input (`packages/services/src/inbox.ts:416`). It doesn't get the thread id or the other posts, so it can't call `inbox_read` or `inbox_post` on its own thread, and agent B, woken by A, never sees the person's earlier posts.

## Scope

The wake input names the thread id, says how to reply in it (`inbox_post` with that thread id), and includes the last few posts before the waking one (author and text, at most 10 posts or a fixed character cap, oldest first). Earlier posts are marked as untrusted quoted content, kept apart from the instruction text, so a post can't pose as instructions. The waking post stays the main input. Build the input in the inbox service, with no new tables.

## Check

`inbox.test.ts`: a wake from a thread with earlier posts gives an input that contains the thread id and those posts in order, inside the untrusted block, and respects the cap. A wake in a new thread contains the thread id and no earlier posts. A post whose text looks like instructions shows up only inside the untrusted block. Live, with the fake runtime or a real agent in local dev: an agent mentioned in a thread can reply to that thread through `inbox_post`. `bun run check && bun run test && bun run build` pass.
