Scope
- `packages/mailbox/src/store.ts`: insert attachments in chunks in `insertInbound` and `createEmail`, so that no statement binds more than 100 parameters. Chunk `findThreadByIds` (or keep only the newest 49 ids, documenting the choice). Replace `attachmentsOf(emailIds)` with a join on the thread, or chunk it.
- Put the limit in one constant (for example `DO_MAX_BOUND_PARAMS = 100`) beside the store. Pass a smaller chunk size into tests.

Check
- `packages/mailbox/src/store.test.ts` adds a bound-parameter guard. A test drizzle wrapper (or `bun:sqlite` with `SQLITE_LIMIT_VARIABLE_NUMBER` lowered, if available) throws above 100 parameters. Under that guard, mail with 20 attachments stores, a `References` header with 120 ids resolves its thread, and a thread with 150 messages reads back with its attachments.
- `bun run check && bun run test && bun run build` pass.
