## Scope

`MachineRuntime.dispatch` marks the run `offered` and tells the relay.

`POST .../claim` is one conditional write with the predicate from seam 3: status queued or offered, agent on this machine, no running run for the agent, no older queued run for the session, no pending files. It mints the run token here and returns run, agent, session, token, `mcpServers` (the platform entry now, connector entries once M3 lands), `inputFileIds` and instructions.

`.../events` with the sequence check and the 409 rule. `.../heartbeat` extends `lease_until` by 90 s and returns `{ }`, or 409 unless running. `.../complete` calls `completeRun`, including `aborted` for an interrupted run.

Carried over from M0 reviews:

- `claimRun` is system-only since M0.4. This task adds the machine claim.
- Write `lease_until` in `toISOString()` format in claim and heartbeat. The run-token check compares it as text, and a SQLite `datetime()` value would refuse tokens silently (M0.5).
- Reconcile the `usage`, `agent` and `session` shapes in the C4 claim and complete bodies with the runs service (M0.6).

## Check

`runs-machine.test.ts` drives the routes with the machine principal:

- queued to offered to running to done;
- a second claim of the same run gets 409;
- two claimers of two queued runs for one agent: one wins, the other gets 409;
- a claim for a newer run while an older queued run exists on the same session gets 409;
- a claim for a run whose agent lives on another machine gets 403;
- a run with `pending_files` cannot be claimed;
- the claim-time token is still accepted by the proxy resolver after three lease periods with heartbeats in between, and refused the moment the run is interrupted;
- after the lease passes the reaper makes the run `interrupted`, a late `events` or `complete` call gets 409, and `complete { status: "aborted" }` is accepted once.

`bun scripts/dev/fake-daemon.ts --echo` completes a real run started from the agent page.
