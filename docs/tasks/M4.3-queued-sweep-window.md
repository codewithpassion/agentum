Found by the M4.2 reviews on 16 Oct 2026, approved by Dom as its own task. The queued-run sweep in `packages/services/src/runs.ts` (from M0.4) looks at a window of 100 runs. That window can fill with queued runs that are never claimed (for example, a machine that stays offline), and then a healthy routine's run left behind by a crash is never swept.

## Scope

Change the sweep's query so runs it can't act on don't keep the runs it can act on out of its window. For example, order or filter so each pass makes progress past runs it has already looked at, or select only runs that are due for the sweep's action. Keep the per-pass limit. Don't change what the sweep does to a run, only which runs a pass sees.

## Check

A `runs` service test seeds more than 100 never-claimed queued runs plus one crash-left run of a healthy routine that sorts after them, and shows one sweep pass (or a bounded number of passes) handles the crash-left run. The test fails on the current code. The existing sweep tests still pass. `bun run check && bun run test && bun run build` pass.
