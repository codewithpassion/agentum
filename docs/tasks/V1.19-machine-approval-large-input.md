From the V1 gate review (`docs/reviews/V1-1.md`, MF1).

## Scope

- Make `requests.open` accept the daemon's truncated string preview for an approval. Two options: let `openInputSchema`'s approval `input` take a string as well as `payloadSchema`, with the string shown as is, or wrap the string in the route as `{ preview: "<text>" }` before calling `open`. Either way the stored display must pass `approvalDisplaySchema`, and the scrub and masker still run on it.
- Leave the daemon's 8192-byte preview rule as it is.
- Take the second option (wrap in the route): V1.20 changes `packages/services/src/requests.ts` at the same time, so this task leaves `packages/services` alone.

## Check

- `routes/machine-requests.test.ts`: a POST with a 9 KB input (the daemon's string preview) opens a request, answers 200 with `pending`, and stores a truncated display with an `sk-` token in it redacted.
- `apps/daemon/src/approvals.test.ts`: the body for an input over the limit passes `createRequestBodySchema`, and the Worker's open input schema accepts it (import the schema, no network).
- `bun run check && bun run test && bun run build` pass.
