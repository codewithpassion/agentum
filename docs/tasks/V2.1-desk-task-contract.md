The contract for V2. Every other V2 task builds on the enums, types and event shape defined here, and no other V2 task touches `packages/db/src/schema` or generates a migration.

## Scope
- `packages/db/src/shared.ts`: `ACTION_LOG_KINDS = ["thought", "tool_call", "tool_result", "note", "error"]`, `DESK_LANES = ["needs_you", "running", "done"]`, `NEEDS_YOU_KINDS` (approval, question, skill_proposal, trigger_proposal, routine_proposal, inbox_reply; V4 and V6 append theirs), `BAND_TONES = ["ok", "waiting", "running", "error"]`.
- Shared, browser-safe types in `@repo/db/shared`: `KeyChip { key, value }`, `ReceiptStep { index, kind (trigger | message | tool | skill | approval | question | result | error), title, detail, in: KeyChip[], out: KeyChip[], countToNext: { n, noun } | null, state (done | running | paused | failed), eventIds }`, `ActionLogEntry { kind, at, text, eventId }`, `StatusBand { tone, text }`, `DeskCard` (id, kind, lane, agentId, runId?, threadId?, title, band, startedBy, at, needsYouKind?).
- A `message.reasoning` event type with payload `{ text }`, capped like `message.assistant`, unless V1 already added an equivalent. Add it to `EVENT_TYPES` and to the payload shapes in `packages/services/src/events/payload.ts`.
- Schema: two indexes on `runs` for the desk queries, `(workspace_id, status)` and `(workspace_id, finished_at)`. Run `bun run generate` in `packages/db` and commit `migrations/` with `meta/`.
- No behaviour change. Runtimes start writing `message.reasoning` in V2.3 to V2.5.

## Check
- `packages/db` test that the migration applies on a fresh `migrated()` database and the new indexes exist; a type test that the shared module imports no drizzle.
- `bun run check && bun run test && bun run build` pass.
