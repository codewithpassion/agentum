The contract for V3. It holds every schema change the profile, the builder and the dry run need. No other V3 task touches `packages/db/src/schema` or generates a migration.

## Scope
- `packages/db/src/schema/agents.ts`: `soul` (text, not null, default `''`), `hands_to` (JSON array of agent ids, default `'[]'`), `email_local` (nullable text, the reserved local part, with a unique index on `(workspace_id, email_local)`). The mailbox and domain are V5's.
- `AGENT_STATUSES` gains `draft`: a builder agent that is not created yet. Lists, the desk, Slack and triggers ignore drafts.
- `packages/db/src/schema/runs.ts`: `dry_run` (boolean, default false).
- `EVENT_TYPES`: `agent.address_reserved` and `run.dry_run_skipped` (payload `{ tool, summary }`: what the run would have done, with no secret values). Add both payload shapes to `packages/services/src/events/payload.ts`.
- Shared in `@repo/db/shared`: `VOICE_PRESETS` (brief, careful, friendly, formal), `AGENT_TEMPLATE_IDS` (sort_inbox, chase_invoices, research_topic), `PROFILE_FIELDS` (does, voice, rules, tools, skills, starts_on, hands_to, runs_on, library, address) and `ProfileGap { field, question }`.
- Add a `dry_run` session origin in `packages/services/src/runs/types.ts` `SESSION_ORIGINS`.
- Run `bun run generate` in `packages/db` and commit `migrations/` with `meta/`. The migration only adds columns and an index, so no table is recreated.

## Check
- `packages/db` test: the migration applies on a fresh `migrated()` database, existing agents get `soul = ''` and `hands_to = '[]'`, and a second agent with the same `email_local` in one workspace fails while one in another workspace succeeds.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-26)

Checked against main at ae74008. Where these differ from the scope above, they win.

- Dom decided on 26 Oct that one mail domain serves all workspaces. Make the index unique on `email_local` alone, not on `(workspace_id, email_local)`. The Check flips: a second agent with the same `email_local` in another workspace also fails. SQLite allows many NULLs, so agents without an address are fine.
- `payload.ts` has no per-type payload shapes (V2.1 found the same), so nothing goes there.
- `run.dry_run_skipped` goes in `EVENT_TYPES`, in `STREAM_EVENT_TYPES` (`apps/web/src/server/session-stream-frames.ts`) so V3.13 sees it live, and out of `DESK_EVENT_TYPES`, which takes every `run.*` type today. Leave `protocol/machine.ts` alone, since dry runs never reach a machine.
- Add `runs.recordDryRunSkip(principal, runId, { tool, summary })` to the runs service. It masks the summary with `secrets.maskerFor`, caps it at 200 characters and appends the event. V3.8 (PiRun) and V3.9 (MCP route) both call it, so neither lane edits services. Do not route it through `ingestRunEvents`, whose `seq` numbering belongs to `toRunEvents`.
- Plumbing that V3.7, V3.8 and V3.9 share. Without it they would edit the same services files in parallel lanes:
  - `RunRecord` in `runs.ts` gets `dryRun`.
  - `CloudStart.run` (`cloud/types.ts`) gets `dryRun`, and `cloud/runtime.ts` passes it from the run row.
  - The run principal (`workspaces.ts:33`, built at `workspaces.ts:267` from the claims `run-tokens.ts` verifies against the live run row) gets `dryRun`, with a test.
- `AgentRecord` and `toRecord` in `agents.ts` carry `soul`, `handsTo` and `emailLocal` read-only, so V3.2 can read them. V3.3 makes the first two writable and V3.4 writes the address.
- `agents.status` is plain text, so `draft` in `AGENT_STATUSES` needs no migration.
- No column for the builder's Rules. Plan default: V3.7 appends them to `instructions` as a "Rules" section. The Agent mock has no Rules row.
- The latest migration is 0016. This one is 0017 unless something merges first.
- Open questions, plan defaults: dry runs always run on the cloud isolate; Hands to is named in the prompt but `send_message` is not limited; no Pause button.
