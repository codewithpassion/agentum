Dom's decision on 16 Oct 2026, from the M0.2 review note in `docs/reviews/tasks/M0.2.md`: add foreign keys before M1, while the tables are empty.

## Scope

In `packages/db/src/schema/*.ts`, every `workspace_id` references `workspaces.id`, and every other `*_id` column that names a foundation table references that table's id. Default `ON DELETE` is restrict; use cascade only where the child row has no meaning without its parent, and say which in the commit message. Nullable columns stay nullable. Regenerate the migration with `bun run generate` and keep the hand-written `events` triggers. The `bun:sqlite` test helper turns on `PRAGMA foreign_keys = ON` so tests match D1, which enforces them. Fix fixtures and seeds that insert children before parents.

## Check

`cd packages/db && bun run generate` produces no diff after the commit. `bun test packages/db` includes a `foreign-keys.test.ts` proving an insert with an unknown `workspace_id` throws and a delete of a referenced workspace throws. `bun run test` passes across the repo, including the M0.4 seed. `wrangler d1 migrations apply DB --local` on a fresh `.wrangler` succeeds.
