## Scope

Split `packages/db/src/schema.ts` into `schema/<module>.ts` and point `drizzle.config.ts` at the list. The nine foundation tables with the columns under C1, `workspace_id NOT NULL` with no default, indexes from the data model. The `events` migration appends two hand-written triggers (drizzle-kit does not emit triggers).

`packages/db/src/atomic.ts`: `atomic(statements)` over `db.batch` for D1 and `db.transaction` for `bun:sqlite`, exported as `@repo/db/atomic`; the rule goes into the `packages/db` README. Delete the notes example and its route.

## Check

`cd packages/db && bun run generate` produces no diff after the commit. `bun test packages/db` includes `events.test.ts` proving `UPDATE events` and `DELETE FROM events` throw, `schema.test.ts` asserting every table except `workspaces` and `__drizzle_migrations` has `workspace_id` with `notnull = 1` via `PRAGMA table_info`, and `atomic.test.ts` proving a failing second statement rolls back the first on `bun:sqlite`. Against the local D1: `wrangler d1 migrations apply DB --local`, then `wrangler d1 execute DB --local --command "DELETE FROM events"` fails, because wrangler applies the real migration.
