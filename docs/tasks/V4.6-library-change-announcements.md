When the library changes, every running machine or VM run whose sync scope covers the path should pull it mid-run.

## Scope
- New `apps/web/src/server/library-notifier.ts`: builds the `notify` dependency of the library service in `compose.ts`. It finds running runs in the workspace whose agent's `librarySyncScope` covers a changed path, skips `byRunId`, and sends `library_changed` through the `MachineRelay` DO of the claiming machine (new `announce(paths)` method in `relay.ts`/`relay-core.ts`, sent only to a daemon whose hello named `library-live`) or calls a `libraryChanged(paths)` RPC on the run's `PiRun` DO for a VM run. Runs in `ctx.waitUntil`, never fails the write.
- `apps/web/src/server/relay-port.ts`: `announce` on `durableRelayPort`.
- New `apps/web/src/server/tick/library.ts` registering a `library.prune-versions` job that calls `pruneVersions`; listed in `tick/jobs.ts`.

## Check
- `apps/web/src/server/library-notifier.test.ts`: a covered machine run gets one frame, an uncovered one none, the writer's own run none, a VM run gets the RPC. `relay.test.ts`: `announce` skips a daemon without the feature. `tick.test.ts` lists the new job.
- `bun run check && bun run test && bun run build` pass.
