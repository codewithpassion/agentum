Asked for by Dom on 19 Oct 2026. Slack's manifest editor warns for apps with `features.agent_view`: "Agent View should include `assistant:write` bot scope" and "Agent View should use `app_home_opened` bot event subscription". The generator is `packages/services/src/slack/manifest.ts` (`SLACK_BOT_SCOPES`, `SLACK_BOT_EVENTS`). Dom also wants the status display that `assistant:write` allows.

## Scope

- Add `assistant:write` to `SLACK_BOT_SCOPES` and `app_home_opened` to `SLACK_BOT_EVENTS`. The events endpoint answers `app_home_opened` with a 200 and does nothing else (no run, no Log entry), so Slack doesn't retry or disable delivery. Check the same for any other event type the app now receives but doesn't handle: unknown event types get a 200, never a 400.
- Status: while a run started from Slack (mention, DM, thread reply, or an M5.9 batch that replies) is queued or running, show a status in that Slack thread with `assistant.threads.setStatus`, for example "is thinking…", and update it to a short label of the current step when the run calls a tool (for example "is reading files…", "is running a command…", "is searching Slack…"), at most once every 5 seconds. Clear it when the reply is posted or the run ends, fails or is cancelled (Slack clears it on a bot reply in that thread; clear it explicitly on failure and cancel).
- Check Slack's current docs (docs.slack.dev, `assistant.threads.setStatus`) for where the method works: agent view DMs only, or channel threads too. Use it wherever Slack allows it and skip it quietly elsewhere. Write what you found in the review file.
- A status call that fails (missing scope on an app not yet reinstalled, rate limit) never fails the run: log one `console.warn` with the Slack error code, and stop trying for that run.
- Say in the review file that existing apps need the manifest regenerated, saved and the app reinstalled.

## Check

- Tests with a fake Slack client: `app_home_opened` and an unknown event type get 200 and start nothing; a Slack-started run sets the status, updates it on tool calls no more than once per 5 s, and clears it on failure and cancel; a `missing_scope` answer stops further status calls and doesn't fail the run; a run not started from Slack makes no status calls.
- `bun run check && bun run test && bun run build` pass.
- Live on staging (controller): after Dom reinstalls Comms-Chief, a DM to it shows "is thinking…" and a step label until the reply arrives; the manifest editor shows no warnings.
