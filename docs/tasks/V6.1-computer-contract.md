Everything the rest of V6 builds on: one machine registry serving two roles, the frozen computer protocol v1, and the schema for attaching a computer to an agent. The integrator replaces `depends_on` with every V5 task id.

## Scope
- Decision, recorded in this task's log and in a short comment at the top of `apps/web/src/server/relay.ts`: one relay Durable Object, not two. `MachineRelay` (`idFromName(machineId)`) holds every socket of one machine, tagged `daemon`, `computer` or `viewer`. One machine identity, one presence, and one `revoke` closes every socket. The viewer hub needs the computer socket in the same object to pump frames. It also needs no new DO class and so no wrangler migration. The daemon keeps its JSON frames (`packages/protocol/src/machine.ts`, logic in `relay-core.ts`). The computer socket speaks frozen v1 in a separate core module that V6.9 adds.
- Schema in `packages/db/src/schema/machines.ts`: `MACHINE_ROLES = ["agent_host", "computer"]` in `@repo/db/shared`. Add a `machine_credentials` table (`machine_id`, `role`, `credential_hash` unique, `created_at`) for the computer role, plus `computer_capabilities` (JSON: desktop, os, arch, workdir, client version), `computer_status` and `computer_last_seen_at` on `machines`. Don't rebuild `machines`, because it is a parent of `agents` and `runs`. A computer-only machine still needs `machines.credential_hash`, so pick and document a way that leaves no usable daemon credential.
- `machine_enroll_tokens` gains `role` (default `agent_host`) and a nullable `machine_id`. A code with a machine id adds the computer role to that existing machine, which is how one machine serves both roles.
- `agents.computer_machine_id` (nullable FK to `machines`). A computer serves at most one agent at a time (a unique index where it is not null). Add a `browser_sessions` table (`agent_id` PK, `session_id`, `current_url`, `updated_at`), as in agentum's `modules/browser/schema.ts`.
- Add a `takeover` kind to V1's pending-request kinds, with payload `{ machineId, reason, note? }`. Add events to `EVENT_TYPES`: `computer.online`, `computer.offline`, `computer.exec`, `computer.file`, `computer.takeover_requested`, `computer.taken`, `computer.handed_back`, `browser.action`. Payload shapes go in `@repo/db/shared` and never carry command output or file bytes.
- Port agentum `apps/web/src/modules/computer/protocol.ts` to `packages/protocol/src/computer.ts` (new `exports` entry). Copy the golden fixtures to `apps/computer/testdata/protocol/`, where the Go client and the TS tests both read them. The frames and fields stay v1, unchanged. Add `computerEnrollRequestSchema` to `packages/protocol/src/machine.ts` (code, role `computer`, client version).
- Run `bun run generate` in `packages/db` and commit `migrations/` with `meta/`.
