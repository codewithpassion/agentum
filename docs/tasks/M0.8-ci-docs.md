From `docs/architecture/build-plan.html#m0`, changed for the GitHub rule in `docs/workflow.md`: the CI workflow exists but triggers only on `workflow_dispatch` until Dom turns on push and PR triggers.

## Scope

`.github/workflows/ci.yml` running `bun install`, `bun run check`, `bun run test` (so each package's bunfig applies), `bun run build` and the bundle grep. Its only trigger is `workflow_dispatch`.

Update the root `CLAUDE.md`, `packages/db/README.md` and `packages/services/README.md`:

- `workspaceProcedure` replaces `protectedProcedure`;
- bearer-authenticated Hono routes (`/mcp`, `/api/proxy`, machine, Slack, trigger and file routes) call services directly and are the documented exception to "the app reaches it only through tRPC";
- services are factories taking `{ db, atomic, ... }` and never `env`;
- multi-statement writes use `atomic`;
- the `Bun.serve` and "don't use vite" text applies to `apps/daemon`, not `apps/web`.

Fix the stale boilerplate text in the READMEs.

## Check

The workflow's steps pass when run locally in the same order. Planting `import "drizzle-orm"` in a route component makes the bundle grep fail locally. `ci.yml` has no `push` or `pull_request` trigger.
