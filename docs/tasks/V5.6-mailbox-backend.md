Implements `MailboxPort` on top of agentic-inbox-hei, the way `docs/decisions/agent-email.md` chose. The controller refines this scope from the decision before dispatch.

## Scope
- Option A (module): port `MailboxDO`, its migrations and the tool functions from agentic-inbox-hei into a portable module (`packages/mailbox/` or as the decision names it), with zod 4 and Apache-2.0 notices on modified files; the DO class itself is exported and bound in V5.7.
- Option B (service binding): add a `WorkerEntrypoint` RPC surface to agentic-inbox-hei (create mailbox, list and read threads, send, reply, and a callback to harbourmaster on inbound mail), and a `MailboxPort` client in harbourmaster over the binding.
- Either way: thread ids and message ids map to `mail_threads.external_thread_id` and `mail_messages.external_message_id`; sends use the `send_email` binding.

## Check
- Port tests against the module (Option A) or a fake binding (Option B), covering create, send, reply threading and inbound callback shape.
- `bun run check && bun run test && bun run build` pass (and agentic-inbox-hei's own tests for Option B).

## Refinements (2026-10-27)

Checked against main at c5ba505. Where these differ from the scope above, they win.

- No V3 or V4 dependency. No other task uses the email lane.
- The controller refines this again from `docs/decisions/agent-email.md` before dispatch.
- Option A facts: `MailboxDO` is in `workers/durableObject/index.ts` with its migrations in `migrations.ts` (drizzle on DO SQLite). A new workspace package (`packages/mailbox/`) needs its own `package.json`, `tsconfig.json` and tests that run under root `bun run test`. DO storage can't run in `bun test`, so test the queries against a `bun:sqlite` drizzle instance, as `packages/db` does. Attachments go in the `FILES` bucket under `${workspaceId}/mail/`. The parser is `postal-mime` (agentic-inbox-hei uses ^2.6.1).
- Don't port the Kumo UI, Access auth, the `EmailAgent`, the API key store or `verifyDraft` (V5.2 default).
