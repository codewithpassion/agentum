Machine runs see library changes within seconds instead of at run start and every 5 minutes, and their own edits reach the library while they work.

## Scope
- `apps/daemon/src/library-sync.ts`: a file watcher (`fs.watch` recursive on `<workDir>/library`, skipping the manifest and conflict copies) feeds the V4.4 debouncer, which runs `syncOut` while a run is active. The 5-minute checkpoint stays as a fallback.
- `apps/daemon/src/client.ts`: handle the `library_changed` relay frame and call `syncIn({ only })` on each running run whose roots cover a path. The hello names `library-live` in `features`, and the claim request sends it in `X-Daemon-Features`.
- `apps/daemon/src/executor.ts`: use the claim's `roots` with modes and `taskFolder`; the prompt names the task folder (V4.8 builder). Stop collecting `[ATTACHMENT:]` files (`apps/daemon/src/attachments.ts`, `run-files.ts`): the task folder is inside the synced home and reaches the library by sync.
- Older Workers: without `roots` the daemon falls back to `paths` as write roots.

## Check
- `apps/daemon/src/library-sync.test.ts` with a fake watcher and clock: an edit is pushed within the debounce window, a burst becomes one sync out, an edit under a read root is refused. `client.test.ts`: a `library_changed` frame triggers a targeted sync in for the covering run only. `executor.test.ts`: no marker parsing, the prompt names the task folder.
- `bun run check && bun run test && bun run build` pass.
- Live (controller, in V4.21): an edit on the machine shows on the library page within 10 s.

## Refinements (2026-10-26)

Checked against main at aac119a. Where these differ from the scope above, they win.

- The daemon already sends `X-Daemon-Features` (`apps/daemon/src/run-api.ts:173`, `FEATURE_LIBRARY_SYNC` and `FEATURE_REQUESTS`). Add `FEATURE_LIBRARY_LIVE` there, and send `features` in the hello (`client.ts:248`), so the relay can skip daemons without it.
- `createDaemonLibrarySync` (`library-sync.ts:94`) takes `paths` and runs syncs in turn. Pass roots with modes, and use the `only` pull from V4.4 for `library_changed`. The 5-minute checkpoint is in `executor.ts` around line 483 (`library-checkpoint`).
- Markers: `run-files.ts:108` and the attachment handling in `executor.ts` (around lines 318 and 559) go. Leave `extractAttachmentMarkers` in `@repo/protocol/attachments`, because `protocol/thread.ts` still uses it for old transcripts.
