From `docs/architecture/build-plan.html#m1`. Reuse: bruce-next `agent.ts`, `env.ts`; Ariadne `masker.ts`, `harness-env.ts`, and the normaliser idea. Paths are in `docs/architecture/reuse.html`.

## Scope

On claim, ensure `~hm-agent/harbourmaster/<workspaceId>/<agentId>/work` (owned by `hm-agent`) and reset `work/.claude/` and `work/.mcp.json`. Start `query()` as `hm-agent` in streaming-input mode with:

- `cwd = work/`;
- the instructions from the claim as `systemPrompt: { preset: "claude_code", append }`;
- `settingSources: ["project"]`, `strictMcpConfig: true`;
- `permissionMode: "bypassPermissions"` with `allowDangerouslySkipPermissions: true`;
- `resume` when the session's `runtime_ref` belongs to this machine;
- `maxBudgetUsd` from agent config;
- a filtered env.

Then `query.setMcpServers(mcpServers)`, then the first user message. One run per agent at a time, locally too.

Normalise SDK messages to `message.assistant`, `tool.call` and `tool.result`. Batch events every 500 ms; heartbeat every 20 s. On a heartbeat 409 or a 1012 close, abort the local process, wait for it to exit, then post `complete { status: "aborted" }`. The local slot is released only after exit. Complete with the final text, usage, and the new session id as `runtimeRef`.

A masker covers all outbound text, with the run token and machine credential as needles. `[ATTACHMENT:path]` markers pass through as text until M1.6.

The live checks need a Claude Code login for `hm-agent` on Dom's machine. That is a step for Dom; put it in the report.

## Check

`bun test apps/daemon` with an injected `queryFn` that yields recorded SDK messages (fixtures under `apps/daemon/fixtures/`):

- the event batches and the completion match goldens;
- the options passed to `queryFn` carry `bypassPermissions`, `allowDangerouslySkipPermissions: true`, `strictMcpConfig: true`, the instructions in `systemPrompt.append`, and no `mcpServers`;
- `setMcpServers` is called with the claim's map before the first message;
- `resume` is passed only when `runtime_machine_id` matches;
- a simulated heartbeat 409 aborts the fake process and posts `aborted` only after it exits.

Live, with a real Claude Code: during a run, `cat /proc/<claude pid>/cmdline` contains no `hm_run_`, and `grep -r hm_run_ ~hm-agent ~/.harbourmaster` finds nothing.

Record two probes in this log: does `canUseTool` fire under `bypassPermissions`, and are the servers from `setMcpServers` connected before the first turn.

Live end to end: `bun scripts/e2e/skeleton.ts` (needs `bun run dev`, a running daemon and a Claude login) creates an agent whose instructions say "you are called Pelican", sends "What is your name? Reply with the name only", and asserts the reply contains "Pelican" (instructions reached the model). It then sends "Reply with exactly the word heron", then "Which word did I ask for in my previous message?", and asserts "heron" (the session resumed).
