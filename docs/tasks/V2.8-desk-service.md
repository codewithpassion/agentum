The desk home shows three lanes over runs, inbox threads and pending approvals. This task computes them in one service call so the page and the Needs you badge read one query.

## Scope
- New `packages/services/src/desk.ts` `createDeskService({ db, ... })` built in `composeWith` (`apps/web/src/server/compose.ts`), with `authorize()` first.
- `desk.get(principal, { agentId?, dayStart })`, where `dayStart` is the viewer's local midnight as an ISO time from the browser:
  - Needs you: V1's open approvals and questions, proposed skill versions (`isPendingProposal`, skills-store), proposed triggers and routines, and inbox threads whose latest post is an agent's and newer than any person's post.
  - Running: runs that are queued, offered, running or waiting (a waiting run also adds its request to Needs you).
  - Done today: runs finished at or after `dayStart`, newest first, capped at 20, with a "+ n more" count.
- Each card gets its band from `statusBand` (V2.2), from one batched read of the latest events per run, not one query per card. Use the V2.1 indexes.
- `desk.needsYouCount(principal)` for the sidebar badge.
- New `apps/web/src/server/trpc/desk-router.ts` (thin), added to `runtime-router.ts`.

## Check
- `packages/services/src/desk.test.ts`: each lane's membership; a waiting run sits in Running and its approval in Needs you; the `dayStart` boundary; the agent filter; a proposal approved elsewhere leaves the lane; two-workspace isolation.
- `apps/web/src/server/trpc/desk-router.test.ts`: 401 without a workspace.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-26)

Checked against main at 4da1878. Where these differ from the scope above, they win.

- Share the Needs you logic with X.2's desk API instead of writing it twice. `needsYou` in `packages/services/src/desk-api.ts` already turns `requests.listPending` into C4 items: it drops expired requests (`listPending` does not), names agents in one batched read, and builds `title` and `detail` with `describe()`. Move that code, with `NeedsYouItem` and `describe`, into `desk.ts` as `pendingRequests(member)`. `createDeskApiService` then takes `desk: Pick<DeskService, "pendingRequests">` and its `needsYou` returns that. Build `desk` before `deskApi` in `compose.ts`. The desk's approval and question cards and `needsYouCount` come from the same items, so the web desk and flightdex always agree. `desk-api.test.ts` passes unchanged, because the C4 shape is binding. `actingMember`, `decide` and `sendToController` stay in desk-api.
- Visibility: `listPending` already applies `visibleSessions` from `sessions.ts`. The Running and Done queries over `runs` join the same condition, so another member's ui session or private Slack DM never shows.
- Proposals: `skillsStore.proposals(principal)` for skill versions. `triggers.list` and `routines.list` records carry `proposedByAgentId` and `approvedAt`; filter them with `isPendingProposal` from `@repo/db/shared`. Approve and reject already exist on the `skillStore`, `triggers` and `routines` routers.
- Inbox: `inbox.listThreads` does not return who wrote the latest post. Read the latest post of each listed thread in one query over `inbox_posts` (`inbox_posts_thread_idx`) and keep the threads whose latest post has `authorKind` agent.
- Bands: done and failed runs need no events (`resultText`, `error`). Read the events of live runs in one query with `inArray(events.runId, ids)` (`events_run_idx`), not one per card.
- `finishedAt` is stored as `toISOString()` text. Parse `dayStart` with `z.iso.datetime()`, normalise it with `new Date(dayStart).toISOString()` and compare strings.
- `startedBy` names people through the `PeopleLookup` port (`infra.people` in `compose.ts`), as the Log does.
- Export `./desk` in `packages/services/package.json`. The service is `services.desk`, next to the existing `services.deskApi`.
