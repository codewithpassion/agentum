The task view needs one run with its context: agent, who started it, where it runs, cost so far, its events and its pending request. V3's "Recent tasks" card reuses the list call.

## Scope
- New `packages/services/src/tasks/service.ts` `createTasksService`, built in `compose.ts`.
- `tasks.get(principal, runId)`: the run (status, input text, timestamps, usage as cost so far), the agent (name, runtime, machine), "started by" in words (a person, Slack, inbox thread, trigger or routine name, or a handoff from another run via `parentRunId` with that run's agent), the session id for the thread, the session's other runs (id, status, input), the run's events, and V1's open request for the run.
- `tasks.list(principal, { agentId?, limit, before? })`: recent runs with title (session title or trimmed input) and `statusBand`.
- New `apps/web/src/server/trpc/tasks-router.ts` (thin), added to `runtime-router.ts`.
- Reads go through `authorize()`. A private session's run is visible only to its actor, as in `visibleSessions`.

## Check
- `packages/services/src/tasks/service.test.ts`: "started by" for each origin and for a handoff; cost from usage; the private-session rule; the agent filter and paging of `list`; two-workspace isolation.
- `apps/web/src/server/trpc/tasks-router.test.ts`: input validation and 401.
- `bun run check && bun run test && bun run build` pass.
