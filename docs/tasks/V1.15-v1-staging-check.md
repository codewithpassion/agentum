The milestone's proof on staging, across all three runtimes and both answer surfaces, plus fixes for whatever only shows up live. Run by the controller with the agent-login flow (`bun run agent-login --env staging`).

## Scope
- Deploy `main` to staging (`staging:deploy`), apply the D1 migration, and confirm the `SessionStream` class migrated (`v5`).
- For each runtime (isolate cloud agent, managed agent, machine agent on Dom's machine with the new daemon), with "Ask me before" on `bash`:
  - the chat streams: a cloud reply grows as it is written; managed and machine events arrive without the 1.5 s poll; a reload mid-run resumes without duplicates;
  - a `bash` call puts the run in `waiting` (chat status line and Slack thread status), the card shows the scrubbed input (try `curl -H "x-api-key: sk-test-1234567890abcdef" https://example.com`: the card, Slack and the transcript all show `[redacted]`);
  - Allow once from the web runs it; Deny from Slack stops it and the web card settles; Always allow removes the rule;
  - an `ask_user` (cloud, managed) or `AskUserQuestion` (machine) question with choices is answered once, and a second answer on the other surface is refused as already answered;
  - with the TTL lowered on staging for the check (a Worker var or a dev-only override, removed afterwards), an unanswered request expires, the card says so, and the run goes on.
- Cancel a waiting run: its requests become cancelled and the Slack card settles.
- Record results, timings and anything odd in `docs/reviews/v1-staging.md`. Fixes found here become small follow-up tasks in V1, not changes in this task.
