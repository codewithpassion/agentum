The Worker side of V1.5 for the machine and managed runtimes, and the minute job that expires unanswered requests. The cloud wake-up is in V1.10 with the rest of PiRun.

## Scope
- `apps/web/src/server/routes/machine-runs.ts`: `POST /:runId/requests` (body `createRequestBodySchema`) calls `services.requests.open` with the machine principal and answers `createRequestResponseSchema`; `GET /:runId/requests/:requestId?wait=<s>` calls `waitForOutcome` (wait capped at 25 s) and answers `waitRequestResponseSchema`. Same `withMachine` and refusal mapping as the other routes. The claim route passes `requestsForDaemon: hasDaemonFeature(header, FEATURE_REQUESTS)`, the same way it passes `libraryForDaemon`. Only a daemon that sends `FEATURE_REQUESTS` in `X-Daemon-Features` uses these routes, so an older daemon keeps running with bypassPermissions and no questions.
- `apps/web/src/server/managed-poller-port.ts`: nothing new if `kick` already serves `resume`; check that a kick on a run whose poller has stopped restarts its alarm (`managed-poller-core.ts`), and fix it if not.
- Tick job `requests.expire` in `apps/web/src/server/tick/runtime.ts` calling `services.requests.expireDue(SYSTEM_PRINCIPAL)`.

## Check
- `routes/runs-machine.test.ts` (or a new `machine-requests.test.ts`): create, repeat create returns the same id, wait returns the outcome once answered, wait times out with `pending`, another machine's credential is refused, a finished run is refused with 409.
- `tick.test.ts`: the job is registered and its name is unique.
- `managed-poller-core.test.ts`: a kick after the alarm stopped schedules it again.
- `bun run check && bun run test && bun run build` pass.

## Refinements (26 Oct 2026, against main)

Checked against the code before V1 started. Where these differ from the scope above, they win.

- A kick on a stopped poller already restarts its alarm. The gap is that `kick` leaves a pending later alarm where it is, which a test asserts ("a second kick while an alarm is pending does not move it"). Change `kick` to move a pending later alarm to now, and update that test; V1.11's `resume` needs it to cut the 15 s wait short.
