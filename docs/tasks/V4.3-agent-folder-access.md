Replaces the home plus `libraryPaths` convention with read-only or read and write folder grants per agent, enforced in one place.

## Scope
- `packages/services/src/library.ts`: `canWriteAt` becomes the real rule from V4.1, and a new `canReadAt` guards `list`, `stat`, `read`, `versions`. A run principal resolves its agent's slug and `agent_library_access` rows once per call. A refused read is `not_found`, a refused write is `ForbiddenError`.
- New `packages/services/src/library/access.ts`: `listGrants(principal, agentId)`, `setGrant(principal, agentId, path, mode)`, `removeGrant`, each with a `library.access` event; people only.
- `packages/services/src/library/sync-paths.ts`: `librarySyncScope(slug, grants)` returns `{ path, mode }[]` (home as `write`, nested roots dropped). `libraryPathsOf`, `libraryPathsError` and `LIBRARY_PATHS_KEY` go, along with the check in `agents.ts`.
- `packages/services/src/runs/machine-claim.ts`: the claim sends `roots` with modes and `taskFolder` to a daemon with `library-live`, and keeps `paths` for older daemons.
- tRPC: `library.access.list/set/remove` in `library-router.ts`.

## Check
- `packages/services/src/library-access.test.ts`: a run reads and writes its home, reads a `read` grant and cannot write it, writes a `write` grant, reads `wiki/` without a grant, cannot see an ungranted folder; people see everything; read-only API keys still cannot write.
- `sync-paths.test.ts` and `runs/machine-claim.test.ts` updated for roots with modes.
- `bun run check && bun run test && bun run build` pass.
