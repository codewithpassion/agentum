A dry run must do the reading for real ("Found 7 studios") and skip every write or send ("Would write pricing-2026-10.md"). Dry runs always run in the cloud isolate, so `PiRun` is the one place that enforces this for built-in and connector tools.

## Scope
- In `apps/web/src/server/pi-run.ts` and `pi-run-core.ts`, a run with `dry_run` set uses the isolate environment and never the Linux VM.
- At V1's approval choke point for cloud tool calls, a dry run answers any call that isn't read-only with a simulated result: "Skipped in dry run: would call <tool> with <short input summary>". It writes a `run.dry_run_skipped` event and does not ask a person.
- Read-only means a connector tool with `readOnlyHint` (`pi-run-mcp.ts`), `web_fetch` with GET, and library reads. Library writes, `run_script` (it can write) and the library shell's write commands are skipped. Mount the library read-only through `createLibraryEnv` if it has that mode, else skip at the tool.
- No secret values reach the summary: use the masker (`@repo/protocol/masker`).
- A dry run ends like any run, with a result and usage.

## Check
- `pi-run-core.test.ts` and `pi-run-mcp.test.ts` with the faux model: a read-only connector tool runs, a write tool returns the skipped text and logs the event, a library write is skipped, the VM is never chosen, and a secret in the input is masked in the summary.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-26)

Checked against main at ae74008. Where these differ from the scope above, they win.

- The choke point is `beforeTool` in `apps/web/src/server/pi-run-gate.ts`. It already returns `{ block: text }` for a denied approval, so a dry run returns `{ block: "Skipped in dry run: …" }` the same way. Check for a dry run before `isRuled`, so no approval request is ever opened.
- `ask_user` is exempt in the gate today. In a dry run, answer it without opening a question ("Nobody answers in a dry run. Go on with a stated assumption."), so nothing reaches Needs you or Slack.
- Read-only tests: `ToolOrigin` (`pi-run-mcp.ts:392`) holds only `server` and `name`. Add `readOnly` from `annotations.readOnlyHint` in `mcpToolOrigins`. Platform MCP tools reach PiRun the same way and carry the hint, so this gate also covers them before V3.9. `replay: "safe"` is not a read-only test: `web_fetch` is `unsafe` even for GET. Allow `web_fetch` with no method or GET, Pi's `read`, and `activate_skill`. Skip `write`, `edit`, `run_script` and `run_skill_script`.
- `createLibraryEnv` has no read-only mode, so skip writes at the tool.
- The isolate: `#selectEnvironment` in `pi-run.ts` takes `input.run.dryRun` (V3.1) and never stores `VM_KEY` for a dry run. Network follows the agent's `networkAccessOf` setting.
- Record the skip with `runs.recordDryRunSkip` (V3.1) through `this.#services()`, passed into the gate as a new dep. The summary is the tool's rule key plus a short input summary. The service masks it.
