The builder reserves an address before the agent exists, and works on a `draft` agent row that becomes the real agent on "Create agent". The mailbox itself is V5's.

## Scope
- `packages/services/src/agents.ts`: `suggestAddress(slug)` (the slug, or slug-2 and so on when taken), `checkAddress(principal, local)` (syntax: lowercase letters, digits, dots and dashes, 2 to 40 characters; a reserved-word list such as postmaster, abuse, admin, noreply; and availability), and `reserveAddress(principal, agentId, local)`, which writes `email_local`, maps the unique violation to `ServiceError("conflict", "That address is taken")`, and logs `agent.address_reserved`.
- `createDraft(principal, values)` inserts a `draft` agent. `activate(principal, agentId)` turns a draft into `active` and logs `agent.created`. `discardDraft` archives it, because its dry-run events keep it referenced.
- `list`, `findAgent` for runs and triggers, Slack routing and the desk skip drafts. Dry runs may still start on a draft (V3.7).
- TRPC: `agents.checkAddress` and `agents.reserveAddress` in `agents-router.ts`.

## Check
- `agents.test.ts`: suggestion skips taken names; syntax and reserved words are refused; a second reservation conflicts; a draft is missing from `list` and the desk; activate and discard.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-26)

Checked against main at ae74008. Where these differ from the scope above, they win.

- Addresses are unique across workspaces (V3.1). `checkAddress` and `suggestAddress` check availability across all workspaces and answer only taken or free.
- Drafts are mostly excluded already. Every caller checks `status === "active"`: `startRun` (`runs.ts:455`), `routines.ts:302`, `triggers.ts:249`, `inbox.ts:322`, `slack/messages.ts:184` and `agents.list`. Two places need work. `agents.list({ includeArchived: true })` must still leave drafts out. `loadActiveAgent` (`connectors.ts:314`) says "That agent is archived" for any non-active agent, so make it say "not active". `agents.get` keeps returning drafts, because the builder reads its own draft.
- Store drafts as `runtime: "cloud"` with `CLOUD_DEFAULT_MODEL`, so the cloud-only `runtimeConfig` keys (network, environment) are valid and a dry run can use them. `agentUpdateSchema` cannot change the runtime, so `activate(principal, agentId, { runtime, machineId, model, runtimeConfig })` sets the chosen runtime with the same checks `create` runs (`assertRuntimeConfig`, `assertModelForRuntime`, the machine check).
- Slugs are unique per workspace including archived agents, so a discarded draft keeps its slug forever. `createDraft` picks a free slug with the same "-2" rule as `suggestAddress`.
- Plan default: a dry run may start on a draft. V3.7 lets `prepareStart` accept one.
