From `docs/architecture/build-plan.html#m1`. Builds on contract C4; the live check needs the M1.1 routes and scripts. Reuse: Ariadne `client.ts`, `backoff.ts`, `enroll.ts`, `install-service.ts` (copy). Paths are in `docs/architecture/reuse.html`.

## Scope

`apps/daemon` on Bun. Commands `enroll <code> --server <url>`, `run`, `status`, `install-service` (systemd user unit, linger preflight, Linux only).

`install-service` also creates the `hm-agent` user, its home, and a sudoers drop-in that lets the daemon's user run exactly `sudo -u hm-agent <claude binary>`. When that fails (no root), the daemon reports `single_user: true` at enrol and runs Claude Code as itself.

Config in `~/.harbourmaster/config.json` (mode 600, owned by the daemon's user). WebSocket client with backoff, ping and close-code handling, with injected sockets and timers. The process awaits a shutdown promise so Bun keeps it alive. `bun build --compile` for linux x64 and arm64.

Running `install-service` with sudo on a real box is a step for Dom; put it in the report.

## Check

`bun test apps/daemon`: reconnect after a 1012, stop after a 4401, no reconnect storm, and the sudoers line is generated with the exact binary path.

`bun run --cwd apps/daemon build` produces `dist/harbourmaster`. On a box with sudo, `./dist/harbourmaster enroll ... && ./dist/harbourmaster run` makes `bun scripts/dev/machines.ts` list it online with `single_user: false`. `sudo -u hm-agent cat ~/.harbourmaster/config.json` is refused.
