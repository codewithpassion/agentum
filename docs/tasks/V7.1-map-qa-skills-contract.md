The schema and shared types for the map, the Q&A board and GitHub skill import.

## Scope
- Q&A tables (master-control `qaQuestions`/`qaAnswers` concepts, on D1). `qa_questions`: workspace, title, body, author kind (`user`/`agent`) and id, `run_id` (nullable), status (`open`/`answered`/`closed`), `accepted_answer_id`, created and updated. `qa_answers`: question FK, body, author kind and id, `run_id`, created. Indexes on (workspace, status, created).
- Skill source on `skills`, as nullable columns or a `skill_sources` table (pick one and say why). It holds `provider` (`github`), `repo_url`, `path`, `ref`, `commit_sha` (pinned), `latest_commit_sha`, `checked_at`. The URL, path and ref rules come from trueforge `packages/trueforge/src/schemas/skill.ts` (MIT), GitHub only.
- `map_positions` (workspace, `node_key`, x, y) so dragged positions persist. Node keys are `trigger:<id>`, `agent:<id>`, `out:slack:<channel>`, `out:library:<folder>`, `out:qa`, `out:email:<agent>`.
- `@repo/db/shared`: `MapNode`, `MapPort`, `MapWire` (from, to, kind, 7-day count, active) and `MapGraph` types. Also `QA_STATUSES`. The `GithubSkillSource` and `FetchedSkillTree` port types go in `packages/protocol/src/skills.ts`, shared by V7.9 and V7.10.
- Events in `EVENT_TYPES`: `qa.asked`, `qa.answered`, `qa.accepted`, `skill.update_available`, `map.edited`, with payload shapes.
- `bun run generate` in `packages/db`, committing `migrations/` and `meta/`.

## Refinements (2026-10-27)

Checked against main at 24c28ad. Where these differ from the scope above, they win.

- depends_on is V6.1, the schema task before this one, so the schema chain stays serial. The latest migration on main is 0018 (V4.1). V5.1 makes 0019 and V6.1 makes 0020, so this one is 0021 if they merge in order. Nothing here needs a V3 to V6 feature.
- This is the only V7 task that changes `packages/db/src/schema`. It takes over the schema needs the later tasks found:
  - `skill_versions.source_commit_sha` (nullable `ADD COLUMN`): the upstream commit a version was imported from. V7.10 moves the pin when such a version is approved.
  - An index `events_workspace_type_created_idx` on `events (workspace_id, type, created_at)`, so V7.2's 7-day counts read only the event types they group. A `CREATE INDEX` does not recreate `events`, so its hand-written triggers stay.
- Every change is a new table, a nullable `ADD COLUMN` or a new index. Check the generated SQL has no `__new_` table: `skills`, `skill_versions` and `events` are parents or carry hand-written triggers.
- Q&A tables in a new `packages/db/src/schema/qa.ts`. `qa_questions`: `workspace_id`, `title`, `body`, `author_kind` (`user`/`agent`, the kinds `memberOf` in `skills-store.ts` gives a user and a run), `author_id`, `run_id` (FK `runs`, nullable), `status`, `accepted_answer_id`, `created_at`, `updated_at`. `accepted_answer_id` is nullable with no foreign key, because one would make a cycle with `qa_answers.question_id`, and a table in a cycle can't be rebuilt parents first on D1. V7.6 checks the answer belongs to the question. `qa_answers`: `question_id` FK, `workspace_id`, `body`, `author_kind`, `author_id`, `run_id` FK, `created_at`, with an index on `(question_id, created_at)`.
- Skill source: a `skill_sources` table keyed by `skill_id` (FK `skills`), not columns on `skills`. Few skills have a source, and the update tick's "oldest `checked_at` first" gets its own index on `(checked_at)` without sparse columns on every skill. Columns as in the scope, plus `workspace_id`, `created_at` and `updated_at`.
- `map_positions`: primary key `(workspace_id, node_key)`, `x` and `y` as `real`, `updated_at`. Node keys as in the scope, plus `trigger:slack:<slackAppId>` for an agent's Slack app, which is not a `triggers` row.
- `@repo/db/shared`: `QA_STATUSES`, `QA_AUTHOR_KINDS`, and the limits V7.6 and V7.7 both enforce: `QA_TITLE_MAX = 200`, `QA_BODY_MAX = 20_000`, `QA_OPEN_PER_AGENT_MAX = 5`. `MapGraph` types: node kinds `trigger` (`http`, `routine`, `mail`, `slack`), `agent` and `output` (`slack`, `library`, `qa`, `email`); port kinds `connector`, `computer`, `browser`, `skill`; wire kinds `trigger`, `handoff`, `slack`, `library`, `qa`, `email`.
