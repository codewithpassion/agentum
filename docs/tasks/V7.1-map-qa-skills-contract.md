The schema and shared types for the map, the Q&A board and GitHub skill import.

## Scope
- Q&A tables (master-control `qaQuestions`/`qaAnswers` concepts, on D1). `qa_questions`: workspace, title, body, author kind (`user`/`agent`) and id, `run_id` (nullable), status (`open`/`answered`/`closed`), `accepted_answer_id`, created and updated. `qa_answers`: question FK, body, author kind and id, `run_id`, created. Indexes on (workspace, status, created).
- Skill source on `skills`, as nullable columns or a `skill_sources` table (pick one and say why). It holds `provider` (`github`), `repo_url`, `path`, `ref`, `commit_sha` (pinned), `latest_commit_sha`, `checked_at`. The URL, path and ref rules come from trueforge `packages/trueforge/src/schemas/skill.ts` (MIT), GitHub only.
- `map_positions` (workspace, `node_key`, x, y) so dragged positions persist. Node keys are `trigger:<id>`, `agent:<id>`, `out:slack:<channel>`, `out:library:<folder>`, `out:qa`, `out:email:<agent>`.
- `@repo/db/shared`: `MapNode`, `MapPort`, `MapWire` (from, to, kind, 7-day count, active) and `MapGraph` types. Also `QA_STATUSES`. The `GithubSkillSource` and `FetchedSkillTree` port types go in `packages/protocol/src/skills.ts`, shared by V7.9 and V7.10.
- Events in `EVENT_TYPES`: `qa.asked`, `qa.answered`, `qa.accepted`, `skill.update_available`, `map.edited`, with payload shapes.
- `bun run generate` in `packages/db`, committing `migrations/` and `meta/`.
