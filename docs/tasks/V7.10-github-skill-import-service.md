Import a skill from a GitHub URL into the existing git-like skill store, pinned to a commit, and notice when upstream moves.

## Scope
- `packages/services/src/skills-store.ts` (or a new `skills-store/github.ts`): `importFromGithub(principal, { url, path, ref })` resolves the commit, fetches the tree through the injected fetcher port, and uses the existing `importNew`/`importOver` path, so approval and `skill.imported` behave as for a `.skill` archive. It stores the source with the pinned `commit_sha`.
- `checkUpdates(batch)` resolves `ref` for skills with a GitHub source. When the commit differs from both the pinned and the last seen one, it records `latest_commit_sha` and writes `skill.update_available` once per new commit.
- `importUpdate(principal, skillId)` fetches `latest_commit_sha` as a new proposed version, which goes through the existing approval and shows in Needs you as a skill proposal (V2). The pin moves when the version is approved.
- tRPC: `skillStore.importGithub`, `skillStore.importUpdate` and the source on the skill read, in `skill-store-router.ts`.

## Check
- `packages/services/src/skills-store/github.test.ts` with a fake fetcher: import pins the sha, re-import over an existing skill, `checkUpdates` is idempotent per commit, `importUpdate` creates a proposed version and approval moves the pin, and fetcher failures surface as messages.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-27)

Checked against main at 24c28ad. Where these differ from the scope above, they win.

- depends_on stays V7.1. Skill proposals already show in Needs you (`desk.ts` reads `skillsStore.proposals`, `components/desk/proposal-actions.tsx`), from V2.
- `importNew`, `importOver` and `publish` are closures inside `createSkillsStoreService` (around lines 522, 1486 and 1507 of `skills-store.ts`). So the new methods go inside the factory, and pure helpers (skill name from the path's last segment or the repo name, the update rule) go in `skills-store/github.ts`.
- `publish` sets `approved` from `caller.kind !== "agent"`, so a person's import is approved at once. `importGithub` keeps that, as the archive import does. `importUpdate` must create a `proposed` version for a user caller: add an optional `status` to `Publication`. Fill `skill_versions.source_commit_sha` (V7.1) on both.
- Moving the pin: when `approve` (`decide`) approves a version with `source_commit_sha`, set `skill_sources.commit_sha` in the same `atomic` write.
- `importGithub` and the first write of `skill_sources` go together. Re-import over an existing skill replaces the source row.
- `checkUpdates(principal, { limit })` runs as `SYSTEM_PRINCIPAL` across workspaces, oldest `checked_at` first over V7.1's index, and sets `checked_at` on every skill it looks at, failures included.
- The fetcher is an optional factory dependency (`github?: GithubSkillFetcher`, with an optional `githubToken?: string`), so `compose.ts` compiles until V7.12. Without it, `importGithub` answers a clear "GitHub import is not set up" error.
- Same-file overlaps: none. No V3 to V6 task edits `skills-store.ts` or `skill-store-router.ts`.
