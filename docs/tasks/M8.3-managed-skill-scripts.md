Asked for by Dom on 17 Oct 2026: a skill that ships a TypeScript script should run on every runtime. M8.1 doesn't sync skills (`docs/reviews/tasks/M8.1.md`: "Skills are not synced"), so a Managed Agent never sees the skill or its script. Agentum had skills code that M8.1 left out. Its source is `/home/roboto/devel/agentum`, read-only, and code can be copied from it.

## Scope

- Give a managed agent its workspace skills (S.1/S.2, the agent's Skills tab) with all their files. Use whatever Managed Agents supports, such as Anthropic's Skills API attached to the agent, or files placed in the session's environment. Pick one, record why in the review file, and keep skills in sync when they change (on agent sync or at session start, whichever the API allows).
- A skill script written in TypeScript runs in the Managed Agents sandbox. Find out which runtime the sandbox has (bun, node with `--experimental-strip-types`, `npx tsx`), and make the skill guidance Harbourmaster adds to the agent say how to run a `.ts` file there. If the sandbox can't run TypeScript directly, say what's needed and do the smallest thing that works, such as installing bun in the environment setup.
- Remove "skills not synced" from the agent form's notes for managed agents once it works.

## Check

Unit tests for the sync against a fake gateway: skills uploaded or attached, a changed skill updated, a removed skill detached. Live, with `ANTHROPIC_API_KEY` from `apps/web/.env.local` stored as the workspace key in the local dev database and a cloudflared quick tunnel (`--config /dev/null`): a skill `ts-hello` with `SKILL.md` and `scripts/hello.ts`, which prints a codeword computed at run time (for example from its argument), is assigned to a managed agent. Asked to use the skill, the agent runs the script and replies with the codeword. `bun run check && bun run test && bun run build` pass.
