From M4 gate round 1 (docs/reviews/M4-1.md, must-fix 1), approved by Dom on 16 Oct 2026: unclaimed runs end after 1 hour with "Never claimed". Never-claimed queued runs pile up without limit, so after about 4,200 of them a healthy crash-left run waited 43 sweep passes.

## Scope

End runs that nobody claims, so they stop holding the sweep and stop blocking routine settlement. In the sweep, move a run that has stayed `queued` or `offered` for more than 1 hour, measured from `created_at`, to `failed` with the error "Never claimed". The hour is a named constant. Use a conditional write guarded on the starting statuses, as the reaper does, so a claim that wins is kept. Write the matching run event. Settlement already treats `failed` as an error, so a routine on a dead machine reaches five errors and switches itself off, and the backlog is bounded by age times firing rate. Keep the per-pass limit and the `swept_at` order. Don't change how the sweep offers runs younger than the cut-off.

## Check

A `runs` service test keeps one never-claimed run per simulated minute for longer than the cut-off, sweeping every minute. It shows the number of never-claimed runs in a starting status stays below a fixed bound, and that a crash-left run created after that is offered within a bounded number of passes that does not grow with elapsed time: run it at 200 and at 3,000 simulated minutes and get the same pass count. A `routines` test shows a routine whose machine never claims switches itself off after five expired runs. Both tests fail on 6ed11d4. A test shows a claim that lands just before expiry is kept. The existing sweep and routines tests still pass. `bun run check && bun run test && bun run build` pass.
