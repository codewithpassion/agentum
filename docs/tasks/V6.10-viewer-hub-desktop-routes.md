People watch and drive the desktop. This ports agentum `viewer-hub.ts` (JPEG frames pushed over a viewer WebSocket, about 16 fps, slowing down when the screen is idle) and `desktop-routes.ts`.

## Scope
- `apps/web/src/server/viewer-hub.ts` lives in `MachineRelay` under socket tag `viewer`. Binary frames are a 4-byte id plus JPEG, there are status and problem messages, acks with `MAX_UNACKED_FRAMES` skipping, and input only while the viewer holds the human lease.
- `apps/web/src/server/routes/desktop.ts` (Clerk session, workspace-checked): `GET /api/machines/:id/desktop` (status), `/desktop/stream` (viewer upgrade with the user header set by the Worker only), `POST /desktop/input`, `GET`/`PUT /desktop/clipboard`, and `POST /desktop/take-control`, `/hand-back` and `/cancel-takeover`.
- Hand-back and cancel call `takeover.handBack` and `takeover.cancel` from V6.7, so the waiting run resumes, which is agentum's `takeover-hook.ts` role. Take-control on an open request calls `takeover.take`.
- Mount the routes in the Worker entry beside the machine routes.

## Check
- `apps/web/src/server/viewer-hub.test.ts` (ported from agentum): frame pacing, ack skipping, idle slowdown, problem codes and input refused without the lease. `routes/desktop.test.ts`: auth, workspace isolation, the take-control to hand-back flow calling the takeover service, and the viewer header being stripped from client requests.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-27)

Checked against main at 26b4c58. Where these differ from the scope above, they win.

- Sources: agentum `modules/computer/viewer-hub.ts`, `desktop-routes.ts`, `desktop-capture.ts`, `desktop-failure.ts` and `takeover-hook.ts`.
- The viewer socket already carries input (`{"t":"input"}` in agentum's viewer hub). Keep input on the socket and drop `POST /desktop/input` unless the port needs it.
- Take control, hand back and cancel are V6.7's tRPC `takeover.*` procedures, so drop those three Hono routes. Fill V6.7's `lease` dependency from the relay port in `compose.ts`.
- The stream and clipboard routes use the Clerk session: mount them on `cookieGroup()` (`routes/groups.ts`, csrf on, as `routes/access.ts` does), read `getAuth(c)` and resolve the principal as `trpc/context.ts` does. They are Hono because the stream is a WebSocket upgrade. Strip any client copy of the viewer user header, as `UPGRADE_HEADERS` does in `routes/machines.ts`.
- Same-file overlaps: `server.ts` and `compose.ts` with V5.7 and V4.21 (worker lane).
