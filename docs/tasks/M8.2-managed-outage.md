From the M8 gate, round 1 (`docs/reviews/M8-1.md`, nit 8), approved by Dom on 17 Oct 2026. When the reaper interrupts a managed run, for example after a `ManagedPoller` outage longer than 90 s, nothing tells Anthropic to stop and nothing closes `managed_sessions`. The Anthropic session keeps spending until it goes idle. Cloud runs got outage tolerance in C.4. Managed runs didn't.

## Scope

1. When a managed run ends as `interrupted` or `failed` by the reaper or sweep, interrupt the Anthropic session and close its `managed_sessions` row, the same way `abandon` does on cancel. Keep it conditional on the run still being the session's current run (M8.1's third fix round).
2. Give managed runs the same outage rule as cloud runs (C.4): the poller's alarm keeps the lease alive, and a short poller outage doesn't interrupt a run that Anthropic is still working on. Reuse C.4's approach where it fits.

## Check

Tests against the fake gateway: a reaped managed run sends the interrupt and closes the session row; a reaped run that is no longer the session's current run doesn't touch the session; a poller that is down for 120 s doesn't interrupt the run, which ends `done`. `bun run check && bun run test && bun run build` pass.
