The VM gets the same live sync as the daemon: a periodic push while it runs, and a pull when the server announces a change. Today it syncs out only at run end in `pi-run.ts` `complete`.

## Scope
- `apps/web/src/server/linux-vm/vm-library-sync.ts`: use `librarySyncScope` with modes instead of `librarySyncRoots`, and the V4.4 `only` pull.
- `apps/web/src/server/pi-run.ts`: while a VM run is running, the alarm runs `syncOut` every 30 s (taking turns with the existing checkpoint and end syncs); new `libraryChanged(paths)` RPC runs a targeted `syncIn`.
- The VM prompt (`linux-vm/vm-tools.ts`) and the isolate prompt (`library-env/library-tools.ts`) name the task folder through the V4.8 builder. Remove `[ATTACHMENT:]` handling in `pi-run-files.ts` and `pi-run-core.ts`.

## Check
- `pi-run-core.test.ts` / `pi-run-files.test.ts` with the fake VM: periodic sync out fires during a run and stops after; `libraryChanged` pulls one path; read-only roots are not pushed; no marker handling remains.
- `bun run check && bun run test && bun run build` pass.
- Live (controller, in V4.21): a person's edit appears in `/workspace/library` mid-run.
