Asked for by Dom on 17 Oct 2026. The Clerk dev instance now accepts Client ID Metadata Documents (CIMD): a client's `client_id` is an HTTPS URL serving a JSON document with its `client_name`, `logo_uri` and `redirect_uris`. Claude.ai connects this way, with `client_id` `https://claude.ai/oauth/mcp-oauth-client-metadata`. `clerkOAuthClientName` in `apps/web/src/server/mcp/clerk-oauth-client.ts` looks only at Clerk's registered OAuth applications, so a CIMD client is stored with `name` null and shows as its URL in Settings → Connected apps.

## Scope

- When the client id is an `https://` URL with a path and no registered Clerk application matches, fetch that URL and use the document's `client_name`. Accept it only when the response is OK, JSON, at most 64 KB, answers within a few seconds, and its `client_id` equals the URL exactly. Trim the name and cap it at 100 characters. Anything else gives null, as today. Never follow the fetch for a non-https id.
- A client stored with `name` null gets its name filled the next time its token is resolved, so the existing staging row for claude.ai is fixed without a migration. A stored name is never overwritten.
- Keep the fetch logic a pure function that takes `fetch`, so it can be unit tested.

## Check

- Unit tests: a valid document gives its name; a mismatched `client_id`, non-JSON, oversized body, non-https id, network error and missing `client_name` each give null; a null stored name gets filled on resolve and a stored name is kept.
- `bun run check && bun run test && bun run build` pass.
