From the build plan's M9 section (docs/architecture/build-plan.html#m9), approved by Dom on 16 Oct 2026. The second M9 page, after Sessions, so it can link into it and reuse its e2e setup.

## Scope

A Log page in the app shell, with a nav entry: the workspace's events, newest first, filterable by agent, event type and date range, paged. Each row shows time, type, agent and a short summary, and links to its session (the M9.1 page) and run where it has one. Data comes through tRPC and the existing events service, with `authorize()` first and the same session visibility rules, so events from another user's private session don't show. Use existing shadcn components only.

## Check

`apps/web/e2e/log.ts`, a dev-login browser script (with a `bun run e2e:log` script): it creates activity, sees the events, filters by agent and by type, and follows a row's link to its session. A service or router test shows events from another user's private session are left out, and that paging and the date filter work. The bundle grep for `drizzle` passes. `bun run check && bun run test && bun run build` pass.
