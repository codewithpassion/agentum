People answer where they already are. A request goes to Slack through the run's agent's own Slack app, and whichever surface answers first wins; the other surface's card updates to show the result.

## Scope
- Manifest: `packages/services/src/slack/manifest.ts` sets `interactivity: { is_enabled: true, request_url: <origin>/api/slack/interactions }`. Installed apps need the new manifest pasted once; the Slack tab (`apps/web/src/components/agent/tabs/slack.tsx`) already shows the manifest, so add one line saying it changed and must be updated in Slack.
- Route `POST /api/slack/interactions` in `apps/web/src/server/routes/slack.ts`: form-encoded `payload`, same signature check as `/events` (`slack/signature.ts`, the app found by `api_app_id`). A `block_actions` answer acks within 3 s and does the work in `defer`; a "Answer" button opens the modal with `views.open`; a `view_submission` answers from the modal.
- Who may answer: the clicking Slack user resolved to a Clerk user through the existing identity links (`slack.ts`); an unlinked user, or one who can't see the run's session, gets an ephemeral "You can't answer this one." The answer goes through `requests.answer` with `via: "slack"`; a `conflict` updates the card to the settled state.
- Posting, as an `events.onAppend` listener (`request.opened`) registered in `compose.ts` beside `slackGateway.notifyNeedsAuth`, deferred: a run started from Slack posts the card in its thread; any other run posts to the run's `on_behalf_of_user_id` as a DM from the agent's app when that person has a linked Slack identity and the agent has an installed app; otherwise nothing. Store `slack_message` on the request.
- Settling: on `request.answered`, `request.expired`, `request.cancelled`, `chat.update` the stored card with `settledCard`.
- New service code lives in `packages/services/src/slack/requests.ts`; reuse `createSlackClient`, `withRetry` and `findInstalledApp`.

## Check
- `slack/requests.test.ts` with a fake Slack client: card posted in the thread for a Slack run and as a DM for a web run with a linked user; no post without an app or link; an answer from Slack calls the service and settles the card; a second click after a web answer shows the settled card; expiry settles the card.
- `routes/slack-interactions.test.ts`: bad signature 401, ack under the deferred work, modal open and submit.
- `bun run check && bun run test && bun run build` pass.
- Live on staging (controller): Dom pastes the updated manifest into one agent's Slack app; an approval from a Slack-started run shows buttons in the thread, Deny there settles it, and the web card shows "Denied in Slack".
