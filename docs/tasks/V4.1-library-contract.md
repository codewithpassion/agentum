Every other V4 task builds on these tables, types and frames. It is the only V4 task that changes `packages/db/src/schema` or generates a migration.

## Scope
- `packages/db/src/schema/library.ts`: new tables. `library_versions` (id ULID, workspace_id, path, version number per path, etag, blob_key under `${workspaceId}/library-versions/<id>` (null for a delete tombstone), size, sha256, op `write | delete | restore | move`, author kind and id, run_id, created_at; index on workspace_id, path, version). `agent_library_access` (workspace_id, agent_id, path, mode `read | write`, created_at; primary key agent_id and path). `library_conflicts` (id, workspace_id, path, conflict_path, agent_id, run_id, status `open | resolved`, resolution, created_at, resolved_at). `library_links` (workspace_id, from_path, target as written, target_key as the wiki page path it would resolve to; primary key from_path and target). `wiki_suggestions` (id, workspace_id, path, base_version_id, blob_key under `${workspaceId}/wiki-suggestions/<id>`, summary, agent_id, run_id, status `pending | accepted | rejected | stale`, decided_by, decided_at, result_version_id, created_at).
- The migration (`bun run generate` in packages/db, commit `migrations/` and `meta/`) also copies each agent's `runtimeConfig.libraryPaths` into `agent_library_access` as `write` rows (hand-written `json_each` insert at the end of the generated file), and writes version 1 rows for every existing `library_entries` file so history starts from today. Check that the `events` triggers survive.
- `packages/db/src/shared.ts`: `LIBRARY_ACCESS_MODES`, `LIBRARY_VERSION_OPS`, `LIBRARY_CONFLICT_STATUSES`, `WIKI_SUGGESTION_STATUSES`, `WIKI_ROOT = "wiki"`, `taskFolderPath(slug, taskId)` returning `agents/<slug>/tasks/<taskId>`, retention constants (`LIBRARY_VERSION_KEEP_DAYS = 30`, `LIBRARY_VERSION_KEEP_MIN = 20`), and new `EVENT_TYPES`: `library.restore`, `library.access`, `library.conflict.resolved`, `wiki.suggestion`, `wiki.suggestion.decided`.
- The access rule, written down as a doc comment on `agent_library_access`: people read and write everything; an agent's run reads and writes its home `agents/<slug>/`, reads `wiki/` and every `read` row, writes every `write` row, and nothing else. Wiki edits from an agent without write access go through suggestions.
- `@repo/db/shared` types: `LibraryChange` (`workspaceId`, `paths`, `byRunId`) for the change notifier, `LibraryAccessGrant` (`path`, `mode`).
- `packages/protocol/src/machine.ts`: `FEATURE_LIBRARY_LIVE = "library-live"`; `daemonHelloSchema` gains optional `features: string[]`; a new relay frame `library_changed` (`paths: string[]`) in `relayFrameSchema`; claim `library` gains optional `roots: { path, mode }[]` and `taskFolder`, sent only to a daemon that names the feature.
- `packages/protocol/src/library.ts`: wire shapes the daemon needs for targeted pulls if any change (none expected beyond the claim).

## Check
- `packages/db/src/schema.test.ts` and `foreign-keys.test.ts` cover the new tables; a migration test (`packages/db/src/library-access-migration.test.ts`) shows `libraryPaths` becoming `write` rows and existing files getting version 1.
- `packages/protocol/src/machine.test.ts`: the new frame parses, an old hello without `features` still parses, a claim without `roots` still parses.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-26)

Checked against main at aac119a. Where these differ from the scope above, they win.

- depends_on is V3.1 only. V3.1 is the only V3 task that touches `packages/db/src/schema`, `shared.ts` and the migrations. No V3 task touches `packages/protocol/src/machine.ts` (V3.1 leaves it alone). V3.1 has merged with `0017_cloudy_sersi.sql`, so this migration is 0018 unless something else merges first.
- Drop the version 1 backfill from the migration. A SQL migration cannot copy R2 objects, and a version row must not point at the live key, because the next write replaces those bytes. V4.2 instead keeps the current bytes as version 1 the first time it changes a file that has no version rows. `sha256` stays not null. The migration test covers the `libraryPaths` copy only.
- The `libraryPaths` copy: `INSERT OR IGNORE INTO agent_library_access ... FROM agents, json_each(agents.runtime_config, '$.libraryPaths')`, with `trim(value, '/')`, skipping empty and non-text values. Copy every agent, archived and draft ones included. The primary key absorbs duplicates. Anything saved to `libraryPaths` after the migration runs is not copied. V3.10's Library row writes there until V4.19 replaces it, so V4.21 runs the same statement again on staging. It is safe to run twice.
- Foreign keys: `agent_id` to `agents`, `run_id` (nullable) to `runs`, `workspace_id` to `workspaces`. `foreign-keys.test.ts` inserts parents first.
- `shared.ts` additions beyond the scope, so no other V4 task edits it: `LibraryAccessMode` type; `NEEDS_YOU_KINDS` gains `library_conflict` and `wiki_suggestion`; `DESK_CARD_KINDS` gains `conflict`, and a suggestion card uses `proposal` like a skill version. `taskFolderPath(slug, taskId)` takes the run id, because a task is one run (V2), so a follow-up run gets its own folder.
- No `library.move` event: `move` logs `library.delete` and `library.write` today (`library.ts` around line 580), and V4.2 records the move as a version op.
- Library events carry `runId` but no `sessionId`, so they never reach a session stream, and the browser has no workspace stream. Leave `STREAM_EVENT_TYPES` alone. V4.15 and V4.18 refetch instead.
- `packages/protocol/src/machine.ts` already has `DAEMON_FEATURES_HEADER`, `hasDaemonFeature` and `FEATURE_LIBRARY_SYNC`. Add `FEATURE_LIBRARY_LIVE` beside them. `daemonHelloSchema` is a `strictObject`, so `features` must be `.optional()` or old daemons fail the hello. The claim's `library` keeps `paths` and `conflicts`, and `roots` and `taskFolder` are optional.
- `packages/protocol/src/library.ts` needs no change. Drop that bullet.
- `packages/library-sync` has no dependency on `@repo/db`, so V4.4 declares its own `"read" | "write"` type.
- Dom's open questions, plan defaults: an agent reads only its home, `wiki/` and its grants (decided 26 Oct), existing `libraryPaths` become `write` grants, and versions are kept 30 days, then the newest 20 per file.
