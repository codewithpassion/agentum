Dry runs also reach the platform MCP tools (`send_message`, inbox, Slack, skills, triggers, routines, library). The read tools must work and the write tools must answer with what they would have done.

## Scope
- `packages/mcp/src/tools/define.ts`: each tool declares whether it writes. When the calling principal is a run with `dry_run` set, a writing tool returns "Skipped in dry run: would <action> <summary>" and records `run.dry_run_skipped` instead of calling its service.
- Mark the writing tools in `agents.ts` (`send_message`, `cancel_run`), `inbox.ts`, `slack.ts`, `skills-write.ts`, `triggers.ts`, `routines.ts` and the library tools' writes in `library.ts`. List and read tools stay as they are.
- The principal must carry the run's `dry_run` flag. If V1's run principal lacks it, add it where the run token is resolved (`packages/services/src/run-tokens.ts`), with a test.

## Check
- `packages/mcp/src/tools/tools.test.ts`: every writing tool, called by a dry-run principal, returns the skipped text, records the event and leaves its service uncalled; read tools work; a normal run is unchanged.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-26)

Checked against main at ae74008. Where these differ from the scope above, they win.

- Tools already declare whether they write: every definition carries `annotations`, `READ_ONLY` or a `WRITE_*` set (`tools/define.ts`). Do not mark tools one by one. Gate once in `registerTools` (`packages/mcp/src/register.ts`) or in `harbourmasterTools` through a new `ServerOptions` field: a tool whose `annotations.readOnlyHint` is not true returns the skipped text.
- The route builds the server in `apps/web/src/server/routes/mcp.ts` (around line 386) with `readOnly: isReadOnly(principal)`. Pass the dry-run option there when `principal.kind === "run" && principal.dryRun` (V3.1), with a recorder that calls `services.runs.recordDryRunSkip` (V3.1). `packages/mcp` stays free of services.
- The run principal already carries `dryRun` from V3.1, so `run-tokens.ts` needs no change here.
- The library `bash` tool is `SCRIPT_WRITE`, so a dry run cannot use it, reads included. Cloud runs read the library with Pi's `read` tool instead. Say so in the skipped text.
- In a cloud dry run, V3.8's gate already blocks these tools before the call leaves PiRun. This task is the backstop for any other holder of the run token.
