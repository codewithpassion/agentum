From M5 gate round 2 (docs/reviews/M5-2.md, finding 3), raised to a task by Dom on 16 Oct 2026. tRPC `runs.start` takes `startRunInputSchema` unchanged (`apps/web/src/server/trpc/runs-router.ts:11-15`), so a browser caller can pick any `origin` and set `private` (`packages/services/src/runs/types.ts:64-67`). A member who knows a future session key (a Slack thread `team:channel:parentTs`, or an inbox thread an agent hasn't been woken in yet) can create that session as private first. When the real Slack mention or inbox wake arrives, `findSession` treats it as foreign and answers `not_found` (`runs/queries.ts:75`), and the thread stops reaching the agent.

## Scope

Narrow the router's input to `origin: "ui"` with no `private` field, so only in-process callers (Slack, inbox, triggers, routines) set other origins or `private`. The service schema stays as it is for those callers. Check for any other browser or MCP entry point that passes a caller-chosen `origin` or `private` into `startRun`, and narrow it the same way.

## Check

A `runs-router` test shows `origin: "slack"`, `origin: "inbox"` and `private: true` are rejected, and a plain `ui` start still works. If another entry point was narrowed, it gets the same test. `bun run check && bun run test && bun run build` pass.
