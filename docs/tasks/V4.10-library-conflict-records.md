A sync conflict today is only a `.conflict-<runId>` file and a `library.conflict` event. To show in Needs you it needs a state a person can resolve.

## Scope
- `packages/services/src/library.ts`: `recordConflict` also inserts a `library_conflicts` row (same `atomic` batch as the event). `pendingConflicts` reads open rows.
- `resolveConflict(principal, id, choice)`: `keep-library` deletes the copy; `keep-agent` writes the copy's bytes over the file as a new version, then deletes the copy. Both close the row with a `library.conflict.resolved` event. Deleting a conflict copy by any other route also closes its row.
- A Needs you item provider for open conflicts, in the shape the V2 desk aggregates.
- tRPC `library.conflicts.list/resolve`.

## Check
- `packages/services/src/library-conflicts.test.ts`: record opens a row; each choice leaves the right bytes and versions and closes the row; deleting the copy closes it; the provider lists only open rows of the workspace.
- `bun run check && bun run test && bun run build` pass.
