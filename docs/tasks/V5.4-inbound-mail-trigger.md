Mail to an agent is a trigger. A new thread starts a session and a task; a reply in the thread continues the same session.

## Scope
- `packages/services/src/mail/inbound.ts`: `receive(message)` finds the mailbox by recipient, records a `mail_messages` row and the thread, and emits `mail.received`.
- With the agent's `mail` trigger enabled, it starts a run through the runs service in the session keyed `mail:<mailboxId>:<threadId>` (created on first mail, like Slack threads), links the thread to the run's task, and saves attachments into the task folder (`agents/<slug>/tasks/<id>/mail/`). The run input quotes sender, subject and body as untrusted content.
- Loop guard: ignore mail from the workspace's own agent addresses, `Auto-Submitted` and list mail; a delivery status notification marks the original outbound message `bounced` and emits `mail.bounced`.
- With the trigger off, the mail is stored and shown, and no run starts.
- tRPC: `mail.threads(agentId)`, `mail.thread(id)` (index rows plus the body from the backend), `mail.threadForTask(taskId)`.

## Check
- `packages/services/src/mail/inbound.test.ts`: first mail makes session, task and run; a reply reuses the session; trigger off stores only; a loop and an auto-reply are ignored; a bounce marks the outbound message; attachments land in the task folder.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-27)

Checked against main at c5ba505. Where these differ from the scope above, they win.

- depends_on adds V4.9. Attachments go into the run's task folder, which V4.9 makes at run start (`taskFolderPath(slug, run.id)` from V4.1). The path is `<taskFolder>/mail/<filename>`. A task is one run, so a reply's attachments land in the reply run's folder.
- `library.write` takes only a user or run principal (`library.ts:86`). Write with the new run's principal (`{ kind: "run", runId, agentId, workspaceId }`). V4.3 lets a run write its home. Skip files over `LIBRARY_FILE_MAX_BYTES` and say so in the run input.
- Start the run with a trigger principal built from the mailbox's `mail` trigger row (`workspaces.ts:41`). Use `reply: { kind: "none" }`, because the agent answers with `mail_reply`. Use `session: { origin: "mail", externalKey: "mail:<mailboxId>:<threadId>" }` and `requestId: "mail:<externalMessageId>"`, so a redelivered mail starts one run. `prepareStart` refuses agents that are not active, so mail to a draft or archived agent is only stored.
- A reply starts a new run in the same session, as V2's follow-ups do. The task view lists the session's runs, so "continues the same task" means the same session.
- Trigger switch: `setTrigger(principal, agentId, on)` sets or clears `disabledAt` on the mail trigger row, and tRPC `mail.setTrigger` exposes it for V5.9. People only.
- Server bits V5.11 only renders: add `mail` to `SESSION_ORIGINS` (`runs/types.ts:30`), `mail: "Mail"` to `ORIGINS` (`tasks/receipt.ts:34`), and a `mail` case to `StartedBy` in `tasks/service.ts` (around line 256) labelled "Mail from <sender>: <subject>".
- Bounce on the desk: a run with a `bounced` outbound message gets an error band "Mail to <address> bounced" in `desk.ts`. V5.10 shows it.
- Same-file overlaps in the services lane: `tasks/service.ts` (V3.7, V4.9), `desk.ts` (V3.7).
