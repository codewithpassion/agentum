Mail to an agent is a trigger. A new thread starts a session and a task; a reply in the thread continues the same session.

## Scope
- `packages/services/src/mail/inbound.ts`: `receive(message)` finds the mailbox by recipient, records a `mail_messages` row and the thread, and emits `mail.received`.
- With the agent's `mail` trigger enabled, it starts a run through the runs service in the session keyed `mail:<mailboxId>:<threadId>` (created on first mail, like Slack threads), links the thread to the run's task, and saves attachments into the task folder (`agents/<slug>/tasks/<id>/mail/`). The run input quotes sender, subject and body as untrusted content.
- Loop guard: ignore mail from the workspace's own agent addresses, `Auto-Submitted` and list mail; a delivery status notification marks the original outbound message `bounced` and emits `mail.bounced`.
- With the trigger off, the mail is stored and shown, and no run starts.
- tRPC: `mail.threads(agentId)`, `mail.thread(id)` (index rows plus the body from the backend), `mail.threadForTask(taskId)`.

## Check
- `packages/services/src/mail/inbound.test.ts`: first mail makes session, task and run; a reply reuses the session; trigger off stores only; a loop and an auto-reply are ignored; a bounce marks the outbound message; attachments land in the task folder.
- `bun run check && bun run test && bun run build` pass.
