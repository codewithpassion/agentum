V1 adds a live event stream, a `waiting` run state, ask-user questions and tool approvals across the machine, cloud and managed runtimes. This task fixes every shape the other V1 tasks share, so they can run in parallel without touching `packages/db/src/schema` or each other's types.

## Scope
- `packages/db/src/shared.ts`:
  - `RUN_STATUSES` gains `"waiting"` (a run with at least one open request; its runtime keeps the lease going).
  - New enums: `REQUEST_KINDS = ["approval", "question"]`, `REQUEST_STATUSES = ["pending", "answered", "expired", "cancelled"]`, `APPROVAL_DECISIONS = ["allow_once", "always_allow", "deny"]`, `TOOL_RULE_MODES = ["ask", "allow"]`, `ANSWER_SURFACES = ["web", "slack"]`, each with its type.
  - New constants: `APPROVAL_TTL_MS = 60 * 60_000` and `QUESTION_TTL_MS = 24 * 60 * 60_000` (defaults until Dom says otherwise), `QUESTIONS_MAX = 4`, `CHOICES_MAX = 6`.
  - `EVENT_TYPES` gains `request.opened`, `request.answered`, `request.expired`, `request.cancelled`, `run.waiting`, `run.resumed`, `tool_rule.changed`.
- New schema `packages/db/src/schema/requests.ts`, table `run_requests`: `id`, `workspace_id`, `run_id`, `session_id`, `agent_id` (all FKs as in `runs.ts`), `kind`, `status`, `tool_use_id` (the runtime's call id), `tool_key` (null for questions), `tool_name` (as the runtime named it), `display` (JSON: the scrubbed input summary for an approval, the questions for a question), `answer` (JSON, null until answered), `answered_by` (Clerk user id), `answered_via`, `created_at`, `expires_at`, `answered_at`, `slack_message` (JSON `{ appId, channel, ts }`, null when no card was posted). Unique `(run_id, tool_use_id)` so a create is idempotent; indexes `(workspace_id, status)` and `(status, expires_at)`.
- New schema `packages/db/src/schema/tool-rules.ts`, table `agent_tool_rules`: `id`, `workspace_id`, `agent_id`, `tool_key`, `mode`, `updated_by`, `updated_at`; unique `(agent_id, tool_key)`. No row means allow, which is today's behaviour.
- `bun run generate` in `packages/db`; commit `migrations/` and `meta/`. Add the two modules to `exports` only through the existing `./schema/*` entry.
- New `packages/protocol/src/requests.ts` (zod, browser safe): `questionSchema` (`question`, optional `header`, optional `choices` up to `CHOICES_MAX`, `multiSelect`, free text always allowed), `questionDisplaySchema` (1 to `QUESTIONS_MAX` questions), `approvalDisplaySchema` (`toolName`, `toolKey`, `summary` string capped at 2 000 chars, `input` scrubbed JSON capped at 8 KB), `approvalAnswerSchema` (`decision`, optional `note`), `questionAnswerSchema` (`answers: Record<question, string>`), and the outcome a runtime receives: `requestOutcomeSchema` = answered with its answer, or `expired`, or `cancelled`. Only types and schemas here; V1.3 writes the functions.
- New `packages/protocol/src/stream.ts` (zod, browser safe): the SSE frames of `GET /api/sessions/:sessionId/stream`. `event` frame = a stored `EventRecord` shape (id, type, runId, seq, actor, createdAt, payload, `truncated: true` instead of the payload when it went to R2); `delta` frame = `{ runId, messageKey, text }`, ephemeral, carrying the full masked partial text so far; `run` frame = `{ runId, status }`; `request` frame = `{ requestId, runId, kind, status }`; `ping`. Only `event` frames carry an SSE `id:` (the event ULID), so `Last-Event-ID` resumes on stored events only.
- `packages/protocol/src/machine.ts`: `FEATURE_REQUESTS = "requests"` for `X-Daemon-Features`; `createRequestBodySchema` (kind, toolUseId, toolName, display) and `createRequestResponseSchema` (`requestId`, `status`, optional `outcome`), `waitRequestResponseSchema` (`status`, optional `outcome`) for the daemon routes V1.9 adds. `claimResponseSchema` gains optional `toolRules: string[]` (the agent's ask tool keys), sent only to a daemon that names `FEATURE_REQUESTS`.
- `packages/db/src/schema.test.ts` and `foreign-keys.test.ts` cover the two tables.

## Check
- `packages/db` tests: both tables migrate, the unique `(run_id, tool_use_id)` and `(agent_id, tool_key)` hold, FKs refuse an unknown run or agent.
- `packages/protocol/src/requests.test.ts` and `stream.test.ts`: each schema accepts a good value and refuses an oversized display, a sixth question, an unknown decision, and a `delta` frame without `runId`.
- `bun run tasks` still passes (no consumer breaks on the new run status: grep for exhaustive switches on `RunStatus` and add the `waiting` arm where TypeScript asks).
- `bun run check && bun run test && bun run build` pass.
