From M7 gate round 1 (docs/reviews/M7-1.md, must-fix 1). A file the agent sends back shows as a chip only for the latest run, and the raw `[ATTACHMENT:path]` text stays in the agent's message.

## Scope

In the chat, show each run's output files as chips on that run's reply, for every run in the session, not only the latest. Remove the `[ATTACHMENT:...]` markers from the assistant text the chat shows. One way is for `sessions.transcript` to return `outputFileIds` per run (or include `run.finished` entries, whose payload already carries `outputFileIds`). `toChatItems` then attaches them to the last assistant item of that run and strips markers from assistant text. The marker regex moves from `apps/daemon/src/attachments.ts` into `@repo/protocol`, which the daemon already imports, so the daemon and the chat share one copy and it cannot drift. The separate "Files from the agent" block goes away, or stays only for a run without an assistant message. The changes go in `packages/protocol`, `packages/services/src/sessions.ts` and `apps/web/src/components/agent/chat/`. In the daemon, only the import of the regex changes.

## Check

A `chat-logic.test.ts` case with two runs in one session, each with an output file. Both chips appear under their own assistant items, and an assistant text `"Here [ATTACHMENT:/w/report.md]"` renders as `"Here"`. A `sessions.test.ts` case shows the transcript carries both runs' output ids. Browser (dev login, `fake` runtime, or a completion posted with `fileIds`): after a second message, the first run's output chip is still visible and opens the file.
