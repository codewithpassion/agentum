The take-over flow from agentum `questions/service.ts` (`requestTakeover`, `settleTakeover`) and `computer/takeover-hook.ts`, rebuilt on V1's pending requests and waiting run state. That way a take-over lands in Needs you like any other request.

## Scope
- `packages/services/src/takeover.ts`: `request(runPrincipal, { reason })` creates a pending request of kind `takeover` for the run's agent computer and puts the run in the waiting state. Only one can be open per computer. It writes `computer.takeover_requested`.
- `take(user, requestId)` records who holds it (`computer.taken`). `handBack(user, requestId, note)` settles it, resumes the run through V1's resume path with the person's note, and writes `computer.handed_back`. `cancel` settles it without a note.
- The first answer wins, the way V1 settles approvals. Expiry follows V1's expiry rules.
- tRPC: `takeover.take`, `takeover.handBack` and `takeover.cancel` in `apps/web/src/server/trpc/`.

## Check
- `packages/services/src/takeover.test.ts`: request puts the run into waiting, a second request is refused, two hand-backs race and one wins, cancel, expiry, and the resume carries the note.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-27)

Checked against main at 26b4c58. Where these differ from the scope above, they win.

- Build on `packages/services/src/requests.ts`. `open` inserts the row, writes `request.opened` and calls `runs.markWaiting`. `answer` settles with a conditional update, so the first answer wins, and `resume` calls `runs.resumeRequest`, which wakes the blocked tool call (`pi-run-gate.ts` waiters, managed `resume`). - In `requests.ts`: `open` accepts kind `takeover` with V6.1's display and TTL, and refuses a second pending takeover for the same agent (one agent per computer, so that is one per computer). `answer` parses `takeoverAnswerSchema`. Add `cancel(user, requestId)`, which sets `cancelled` and resumes, so the tool returns that the person cancelled. `expireDue` needs no change.
- `writer()` admits only system or the claiming machine, so runtimes open with `SYSTEM_PRINCIPAL`, as `ask_user` does.
- New `takeover.ts`: `take(user, requestId)` checks a pending takeover the user can see and writes `computer.taken`. `handBack(user, requestId, note)` answers with `{ note }` and writes `computer.handed_back`. The desktop lease is the relay's: give the service an optional `lease` dependency (`take`, `release`), which V6.10 fills from the relay port.
