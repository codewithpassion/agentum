The take-over flow from agentum `questions/service.ts` (`requestTakeover`, `settleTakeover`) and `computer/takeover-hook.ts`, rebuilt on V1's pending requests and waiting run state. That way a take-over lands in Needs you like any other request.

## Scope
- `packages/services/src/takeover.ts`: `request(runPrincipal, { reason })` creates a pending request of kind `takeover` for the run's agent computer and puts the run in the waiting state. Only one can be open per computer. It writes `computer.takeover_requested`.
- `take(user, requestId)` records who holds it (`computer.taken`). `handBack(user, requestId, note)` settles it, resumes the run through V1's resume path with the person's note, and writes `computer.handed_back`. `cancel` settles it without a note.
- The first answer wins, the way V1 settles approvals. Expiry follows V1's expiry rules.
- tRPC: `takeover.take`, `takeover.handBack` and `takeover.cancel` in `apps/web/src/server/trpc/`.

## Check
- `packages/services/src/takeover.test.ts`: request puts the run into waiting, a second request is refused, two hand-backs race and one wins, cancel, expiry, and the resume carries the note.
- `bun run check && bun run test && bun run build` pass.
