Machine runs start Claude Code with `permissionMode: "bypassPermissions"` (`apps/daemon/src/executor.ts` `buildOptions`), so nothing asks anyone. The Agent SDK (0.2.119 in this repo) offers two ways in: a `PreToolUse` hook, which runs even under bypassPermissions and can return `permissionDecision` plus `updatedInput`, and `canUseTool`, which needs a mode other than bypass. `AskUserQuestionInput` carries an optional `answers` map that the permission layer fills in.

## Scope
- First unit, a short spike in a scratch script under `/home/roboto/devel/harbourmaster-wt/tmp/V1.12/` with the real SDK and `claude` binary: confirm that under bypassPermissions (1) a `PreToolUse` hook that awaits for more than 60 s with a raised matcher `timeout` still decides the call, (2) `permissionDecision: "deny"` with a reason reaches the model, (3) `AskUserQuestion` is offered in SDK mode and `updatedInput` with `answers` plus `allow` returns those answers to the model. If (1) or (3) fails, use `canUseTool` with `permissionMode: "default"`, returning `allow` at once for every tool without a rule. Write the finding at the top of `apps/daemon/src/approvals.ts`.
- New `apps/daemon/src/approvals.ts`: the gate the chosen mechanism calls. `toolKey({ runtime: "machine", name, server })` with the claim's MCP server names; rules come in the claim's optional `toolRules` (V1.1 schema, sent by V1.5 and V1.9 to a daemon that names `FEATURE_REQUESTS`). A ruled call opens a request with `POST /api/machines/runs/:id/requests` and long-polls `GET …/requests/:requestId?wait=25` until an outcome; allow lets the call run, anything else denies it with `outcomeText`.
- `AskUserQuestion`: always routed through the platform as a `question` request with the questions from its input; the answer goes back with `askUserQuestionAnswers`. Expired or cancelled denies the call with `outcomeText`.
- `apps/daemon/src/run-api.ts`: the two calls, with the run's existing auth and backoff. The heartbeat and event batcher keep running while a call waits (they do already; keep a test).
- Send `FEATURE_REQUESTS` in `X-Daemon-Features` on claim (`client.ts`).
- An abort (run cancelled, 1012 close) ends the wait at once.

## Check
- `approvals.test.ts` with a fake run API: no rule never calls the API; a ruled `Bash` waits and runs after allow; deny returns the text; `AskUserQuestion` input gets the answers map; abort ends the wait; repeated polls stop when the outcome arrives.
- `executor.test.ts`: the options carry the hook (or `canUseTool`) and the claim's rules reach the gate; an old claim without `toolRules` behaves as today.
- `bun run check && bun run test && bun run build` pass.
- Live on staging (controller, Dom's machine with the new daemon): a machine agent with "Ask me before" on `bash` waits, is denied from Slack, and says so; an `AskUserQuestion` with choices is answered on the web.
