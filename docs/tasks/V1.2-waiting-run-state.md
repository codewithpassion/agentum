A run that asks a person something moves to `waiting` and back to `running` when the answer comes. Every rule in the runs service that reads `running` today has to decide what `waiting` means, before the requests service (V1.5) starts moving runs there.

## Scope
- `packages/services/src/runs.ts`:
  - new `markWaiting(principal, runId)` and `markRunning(principal, runId)` for the system principal: compare-and-set `running -> waiting` and `waiting -> running`, each appending `run.waiting` / `run.resumed`. `markRunning` also moves `lease_until` to now plus the runtime's lease, so a runtime that died while waiting is still reaped.
  - `heartbeatRun` and `ingestRunEvents` accept `running` or `waiting` (the daemon keeps heartbeating and uploading while it waits).
  - `claimRun` and `claimRunForMachine`: the one-running-run-per-agent check counts `waiting` siblings as busy.
  - `completeRun` and `abortedCompletion` accept a `waiting` run; `cancelRun` cancels a `waiting` run like a running one. Leave closing its open requests to V1.5 (it subscribes to the run end).
  - `reapExpiredLeases` reaps `waiting` runs whose lease passed, the same as `running`.
  - `ACTIVE` includes `waiting`.
- `packages/services/src/run-tokens.ts`: run and session tokens are valid while the run is `running` or `waiting` with a lease in the future (`not_running` otherwise).
- `packages/services/src/slack/status.ts`: a `run.waiting` event sets the thread status to "is waiting for an answer…"; `run.resumed` goes back to thinking.
- `packages/services/src/sessions.ts`: `latestRun` and the queue treat `waiting` as active.
- `packages/services/src/managed/service.ts`: only the status checks that refuse a non-`running` run accept `waiting` too. Managed waiting itself is V1.11.

## Check
- `runs.test.ts`: running to waiting to running with both events; a heartbeat and an event batch on a waiting run are accepted; a waiting run blocks the agent's next claim; cancel and complete from waiting; the reaper interrupts a waiting run with an expired lease; `markRunning` on a cancelled run changes nothing.
- `run-tokens.test.ts`: a token works while waiting and fails after the run ends.
- `slack/status.test.ts`: the waiting label and the return to thinking.
- `bun run check && bun run test && bun run build` pass.
