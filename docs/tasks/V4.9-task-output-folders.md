Each task gets `agents/<agent>/tasks/<id>/` in the library. It is the one place a task's files live, for every runtime, and the task view lists it.

## Scope
- `packages/services/src/runs.ts`: at run start, create the task folder (`taskFolderPath` from V4.1, through `library.mkdir` with the run principal) for the task the run belongs to; machine claims and cloud starts carry it.
- New `packages/services/src/library/task-files.ts`: `taskFiles(principal, taskId)` lists the folder recursively, plus the files the task's runs wrote outside it (from `library_versions.run_id`) and the task's open conflicts. tRPC procedure on the tasks router from V2.
- `packages/services/src/managed/service.ts`: the managed prompt names the task folder as a library path reached through the library MCP tools.
- `packages/services/src/sessions.ts`: transcripts stop building `outputFileIds` for new runs; old runs keep theirs so history still shows them.

## Check
- `runs.test.ts`: a new run's task folder exists and the claim names it. `library/task-files.test.ts`: folder files, outside edits with their version, and conflicts are listed for the right task only. `managed/managed.test.ts`: prompt names the folder.
- `bun run check && bun run test && bun run build` pass.

## Refinements (2026-10-26)

Checked against main at aac119a. Where these differ from the scope above, they win.

- A task is one run (V2), so the folder is `taskFolderPath(slug, run.id)`. A follow-up run gets its own folder. `tasks.get` takes `runId`.
- Dry runs get no folder. A dry run writes nothing, so check `run.dryRun` (on `RunRecord` from V3.1).
- Where to make the folder: `library` is built before `runs` in `compose.ts` (lines 394 and 480), so give `createRunsService` an optional `library: Pick<LibraryService, "mkdir">` and create the folder after the run row lands. Put `taskFolder` in the claim's `library` (`machine-claim.ts`, V4.3 made the roots) and on `CloudStart`.
- `taskFiles` reads `library_versions.run_id` for edits outside the folder and `library_conflicts.run_id` for conflicts. Add the procedure to `tasks-router.ts` as `tasks.files`.
- Managed prompt: `workspaceInstructions` is called inside `systemOf` (`managed/service.ts` around line 193). V3.3 puts `agentPrompt` first in the same function.
- Outputs: `runs.ts` writes `outputFileIds` around line 1197, and `sessions.ts` reads them around line 476. New runs write `[]`, and old rows still read.
- Same-file overlaps with V3, all in the services lane: `runs.ts` (V3.1, V3.7), `cloud/runtime.ts` and `cloud/types.ts` (V3.1, V3.3, V3.7), `managed/service.ts` (V3.3), `sessions.ts` (V3.7), `machine-claim.ts` (V3.3), `compose.ts` (V3.2, V3.6, and V4.6 in the worker lane).
