Found by the local end-to-end run on 16 Oct 2026 and approved by Dom. A real agent mentioned in an inbox thread replied through `inbox_post`, and then its final answer was posted to the thread again, so "ahoy" appeared twice. Its first `inbox_post` call also failed because it passed `message` instead of `text`.

## Scope

A woken agent's reply lands in the thread exactly once. Pick one rule and make the wake text (M6.2, `packages/services/src/inbox.ts`) match it. Either the final answer is the reply and the inbox gateway posts it, and the wake text says not to call `inbox_post` on this thread. Or a run that already posted to its own thread through `inbox_post` doesn't have its final answer posted again. Prefer the first if it keeps the gateway simpler. Make the wake text name the `inbox_post` arguments exactly as the tool's schema defines them (`packages/mcp/src/tools/inbox.ts`), taken from the schema rather than typed by hand if that's practical.

## Check

An `inbox.test.ts` case: a woken run that finishes with an answer leaves exactly one post from it in the thread, under whichever rule was picked. If the second rule was picked, a run that called `inbox_post` and then finished leaves one post. A test shows the argument names in the wake text match the `inbox_post` schema. Live, in local dev with the compiled daemon and a real agent: mention it in a thread, and exactly one reply appears. `bun run check && bun run test && bun run build` pass.
