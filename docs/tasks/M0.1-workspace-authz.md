From `docs/architecture/build-plan.html#m0`. Provides contract C2. Reuse: flightdex-v2 `workspaceProcedure` and `authenticate.ts` (borrow), the-brain principal chain. Paths are in `docs/architecture/reuse.html`.

## Scope

`workspaces` and `identity_links` tables. `createPrincipalResolver({ db, runTokenKey, verifyClerkOAuthToken, isOrgMember, allowedOrgIds })` with all four bearer prefixes implemented against the foundation tables (machine credentials, trigger tokens in a stub table that M4 replaces, run tokens by HMAC plus the runs row check) and the `system` kind for the tick. `isOrgMember` runs for `api_key` and `oauth` principals on every request, cached 60 s. An org not in `allowedOrgIds` gets no workspace.

Clerk restricted sign-up and Organizations are turned on in the Clerk dashboard as part of this task. That is a step for Dom; put it in the report.

`authz.can()`. `workspaceProcedure` replacing `protectedProcedure` in `init.ts`, `ctx.principal` in `context.ts` and the add-clerk template copy. `create-dev-user` creates an org and a membership, adds the org to the dev allow-list, and `/dev-login` calls `setActive` with it.

## Check

`bun test packages/services` includes `authz.test.ts` (a member of A cannot read B's row through any service) and `principal.test.ts` (each prefix resolves to its kind; unknown prefix is null; an `api_key` principal whose `isOrgMember` answers false resolves to null; an org not in `allowedOrgIds` resolves to null). A router test builds a context from a fake Clerk session with an org and asserts `me` returns `{ userId, workspaceId }`. Browser: dev login lands on the app, not on the create-organization screen.
