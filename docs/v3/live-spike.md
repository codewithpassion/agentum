# L.0 local realtime spike — 27 October 2026

**Status: partial, not an L.0 sign-off.** The fixture exercises local workerd, but its two clients are Bun WebSockets, not browsers. It does not prove a secure identity filter, production ticket verification, or staging behaviour. Complete those checks before treating L.0 or R1.14 as passed. No product bindings, services or database were changed.

## Reproduce

From `scripts/spikes/live-artifacts`, run `bun install --frozen-lockfile`, then `bunx wrangler dev --local --port 18987 --persist-to .state` in one terminal. After it reports ready, run `bun run check.ts` and `bun run client.ts` in another. Stop Wrangler afterwards. `.state` is disposable. The fixture has unauthenticated test endpoints and predictable tokens; never deploy it. Compatibility date is the web Worker's `2026-08-19`.

## Run log and decisions

- **Hibernation:** `client.ts` on Wrangler 4.153.0 / local workerd: `before={"starts":6,"sockets":2}`, after 15 seconds `after={"starts":7,"sockets":2}`; post-idle edits converged. This counts DO constructor runs stored in SQLite and checks `ctx.getWebSockets()`. It demonstrates local hibernation with two protocol clients, not two browsers or staging. Decision: pursue hibernating y-partyserver; require browser and staging checks in L.10. If they fail, fix timers/lifecycle and repeat, or use a non-hibernating room temporarily with explicit cost and unmet acceptance criterion.
- **Agent awareness:** two clients both observed server-created `Agent` via `applyAwarenessUpdate(..., null)`. Decision: use this path, but rebuild or republish ephemeral agent state after wake and clear it after five seconds; the fixture does not test that lifecycle.
- **Spoofing:** a client sent `user.name = Forged` and the other received it. y-partyserver 2.2.0's `handleMessage` applies and broadcasts raw awareness bytes. Decision: the default handler is unsafe for trusted identity. Intercept awareness before the base handler, decode and validate client IDs, bind them to one connection, replace identity from authenticated attachment, bound size/rate/allowed cursor fields, then broadcast sanitized updates. Reject attempts to mutate another connection's IDs or the reserved agent ID. Reconstitute attachment ownership on wake and clean it on close. Until malicious-packet, cross-ID, reconnect and hibernation tests pass, do not ship presence; fallback is a separate authenticated server-owned presence protocol. This design is not implemented or proven here.
- **DOM-free conversion:** inside the DO, `typeof document` was `undefined`; both `prosemirror-markdown` and `MarkdownManager` -> `@tiptap/y-tiptap` Y.XmlFragment -> ProseMirror -> Markdown returned `# Heading\n\nHello **world**.` Decision: use Tiptap's headless MarkdownManager and shared Tiptap schema; retain ProseMirror Markdown as fallback for its supported subset. One input is not a fidelity or hostile-input test. The complete schema, tables, sanitisation and corpus remain L.2 work.
- **Concurrent insert:** cloned Y.Text replicas; human inserted at offset 6, agent resolved a relative position captured before that edit, inserted and synchronized. Both yielded `hello human agent world`. Decision: use Yjs relative positions with explicit association and guard deleted/missing targets. This is not a browser/ProseMirror binding test; test structural changes, selections and deletion in L.2.
- **5 MiB:** a 5,242,880-character document encoded to 5,242,900 bytes; SQLite accepted 41 ordered 128 KiB snapshot chunks and one subsequent update row; reconstruction yielded 5,242,884 characters. Decision: transactional generation-tagged chunked snapshots plus ordered update rows, with atomic generation switch and recovery tests. Split oversized updates too. Enforce the 8 MB limit before accepting an update using an agreed canonical representation. This fixture does not test limits, crashes, compaction, hostile updates or performance. [Cloudflare limits](https://developers.cloudflare.com/durable-objects/platform/limits/) govern actual limits.
- **Ticket and revocation hooks:** `onBeforeConnect` consumed a fixture token in the room's SQLite primary key, replay returned 403; RPC closed exactly one participant and the other stayed connected. Decision: use room-scoped atomic consume and attachments for targeted revocation, but replace fixture tokens with signed, short-lived claims, enforce artifact binding, expiration, role and audience; verify signature before consumption, protect RPCs, and schedule connection expiry. Test races, invalid/wrong-room/expired credentials, restart, renewal and close within five seconds. Fixture tokens are neither signed nor expiring and do not prove production security.

## L.1 proposed contracts and subsequent phases

- **Phase 1:** define `RoomTicketClaims` with `jti`, `artifactId`, `participantId`, authenticated display name, kind, role, `issuedAt`, `expiresAt` and connection expiry. Room consumes `jti` once and derives identity solely from claims; service authorizes issuance. `AwarenessEntry` separates immutable server identity from bounded cursor/selection/status fields, with reserved agent identities. `CommentAnchor` carries Yjs relative start/end positions and detached state. Room RPCs: `applyAgentOps(ops, origin)`, `read(view)`, `setAgentPresence(entry | null)`, `refresh(participantId)`, `checkpoint()`, `restore(versionId, byParticipant)`, `presence()`. Define encoded-position versioning and limits in protocol. Speaker envelopes derive actor from server session and escape user text. Preserve artifact/version and session relations, with checkpoint consistency and replay semantics explicit.
- **Phase 2:** reserve deck kind and stable slide/element IDs; property-level map operations and selected slide/element awareness extend the room and participant contract. Deck validation and presentation state need separate tests; the text insertion result does not prove deck convergence.
- **Phase 3:** include guest actor, scoped artifact ID, grants with role/expiry/revocation, and member grants in the migration once. Guest identity must be distinct from workspace principal; issuance and refresh recheck the grant, while revocation closes attached sockets. Guest-triggered runs enforce artifact and tool scope independently of presence.
- **Phase 4:** leave room operation origin and stable IDs suitable for suggestions/review, export from checkpoints, and scoped embeds; markdown does not preserve all rich formatting. Mention mail and page element bridge remain separate permissions and delivery contracts.
