# L.0 local realtime spike — 27 October 2026

**Status: local spike complete; staging not run.** The fixture exercises local workerd and two isolated Chromium contexts. It is a prototype, not production authentication or an R1.14 staging sign-off. No product bindings, services or database were changed.

## Reproduce

From `scripts/spikes/live-artifacts`, run `bun install --frozen-lockfile`, then `bunx playwright install chromium`, create `.dev.vars` containing `LOCAL_FIXTURE_CAPABILITY=local-only`, and run `bunx wrangler dev --local --port 18987 --persist-to .state` in one terminal. After it reports ready, run `bun run check.ts` and `bun run browser-test.ts` in another. Stop Wrangler afterwards. `.state` is disposable. The fixture issuer and RPC endpoints are unauthenticated and the HMAC key is public; never deploy it. The Linux `/proc` build guard permits only explicit `wrangler dev --local`; deploy and versions upload fail before bundling. Without the separately supplied local capability every HTTP route returns 403. This protects ordinary commands, not deliberate guard removal or remote capability provisioning. Delete `.state` for a fresh run. Compatibility date is the web Worker's `2026-08-19`.

## Run log and decisions

- **Hibernation and browsers:** local Wrangler 4.153.0 / Chromium 141 Playwright run, two isolated contexts: before `{"sockets":2,"starts":7}`, after 15 seconds `{"sockets":2,"starts":8}`. Edits converged after wake. Staging was not run. Decision: pursue hibernating y-partyserver; repeat in staging for L.10, or use a non-hibernating room temporarily with explicit cost and unmet acceptance criterion.
- **Agent awareness:** server `applyAwarenessUpdate(..., null)` reached both browser contexts. Decision: use this path, but republish ephemeral agent state after wake and clear it after five seconds; lifecycle is not tested here.
- **Spoofing boundary:** server intercepts awareness before the base handler, admits one ticket-bound client ID, overwrites id/name/kind/color with claims and accepts only a bounded numeric cursor. Forged identity arrived as the signed identity; a packet for the other client's ID did not reach peers, including after hibernation. SQLite reserves client IDs across simultaneous upgrades and attachment state survives wake. Agent IDs avoid reserved IDs. Decision: use this boundary as a prototype; if production cannot enforce ownership and cleanup, use a separate authenticated server-owned presence protocol. Production still needs rate limits, reconnect/abandoned reservation cleanup, expiry and extensive malformed-packet tests.
- **Reconnect clock:** a client sent its own clock 999999, then closed cleanly. A fresh ticket with the same ID connected but its low-clock replacement presence remained invisible to the observer. A connection with a distinct ID was visible. Choose connection-unique awareness IDs, allocated and bound to each fresh ticket; L.3 must ensure IDs are not reused while peer metadata can retain them and implement lifecycle cleanup. Deleting server metadata alone cannot clear peer clocks. This is a local prototype decision, not an implemented production lifecycle.
- **DOM-free conversion:** inside the DO, `typeof document` was `undefined`; both `prosemirror-markdown` and `MarkdownManager` -> `@tiptap/y-tiptap` Y.XmlFragment -> ProseMirror -> Markdown returned `# Heading\n\nHello **world**.` Decision: use Tiptap's headless MarkdownManager and shared Tiptap schema; retain ProseMirror Markdown as fallback for its supported subset. One input is not a fidelity or hostile-input test. The complete schema, tables, sanitisation and corpus remain L.2 work.
- **Concurrent insert:** two Chromium replicas shared a room. One captured a relative position, queued its own `human ` update without sending it, then the room resolved the position and inserted `agent ` before the queued update was delivered. Both replicas converged to `agent human hello` (concurrent ordering may vary), retaining both contributions. The synchronous primitive probe also yielded `hello human agent world`. Decision: use Yjs relative positions with explicit association and guard deleted/missing targets. This is not a browser/ProseMirror binding test; test structural changes, selections and deletion in L.2.
- **5 MiB:** a 5,242,880-character document encoded to 5,242,900 bytes; SQLite accepted 41 ordered 128 KiB snapshot chunks and one subsequent update row; reconstruction yielded 5,242,884 characters. Decision: transactional generation-tagged chunked snapshots plus ordered update rows, with atomic generation switch and recovery tests. Split oversized updates too. Enforce the 8 MB limit before accepting an update using an agreed canonical representation. This fixture does not test limits, crashes, compaction, hostile updates or performance. [Cloudflare limits](https://developers.cloudflare.com/durable-objects/platform/limits/) govern actual limits.
- **Ticket and revocation hooks:** fixture HMAC tickets carry artifact, participant, identity, role, client ID, unique ID and expiry; room SQLite consumes the unique ID once. Local browser test: replay, wrong artifact, expired and tampered signature each returned 403; a read-only client's update did not reach its peer; targeted RPC closed one participant while the other remained connected. Decision: room-scoped atomic consume and attachments are viable, but production needs a private signing key, authenticated issuance and RPC, bounded lifetime/audience, connection expiry and renewal, race/restart tests and abandoned reservation recovery. The public fixture key and issuer provide no real authentication. Staging was not run.

## L.1 proposed contracts and subsequent phases

- **Phase 1:** define `RoomTicketClaims` with `jti`, `artifactId`, `participantId`, authenticated display name, kind, role, `issuedAt`, `expiresAt` and connection expiry. Room consumes `jti` once and derives identity solely from claims; service authorizes issuance. `AwarenessEntry` separates immutable server identity from bounded cursor/selection/status fields, with reserved agent identities. `CommentAnchor` carries Yjs relative start/end positions and detached state. Room RPCs: `applyAgentOps(ops, origin)`, `read(view)`, `setAgentPresence(entry | null)`, `refresh(participantId)`, `checkpoint()`, `restore(versionId, byParticipant)`, `presence()`. Define encoded-position versioning and limits in protocol. Speaker envelopes derive actor from server session and escape user text. Preserve artifact/version and session relations, with checkpoint consistency and replay semantics explicit.
- **Phase 2:** reserve deck kind and stable slide/element IDs; property-level map operations and selected slide/element awareness extend the room and participant contract. Deck validation and presentation state need separate tests; the text insertion result does not prove deck convergence.
- **Phase 3:** include guest actor, scoped artifact ID, grants with role/expiry/revocation, and member grants in the migration once. Guest identity must be distinct from workspace principal; issuance and refresh recheck the grant, while revocation closes attached sockets. Guest-triggered runs enforce artifact and tool scope independently of presence.
- **Phase 4:** leave room operation origin and stable IDs suitable for suggestions/review, export from checkpoints, and scoped embeds; markdown does not preserve all rich formatting. Mention mail and page element bridge remain separate permissions and delivery contracts.
