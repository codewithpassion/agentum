## Task-ready scope and check per must-fix

### MF1, V1.19: a large tool input opens a machine approval

Scope
- Make `requests.open` accept the daemon's truncated string preview for an approval. Two options: let `openInputSchema`'s approval `input` take a string as well as `payloadSchema`, with the string shown as is, or wrap the string in the route as `{ preview: "<text>" }` before calling `open`. Either way the stored display must pass `approvalDisplaySchema`, and the scrub and masker still run on it.
- Leave the daemon's 8192-byte preview rule as it is.

Check
- `routes/machine-requests.test.ts`: a POST with a 9 KB input (the daemon's string preview) opens a request, answers 200 with `pending`, and stores a truncated display with an `sk-` token in it redacted.
- `apps/daemon/src/approvals.test.ts`: the body for an input over the limit passes `createRequestBodySchema`, and the Worker's open input schema accepts it (import the schema, no network).
- `bun run check && bun run test && bun run build` pass.

### MF2 and MF3, V1.20: scrub question displays, keep answers raw on the row

Scope
- In `requests.open`, run each question's text, header and choices through the masker and `redactText` before storing and announcing the display.
- In `requests.answer`, store the parsed answer raw in `run_requests.answer`. Put only the `request.answered` event payload through the masker and `redactText`, for both the note and the answer texts.
- Keep the question keys unredacted on the row, so they match what the runtime asked. If the display text differs from the runtime's original (masked or redacted), map answers back by question index. `askUserQuestionAnswers` and the managed `outcomeText` then get the runtime's own question text.
- The web card and Slack read the answer only from events or `settledFromEvent`, never from the raw row, or they redact it again when they render. Check `requestRecord`'s `answer` in `listPending` and the tRPC `answer` result, and redact there too.

Check
- `requests.test.ts`: a question containing `sk-…` and a granted secret's value is stored and announced as `[redacted]` and `[secret:NAME]`. A free-text answer `sk-…` reaches `outcome()` raw, appears redacted in the `request.answered` event, and appears redacted in the tRPC answer result.
- `packages/protocol` or the daemon test: an answer to a question whose display was masked still fills `askUserQuestionAnswers` for the original question text.
- `bun run check && bun run test && bun run build` pass.
