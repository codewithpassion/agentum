# M9 gate review 1, commit 90def14

## Verdict

Clean. Nothing is must-fix. The diff m9-start..90def14 delivers both pages in the build plan's M9 section. Sessions has a list across agents and origins, a transcript with collapsed tool cards and file chips, and agent and origin filters. Log filters by agent, type and date, pages its results, and links each row to its session. Run ids show as text because the app has no run page. The M9.2 task log already accepted that.

Both pages go through tRPC `workspaceProcedure` to the `sessions` and `events` services. `events.list` calls `authorize()` first. It reuses `visibleSessions`, so another user's UI chats and Slack DMs stay out of both pages. I checked the event writers (runs, Slack, Slack gateway, inbox, connector proxy). Each event that belongs to a session carries its `sessionId`, so private content cannot show through the "no session, whole workspace" branch. The pages use existing shadcn components only (NativeSelect, Input, Label, Table, Badge, Button). No component under `components/ui/` changed.

M6.3 and M7.3 touch `inbox/wake-input.ts`, `protocol/attachments.ts` and `daemon/executor.ts`, none of which feed the M9 pages. M5.5 adds no code in this range. The chat-logic change that pairs tool calls with their results came in with M9.1, and the agent chat tab now gets it too.

Gate commands in the review checkout: `bun run check` passed, `bun run test` passed, and `bun run build` passed. The bundle grep found no `drizzle` in `apps/web/dist/client`. `git status` stayed clean. Running `vite dev` did not regenerate `routeTree.gen.ts`.
