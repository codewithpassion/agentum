# M4 gate review, round 1

Commit 6ed11d4 on main. M4 merges reviewed: 80562ca (M4.1 HTTP triggers), 2a55bac (M4.2 routines, with its main merges 348e3c6 and 1790a04), bc910cf (M4.3 queued-sweep window, with e41decb). Read against `docs/architecture/build-plan.html#m4`, the three task files, CLAUDE.md and "Rules that are easy to break" in docs/HANDOVER.md.

## Verdict

Not clean. One must-fix and seven nits.

M4.1 and M4.2 meet their scope and checks. The tick's `fireDue` and `settleRuns` have no starvation path left. Both order by the oldest waiting item (`next_run_at`, first unjudged run id), every routine they handle moves past the rest, and the work per routine is bounded. With more due routines than `TICK_BATCH`, every routine still fires every few ticks.

The open path is the one M4.3 was filed for. The fix there made the sweep rotate through its backlog, but nothing bounds the backlog. A healthy run left queued by a crash waits about N/100 sweep passes, and N grows by one run per slot for every routine whose machine stays offline. Both the M4.2 and M4.3 reviews deferred queued-run expiry as beyond scope. At the milestone gate it becomes the remaining starvation case, so I've made it must-fix. Dom may choose to defer it again instead.

`bun install --frozen-lockfile`, `bun run check`, `bun run test` and `bun run build` pass at 6ed11d4, and `apps/web/dist/client` has no `drizzle`. The log is in `checks.log` next to this file.

## Must-fix 1: bound never-claimed queued runs

Scope: end runs that nobody claims, so they stop holding the sweep and stop blocking routine settlement. In the sweep, move a run that has stayed `queued` or `offered` past a fixed age, measured from `created_at`, to an ended status with a clear error such as "Never claimed". Pick an age well above normal machine reconnects, for example one hour, and make it a named constant. Use a conditional write guarded on the starting statuses, as the reaper does, so a claim that wins is kept. Write the matching run event. Settlement already treats `failed` and `interrupted` as errors, so a routine on a dead machine reaches five errors and switches itself off, and the backlog is bounded by age times firing rate. Keep the per-pass limit and the `swept_at` order. Don't change how the sweep offers runs younger than the cut-off. A second option is for `fireDue` to skip, and count as an error, a slot whose routine still has an unclaimed queued run. That bounds routine growth but not runs from other sources, so prefer expiry. Dom may have a view on the age and the status (`failed` or `interrupted`).

Check: a `runs` service test keeps one never-claimed run per simulated minute for longer than the cut-off, sweeping every minute. It shows the number of never-claimed runs in a starting status stays below a fixed bound, and that a crash-left run created after that is offered within a bounded number of passes that does not grow with elapsed time. Run it, for example, at 200 and at 3,000 simulated minutes and get the same pass count. A `routines` test shows a routine whose machine never claims switches itself off after five expired runs. Both tests fail on 6ed11d4. The existing sweep and routines tests still pass. `bun run check && bun run test && bun run build` pass.
