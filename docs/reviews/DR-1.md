# DR gate review, round 1

Milestone DR (v4 dream) at `ee4f9487` on `main`, reviewed as `git diff dr-start..ee4f9487`. I judged only the DR work: the contract, the merge, reconcile and prune steps, the inputs, the dream run (schedule, model, write, diary, undo, cost), skill proposals, the diary on the Knows tab and held-batch approval. DR.9 to DR.14 are known follow-ups and are not repeated here.

Verdict: clean. I found no must-fix and 12 nits.

## What I checked

I traced every path that takes a dream's material to a person. Code decides which person a note belongs to, from the evidence the note cites (`extract.ts`, `scopeOf`). The model never decides it. Extraction makes one model call per person, so no call sees two people's words. Merge, reconcile and prune each work on one kind and one `userScope` at a time (`scopeGroups` in `steps/groups.ts`, used by `reconcile.ts` and `prune.ts`), so a question or a drop reason never mixes scopes. Promote never sees private evidence or evidence tied to a person. The diary prints no private note text and no drop reason for a private note.

On the read side, `dream.changes`, `memory.changes` and `memory.list` give a person only their own private rows and file. The library's `canReadAt` guards `readVersion` and `versions`, so another person's private file cannot be read by version id either. The desk, the rail and `dream.answer` show a private question to its person alone. The held-batch card goes only to the owner or an admin, and its band is the redacted diary. `index.md` lists shared notes only. I found no path that puts one person's private note text in front of another person.

I checked whether a private session can lose its person and come out as shared evidence. That would happen if a private session's actor were not a user, because `tagsFor` then sets no `userId` and outside text would read as shared. It cannot happen today. Only four things make a private session: a Slack DM, whose actor is the mapped Clerk user (`slack.ts`); a private `ui` conversation started by a user; a child run that inherits its private parent's user actor (`runs.ts`, `privateParentActor`); and a builder dry run, which the collector skips. Artifact sessions are never private (`sessionPrivacy`), and mail and A2A starts never set the flag.

`run()` refuses a paused agent, so Dream now and the tick both refuse, and no run is recorded. `fireDue` skips paused agents and leaves their slot due. `trigger.test.ts` covers both. Every memory write goes through `commitFiles`, which writes one library commit together with the `memory_changes` rows and the run row. That holds for a dream applied at once, an approved held batch and an undo, and each of the three also writes or appends the diary. A failed model call fails the run and writes nothing, and the run keeps its usage. Dream cost goes into the spend rollup. Each active agent has one live `dream` trigger, kept in step by `memory.rules.set` and the minute tick, and a slot is claimed with a compare-and-swap. The triggers service refuses to create, reassign, enable or revoke a dream trigger.

I ran `bun run check` (clean, boundary-lint clean), `bun run test` (14 of 14 tasks, 0 fail) and `bun run build`. The build replayed from the turbo cache, and the grep of `apps/web/dist/client` for `drizzle` found nothing.

## Findings

| # | Severity | Finding | Area | Resolution |
|---|---|---|---|---|
| 1 | nit | Undo reads the version ids (`ensureUntouched`) before it loads the files and their etags (`loadEveryMemoryFile`). A person's write that lands between the two gets loaded, its etag is used, and the restored base bytes overwrite it. Their note disappears while its `memory_changes` row still says `applied`. `decide` reads in the safe order and has a comment saying why. Undo does not. The window is narrow, and the library keeps the version. | undo (`dream/undo.ts`) | Load the files first and check the versions after, as `decide` does. Add a test that writes between the two reads. |
| 2 | nit | `dream_runs.error` can hold a `MemoryCodecError` message such as `private/<userId>.md:3: ...`. The dream card and Earlier dreams show `run.error` to every workspace member, which reveals the user id of a person who has private notes with the agent. No note text shows. | dream run, Knows tab | Store a generic message when the bad path is a private file, or show the error only to the owner or an admin. |
| 3 | nit | `dream.runNow` (through `ownerSession` and `runner.run`) does not check `agents.status`. A direct call can start a dream for an archived or draft agent. Only the UI disables the button, while `fireDue` filters on `active`. | dream run (`dream.ts`, `dream/run.ts`) | Refuse an agent that is not active in `run()`, next to the paused check. Add a test. |
| 4 | nit | `collectChange` skips dream rows that a person rejected (`writtenBy: dream`, status `rejected`), so they never reach the next dream as rejected memory proposals. DR.3 and the design list rejected memory proposals as input "so it stops proposing the same thing". The window moves on, so the cost is small: the note comes back only if new evidence repeats it. | inputs (`dream/collect.ts`) | Collect rejected dream rows as `memory_proposal` items and keep their scope. |
| 5 | nit | A held batch can hold another person's private notes. The owner approves or rejects it without seeing them: `dream.changes` hides those rows, but the diary count ("Wants to add 3 notes") includes them. The person the notes belong to never reviews them. Nothing leaks, but the owner approves what they cannot see. | held batch, Knows tab | Product question for Dom. Either the held card says how many private notes it includes, or the person decides their own rows. |
| 6 | nit | Carried from the DR.4 review and still open. A finished dream never calls `spend.enforceCap`, and a dream does not check the cap before it starts. A dream that crosses the weekly cap pauses the agent only after its next ordinary run, although the design says the dream "counts against the agent's spend cap". | cost | Call `spend.enforceCap(agentId)` after a dream that used tokens. |
| 7 | nit | Carried from DR.4. A pause that lands between `fireDue` and `run()` loses that night's dream, because `fireOne` has already moved the slot. A pause that lands while a dream is thinking lets that dream finish and write. Neither case starts a dream for an agent that is already paused. The repo's rule in `spend.ts` is that a pause only stops what starts next, so this meets the paused-agent rule. | schedule | Leave the slot alone when `run()` refuses because of a pause. |
| 8 | nit | Carried from DR.4. `claim` checks for a running dream and then inserts, with no unique index, so Dream now and the tick can start two dreams at once. The file etag stops the second write, but both cost money, and two held batches or two copies of a question are possible. | dream run | A partial unique index on `dream_runs(agent_id) where status = 'running'`, in a later contract task. |
| 9 | nit | Carried from DR.4. Merge and prune text from the judge is not checked against the never list or the secret patterns. Only extracted candidates are. A merged note can bring in a never-list word that no input note held. | merge, prune | Run `findSecret` and `neverEntryIn` on merge and prune text in `run.ts` before `rowsFromPlan`, and drop the change when either matches. |
| 10 | nit | Carried from DR.4. Answering a question is not atomic. Undo and reject leave the run's open questions open, so a question can outlive the notes it asks about. | questions | Close a run's open questions on undo, and on reject when they name held notes. |
| 11 | nit | The DR.7 walkthrough seeds only shared conversations. The private-note path, the outside-evidence hold and a private question have unit tests but no end-to-end or browser proof. | walkthrough | Add a private Slack DM set to `seed-dream.ts` and one walkthrough step that checks three things: the note lands in the person's file, the diary says "Added a private note.", and a second member sees neither the note nor its question. |
| 12 | nit | Carried from DR.4. `dream/trigger.ts` does not revoke an archived agent's trigger. An agent whose workspace timezone is invalid is retried every minute and can crowd the batch of 100. | schedule | Revoke the trigger on archive, and skip a timezone that `nextDreamSlot` cannot use. |
