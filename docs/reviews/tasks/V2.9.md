# V2.9 review

## Verdict

Round 1, commit 3cf3b02: clean, no must-fix. The reviewer ran `bun run check`, `bun run test` and `bun run build` and found no `drizzle` in `apps/web/dist/client`. Visibility, the lifted title helpers, the session-wide events, the open request, null cost and "started by" all match the Refinements.

## Nits left

- `get` reads at most 1500 of the session's stream events, oldest first, and sets `eventsTruncated`. A session past the cap loses its newest events, which V2.11 would miss for the current run. No test covers paging past 500.
- An inbox run loads the title sources twice in `get` (once for the title, once in `startedByOf`).
- `agent.machine` comes from `sessions.runtimeMachineId`, so a queued run whose session has not run on a machine yet shows `machine: null` even when the agent is bound to one.
- A handoff's parent-run lookup does not apply session visibility, so it names the parent's agent even when the parent sits in another member's private session.
- The `run.queued` payload is parsed with a bare `JSON.parse`. A malformed payload would throw instead of falling back to the session's origin.

## Beyond the scope

- Return the newest events when a session passes the cap, or let V2.11 ask for one run's events.
- A shared `personName` lookup: `desk.ts`, `events.ts` and `tasks/service.ts` each wrap `PeopleLookup` with a try and a log.
