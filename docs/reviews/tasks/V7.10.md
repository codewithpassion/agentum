# V7.10 review

Implemented by Codex, reviewed by Opus.

## Verdicts

- Round 1 (6665b78): must-fix. An agent's GitHub re-import over its own skill moved the pin before approval.
- Round 2 (c84f6b9): must-fix. The first fix left an agent's re-import from a different ref, path or repo with a mismatched source after approval.
- Round 3 (b7038e7): clean. An agent's re-import that changes the source location is now refused.

## Nits left

- A fetcher failure of any kind is rethrown as an `invalid` error, so a GitHub 404 reaches tRPC as a bad request.
- `hasGithubUpdate` remembers only the last notified commit, so B, C, B notifies B twice.
- Two overlapping `checkUpdates` runs can both write `skill.update_available` for one commit, because the `latest_commit_sha` update has no compare-and-set.
- `skill.update_available` for an agent-owned skill carries no `agentId`.
- Approving an older proposed GitHub version can move the pin backwards.
- `createGithubSkillFetcher` has no tests (token header, truncated trees, symlinks, byte cap, URL encoding of slashed refs).
- File bodies are read in full before the byte cap is checked, and the tree JSON has no size bound.
- A repo renamed or transferred (301) fails with a generic message, because redirects are refused.
- The agent source-location check runs after the upstream fetch, so a refused import still costs two requests.
- An agent's first import writes `commit_sha` before approval. A rejected proposal leaves a pin to an unapproved commit.
- The location-change test covers `ref` only.

## Ideas beyond scope

- Carry the source location on the proposed version so an agent can switch repos through review.
- Map GitHub 404 and rate limit responses to distinct service error codes.
