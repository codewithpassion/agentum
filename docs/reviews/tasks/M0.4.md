# M0.4 Runs service, fake runtime, seed, task review

## Verdicts

Round 1, commit 184559e: must-fix. `completeRun` wrote the run row and the session's `runtimeRef` as two separate writes, against the `atomic` rule.
Round 2, commit 8eba195: must-fix. The fix re-read the run and compared only the status, so two concurrent identical completions could both pass and both deliver the reply.
Round 3, commit 8155614: must-fix. The run now also has to carry the `finishedAt` this call wrote, but the new test ran the two calls in sequence and passed without the check.
Round 4, commit 17b470e: clean. The test starts both calls before either writes, on a clock that moves on every read. It failed 5 of 5 times with the check removed and passed 50 of 50 with it. Fix rounds: 3.

## Nits left

- Two completions within the same millisecond still tie in `completeRun`, because the `runs` table has no per-call column to use as a nonce. Exact fix: have `Atomic` in `@repo/db` return each statement's changed-row count (D1 `meta.changes`, bun:sqlite `.run().changes`). Narrower fix: when there is no `runtimeRef` the run write is one statement and can use `.returning({ id })` like `claimRun` and `cancelRun`.
- The race test is named "identical completions" but sends different text, and does not check which text won.
- A duplicate `requestId` returns the existing run without checking that the agent or actor matches, so a colleague in the same workspace who reuses an id gets the other run's ids.
- `startRun` returns `status: "queued"` even when the fake runtime finished the run inside `dispatch`.
- Status changes and their events are separate writes, so a crash between them leaves a run without `message.user`, `run.started`, `run.cancelled` or `run.interrupted`. Same for the agent insert and `agent.created`.
- `ingestRunEvents` dedupes by reading the highest seq, with no unique index on `(run_id, seq)`. Two concurrent identical batches are both stored.
- `cancelRun` never lets a run get `process_ended_at`: a daemon that posts `aborted` after a cancel gets a 409, and the UI waits the full ten minutes before offering Retry. Accepting `aborted` for `cancelled` runs would fix it.
- A run cancelled while the sweep downloads its files keeps the new file rows, unattached.
- Until M0.7 binds R2, `unboundBlobs` rejects any event payload over 64 KB. A user message of 64 to 100 KB leaves the run queued with no `message.user` event.
- `agents.ts` uses `new Date()` and `ulid()` directly, not an injected clock. `update` accepts edits to an archived agent. `agents.status` is plain text in the schema, so `AGENT_STATUSES` is enforced only at parse time.
- The `seed-fake-agent.ts` helpers are exported but only `main` is used.

## Decisions to know about

- `@repo/services/runs/types` is a second subpath. The re-exports from `runs.ts` tripped Biome's `noBarrelFile`, which wins over the one-subpath-per-module rule.
- `getRun`, `waitForRun`, `cancelRun` take the principal first, because every workspace read calls `authorize()`. The sketch's `waitForRun(runId, waitMs)` had none.
- `ingestRunEvents` and `completeRun` accept the `system` principal and the machine that claimed the run, not a run principal. The build plan sends run data on the machine credential.
- `claimRun` is system-only for now. M1 adds the machine claim.
- `sweepQueuedRuns` ages `queued` and `offered` runs by `created_at`, since the table has no `offered_at`.
- A trigger principal may start only its own agent. A `ui` session belongs to the actor who opened it.
- The gateway's optional `downloadPendingFiles` is how the sweep downloads leftover `pending_files`. The Slack gateway (M5) implements it.
- A gateway error from `deliver` reaches the `completeRun` caller after the run is already `done`.
- `FakeRuntime` finishes the run inside `dispatch`. It is registered in the app only in dev builds (`import.meta.env.DEV`).
- `EVENT_TYPES` gains `run.cancelled`; `AGENT_STATUSES` is new in `@repo/db/shared`. `apps/web` gains a `zod` dependency, and the root `package.json` gains `@repo/db`, `@repo/services` and `drizzle-orm` so `scripts/dev` resolves them.

## Ideas beyond the scope

- Deliver a failed run's error to the reply target as well as the done case.
- Let a run pass its own output files to a child run (today only the user's uploads can be attached).
- `startRun` could also write its session, run and two events in one `atomic` write if the events service exposed its row as a statement.
