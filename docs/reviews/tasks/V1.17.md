## The rule

A run still `queued` or `offered` after an hour is failed "Never claimed" only when its agent has been free for that hour. The sweep spares a run while any run of the same agent is `running` or `waiting`, or finished within the last hour after being claimed (`started_at` set). So the hour counts from `created_at` or from the moment the agent was last free, whichever is later. A run that failed "Never claimed" never extends another run's window, because it was never claimed. The cut-off still fires when no runtime ever picks the run up: with no live run and no recent finish, the old rule applies unchanged. A machine that goes offline mid-run is covered by the lease reaper, which ends that run, and the queued run then fails one hour later.

The change is one `notExists` clause in `expireUnclaimedRuns` in `packages/services/src/runs.ts`.

## Decisions

- `managed.test.ts` "the sweep ending a run that is not the session's current run" relied on the old behaviour (a run queued behind a running one failing after an hour). It now ends the first run before queuing the second, so the second fails with the agent free. It still checks the session stays open.
- The README paragraph on the tick now states the rule.

## Nits left

- A routine that fires faster than its agent finishes runs now grows the queue without bound. The hour cut-off used to cap it, and five "Never claimed" errors switched the routine off. `routines.ts` has no overlap guard.
- A queued run of a busy agent can lose every claim to newer runs and is then never cut off. `claimRun` keeps session order but not oldest-first order across the agent. Only the cloud runtime offers the oldest run first.
- No index covers `runs (agent_id, status)` or `(agent_id, finished_at)`, so the new subquery scans per candidate each minute. `claimRun` uses the same pattern.
- The new tests spare runs only behind `waiting` siblings. No test covers a `running` sibling or an `interrupted` or `cancelled` one within the hour.

## Ideas beyond the scope

- An overlap guard or a queue-depth limit per routine, to bound the queue the new rule can grow.
- An `(agent_id, status)` index on `runs` if the sweep shows up in D1 timings.
