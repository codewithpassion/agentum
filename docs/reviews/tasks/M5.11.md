# M5.11 review: real Slack mentions

## Verdicts

- Round 1 (bc54303): not clean. Two must-fix: `@name@host` (a full email) came out garbled, and a non-ASCII name such as `@zoë` was cut short and reported wrongly.
- Round 2 (e3c442c): not clean. One must-fix: the name pattern lacked combining marks (`\p{M}`), so Hindi names and decomposed accents were cut short.
- Round 3 (9f3cbe7): clean.

## What changed beyond the scope text

`SlackClient.postMessage` escaped every `<`, `>` and `&` on purpose, so an agent could never write a mention. A real `<@U…>` would have been neutralised. It now lets a well-formed user mention (`<@` then U or W plus 8 or more capitals and digits) and channel link (`<#` then C or G plus 8 or more) through. `<!here>`, `<!channel>`, `<@U…|label>`, masked links and short ids stay escaped, and `postEphemeral` is unchanged. Side effect: an agent that writes a raw `<@U…>` can tag any workspace member, not only linked people, which the scope asks for ("passes through unchanged").

Harbourmaster stores no display name for a person, only the email. Matching uses the email, the part before its `@`, the Slack display name, real name and username.

## Nits left

- `mentions.ts`: names are not Unicode-normalised before comparison, so a decomposed spelling does not match a composed Slack name.
- `mentions.ts`: U+200C and U+200D (Persian and Indic names) are not in the name pattern.
- `mentions.ts`: `@ann@bob` is read as one name and matches nobody. A plus-address (`@dominik+x@host`) converts only up to the `+`.
- `mentions.ts`: a doc-comment line is longer than the others.
- `client.ts`: every `postMessage` caller gets the pass-through, including `replyInThread`, which posts fixed text. An opt-in flag would be narrower.
- `LinkedPerson` (people.ts) and `MentionPerson` (mentions.ts) repeat one shape.
- `slack-send.ts`: a DM send whose text has `@` loads the linked people twice (target resolution and mention conversion), so 2N `users.info` calls.
- `textLength` in the send event now counts the converted text.

## Ideas beyond the scope

- A cache for `users.info` lookups, shared by `slack_send` and the thread reply.
- Optional `@here` and `@channel` support per agent, if Dom wants it later.
- Match on first names (`@dominik` for "Dominik Fretz") if a stored Harbourmaster display name is added.
