## Deviations from the task file

- The managed prompt names the task folder in the per-run message (`messageOf`), not in `systemOf`. The system text is part of the agent fingerprint, so a run id there would register a new agent and drop the session for every run. The system text stays the same for every run, and a test shows one registered agent across two runs.
- `completeRun` still stores the `fileIds` a runtime reports, so "new runs write `[]`" holds only for runtimes that stop sending files. Slack file delivery (`uploadOutputs`) and the files service read `runs.outputFileIds` through the run principal, and `slack-events.test.ts` "an output file of a finished run is uploaded to the thread" fails when `completeRun` writes `[]`. A new run starts at `[]`, and `sessions.ts` already skips empty lists, so it needed no change.
- `taskFolder` goes only to a `library-live` daemon, because the claim schema is strict. The daemon falls back to `taskFolderPath` itself.
- `tasks.files` is a method on the tasks service (`ctx.services.tasks.files`), not a separate service, so `compose.ts` did not change.
- `run-library.test.ts` now expects an `agents` folder in a run's root listing, the run's own task folder.
