## Resolved reading

The task's Refinements say "`agents/<slug>/` and the task folders each kept as one node". It is built as one node per agent folder with its task folders folded in, because task folders are per run and would grow without bound.

## Nits left

- `graphOutputs` reads all of `library_versions`, `qa_questions`, `qa_answers` and `slack_threads` for the workspace on every load, with no time bound.
- Slack-origin `run.queued` events join every `slack_apps` row of the agent, so an agent with one app per Slack team shows the same count on each app wire.
- `mail.received` joins every unrevoked mail trigger of the agent, so two mail triggers would double the count.
- A run whose parent is the same agent (self inbox wake) draws an `agent:a -> agent:a` hand-off wire.
- Counts, folder names and the `waiting` flag include runs from other users' private UI sessions, where the desk, event log and `listPending` filter through `visibleSessions`. An agent can show `waiting` with no `pendingRequest`.
- A node with a stored position still takes a column slot, leaving a gap in the auto layout.
- The workspace isolation test seeds only a foreign event and agent, not foreign triggers, Slack apps, outputs or positions.
- `like 'agents/%'` is case-insensitive in SQLite.

## Beyond scope

Bound `graphOutputs` to a recent window or keep a small destinations table once history is large. Filter the graph through `visibleSessions` if private sessions should stay off the map.
