# M3.2 review

## Verdicts

Round 0, commit 00fba25: not clean. Two must-fix: the OAuth discovery, registration and token fetches followed redirects, and "Set client" was hidden for a server that advertises registration but refuses it.

Fix round 1, commit 174b47c: clean, with three test nits.

## Decisions

- Migration 0007 adds `oauth_states` (state primary key, connector, owner kind and id, `initiator_user_id`, verifier, redirect URI, `return_to`, expiry). The minute tick job `access.purge-oauth-states` deletes rows past expiry. A state lives 10 minutes.
- Adding a connector now runs discovery (RFC 9728, then RFC 8414) when the probe gets a 401. A server with metadata becomes `oauth` and its endpoints, scope and RFC 8707 resource go into `connectors.oauth`. A server without becomes `header`. This replaces M3.1's `resource_metadata` substring match.
- `connectors.oauth` also holds the OAuth client: registered on the fly (RFC 7591, re-registered when the app origin changes) or typed in with `connectors.setOAuthClient`. The client secret is AES-GCM ciphertext bound to the connector row. The connector summary only says `{ canRegister, clientConfigured }`.
- `GET /connect/:connectorId?as=user|agent:<id>&return_to=<path>` needs a Clerk session (signed out goes to `/login`, no workspace is 403). `return_to` must be a same-origin path (no scheme, `//`, backslash, whitespace or control character) or the request is a 400 and nothing is stored.
- `GET /api/connectors/oauth/callback` deletes the state row first (`DELETE ... RETURNING`), so a state works once and a refused callback burns it. A caller other than the initiator, or in another workspace, gets a 403. After that, a provider error, an expired state, a refused code or a version conflict redirects to `return_to` with `connect_error=...`, and success with `connected=1`.
- The OAuth credential secret is the encrypted JSON `{"accessToken": string, "refreshToken": string | null}`. `expires_at` and `scopes` are plain columns. M3.3 refreshes with the client and token endpoint in `connectors.oauth`. Re-authorising writes through the same version fence as a header paste, so `version` goes up by one, `status` returns to `ok` and `refreshing_until` clears.
- `connectors/credential-write.ts` is the one fenced credential write, now used by both the header paste and the OAuth callback. `oauth.ts` takes a `nowMs` option so `expires_at` follows the injected clock, and every fetch in it uses `redirect: "manual"`.
- The SSRF guard still has no loopback exception. The browser check reached the stub through a cloudflared quick tunnel. `stub-mcp.ts --oauth` builds its metadata URLs from `X-Forwarded-Host` and `X-Forwarded-Proto`, which is also how the tests give the stub a public-looking host.

## Checks

`bun run check && bun run test && bun run build` pass, and the grep for drizzle in `apps/web/dist/client` finds nothing. `oauth.test.ts` (copied, with the un-awaited `rejects` assertions awaited) passes. `oauth-callback.test.ts` covers a callback by a different signed-in user (403, state row deleted), an off-site `return_to` at `/connect` (400), and `?as=agent` from a non-member (refused), plus the happy paths and denial. Live, against `vite dev` on port 3217 with the stub behind a quick tunnel: dev login, add the tunnel URL on `/connectors` (became OAuth with Connect), Connect and Approve on the stub's consent page (back on `/connectors`, badge "connected"), create an agent, assign the connector, "Connect as this agent" and Approve (back on the agent's Connectors tab, `You: ok, Agent: ok`). The local D1 then held two `credentials` rows, one `user` and one `agent`, both `version = 1`, and no `oauth_states` rows.

## Nits left

- A state does not record which client it was started with. Two first-time starts at once, or "Set client" mid-flow, can leave the earlier flow's token exchange failing. `saveConfig` rewrites the whole `oauth` JSON without a fence.
- Zod parse failures in the services (an over-long `error_description`) are not `ServiceError`s. The callback route maps `ZodError` to 400, `/connect` too.
- A cross-site GET to `/connect/:id` triggers discovery and client registration before any state exists. Low impact.
- A signed-out visitor goes to `/login` with no way back to the connect URL.
- The agent page's search schema drops `connected` and `connect_error`, so an agent-flow denial shows nothing. `connect_error` on the Connectors page is plain text from the query string.
- The `?as=agent` route test for an outsider is stopped by the connector lookup. The workspace check on the agent is covered by the service test.
- `resource` from the protected-resource metadata and `issuer` from the AS metadata are not checked against the URLs they were fetched from. `response.json()` on server-controlled responses has no size cap.
- The replacement branch of `writeCredential` runs the fenced update and the `alongside` write as two statements (carried over from M3.1).
- No test covers a version conflict at the callback ending in a redirect, or a malformed callback request, and the redirect test only checks the `redirect` option.
- The stub mints the code when the consent page renders, so Deny still leaves a valid code. It ignores `resource` and never expires codes.

## Ideas beyond the scope

- Store `client_id` on the state row and use it at the token call.
- A "Test connection" action and revoke or delete for connectors and credentials.
- Return the person to the connect URL after sign-in.
