# V3.17 review

## Verdicts

Round 1 (d0c3588): clean, no must-fix. The reviewer ran check, test, build and the drizzle bundle grep, all passing.

## Nits left

- `lifecycle.ts` step label uses the raw path while `setGrant` stores the normalised one, so an error can name `/notes/` for a stored `notes`.
- `draft.library` accepts any non-empty string, so a path `normalizePath` rejects, or the whole library, fails only after `activate` as a partial failure. A check in `create` before activation would avoid a half-built active agent.
- The failing-grant test uses one folder, so it does not show later grants landing under "Not done". `runSteps` is shared and covers it.

## Beyond the scope

- The cloud VM sync (`librarySyncRoots` in `apps/web/src/server/linux-vm/vm-library-sync.ts`, called from `pi-run.ts`) still reads only `runtimeConfig.libraryPaths`. Until V4.7 moves it to grants, a cloud agent made in the builder gets its folders as grants but they are not synced into its VM. Merge V3.17 after V4.7, or accept the gap in between.
- `apps/web/src/components/agent/profile/library-row.tsx` still writes `runtimeConfig.libraryPaths` from the profile. V4.19 covers it.
