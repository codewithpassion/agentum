- `chat-logic.ts` returns the "too large" marker for an oversized paired result, but an offloaded event stores an empty payload with no `toolUseId`, so it never pairs. The matching test covers a state that cannot happen.
- `transcript-view.tsx`: a failed tool result (`ok: false`) no longer shows as failed, because the card shows only input and output text.
- `session-transcript.tsx` copies `messageOf` and the load-and-poll effects from `tabs/chat.tsx` instead of sharing a hook.
- `sessions-logic.ts`: `ORIGIN_VALUES` is a hand copy of `SESSION_ORIGINS`, with no test that keeps them equal.
- `routes/_app/sessions.tsx` imports `agentNameMap` from the inbox feature.
- `packages/services/src/sessions.ts`: the list sorts by `createdAt` while each row shows last activity. This keeps the chat history order as it was.
- `session-filters.tsx`: Slack is one origin in the filter, so Slack thread and Slack DM cannot be filtered apart.
- `e2e/sessions.ts`: the tool card and chip are found by their text, not by `data-testid`. The tool input is not asserted. Only the agent filter runs in the browser.
- `sessions-router.test.ts`: the `startOutsideBrowser` helper hardcodes "user_1" in an error message, and one comment says the browser schema refuses "trigger" when it refuses every origin except `ui`.
