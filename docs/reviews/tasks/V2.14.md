## Findings

1. Machine tasks showed no thoughts even on a V2.5 daemon. Sonnet, Haiku and Opus 5.5 return a `thinking` block with `thinking: ""` and only a signature unless the query asks for a summary, and `normalize.ts` drops empty thinking. Confirmed with the Agent SDK directly (default gives an empty block, `thinking: { type: "adaptive", display: "summarized" }` gives text, on all three models). Fixed in `apps/daemon/src/executor.ts` (one option, plus an assertion in `executor.test.ts`). A daemon needs a restart to get it.
2. A second `agent-login` for the same user ended the first browser session: calls from the first session answered 401 straight after the second sign-in. Use one browser session per user at a time, or sign in again after starting another.
3. A task that waits for approval shows in both Running (band "Waiting for approval: ...") and Needs you (the approval card). That looks intended. Noting it so nobody counts it twice.

## Nits left

- `executor.test.ts:710`: the test title ("carry the permission mode, strict MCP, ...") does not mention the new `thinking` assertion.
- `executor.ts` forces adaptive thinking on every model. It worked on Sonnet, Haiku and Opus 5.5. A model without thinking support, or a much older `claude` binary that does not know `--thinking-display`, was not tried. The daemon has no minimum CLI version check.
- Machines enrolled before this commit show no thoughts until their daemon is upgraded, so the task file's "only with a daemon that includes V2.5" also needs this commit.
