# LX.4 — sandboxed deck embeds

Implementation commit: `b4c55f9f` (`feat(decks): render authorized artifact pages as sandboxed embeds`).

Implemented 2026-10-27 for live-artifacts PRD R4.5 and the deck embed design. This is a bounded member feature with production wiring, rather than an iframe-only prototype. `docs/tasks/LX.4-deck-embeds.md` is intentionally unchanged.

## Production wiring

- `packages/protocol/src/deck.ts` defines the immutable source identity: `artifact:ARTIFACT_UUID:VERSION_ID:SHA256:PATH.html`. Version IDs include the existing ULIDs. The constrained path grammar excludes queries, fragments, escapes, traversal, arbitrary URLs, SVG, and inline HTML.
- `packages/live-deck/src/index.ts` admits `type="embed"` with a required `prop-src` identity. Scene, constrained HTML, local operations, network updates, and checkpoint restore all validate it. The existing host ownership callback must admit the exact identity. Images still require their original `/files/…` grammar. Limits are 16 embeds per slide and 128 per deck, alongside the existing element, nesting, scene, and update limits.
- `packages/services/src/live-artifacts/service.ts` derives authorized source identities from joined artifact/version/file rows with matching workspace IDs, a published version, a nondeleted `page` artifact, and `workspace` audience. Private pages, proposed versions, other workspaces, documents, dashboards, and apps are not eligible. The bounded catalog reads at most 2,000 file rows. This uses existing artifact ownership tables; no schema or migration was added.
- The existing `ownBlobUrls` policy/session field now also carries immutable embed identities for decks. Its TypeScript shape is unchanged. `production-room.ts` already obtains it through `roomPolicy`; all existing `Deck` instances use that exact policy for tools, binary admission, recovery and restore. `artifact-room.ts` refreshes the policy for `deck_read` and returns `embedSources`, enabling agents to discover usable file identities. `deck_write` uses the actual constrained-HTML adapter and guarded room commit, not a separate embed endpoint.
- `liveArtifacts.resolveEmbed` is a workspace/member procedure. It authorizes access to the deck and rechecks the exact source before calling the production `embedUrl` port in `infra.ts`. That port uses the existing artifact view signing key to mint a five-minute, member-only, version/file/hash-bound content URL. Scene state never stores bearer URLs. There is no share/public fallback.
- `artifact-content/routes.ts` remains the serving boundary. An embed claim must name a real manifest HTML file with the expected SHA-256; alternate HTML documents, alternate frame/document destinations, entry redirects, and the generated document page are refused. The version's ordinary relative JS/CSS/image assets and `_hm/bridge.js` continue through the existing route. All response paths retain the existing CSP/header wrapper. Content-addressed R2 blob integrity remains the existing artifact-storage contract.
- `deck-page.tsx` supplies the member resolver and authorized source catalog. The actual editor has a **Embed page** picker; the main editor scene and presentation use `DeckEmbed`. Thumbnails and speaker next-slide previews do not execute embeds. The component validates the resolver's local content URL against the source artifact, version, and file path, refreshes expiring URLs, and shows explicit loading/refusal states.
- `sandbox-frame.tsx` extracts the existing frame/nonce/navigation-blanking shell without its member tRPC import. The existing `ArtifactFrame` still supplies its normal member/link calls. Decks use the shared shell in preview mode, which supplies no privileged tool/storage/message handlers. Sandbox tokens, opaque origin, source/nonce checks, link confirmation, and CSP are preserved. A missing member resolver yields an explicit unavailable message; no guest-to-member identity conversion exists.
- Presentation uses measured scene transforms instead of CSS `zoom`; this fixes actual embedded-control hit testing on narrow Chromium viewports.

## Concurrent edits and export behavior

Embed props and styles retain Y.Map key identity. Guarded HTML writes merge independent embed keys, protect same-key ABA edits, and retain element/type/replacement guards. Human geometry edits do not block an independent agent change; contested keys are skipped with reasons. Existing editor undo origins, room checkpoint transactions and authoritative restore semantics are reused. Restore invalidates retained observations.

Checkpoint HTML explicitly renders an embed placeholder. PPTX and print/PDF rendering produce visible placeholders for pinned embeds and structured `embed_placeholder` warnings, retaining the existing warnings for unsupported flow geometry. The original constrained interchange still preserves source identity. The export/download service has only a minimal inventory integration: it accepts well-formed authorized embed identities so the core can validate a placeholder export; its asset read path still accepts only `/files/…` and never downloads HTML. A real service export test verifies the PPTX placeholder and warning while only the existing PNG is read.

## Remaining acceptance and limits

- The full-app signing key remains unavailable. No real-key full-app Clerk/member session, deployment, production browser, real email, or externally shared/guest embed acceptance is claimed. Those remain controller-owned gates.
- The requested guest integration thread could not be read: T3 returned `thread_not_found` / “no longer available.” No admission/auth/runtime code was changed, and no room/session type expansion was necessary. Guest integration must keep the resolver absent unless a separately authorized guest content contract is implemented.
- Only workspace-visible published page files in the bounded catalog are supported. Publishing an ordinary page and setting its audience to workspace uses existing artifact tools; this feature does not introduce another page authoring or upload system. Private-source ACL propagation and app bridge permissions remain unsupported and fail closed.
- Policy changes or deletion can make a previously embedded source unavailable; a fresh member URL is refused. Existing signed URLs retain the ordinary five-minute artifact-token validity window. As with existing owned-image validation, revalidation of a now-unauthorized stored source can reject loading/mutating that checkpoint; recovery requires restoring an authorized checkpoint or restoring source eligibility. Instant token revocation is not added to the R2-only serving boundary.
- Interactive content is not captured into static exports. Flow layouts retain the existing explicit export limitations. Neither export downloads nor guest authorization was redesigned.
