## Behaviour worth knowing

- `SyncOptions.roots` is `SyncRoot[]` (`{ path, mode: "read" | "write" }`). The longest containing root decides a path's mode, and `read` wins when one path is listed with both modes.
- Sync out never sends, writes or deletes under a read root. A local edit, new file or delete there goes into `SyncOutResult.refused`. The manifest entry stays.
- Sync in treats the library as truth under read roots: an edited or deleted local file is restored even when the etag is unchanged, and a library delete removes the local file. Write roots keep `kept`.
- `SyncInOptions.only` pulls just those paths (files or folders inside the roots) and removes locally what the library deleted. `only: []` pulls nothing.
- `createCoalescer` is exported from the barrel with `quietMs` 1500, `maxMs` 5000 and an injectable clock. It does not serialise batches.
- The daemon and VM call sites map their string paths to `{ path, mode: "write" }`. `LibrarySyncState.roots` stays strings.
