# V6.20 review: Revoke button on the Machines page

## Verdict

Round 1 at caa4aca: clean, 0 fix rounds. The reviewer re-ran check, test, build and the drizzle bundle grep, all passing.

## What shipped

Each machine that is not revoked gets a Revoke button on `/settings/machines`. It opens an alert dialog, and Revoke calls `machines.revoke` and reloads the list. `machines.list` still returns revoked machines, so a revoked one stays in the table with a "Revoked" badge and no button. `canRevoke` and `revokeMachine` live in `machine-logic.ts` with tests. The dialog is `revoke-dialog.tsx`.

Local browser check (dev server, dev login, one machine row inserted by hand): Cancel left the machine online, confirming set it to revoked, and the row showed "Revoked" with no buttons.

## Nits left

- The tests cover `canRevoke` and `revokeMachine`, not the dialog wiring. The repo has no component test setup.
- `closeRevoke` does not reload the list. If the relay call fails after the service marked the machine revoked, the row keeps its button until the next load. Retrying is safe.
- No success toast, unlike the secrets dialogs.
- `revoke-dialog.tsx` imports `./machine-logic` without `.ts`, matching `machine-row.tsx`.

## Ideas beyond scope

- Reload the list when the revoke dialog closes after an error.
- A component test setup for dialogs.
