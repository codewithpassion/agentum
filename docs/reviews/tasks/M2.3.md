# M2.3 review

## Verdicts

Round 0, commit 7693e06: clean. No must-fix, eight nits. No fix rounds.

## Decisions

- `inbox_list`, `inbox_read` and `inbox_post` are real tools with strict input schemas. `placeholderTool` and the `not_implemented` error code are gone, because nothing else used them.
- `McpPorts` gets `inboxList`, `inboxRead` and `inboxPost`. The web app's ports call `services.inbox` as the caller's principal, so a read-only key can read but not post, and a run token posts as its agent with its run id. The inbox service already supported this since M6.1.
- `inbox_post` trims its text in the schema, because the service rejects empty text with a `ZodError` that the tool layer would show as a generic failure.
- `inbox_read` puts the untrusted-data notice first, as `read_session` does, because posts carry other people's and agents' words. The notice constant moved to `tools/define.ts`.
- There is no tool to create a thread, since the task names three tools. The smoke script uses the first thread from `inbox_list`, or the one named by `--thread`.
- The smoke script counts polls, not elapsed time: 11 reads with a 1 s sleep between them.

## Checks

`bun run check && bun run test && bun run build` pass, and the grep for drizzle in `apps/web/dist/client` finds nothing. Five tests in `apps/web/src/server/routes/mcp.test.ts` cover a write key posting with a mention and reading the reply with the run id, listing, a read-only key refused on post, a run token posting as its agent, and an unknown thread. `packages/mcp` tests cover the three tools, and `scripts/smoke-mcp.test.ts` covers the poll.

Live, against `vite dev` on port 3517 with a fresh local D1: dev login, made a write key and a fake agent "Fake Echo" (slug `fake-echo`) and a thread in the UI, then `bun scripts/smoke-mcp.ts --key hm_key_... --server http://localhost:3517`. It listed nine tools, passed the earlier steps, started a run with `inbox_post`, and `inbox_read` showed the reply carrying that run id. Without a thread it stopped with the "create one on the Inbox page" message.

## Nits left

- `PostInfo.authorKind` is typed `string`, not `"user" | "agent"` (`packages/mcp/src/ports.ts`).
- `toPostInfo` drops `fileIds`, so a reply with files shows no sign of them through `inbox_read`.
- The `inbox_list` description does not say it returns at most 50 threads, and `inbox_read` does not say it returns the newest 500 posts.
- `inbox_list` prints thread titles without the untrusted-data notice.
- The fake thread in `scripts/smoke-mcp.test.ts` has `lastPostAt: null`, and the "third read" test repeats the default case.
- The smoke poll counts polls, so slow calls can stretch the wait past 10 s.
- The task's "seeded fake agent" does not exist in a fresh local D1. The live check made one in the UI.

## Ideas beyond the scope

- An `inbox_create_thread` tool, so an agent or a smoke script can start a thread itself.
- Show file chips for a post's `file_ids` in `inbox_read`.
- Let `inbox_read` take an `after` post id for long threads.
