# V1.5 review

## Verdicts
- Round 1 (76a3d71): must-fix. A `noBarrelFile` suppression re-exported router schemas from `requests/records.ts`, and `open` fell back to `toolName.toLowerCase()` instead of the canonical `toolKey()`, so `always_allow` rules would not match.
- Round 2 (40a5d45, fix commit only): clean. The router schemas now live in `requests.ts`, and `open` derives the key from the agent's runtime through `toolKey()`. A test covers `WebFetch` to `web_fetch`.

## Nits left
- The wake-up runs on every close, even while another request keeps the run waiting. This follows the Check line "resume is called once per close", not the scope sentence.
- `answer` checks for pending rows and then calls `markRunning` non-atomically. A request opened in between can leave the run `running` while pending.
- The compare-and-set, rule upsert, `request.answered` append and resume are separate writes. A throw after the compare-and-set leaves the row answered with no event or wake-up.
- A throw from `announce` or `resume` in `expireDue` skips later rows that are already `expired`.
- The stored answer is redacted, not only the event, so the agent receives `[redacted]` in place of a pasted secret. Question answers also have their keys redacted.
- An approval answer sent to a question request throws a ZodError (500) instead of a `ServiceError` (400).
- `open` can insert a pending row for a run that ends between the status check and the insert. Expiry clears it.
- `setRule` and its `tool_rule.changed` append are not atomic together. `answer` and `setRule` do not check read-only API keys.
- `capInput` can split a surrogate pair when it truncates.
- `runs.ts` and `RuntimeAdapter` import types from the requests service, a type cycle. A narrow `{ id }` type would avoid it.
- `machine-claim.ts` runs the ask-key query before the claim compare-and-set.
- The expire-twice test does not assert a single `request.expired` event.
- Tool key fallback in `open` assumes `machine` if the agent lookup misses, and passes no `serverKeys`, so an MCP name without a supplied key is stored lowercased.

## Ideas beyond scope
- Make the answer, rule upsert, event append and pending check one `atomic` batch.
- Retry sweep for answered rows that lack a `request.answered` event.
