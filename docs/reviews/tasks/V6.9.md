## Decisions

Relay: V6.1's one-object decision is written at the top of `relay.ts`. `machine-relay-core.ts` (not in the task's file list) is the pure part of `MachineRelay`: it routes each socket by tag to the daemon core (`relay-core.ts`, unchanged apart from exported header and key constants) or the computer core (`computer-relay-core.ts`), so the mixed-tag test in `relay.test.ts` runs the real routing with fake sockets. The Worker stamps `x-hm-role` (`daemon` or `computer`) next to the identity headers, and `fetch` refuses a missing or unknown role with 400.

One alarm, two cores: a Durable Object has one alarm, and both cores arm and clear theirs. `relay-alarms.ts` gives each core a storage view with its own wake time (`alarm:<name>` keys) and arms the real alarm at the earliest. An alarm armed before this deploy (no stored wake times) runs the daemon handler.

Outcome types: the RPC surface is `ComputerOutcome` and friends in `packages/services/src/machines/types.ts`, not the frozen `RequestOutcomeSchema` in `@repo/protocol/computer`, because that schema has no slot for the computer's own error `code` (`not_found`, `read_only`) which agentum's client logic reads. Mapping: a reply with `error` is `reason: "client_error"` with its `code`; `stale`, `duplicate_id` and `interrupted` keep their own reasons; `queue_full` is the relay's own refusal. V6.11's adapters turn these into the port's failures. Inputs are the protocol request types minus `op`, so the DO builds the frame and the timeout.

Exec cap: agentum ran one command at a time. Here up to `MAX_IN_FLIGHT_EXEC` (4) are in flight and `MAX_QUEUE_DEPTH` (32) wait, then `queue_full`. A queued command is checked against the lease again when it gets its slot, and its timeout starts when it is sent. The Go client has the same limits.

Offline message: agentum read the host name and last-seen time from D1. The core keeps last-seen in DO storage (hello, each alarm, socket close) and uses the hello's hostname as the name, then calls `offlineMessage` from the protocol.

Presence: the hello and the 60 s alarm call `markComputerOnline`, a closed last socket calls `markComputerOffline`, and the alarm closes a socket with no heartbeat for `STALE_AFTER_MS` (4408) and marks it offline. A `"revoked"` answer closes with 4401. A D1 failure is logged and never costs the socket.

The `/enroll` route now parses `machineEnrollRequestSchema`, so a computer body enrols (V6.2's note).

## Nits left

- `relay-alarms.ts` `fire()` deletes due wake times before the handlers run. If a core throws, the runtime's retry finds nothing due and runs the daemon handler, so the failed computer alarm is lost until the next hello or op. D1 errors are caught, so a throw is rare.
- A socket accepted with no tag goes to neither core. A code deploy disconnects every socket, so none should exist.
- `revoke()` fails requests already sent. Execs waiting for a slot resolve `offline` once the slots free, not `revoked`.
- One failed orphan write leaves the write chain rejected for the life of the instance.
- After the alarm closes a stale socket, the close event writes last-seen and marks offline a second time (agentum does the same).
- `relay.ts` revoke closes sockets through both cores and then closes every socket again. The second close is caught.
- `clipboardGet` defaults its principal to a generic agent. `relay.ts` always passes one.
- The core receives every socket and filters by `getTags`, where the task text says `getWebSockets("daemon")`. Same result, and it works with the fake sockets in tests.

## Ideas beyond the scope

- `releaseAgentLease` (agentum) is not ported. An agent's desktop hold ends at its 10-minute idle backstop, not at the end of its run. V6.11 or V6.12 can add the RPC when a run ends. Callers must always set `agentId` on an agent principal: one without it matches any holder.
- The viewer hub (V6.10) needs a status-changed hook in the computer core (agentum's `viewers.statusChanged()`), and its `viewer` tag in `machine-relay-core.ts`.
