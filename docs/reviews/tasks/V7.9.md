## Nits left

- `github-skill-source.ts:380-405`: GitHub answers HTTP 422 for an unknown branch or tag, so `resolveCommit` reports `request_failed` "HTTP 422" instead of a not-found message. Worth fixing before V7.12 shows the message to users (treat 422 like the 404 path).
- `:324`, `:153`: an odd filename outside the selected folder (unsafe path, non-UTF-8) fails the whole import. Checking only included entries would avoid it.
- `:455-459`: the 50 MiB cap counts compressed bytes, as the task specifies. A gzip bomb can burn Worker CPU on skipped data. A cap on decompressed bytes would close it.
- `:475`: a ref with a trailing slash passes the schema and ends as HTTP 422.
- `:356-358`: a selected path that is a symlink or a file gets only the "must contain SKILL.md" message.
- `:402-405`: a 401 from a bad token gives no hint that the token is the cause.
- `:236`: "(5 MiB)" is hand-written beside `SKILLS_MAX_BYTES`.
- `:241-242`: path limits 512 and 20 copy `SKILL_PATH_MAX_BYTES` and `SKILL_PATH_MAX_SEGMENTS` from `skills-store/paths.ts`, which is not exported.
- `:509`, `:359`: an upper-case SHA is returned as given.
- Tests lack cases for a 422 on an unknown ref, a selected path that is a symlink, and trailing data after the tar end.

## Beyond scope

- A decompressed-bytes cap and a 422 message are the two worth a small follow-up task.
