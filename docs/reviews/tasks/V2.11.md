# V2.11 review: task view page

## Verdict

Round 1, at da67ed7: clean, no must-fix. `bun run check`, `bun run test` and `bun run build` passed, and `apps/web/dist/client` has no `drizzle`. No fix rounds.

## Browser check (dispatcher)

Local dev server, a scripted machine daemon, the dev user. A machine run with two tool calls showed steps 1 and 2 with their in chips and a "5 bills" count link, live as the events arrived. A run that asked for approval showed the paused step with the request card, and "Allow once" in the card settled it in place, flipped the step to done, added the assistant step and moved the pill from "Paused, needs you" to "Done". Cost ($0.18) appeared after the run finished. Stop task moved a running task to Cancelled.

## Decisions

- A task is one run. The page filters the session's events to its own run. Moving the view to a follow-up run is V2.12's, because the composer knows the new run id.
- One `tasks.get` refetch happens when the run turns terminal, for the cost and end time the stream does not carry. Otherwise the receipt and log are rebuilt from the event list.
- The transport is `use-session-events.ts` (generic: `lastEventId`, `onFrame`, `refetch`), so V2.12 can share the one EventSource. Its rules (`MAX_FAILURES`, closed-source fallback, 10 s poll, focus retry) are in `session-events-logic.ts`.
- "Later in this thread" lists runs newer than this one next to "Earlier in this thread", so a follow-up stays reachable.
- `useNowMs` is copied from `desk.tsx` into `components/task/use-now-ms.ts`.
- Out chips only show primitive fields of a result. A result that is an array shows its length in the count link instead.

## Nits left

- Poll mode refetches every 10 s even after the run ended (`use-session-events.ts`).
- Poll mode on a session past the `tasks.get` event cap never shows newer events.
- A failed `requests.pending` fetch is not retried until the next refetch (`task-page.tsx`).
- "cost so far" is stale while the run is live.
- `countText` singularises by dropping a trailing "s", so "1 status" reads "1 statu". The test pins "1 new".
- Receipt chip key `key=value` can collide when a step has two identical chips.
- `receiptRunOf` strips "Handoff from " from the service label to get the parent agent name.
- "Cancelled" uses the green `ok` tone, as the desk's band does.
- `MAX_FAILURES`, `FROM_START` and the stream URL exist in both `use-session-stream.ts` and `session-events-logic.ts`. `useNowMs` exists in `desk.tsx` and `use-now-ms.ts`.

## Beyond the scope

- `tasks.get` could return the parent agent name and `parentRunId` on `run`, which would drop the label parsing.
- The chat could move onto `useSessionEvents` and share the transport rules.
- `tasks.get` could return costUsd in the stream (a `run` frame field) so the cost updates live.
