## Decisions

- Data: `task-page.tsx` holds a second reducer (`thread-state.ts`) over the same frames `useSessionEvents` delivers, so there is one EventSource. `tasks.get` events seed it, and a refetch resets it and replays the event frames received since. Deltas are not stored, so the next delta restores any streaming text a reset dropped.
- Runtime: assistant-ui's external store runtime with `convertMessage` (`thread-parts.ts`). It always reports `isRunning: false`, because assistant-ui disables the edit composer while a thread runs, and "Edit and resend" must work on a live run. The main composer disables itself from the thread's own status instead.
- Requests are `data-request` parts that look up V1's `RequestCard` by id in the page's `requestViews`. That map holds this run's requests only, so a request of an earlier run in the session shows no card in the thread.
- Attachments: the adapter uploads on add, keeps the server file id in a `file` content part, and `onNew` reads the ids from there. The library picker adds a complete attachment with the same part. Text is required to send, because `runs.start` refuses empty text.
- Licence: the runtime glue (adapter, converter, start-input helpers) was written for Harbourmaster. Nothing was copied from trueforge's `assistant-ui-runtime`, so no Apache header or licence file is added. The containers follow trueforge's patterns but are written on shadcn components.
- The five chat files moved to `components/thread/` (`upload-file`, `library-picker`, `file-chips`, `save-to-library`, `use-file-infos`, with tests). The chat tab, transcript view and session transcript import them from there, so V2.13 can delete `components/agent/chat/`.
- `bun add` bumped the `latest` TanStack entries in `bun.lock` as well. `@assistant-ui/react` is pinned at 0.15.31.
- The "edited" mark lives in the browser tab only (sessionStorage, `edited-marks.ts`), because no event records an edit and only V2.1 may change the schema. It shows on the old turn in the new run's view of the same tab, and is gone in another tab or browser.

## Nits left

- A second send while the first is still starting throws and restores the text, but the files of that second send are not restored (same for a failed `runs.start`, which restores text only).
- A failed edit shows a toast, but the edit composer has already closed, so the edited text is lost.
- Send looks enabled in a few states where assistant-ui would block it (asChild lets the Button's own `disabled` win); clicking does nothing.
- A tool call with no result keeps its spinner after the run is cancelled or fails.
- A string or array tool input shows JSON-quoted in the card's input section.
- The tool group label "Read ×3" reads as "multiplication sign" to a screen reader.
- `edited-marks` only grows within a tab.
- After a thread reset, `isLateDelta` cannot catch a late delta for a message that finished earlier in a still-running run.
- No tests cover the in-flight guard, the mark-after-start order or the empty-text guards, which rest on the browser check.
- The receipt on the same page hydrates with a different time zone text (existing, in `receipt.tsx`).

## Beyond the scope

- Assistant files: the protocol fold gives assistant messages only `{attachment, path}` markers, so agent output shows a path line, not a chip with "Save to library". `foldThread` could resolve markers to file ids.
- A `message.edited` event would let the mark survive another tab and a reload.
- The receipt and the thread both show the open request card on the task page. One of them could drop it.
- The old chat tab could move onto this runtime, or go with V2.13.
