# V6.10 review

Viewer hub and desktop routes. Built by Haiku workers, integrated and reviewed by the dispatcher.

## Verdicts

Round 1 at 3429581: clean after 0 fix rounds. The reviewer found no must-fix. It checked header spoofing on both relay upgrades, cross-workspace access, the cross-site socket check, that a viewer connecting leaves the computer's generation and sockets alone, input without the lease, frame privacy between viewers, the status hook coverage and every lease release path.

## Decisions

The viewer hub (`viewer-hub.ts`) is a factory over fake-able sockets and lives in `MachineRelay` under tag `viewer`. `machine-relay-core.ts` routes viewer sockets to it, `relay.ts` accepts them without `connect` (so the computer's generation and the daemon's identity are untouched), and the computer core calls a new `statusChanged` hook on lease changes, hello, accept and close. The Worker stamps `x-hm-role: viewer` and `x-hm-viewer-user` next to the identity headers. `RelaySocket.send` now takes `string | ArrayBuffer` because frames are binary.

Routes: `routes/desktop.ts` is mounted at `/api/machines/:id/desktop` in `routes/runtime.ts` (beside the machine routes, so `server.ts` is untouched). `:id` is a machine id. It serves status, `GET`/`PUT` clipboard and the stream upgrade, with the Clerk session on `cookieGroup()`. `POST /desktop/input`, take-control, hand-back and cancel-takeover are not ported: input rides the viewer socket and the other three are V6.7's `takeover.*` tRPC procedures. The stream refuses an `Origin` that is not the request's own, because csrf skips GET and the socket can drive the desktop. Agentum's `pendingTakeover` field is left out.

Services: `machines.requireComputer`, `desktopStatus`, `clipboardRead` and `clipboardWrite` give the routes a workspace-checked machine lookup. `machines/lease.ts` (`createTakeoverLease`) is the relay-backed lease V6.7 asked for, filled in `compose.ts`. `take` throws a conflict with the relay's reason when refused. `release` lets go of whichever person holds the desktop, read from `computerStatus`, so a hand-back by someone else still frees it and the relay port is unchanged.

Takeover service: `take` now takes the lease before it writes `computer.taken`. A new `onEvent` listener (registered with `events.onAppend` in `compose.ts`) releases the lease when a takeover request expires or is cancelled because its run ended. A person's cancel releases twice, which is harmless.

Check mismatch: the task's Check puts the take-control to hand-back flow in `routes/desktop.test.ts`. Those routes are gone, so the flow is tested in `apps/web/src/server/takeover-compose.test.ts` against the composed services and a recording relay.

## Nits left

- `lease.release` reads the status and then releases that holder in a second call, so a change of holder between the two leaves the new holder with the desktop.
- `handBack` resumes the run (`requests.answer`) before it releases the lease, so the agent's first desktop op can meet `human_in_control` or `desktop_busy`. Predates this task.
- A take that races with expiry can take the lease after the expiry listener released it, leaving a person holding the desktop with no request open until the human idle timeout.
- No test for the run-ending cancel path in `takeover-compose.test.ts` (it is covered in `takeover.test.ts`).
- An idle viewer that sends no acks after an eviction is picked up by the next alarm or status change, up to 60 s, and no alarm is armed while the computer is offline.
- Each viewer `input` message resets the pump's retry time and joins an unbounded input chain, so a viewer without the lease can keep the pump at full rate. Agentum did the same.
- An open viewer socket is not re-checked, so a person removed from the workspace keeps watching until the socket closes. Only machine revoke closes it.
- The `viewer` branch in `machine-relay-core.ts` `connect` is reached only by tests, since `relay.ts` skips `connect` for viewers.
- The stream's Origin check accepts only the request's own origin. Agentum also accepted `PUBLIC_APP_URL`.
