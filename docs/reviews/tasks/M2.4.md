## What changed

The sessions visibility rule moved out of the sessions service into an exported `visibleSessions(db, reader)` in `packages/services/src/sessions.ts`. The sessions service and the runs service both call it. In `runs.ts`, `requireVisibleSession` applies it to user principals, and `getRun` and `cancelRun` use it. A run in another user's private `ui` session answers the same not-found as an unknown id. Machine, run, trigger and system principals keep their access. `waitForRun` goes through `getRun`, so it follows the rule too.

## Nits left

- `getRun` adds one sessions query per call for users, and `waitForRun` repeats it on every poll.
- `visibleSessions` is public on the `@repo/services/sessions` subpath while its `Reader` parameter type is not exported.

- The `cancelRun` test covers only the private-session case, not a shared session.

## Ideas beyond the scope
