# M4.3 review

## Verdicts

- Round 0, commit 6b6292f: clean. No race with claims, the order guarantees progress past runs nobody claims, and the new test fails on the code before the change.

## Decisions

- The sweep remembers what it looked at in a new nullable column, `runs.swept_at`, and orders by `coalesce(swept_at, created_at), id` under the same limit of 100. A minutely routine on an offline machine keeps adding runs nobody claims, so no order on `created_at` alone can reach the crash-left run. Filtering on machine liveness would tie the sweep to the machines schema and cover one cause only.
- Each row is stamped with its own update before the sweep acts on it. A run whose offer throws every time still moves to the back. One `UPDATE ... WHERE id IN (...)` would carry 101 bound parameters, and D1 allows 100.
- The stamp only applies while the run is `queued` or `offered`, and it touches no status, so it cannot race a claim. A pass reaches all N stale runs in about N/100 passes.
- Migration 0013 is a plain `ALTER TABLE runs ADD swept_at text`. `RunRecord` gains no field.

## Nits left

- `runs.ts` sweep loop: the new `biome-ignore` reason replaced the old "one run at a time keeps a failure to that run".
- A failed stamp write is reported as that run's failure and skips its offer, where before the change the run would still have been offered.
- Each pass does up to 100 extra single-row writes, including runs the sweep then leaves alone.
- The test's crash-left run is the same kind of spy run as the other 105. It does not model a healthy routine against an offline machine.
- The test advances the clock 61 s between the two passes, which the cutoff does not need.

## Ideas beyond the scope

- Nothing expires a queued run, so runs nobody claims still pile up and get offered every pass until someone cancels them. A cap on offers per run, or failing a run after a day, would stop the growth.

## Steps for Dom

- Apply migration 0013 to remote D1 before the deploy: `wrangler d1 migrations apply DB --remote`. The new sweep reads and writes `swept_at`, so the code fails without it.
