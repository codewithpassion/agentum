## Decision for the log

The task says to gate `/api/machines/ping-do` behind auth or remove it, but its check curls it with no login. It is mounted in dev builds only (`import.meta.env.DEV`), together with the atomic probe, so a deployed Worker has neither. The real relay route replaces it. The reviewer accepted this. It means the DO is not yet proven in a deployed Worker or a PR preview.

## Nits left

- `server.ts`: services are composed only for `/api/*`. A lane that mounts `/mcp` or `/files/:id` at the root must widen that middleware.
- `trpc/context.ts`: SSR builds the services once per tRPC call, not once per request. Same as before this task.
- `server.ts`: dev routes (and drizzle `sqlite-core`) are in the production bundle, unmounted. A dynamic import inside the DEV check would drop them.
- `routes/dev.ts`: the probe creates a scratch `atomic_probe` table in local D1 outside migrations.
- `tick/tick.test.ts`: the real jobs are checked for success and no events, not for running exactly once. The once-each check uses stand-in jobs.
- `tick/registry.ts`: sweep and reap run in parallel on the same runs table. Nothing tests that the pair is race-free.
- `components/shell/nav-registry.ts`: `to: string` gives up typed link targets.
- `routes/_app/agents.$agentId.tsx`: only a 401 is handled, a missing agent shows the generic error page.
- `wrangler.jsonc`: `PUBLIC_BASE_URL` is empty in staging and previews until O.1, which narrows its generated type.
- `package.json`: `check` runs the boundary lint before any build, so the no-drizzle-in-client rule only bites after `bun run build`.
