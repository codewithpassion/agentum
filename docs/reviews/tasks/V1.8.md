## What changed

`PiRun` reads `docs["pi.live"]` from the root conversation's `viewState()` and offers it to `deltaPublisher` (`apps/web/src/server/pi-run-deltas.ts`). At most one `delta` frame goes out per 250 ms, with the full text so far under `messageKey` `<runId>:<message timestamp>`. Only `text` blocks are read, so thinking, tool-call arguments and tool output never become deltas.

Before a frame leaves, the text is cut and masked. The cut holds back the last word, anything that begins a granted value (`Masker.unfinishedTail`), and any granted value the cut would split (`Masker.cutBeforeWhole`). The held text is then masked with the run's masker and passed through `redactText`. If the masker read fails, the frame is dropped. Frames go through `streamPublisher` with `waitUntil` as `defer`, so their order is kept and a failed send is dropped.

One shared, ref-counted view serves all runs followed at once, and frames carry the newest run's id (`RUN_KEY`), like the rest of the object. The session id is stored beside the run (`SESSION_KEY`). `packages/services` exports `./events/scrub`. `Masker` in `packages/protocol` gained `unfinishedTail` and `cutBeforeWhole`, with tests.

## Nits left

1. `packages/protocol/src/masker.ts:153`: `cutBeforeWhole` costs run length times needles when a periodic secret such as `aa` repeats through a long run. 92 ms for 60k characters and 11 secrets, once per text change.
2. `apps/web/src/server/pi-run-deltas.test.ts:281`: the 60k PEM test compares wall-clock time to 50 ms. It measures 12 to 15 ms, so a slow CI runner could flake.
3. `packages/protocol/src/masker.test.ts`: no unit case for cut 0, empty text or a self-overlapping value. The fuzz covers them.
4. `apps/web/src/server/pi-run-deltas.ts:79`: an offer inside the 250 ms gap is dropped with no trailing send. The next commit or the stored event covers it.
5. Two adjacent granted values that share characters can leak a one-character fragment (`"ba"` and `"\nbc"` on `"baba\nbc"`). The final masked transcript is ambiguous in the same way.
6. The failed-publish test covers a path only a fake publisher reaches, because the real `streamPublisher` never rejects.
7. One frame can go out after unsubscribe, because a running callback is not awaited.
8. `viewState()` keeps the whole active transcript in object memory for the run. A narrower read would cost less on long sessions.

## Ideas beyond the scope

- V1.14: the reducer should drop a delta once the final message for that run is in, because deltas and stored events travel through different publishers and a late delta can land after its `message.assistant` event.
- A trailing send when the model goes quiet inside the 250 ms gap would show the last words sooner.
