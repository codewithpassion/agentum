# M5.9 review: Slack "all messages" mode, batched runs, channel history

## Verdicts

- Round 1 (7bd8eff): not clean. Two must-fix. A batch bigger than the message or prompt cap marked only the messages it showed, so the rest were already old enough to start a second batch the next minute, inside the five minutes. The `slack_send` `thread_ts` description promised that a ts shown by `slack_history` works, but the service accepted only started threads and stored messages.
- Round 2 (7b252c0, fix commit only): clean.

## Fixed in round 2

- A batch takes in up to 1000 messages and marks all of them. The prompt shows as many as fit in 90 000 characters and ends with a line that counts the rest and points to `slack_history`.
- `slack_send` accepts a thread when the agent started it, when a stored message of the app is in it, or when Slack's `conversations.replies` finds the ts in the channel. A failing Slack call refuses the send.
- In "all" mode, a stranger's reply in a thread the app knows, and another person's reply in a `ui` or private session thread, are stored for the next batch.
- The services no longer take the unused `atomic` and `clock` options. The batch `requestId` uses the first message id from `findDueBatches`.

## Nits left

- `formatBatchPrompt` still returns `included`, which only tests read now.
- `DueBatch.botUserId` is never read.
- The live thread check in `slack-send.ts` accepts any message in the answer and does not compare its ts with the requested one. A reply's ts goes to Slack as `thread_ts`, not the parent's.
- No test sends a real `thread_not_found`, or a transient answer to `conversations.replies`. No test covers another person's reply in a `ui` or private session thread being stored.
- `lookupNames` in `batch.ts` runs before `startRun`, so a channel whose start keeps failing makes up to 26 Slack calls every minute.
- `searchMessages` filters time on when the row was stored. The hit's time comes from the Slack ts. A person linked twice to one Slack user would show a hit twice.
- `findChannel` in `slack-history.ts` relies on `listChannels`, which stops after 5 pages of channels.
- Search and history are open to anyone who can run the agent, including private-channel content. The task allows this.
- An edit that empties a message's text is ignored, so the stored copy keeps the old text.
- The prompt names authors with `users.info` lookups (at most 25 per batch). A name Slack does not return falls back to the Slack user id.
- DMs that start a run are stored (the task asks for it) but search never returns them.
- `slackFailure` says "Slack refused the message" and, for `missing_scope`, names the `im:write` scope, even when the call was a history read.

## Ideas beyond the scope

- Show batch runs in the Log with the channel name (the `slack.batch_started` event carries the channel id and count).
- A per-app batch delay instead of the fixed five minutes.
- A setting to exclude channels from "all messages" mode.
- Search over attachments and file names.
