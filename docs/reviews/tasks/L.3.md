# L.3 — Realtime artifact room

Implemented `apps/web/src/server/live-artifacts/artifact-room.ts`, `storage.ts`, `anchors.ts` and the required typed ports in `ports.ts`. This is a concrete, hibernating SQLite Durable Object, deliberately unexported from the production server and unbound in production Wrangler configuration. No production compose/routes, service/DB/schema or task files were authored in this lane. Main was merged to consume the L.2 validation fixes, L.4b authorization/outbox and original-revert-actor fixes, L.6 identities and L.Q quota changes; their existing exports are preserved.

## Transport and admission

Native Durable Object hibernation is the justified fallback to `withYjs`: implementing the small standard Yjs sync/awareness wire surface makes the candidate-validation boundary explicit. No stock `withYjs`/YServer handler receives an update. Sync message 0 contains step1/state-vector (0), step2 (1), or update (2). Every incoming document update passes `LiveDocument.applyUpdate` on a disposable candidate; the resulting delta is durably stored and again passes `LiveDocument.applyUpdate` before authoritative application and broadcast. RPC operations use the same candidate/persistence boundary. The full encoded Yjs state, including retained CRDT tombstones, is conservatively capped at 8 MiB. Rejected mutations leave authoritative bytes/revision unchanged. Socket errors include a bounded control response and closure; an oversized document reports `Document exceeds 8 MiB`. Viewers/commenters complete read synchronization but their step2/update payloads are ignored without applying or relaying bytes.

The room verifies the existing private HMAC ticket with `@repo/services/live-artifacts/ticket`: signature, schema, audience, artifact/workspace, issue/admission/connection times. It then **always** awaits `ArtifactRoomService.admit(scope, ticket, context)` before consuming the JTI in SQLite and attaching or renewing. Current role must equal the ticket role: an old unexpired ticket is refused after downgrade as well as revoke/deletion. Unique SQLite JTI insertion is the atomic single-use boundary, including simultaneous upgrades and renewals. Expired admission JTIs can be pruned because those signed tickets can no longer be admitted. Connections expire at the signed connection expiry, bounded to 15 minutes; an alarm and every message enforce expiry. Renewal uses a fresh ticket, consumes it once and cannot change the participant/kind or revive an expired connection.

L.7's admission adapter must authenticate the initial `context.request` through the real session/bearer/guest resolver and call the merged `LiveAdmissionPort.admit(principal, { artifactId, ticket })`. It must return trusted identity plus an opaque `authorizationRef` bound to that credential/session, persisted only in the server socket attachment. Renewal receives this reference instead of a browser-supplied principal. Resolve it freshly, preserving current membership/admin, credential read-only, run chain, artifact scope, grant expiry and revocation restrictions. **Never manufacture a privileged Principal from signed participant/role claims.** The explicit request/reference context avoids relying on a ticket-only principal reconstruction. A trusted upstream broker with a durable credential capability registry can implement the same contract.

Every message additionally invokes `authorize(scope, subject)` with the attachment's authorization reference, so delayed invalidation delivery cannot permit a newly received write/read-sync message under stale permissions. RPC edit/revert actors are trusted internal adapter arguments and are freshly authorized; do not expose room RPCs as unauthenticated HTTP endpoints. Scope is resolved from the namespace object ID by trusted `open`, persisted immutably and compared against tickets. L.7 must route a namespace ID to its exact artifact/workspace and supply a nonblank private signing key. The public fixture key and signing issuer exist only in `fixtures/worker.ts`; that entrypoint is never imported by the production room.

## Presence and client adapter

Awareness uses standard message 1 and query message 3. A bounded packet may contain exactly one entry. Client awareness IDs, clocks, identity, status and unknown fields cannot become authoritative. The room accepts only schema-validated cursor/pointer/selection/slide fields, overwrites id/name/kind/color from trusted current identity, assigns a monotonically allocated **connection-unique server ID**, and increments its own lifecycle clock. Close/revoke/expiry emits a higher-clock null entry for that ID. Reconnecting never reuses the old ID, so a poisoned peer clock cannot suppress new presence. Socket identity, ID, clock, expiry and current presence survive hibernation through attachments; no interval holds the room awake.

The editor transport must handle JSON control frames separately from binary Yjs frames:

- server `session`: `{ type, awarenessId, expiresAt }`;
- client renewal: `{ type: "renew", ticket }`;
- server `renewed`: `{ type, expiresAt }`;
- server `role`: `{ type, role }`;
- server `error`: `{ type, message }`, followed by closure for rejected input.

This is Yjs document/sync and awareness compatibility, with an explicit application control adapter; a stock provider that blindly decodes every text frame as binary needs that adapter. Use the assigned awareness ID for the local awareness controller (its independent `clientID`), without changing the Y.Doc's CRDT client ID. The server remains safe if a client continues supplying an arbitrary awareness ID: it always rewrites it and never lets a packet affect another connection's lifecycle. UI presence can also consume the room's authoritative `presence()` projection.

`setAgentPresence(entry | null)` resolves identity through the trusted port, uses a distinct reserved server ID and persists a five-second deadline. Heartbeats update the server clock/deadline; explicit clear, authorization refresh and alarm expiry send higher-clock removal. Presence reads and new admissions exclude expired agents even if an alarm is delayed. The real workerd test observes null awareness delivery after five seconds. L.7 must heartbeat while a tool is active and clear in its completion/failure cleanup.

## Persistence, revisions and RPCs

SQLite stores ordered update rows as generation/sequence-tagged BLOB chunks, each at most **512 KiB**. Compaction triggers after **500 updates or 1 MiB** of accumulated encoded updates. All snapshot chunks, the active generation/sequence/revision pointer and deletion of superseded rows commit in one synchronous SQLite transaction. A thrown/interrupted generation transaction leaves the previous complete generation plus its update tail recoverable. Recovery checks chunk order, lengths and the byte manifest and fails closed on missing/incomplete data. Authoritative global and per-block revisions persist; per-block guard translation validates the original room guard before adjusting a disposable controller's revision seed. This preserves valid guards on unchanged blocks across unrelated edits, compaction and restart without editing engine internals.

The room exposes these trusted RPC methods:

- `read("outline" | "markdown")` -> `{ content, revision, present }`; outline content is the engine's current block projection with persisted room block revisions.
- `applyAgentOps(ops, origin)` -> `{ revision, changeId }`. `changeId` deduplicates the exact origin and rejects a colliding origin. The origin's run/tool/participant attribution accompanies checkpoints.
- `revert(changeId, byParticipant)` -> **`{ revision, byParticipant }`**. Before/update Yjs records are chunked durably. Selective undo reconstructs the recorded origin after restart and preserves later human edits. The first successful undo's actor and revision commit with the update, before acknowledgment. Every idempotent replay, including another authorized caller after restart, returns that original actor/revision. L.7 maps the merged `LiveChangePort.revert(scope, input)` to this RPC; the service validates run/tool/revision provenance before calling and audits the returned original actor through its conditional finalization.
- `restore({ snapshot, versionId, byParticipant, requestId })` -> `{ state, revision }`. Owner-only, current authorization, validated rich content as one new monotonic revision. Stable `requestId` is mandatory: exact resulting state/revision, request actor/version provenance and document update commit together. Retry returns the original restore snapshot even if later edits occurred; a different actor/version cannot reuse the ID. L.7 must allocate/preserve this ID over the whole service restore/save retry, rather than blindly calling a fresh restore again.
- `checkpoint()` -> `{ artifactId, versionId, revision }`.
- `presence()`, `setAgentPresence(entry | null)`, `refresh(participantId?)`, `disconnect(participantId)`.
- `resolveAnchor(anchor)` -> `{ anchor, quote }`, mapping `LiveAnchorPort.resolve`. Use plain JSON relative positions across RPC boundaries: Yjs's structurally JSON-compatible ID objects must pass through JSON serialization rather than be sent as arbitrary runtime classes.
- `guardAgentSnapshot({ snapshot, runId })`, mapping `LiveAnchorPort.guardAgentSnapshot`. Current document comment ranges come from the mandatory trusted `protectedRanges(scope)` callback. Agent mutations, binary agent updates, reverts and guarded checkpoints refuse deletion of anchored CRDT characters, including cross-inline ranges or replacement with identical text. Detached comments do not freeze unrelated text. The anchor adapter projects text runs once per candidate and compares CRDT character intervals, avoiding per-character metadata for a multi-megabyte document. Engine semantic guards run as well; checking only at checkpoint time would be too late.

`ownBlobUrls(scope)` is mandatory and trusted. Browser fields never supply image ownership policy. Verified URLs persist for deterministic recovery, including when a deleted artifact can no longer supply a content policy; every mutation refreshes policy from the service before candidate validation. Only a successfully validated document commits its recovery policy; a rejected update under a newly restrictive policy cannot make the previous generation unrecoverable. `refresh` closes/downgrades sockets independently of a blob-policy outage. The fixture accepts an own-image through the port and refuses a binary update replacing it with another artifact's image.

## Checkpoint and access adapters

Dirty state carries a durable deadline at most five minutes after its first uncheckpointed mutation. Alarms persist across hibernation; the last participant's socket-close handler also checkpoints. A checkpoint first freezes its exact state/revision, restore provenance and agent origins under a stable `checkpointId` in SQLite. The mandatory `save` port acknowledges only after its authorized R2/DB/version/event commit. Errors, remote success followed by acknowledgment loss, and runtime restarts retain that same pending ID and snapshot. An alarm retries after five seconds. Acknowledgment clears only that pending generation's provenance; later dirty state is retained for another checkpoint.

L.7 must implement `save` idempotently by checkpoint ID and reconcile already-committed revisions/restore provenance. In particular, a service `restore` can mutate the room and then fail its DB save: retry the stable restore operation or pending checkpoint, preserve `artifact.restored` source-version/actor events, and never restore a second time. A plain call to the current revision-increasing service checkpoint API, without an idempotency/provenance reconciliation adapter, does **not** satisfy this port. The room fixture simulates both DB failure and lost acknowledgment; actual authorized R2/DB composition remains L.7. Blob quota enforcement is the merged L.Q service responsibility.

L.4b's durable `artifact_room_invalidations` outbox delivers `rooms.refresh(scope, participantId?)` here. Refresh is idempotent, including already closed sockets and soft-deleted artifacts: reauthorize, close revoked/deleted sockets, downgrade current roles, overwrite current identity and clear revoked agents. Membership mutations must enqueue invalidation atomically with the grant write. L.7 must install the system `retryInvalidations` sweep/queue, including pagination and retries, and coordinate current authorization with mutations or access generations. Room callbacks and outbox delivery must meet the five-second access-invalidation budget; delayed external processing cannot be repaired by claiming a fifteen-minute socket expiry is immediate revocation. No best-effort-only invalidation adapter is provided here.

## Independent review — 2026-10-27

Reviewed bounded merged implementation `4b859af2` in checkout `447fb7f72b6489e3f815acb2dfb1bcb2aea42fe4` (the room paths are unchanged). Verdict: **changes required**. The following are room defects, independent of the production adapter gates.

### High — checkpoint retries can be postponed indefinitely by activity

`schedule()` sets a pending checkpoint's retry to `Date.now() + 5000` on every call, rather than retaining the first retry deadline. Each successful mutation and agent presence heartbeat calls `schedule()`, replacing the alarm. Repro: make `save` fail, creating a durable pending checkpoint; keep editing or heartbeat agent presence more frequently than five seconds after the save recovers. Each activity moves the alarm forward, so the pending save is never retried while activity continues. This violates the five-minute checkpoint requirement even with a correct, available idempotent save adapter. Persist a retry deadline and do not postpone it on subsequent scheduling.

### Medium — later dirty activity loses its original checkpoint deadline

After a pending checkpoint succeeds, `saveCheckpoint()` sets `dirtySince = Date.now()` whenever later revisions exist. Repro: fail a checkpoint, edit again while it is pending, wait more than five minutes, then allow the pending checkpoint to succeed. The later edit remains unsaved but receives a new five-minute deadline from the acknowledgement, potentially almost ten minutes or longer after the edit. Track the first dirty time after the frozen pending revision independently and preserve it across retries and restart. A prolonged save outage itself cannot meet the deadline, but once saving recovers the room must not add another five-minute delay.

### Medium — awareness query omits active agent presence

`sendPresence()` answers standard awareness query message 3 with socket presences only; unlike initial admission and `presence()`, it never sends the persisted active agent. A client that issues a query after missing or clearing the broadcast cannot recover the agent caret/status until another heartbeat. In a temporary real-workerd fixture probe, publish the agent, clear the observer's received messages, send binary `[3]` and inspect returned awareness frames: none contains the active agent, although `presence()` reports it. Include the unexpired agent entry in the query response.

### Security and integration boundaries

The room serializes its own admission, socket messages, refresh and RPC operations and validates candidate Yjs state before durable application. SQLite consumes ticket JTIs transactionally; attachments retain credential references and unique server awareness IDs. The fixture exercises hostile updates, replay, role and expiry, hibernation, recovery, anchors, restore and revert, but its `admit` derives identity from signed claims and its `authorize` ignores credential references. It is therefore **not** evidence of real credential authentication or current credential revocation. L.7 must authenticate the request and freshly resolve the stored credential reference, and must coordinate access mutations with room authorization using a real generation/serialization mechanism; simply reading current rights before a later mutation has a TOCTOU window. Broadcasts to existing sockets do not reauthorize each recipient, so durable invalidation delivery within five seconds is also mandatory. Trusted RPC callers must authorize reads, presence, checkpoint and anchor methods at their own boundary; these methods do not accept an authenticated actor. Do not expose the room RPC surface directly to untrusted callers.

Actual R2/DB save must be idempotent by checkpoint ID and reconcile restore provenance, events and revision after ambiguous success; a bare revision-increasing service call does not fulfill this contract. L.7 must also install durable invalidation delivery and the editor control/awareness adapter. Staging hibernation remains L.10. These are required integration gates, not evidence that this bounded room has already met end-to-end security or persistence requirements.

## Controller remediation

Pending checkpoint retry deadlines are persisted and only advanced by an actual save attempt; activity scheduling reuses the stored deadline. Freezing a pending snapshot clears the first-dirty timestamp atomically, so later edits establish their own persisted deadline, which acknowledgement does not reset. Awareness query replies include unexpired stored agent presence. The real workerd fixture now verifies activity does not postpone retries, later dirty timestamps survive restart and acknowledgement, and queries recover the active agent. All fixture scenarios passed (41.89 seconds). Combined root `bun run check`, `bun run test`, and `bun run build` passed after the room fixes, shared codec and editor merge.
