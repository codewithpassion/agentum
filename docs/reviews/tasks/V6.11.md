# V6.11 review: computer and browser ports, Browser Run binding

## Verdicts

- Round 1 (7614b0b): clean after 0 fix rounds. The reviewer re-ran check, test and build, found no must-fix, and grepped `apps/web/dist/client` for `playwright` and `drizzle` with no hits.

## Decisions

- The `BROWSER` binding is `{ "binding": "BROWSER" }` in `wrangler.jsonc` at top level, in `env.staging` and in `env.staging.previews`. No `remote: true`, as the task's refinements say. `vite dev` boots with it. A local browser tool call would launch a local Chrome, which was not tried. No live Browser Run call was made anywhere.
- `@cloudflare/playwright` 1.3.5 is pinned in `apps/web`. Only `apps/web/src/server/browser-run.ts` imports it. `launch` uses `keep_alive` and `persistent: true` as agentum does. `release` closes a browser from `connect` (a disconnect) and leaves a launched one open, because Playwright's `close()` on a launched browser ends the session.
- `BrowserService.screenshot` now returns `{ bytes, entry, pageUrl }` (services lane, V6.6 code). The port needs the image bytes and the page URL, and reading them back from the library would cost a second call. The port sets no `url`: the file is in the run's task folder and the Files panel shows it.
- `Composed` gains `relay`, because the computer tools act per machine and no service owns that. `Infra.browserDriver` is optional and defaults to a driver that rejects, so every existing `composeWith` caller still works.
- The computer port keeps each agent in `${workdir}/${agentId}` on the machine (agentum's layout). File reads and writes and directory listing are built on the relay's `exec`, `file_get` and `file_put`, ported from agentum's `remote-client.ts`.
- `resolveRunComputer` (in `mcp/ports.ts`) finds the run's computer from `agents.get` and `machines.list`, so no new service method was needed. Desktop tools show only when the machine's hello says `desktop: true`.
- `run-tools-ports.test.ts` covers the wiring through the MCP server: a run gets browser tools, a run with an attached computer gets computer and desktop tools, a revoked computer drops them, a user principal gets neither.

## Nits left

- `browser-run.ts`: a launched browser is never disconnected, so its socket lasts until the request ends. If Browser Run refuses a second connection while that socket drains, the next call's `connect` fails and the service launches a second session. Watch for it in the staging check. The fix is `acquire()` then `connect()`, so `release` is always a disconnect.
- `browser-run.ts`: the package is a static import through `compose.ts`, so it initialises at Worker cold start. A dynamic import inside the driver would avoid that. It has no unit test, as in agentum.
- `service.ts` screenshot takes one extra `page.snapshot()` for the URL, so a screenshot costs three page evaluations. `page.url()` would do.
- `browser-ports.ts`: every `conflict` service error maps to `offline`, so a Playwright timeout on a bad selector tells the agent to ask the person to reconnect. The same message hits a deployment with no browser configured, which also says "retry" when retrying cannot help.
- `browser-ports.ts` drops the saved library entry, so `browser_screenshot` never returns `url`/Markdown although its description offers them. `browser-ports.test.ts` stubs the service, not the driver.
- `resolveRunComputer` runs before the MCP handler with no guard and lists all workspace machines to find one. A failed lookup fails the whole request.
- `computer-ports.ts`: `listDir` of a missing path or a file returns an empty list, not `not_found`. `wc -c` in the list script reads whole files and blocks on a FIFO until the timeout (`stat -c %s` is better). An oversized read fetches a whole first chunk only to learn the size, and still records a `computer.file` event with `bytes: 0`. Each op calls `relay.computerStatus` for `workdir`. A timed-out exec is not cancelled on the machine, because `MachineRelayPort` has no cancel.
- Agents sharing one machine are separated by directory convention only. Exec gives a full shell, so they can read each other's files. The attach rule allows one agent per computer, so in practice this does not arise.
- `BrowserPort` in `packages/mcp/src/ports.ts` says the adapter enforces public destinations through redirects and DNS. `validateUrl` does neither (a V6.6 nit).
