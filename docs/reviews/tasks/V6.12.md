# V6.12 review

Managed agents get their computer: the `desktop_screenshot` and `request_human_takeover` custom tools. Implemented by the dispatcher in b1b69b9.

## Verdicts

Round 1 at b1b69b9: clean, no must-fix.

## Nits left

- `computerOf` in `managed/service.ts` does not skip a revoked machine, and revoking a machine does not clear `agents.computerMachineId`, so a managed agent whose computer was revoked still gets the desktop tools. `cloud/runtime.ts` filters with `ne(machines.status, "revoked")`.
- `computerOf` parses the stored capabilities with an unguarded `JSON.parse` and a cast. `cloud/runtime.ts` has a zod-based `desktopOf` for the same job.
- Answering a screenshot is not idempotent. If a step fails after the image is sent and before the cursor moves (for example a later blocked call's `requests.open` throws), the retry sends a second result for the same tool use.
- When one blocked call is answered at once and another opens a request for a person, the next poll is `POLL_MS`, not `WAITING_POLL_MS`. That only polls faster once.
- `managed/types.ts` imports the `ToolResultImage` type from `gateway.ts`. The import is type-only, so there is no runtime cycle.
- A `request_human_takeover` call whose `requests.open` fails with any service error (no computer, a takeover already pending, run not running) answers with that error text instead of failing the run.

## Beyond scope

- `gateway.registerAgent` and `syncAgent` take `desktop` as optional. The managed service is the only caller and always passes it.
- A screenshot taken while a person holds the computer depends on what V6.13's `desktopScreenshot` returns (`human_in_control` should become a text result there).

## Steps for Dom

None. V6.13 passes `desktopScreenshot(machineId)` into `createManagedService` in `compose.ts`. It returns `{ ok: true, image: { data, mediaType } }` or `{ ok: false, message }`, and without it the tool answers that screenshots are not available.
