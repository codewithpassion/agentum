## Implemented consumers and boundaries

- **External document images:** the mounted document editor exposes **Image URL / Insert image URL**. `documentServices.importImage` calls the authenticated tRPC mutation, which checks current write authority before fetching and again before the existing file upload/room ownership registration. Only the resulting `/files/<id>` URL enters the editor's shared schema and ownership set. No external URL becomes scene/document content. This is URL insertion through the editor; bulk Markdown creation/import is not newly made into an external-network importer.
- Original implementation (superseded by the public-egress follow-up below) deliberately supported only HTTPS `images.unsplash.com`, `upload.wikimedia.org` and `images.pexels.com`. Caller-controlled DNS names, IP literals, arbitrary hosts, credentials, alternate ports and fragments are refused. Every redirect uses the same fixed-origin policy; at most three redirects, one ten-second total deadline, eight MiB of streamed response bytes, raster MIME allowlist and matching byte signatures. There is no general URL proxy or configurable caller-supplied host allowlist. Unsupported sources can use the existing file upload.
- **Guest deck embeds:** a distinct guest service resolves only an exact source retained in the invited deck's current accepted room state. It joins the source artifact, workspace, published version, exact path and hash, and requires the source still be a non-deleted workspace page. It returns no source catalog and constructs no member Principal. Signed read capabilities bind the deck, guest, exact grant/member row, stable session reference, source version/path/hash and expiry. Every content/subresource request rechecks the current grant/session, workspace switch, source eligibility and retained reference. Missing guest content authorization fails closed. Guest content uses `no-store, no-transform`.
- The mounted guest deck consumer uses the existing sandbox frame (`allow-scripts allow-forms`) in preview/read-only link-renderer mode, with no tool/storage/message authority. Its resolver rechecks every two seconds and removes refused content; successful rechecks retain the existing valid frame rather than reloading it every two seconds. Member embed refresh cadence is preserved.
- Guest ownership policy exposes own image URLs plus the invited deck's retained embed identities, rather than all workspace source identities. The guest client fetches only `/files/` entries as image blobs. This avoids interpreting an embed identity as an image URL during guest startup.
- **Discovery:** the authenticated discovery endpoint uses bounded keyset pages; the actual member deck service walks every page and combines discovered sources with retained ownership policy. Cursor advancement uses raw rows before filtering so an ineligible HTML-like filename cannot hide later eligible files. The existing exact contextual room admission, retained-element checks and cold recovery from `2188a62b` are unchanged.

## R1.9 public HTTPS transport follow-up

The three-host restriction is removed in `2e716c34`; it was not approved product scope. The mounted Image URL control and authenticated insertion/storage path now accept broader public HTTPS sources, including redirects between unrelated public hosts, under the existing raster type/byte limits. ### Authoritative transport evidence and repository primitives

- Cloudflare documents that [`global_fetch_strictly_public`](https://developers.cloudflare.com/workers/configuration/compatibility-flags/#global-fetch-strictly-public) sends same-zone requests through the public front door; without it, same-zone fetches can go straight to the origin and bypass Cloudflare security. The parent app has no such flag, so using its ordinary `fetch` after removing the allowlist would be insufficient.
- Cloudflare's [bindings/security explanation](https://blog.cloudflare.com/workers-environment-live-object-bindings/) describes the private-origin SSRF exception and the public-internet boundary. The [workerd network configuration](https://github.com/cloudflare/workerd/blob/main/src/workerd/server/workerd.capnp) specifies the default internet service as `allow = ["public"]` and states that DNS-resolved addresses are filtered by that transport policy. This is the connection's address check, not an application DNS preflight that could race a later lookup.
- The [Worker Loader API](https://developers.cloudflare.com/dynamic-workers/api-reference/) supports per-Worker compatibility flags and isolated bindings, and documents that omitted `globalOutbound` inherits the parent's network capability. This parent Worker uses ordinary native public internet outbound; the image adapter must not be transplanted under a private-network/proxy `globalOutbound`. No VPC binding, external-server binding, credential proxy or parent environment is supplied to the image Worker.
- Repository inspection: `connectors/safe-url.ts` and `web-fetch/guard.ts` provide useful lexical protocol/IP/name checks, but do not pin DNS/connection addresses. `web-fetch.ts`, `secrets-outbound-core.ts` and `app-gateway/app-outbound-core.ts` handle URL/host policy, redirects and credential injection, not a stronger public-peer transport. None was treated as DNS rebinding protection. The image path reuses only the shared lexical URL check; it deliberately does not use the secret-injecting egress paths.
- Cloudflare's [`resolveOverride` contract](https://developers.cloudflare.com/workers/runtime-apis/request/) is limited by zone/hostname restrictions, so it is not a general mechanism for pinning a caller-supplied public URL to an application-validated IP while preserving TLS identity. No DNS-preflight/second-resolution workaround was added.

### Implemented boundary

`public-image-fetch.ts` loads a small fixed-code image-only Worker using the existing LOADER binding. Only that Worker receives `global_fetch_strictly_public`; the parent app, guest restricted runtime and agent runtimes are unchanged. It receives an empty environment, no secrets or private service bindings, and one subrequest per invocation. Its native HTTPS fetch verifies TLS through the platform and cannot accept caller `cf`/Host/TLS overrides. A cached immutable code identity is used; future code/config changes must bump that identity.

The adapter reconstructs both sides of the service-bound request. Only GET, a fixed raster Accept header and deadline/cancellation state reach the external request. Caller Cookie, Authorization, Referer, proxy headers, body and arbitrary fetch options are discarded. The internal absolute deadline header is consumed by the image Worker and never forwarded. HTTPS, absent userinfo/default port, internal host names, IPv4/IPv6 literal variants and every redirect target are checked at the service layer. Public-address enforcement for DNS results occurs in the runtime network transport. Redirect following is disabled both on the Worker stub and the native external fetch; the authenticated service alone follows at most three checked redirects.

One ten-second deadline covers the whole redirect chain, including Worker loading and streaming. Each image Worker receives the same absolute deadline and independently enforces its remaining time, as well as observing request cancellation; an earlier caller deadline does not silently become a fresh ten-second budget on every hop. Eight MiB is counted on streamed response bytes, and declared raster MIME must match the supported PNG/JPEG/GIF/WebP/AVIF signature. SVG/HTML, invalid signatures, oversize bodies and stalled bodies are refused. Existing write authorization before network I/O and reauthorization before upload/ownership registration are preserved. Only the acknowledged owned blob URL enters shared document state.
