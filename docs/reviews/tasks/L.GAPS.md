# L.GAPS — image ingestion, guest embeds and complete discovery

Implementation on 2026-10-28 against the three unassigned gaps in `L.A.md` and live-artifacts PRD R1.9/R4.5. This file records local implementation evidence, not all-phase or deployed acceptance. The initial checkout did not contain this review file.

## Implemented consumers and boundaries

- **External document images:** the mounted document editor exposes **Image URL / Insert image URL**. `documentServices.importImage` calls the authenticated tRPC mutation, which checks current write authority before fetching and again before the existing file upload/room ownership registration. Only the resulting `/files/<id>` URL enters the editor's shared schema and ownership set. No external URL becomes scene/document content. This is URL insertion through the editor; bulk Markdown creation/import is not newly made into an external-network importer.
- External ingestion deliberately supports only HTTPS `images.unsplash.com`, `upload.wikimedia.org` and `images.pexels.com`. Caller-controlled DNS names, IP literals, arbitrary hosts, credentials, alternate ports and fragments are refused. Every redirect uses the same fixed-origin policy; at most three redirects, one ten-second total deadline, eight MiB of streamed response bytes, raster MIME allowlist and matching byte signatures. There is no general URL proxy or configurable caller-supplied host allowlist. Unsupported sources can use the existing file upload.
- **Guest deck embeds:** a distinct guest service resolves only an exact source retained in the invited deck's current accepted room state. It joins the source artifact, workspace, published version, exact path and hash, and requires the source still be a non-deleted workspace page. It returns no source catalog and constructs no member Principal. Signed read capabilities bind the deck, guest, exact grant/member row, stable session reference, source version/path/hash and expiry. Every content/subresource request rechecks the current grant/session, workspace switch, source eligibility and retained reference. Missing guest content authorization fails closed. Guest content uses `no-store, no-transform`.
- The mounted guest deck consumer uses the existing sandbox frame (`allow-scripts allow-forms`) in preview/read-only link-renderer mode, with no tool/storage/message authority. Its resolver rechecks every two seconds and removes refused content; successful rechecks retain the existing valid frame rather than reloading it every two seconds. Member embed refresh cadence is preserved.
- Guest ownership policy exposes own image URLs plus the invited deck's retained embed identities, rather than all workspace source identities. The guest client fetches only `/files/` entries as image blobs. This avoids interpreting an embed identity as an image URL during guest startup.
- **Discovery:** the authenticated discovery endpoint uses bounded keyset pages; the actual member deck service walks every page and combines discovered sources with retained ownership policy. Cursor advancement uses raw rows before filtering so an ineligible HTML-like filename cannot hide later eligible files. The existing exact contextual room admission, retained-element checks and cold recovery from `2188a62b` are unchanged.
