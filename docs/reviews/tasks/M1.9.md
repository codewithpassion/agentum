# M1.9 review

## Verdicts

Round 0, commit d244c90: clean, nine nits. No fix round was needed. One nit (the locale one) was fixed afterwards, see below.

## Decisions

- Multi-user file transfer goes through sudo as hm-agent. The sudoers rule gains four commands next to M1.4's `mkdir` and `rm`: `/usr/bin/dd` (writes stdin to a file), `/usr/bin/realpath`, `/usr/bin/stat` and `/usr/bin/head` (vet and read a file). They add no privilege, since Claude Code already runs arbitrary commands as hm-agent. They all run as hm-agent, which cannot read the daemon's config, so the config stays out of reach. `install-service` writes the rule, as before.
- `work-files.ts` holds both ways to reach the work directory behind one `WorkFiles` interface (`write`, `resolveOutbound`, `read`). `run-files.ts` and the executor no longer know which mode they run in. The single-user implementation is the old `node:fs` code, and its `write` now also refuses a path outside the work directory.
- Input files: `mkdir -p <dir>`, then `dd of=<file> status=none` with the bytes on stdin. `prepareWorkDir` now empties `inbox/` in multi-user mode too.
- Attachments: a marker path is checked lexically against the work directory first, so a plain `/etc/passwd` costs no sudo call. Then `realpath -e` resolves symlinks and the result must sit inside the real work directory, then `stat -c "%s %f"` gives size and raw mode (regular file, at most 50 MB), then `head -c <size>` reads the bytes.
- `CommandRunner` takes an optional stdin and `CommandResult` carries optional `stdoutBytes`, for binary output.
- The M1.6 "not supported yet" failure and refusal are gone.
- Fixed after the review: `stat %F` prints a translated type name, and sudo passes `LANG` through, so a non-English host would have refused every attachment. The code now reads the raw mode (`%f`) and checks the file type bits.

## Checks

`bun run check && bun run test && bun run build` pass. Daemon tests cover the exact argv for writing an input file (`mkdir`, `dd` with stdin) and for reading an attachment (`realpath` twice, `stat`, `head`), a path outside the work directory refused on both without a sudo call, a symlink that escapes refused after `realpath`, a directory, an oversize file, and a missing file. Executor tests run a multi-user run end to end against a fake runner. The M1.6 file tests pass unchanged for single-user.

The live part was not run: this box has no sudo and no hm-agent.

## Nits left

- `realpath` output is trimmed, so a name ending in whitespace is reported as missing. `realpath -z` would fix it. `work-files.ts`.
- A swap of a symlink between the `realpath`/`stat` checks and `head` is possible. It reaches only what hm-agent can read.
- `read` trusts any `OutboundFile` it is given. Only `resolveOutbound` feeds it today.
- `read` falls back to the text of stdout when a runner has no `stdoutBytes`. Only test fakes lack it.
- A multi-user read holds up to 50 MB in memory and does not stop on an abort.
- `dd` copies in 512-byte blocks. `bs=1M` would be faster for big inputs.
- The new commands use `/usr/bin/...` and `mkdir`/`rm` use `/bin/...`. A system without merged `/usr` could miss `/usr/bin/dd`.
- Missing sudo permission (an old rule) shows up as a `missing` attachment note, not as a sudo error. Input files fail with the sudo message.

## Ideas beyond the scope

- Stream input files to disk and attachments from disk, so large files do not sit in memory, on both modes.
- Have `enroll` or the daemon check at start that the sudoers rule has the new commands, and say "run install-service again" if not.
