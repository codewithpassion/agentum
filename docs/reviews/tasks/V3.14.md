## Findings (nothing fixed, none over the 50-line bar looked like a wiring gap)

- The mock's draft has `research` reserved and "Where it runs" flagged. The live builder slugs the name (`researcher`), and flags the runtime only when the model leaves it open or invalid. A description that says nothing about it gets a runtime chosen for it (Cloudflare, no flag). Worth a decision whether the builder should always leave the runtime to the person.
- The voice chip reads "Careful", the mock says "Careful, cites sources".
- Voice edits on the profile save only through the Save button that appears when the field is dirty. Leaving the field does not save, and nothing says so.
- Tools on the draft stay empty because the workspace has no web search connector. The mock's "Web search, Browser" chips have nothing to pick. The dry run still fetched pages with the built-in fetch.
- The dry run holds back `harbourmaster/bash` even for a read-only `ls`, and `Read` on a directory returns EISDIR. Both come from the agent's own choices, but the first costs the dry run some of its reads.
- The profile's Hands to row stays empty after Create even though the description says "ask Bookkeeper", and no agent named bookkeeper exists in this workspace.
