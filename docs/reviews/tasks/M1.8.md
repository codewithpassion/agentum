# M1.8 review

## Verdicts

Round 0, commit 77b820c: clean, with three nits. No fix round was needed.

## Decisions

- `completeRun` with `aborted` on a running run goes through one function, `abortedCompletion`, which keeps `completeRun` under the complexity limit. It does one conditional write (`WHERE id = ? AND status = 'running'`) that sets `interrupted`, `finished_at`, `process_ended_at` and `error = "Aborted by the machine"`, then appends `run.interrupted` with the caller's actor. A lost race gets 409. An interrupted run keeps the old path.
- The comment in `apps/daemon/src/run.ts` now says what happens. No daemon logic changed.

## Checks

`bun run check && bun run test && bun run build` pass. New tests: the service test in `packages/services/src/runs/machine-claim.test.ts` (machine A interrupts, repeat gets conflict, machine B is forbidden and the run stays running) and `apps/web/src/server/routes/runs-machine.test.ts` (run token refused by the resolver, next run of the agent claimable at once).

Live, on this box in `single_user` mode, against `vite dev` on port 3187 and the compiled daemon with its own HOME: an agent ran `sleep 60` through Bash, the daemon got SIGTERM while the tool call was active, and within 4 s the row was `interrupted` with `error` "Aborted by the machine" and `process_ended_at` set. In the browser, the chat for that session showed "Interrupted", Retry enabled and Send enabled once text was typed.
