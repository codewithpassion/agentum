# V5.9 review: Mail on the agent profile

## Verdicts

Round 1 (cfdd681): not clean, one must-fix. The Mail list fired up to 30 `thread` queries, each reading the mailbox Durable Object, and threads past 30 got no chips. Fixed in f9c9b7b: the `threads` service now returns `messageCount`, `lastDirection` and `lastStatus` per thread, and the list reads those.

Round 2 (f9c9b7b, fix commit only): clean.

## What changed in services

Two small service changes, both with tests, because the profile could not read this state otherwise. `mail.get` returns `triggerDisabledAt`, since `triggers.list` only returns http triggers and the profile never sees the mail trigger. `mail.threads` returns the message count and the newest message's direction and status.

The mail tRPC router is merged flat, so the calls are `getTrpc().mailbox.get`, `setTrigger`, `threads` and `thread`, with no `mail.` prefix.

## Nits left

- `threads` loads every message row of the agent's threads, without a limit, and groups them in JS (inbound.ts). A `max`/`groupBy` subquery would return one row per thread. Ties on `createdAt` pick the newest by row order.
- The "Mail to" switch shows for `failed` and `provisioning` mailboxes. It is hidden only when disabled.
- The header shows no chip while the mailbox is active.
- The Email channel chip opens the Mail sheet even with no address yet.
- `?mail=<threadId>` opens any thread of the workspace under this agent's page, without checking it belongs to this agent.
- A held message shows a fixed approval note, not a link to the approval request (`requestId`).
- Duplicated tone-to-class maps, two `CHIP_CLASS` exports and three `errorMessage` copies in the new files.

## Beyond scope

- Approve or deny a held message from the thread view.
- Reply from the thread view.

## Steps for Dom

None. Mail routing still needs the Cloudflare Email Routing token for a real address to go active, as in V5.3.
