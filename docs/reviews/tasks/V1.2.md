# V1.2 review: the waiting run state

## Verdicts

Round 1 (c69bf59): not clean. Two must-fix findings in scope, two more outside it.
Round 2 (9caa3f8, the fix commit only): clean.

## Fixed after round 1

- The Slack `run.waiting` and `run.resumed` labels were dropped by the 5 s status interval. They now skip it.
- `markRunning` reset a cloud or managed run's 10 minute lease to 90 s. It now uses the agent runtime's own lease.

## Nits left

- `stopOnRepeat` still needs `running`, so a waiting run is never repeat-stopped. Intended, since a waiting run makes no calls.
- `markRunning` revives a waiting run whose lease passed but which the reaper has not swept yet.
- Conflict messages read "Run is waiting, not running" where a waiting run is refused.
- The `["running", "waiting"]` literal repeats in `managed/service.ts`, `runs/machine-claim.ts`, `run-tokens.ts`; `LIVE` in `runs.ts` is not exported.
- No tests for the refinement items: `refuseBusyAncestor` with a waiting ancestor, the managed per-session sibling check, `otherRunActive` in sessions, a session token while waiting, and the managed lease entry of `markRunning`.
- `markRunning` calls `adapterFor` only for the agent's runtime.

## Beyond the scope

- `apps/web/src/components/agent/chat/chat-logic.ts:27-28,73`: `isRunActive` leaves out `waiting`, so a waiting run cannot be cancelled in chat, polling stops, the composer unblocks, and `statusLine` shows "Interrupted…". V1.6 owns this file and should add `waiting`.
- `managed/service.ts` `rearm` (~1106) wakes only `running` managed runs. V1.11 needs `waiting` there.
- `apps/web/src/server/pi-run.ts:254` and `pi-run-core.ts:409` treat only `running` as claimable or retryable. V1.10 covers them.

## Steps for Dom

None. Nothing calls `markWaiting` or `markRunning` yet; V1.5 does.
