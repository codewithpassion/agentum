## Nits left

- `agents.ts` address check allows leading, trailing and doubled dots (".ab", "a..b", "ab."). That matches the spec wording, but these are not valid email local parts.
- `agentActivateSchema` defaults `runtimeConfig` to `{}`, so activating without it wipes the draft's config. Falling back to the draft's own config would be safer.
- The draft insert retries on a unique violation without a cap.
- `reserveAddress` accepts an archived agent, including a discarded draft.
- `checkAddress` reports an agent's own current address as unavailable, though reserving it again succeeds.
- `discardDraft` returns success for any archived agent, including one that was active before.
- `archive` on a draft returns it unchanged without archiving, so callers must use `discardDraft`.
- `desk.test.ts` does not cover the new draft filters for proposed triggers, proposed routines and answered threads.

## Ideas beyond scope

- Tighten the address syntax before V5 mailbox work so only deliverable local parts get reserved.
- `activate` and `reserveAddress` write the row and then the event without `atomic`, like `create`, `update` and `archive` already do in this service. One pass could move them all onto `atomic`.
