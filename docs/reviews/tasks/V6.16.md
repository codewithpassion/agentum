## Gap fixed

The README's desktop `docker run` uses `--cap-drop ALL`. On this host Chromium's sandbox then aborts at `sys_chroot` (`Check failed: sys_chroot("/proc/self/fdinfo/") == 0`), and the daemon reported "the desktop is not available to agents". The cause is `packaging/desktop/seccomp.json`: its `chroot` allow rule applies only to a container holding `CAP_SYS_CHROOT`, so dropping every capability blocks the call on any host. Adding `--cap-add SYS_CHROOT` fixes it, with the other documented flags kept. `apps/computer/README.md` now has the flag and a sentence on why. `--cap-drop ALL` is untested by `test-desktop-image.sh`, which runs with Docker's default capabilities (V6.3 nit), which is how this got through.
