# V2.6 review

Implemented by Codex in two commits (tests first, then `packages/protocol/src/thread.ts`), reviewed by Opus.

## Verdicts
- Round 1 at d457913: not clean. One must-fix: `addReasoning` put a later turn's reasoning above an earlier turn's text and tool calls. Fixed in 69b7f7f, which also keeps a settled request card settled when a late `pending` frame or a different closing status arrives.
- Round 2 at 69b7f7f: clean.

## Nits left
- A late `pending` request frame still moves a `running` message to `waiting` even when the card is already answered (`thread.ts` request branch of `applyAssistantFrame`).
- `applyFrame` copies the `seen` set, cursors and message array per frame, so `foldThread` over a long session is O(n^2).
- `seen` keeps every event id for the life of the list.
- Fold state hangs on a symbol property of the returned array. Spreading, `structuredClone` or serialising the list drops replay protection. V2.12 must keep the same array between frames.
- Late-delta detection remembers only the last finished key per run, so it relies on V1 sending keys in order.
- `requestPart` drops `toolName` from `request.opened`.
- A delta ending in a half-written `[ATTACHMENT:` marker shows as raw text until the stored message replaces it (the old chat does the same).
- A runless event gets the id `"runless"` when it has no event id. This cannot happen today.

## Beyond the scope
- Keep the fold state in the external store instead of a hidden property once V2.12 shows what it needs.
