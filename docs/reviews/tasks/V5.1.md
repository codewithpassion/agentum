## What changed

Migration 0019 adds `agent_mailboxes`, `mail_threads` and `mail_messages` (`packages/db/src/schema/mail.ts`), with the column names and foreign keys from the task's refinements. `mail_messages` also carries `rfc_message_id`, filled for outbound rows so a bounce that names the original RFC `Message-ID` can find them. Messages are unique per thread and external message id, so V5.4's upsert on a duplicate delivery has a key. There is no `task_id` and no backfill.

`packages/db/src/shared.ts` gains the `mail` trigger kind, the mailbox and message status enums, `MAIL_DIRECTIONS`, the eight `mail.*` and `mailbox.*` event types, `MAIL_SEND_TOOL` and `mailToolKey`. The session origin `mail` is left to V5.4, as the refinements say.

`packages/services/src/mail/types.ts` defines `MailboxPort`, `EmailRoutingPort`, the inbound and outbound shapes from the V5.2 decision, `MailError`, and the inside and outside rule as a doc comment. It has an `exports` subpath, `@repo/services/mail/types`. `packages/mcp/src/ports.ts` is untouched, as the refinements say.

## Beyond the scope

- `mail_messages` has no mailbox column. A list by mailbox goes through `mail_threads.mailbox_id`. If V5.3 or V5.10 needs a direct index, add it then.
- The unique index on `(thread_id, external_message_id)` means a duplicate delivery must resolve its thread first. `mail.receive` already does.
