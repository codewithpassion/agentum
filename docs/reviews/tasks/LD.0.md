# LD.0 work in progress

`@repo/live-deck` is an isolated prototype, not phase 2 acceptance. `Deck` stores slide IDs in a Y.Map, uses fractional order keys, and keeps element style and property keys in separate shared maps. `read` returns a scene snapshot and opaque canonical revisions. `write` accepts the observed snapshot and a constrained XML-shaped HTML slide, compares the proposed changes against that snapshot, and skips elements changed in the current scene. It must be called on the authoritative, synchronized room document; an offline replica cannot detect updates it has not received. Observations must be retained server-side, not trusted from an agent.

`RichTextCodec` is mandatory. L.2 integration must provide a DOM-free implementation backed by the shared schema, strictly validate paragraphs, lists, inline marks and safe links on both parse and serialize, reject unknown nodes and attributes with paths, and convert to/from the supplied Y.XmlFragment. The codec is a trusted security boundary; the minimal codec in the tests is not production code. The XML-shaped interchange uses explicit closing tags and a narrow set of attributes; it is not a general HTML parser. Slide HTML must never be rendered directly.

Remaining work before this slice is complete: implement and validate theme and sections, table cell fragments, full slide/element operations and restoration validation; extend path reporting into rich text; enforce theme font membership and all limits under concurrent mutations; audit revision guards against changes reverted to their original value and against forged observations; and complete hostile input and concurrency coverage. In particular the present value-based revisions do not detect a human edit subsequently reverted, so they do not yet meet R2.4. Direct Yjs updates are not validated by this package and need an authoritative validation boundary before application. Do not integrate this prototype as a trusted production boundary.

Dependencies: Yjs and fractional-indexing use MIT licences, and saxes uses ISC. See their upstream repositories: https://github.com/yjs/yjs, https://github.com/rocicorp/fractional-indexing, https://github.com/lddubeau/saxes. Earlier phases and L.2 integration remain gates.
