## Contract and behavior

- `LiveSuggestion` in `@repo/protocol/live`: stable id (trusted tool call changeId), kind, immutable origin/run/tool-call attribution, author name, creation time, inert preview text, base revision, pending/accepted/rejected/conflict, deciding participant/time, applied revision, explicit conflict diagnostic.
- Member tRPC `liveArtifacts.suggestions({artifactId})`, `setSuggestionMode({artifactId,enabled})`, `decideSuggestion({artifactId,suggestionId,decision:'accept'|'reject'})` return `{mode:boolean,items:LiveSuggestion[]}`. Service performs current access checks; real composition registers the authenticated actor and calls the authoritative room. Mode is an explicit artifact-wide choice for member-triggered agent edits, writable by current member editors. Mode persists across restart.
- Room `listSuggestions(subject)`, `setSuggestionMode(enabled,subject)`, `decideSuggestion(input,subject)`. Decisions require a currently authorized human editor/owner; agents cannot decide. Current guest editors may decide; viewers/commenters cannot. Access fences and the existing room exclusive queue serialize access mutations, browser edits and decisions. Already decided records return the same winner after fresh authorization.
- Guest HTTP `GET /api/guest/artifacts/:artifactId/suggestions`, `POST .../decide-suggestion` with `{suggestionId,decision}`. Existing rotating cookie/session and CSRF route checks apply. Private `guestSuggestions(sessionToken,decision?)` resolves the scoped current session and registers an opaque credential; serialized room authorization checks it again. Guest UI lane owns `/g` mounting.
- `RoomIdentity.forceSuggestions` is derived from persisted `runs.actorKind === 'guest'` in the run or its persisted ancestry, through the authenticated service identity and fresh room authorizer. It never comes from model/caller mode. The room normalizes mode on both document and deck agent operations, overriding a direct request. Guest runtime lane must preserve this field when integrating its dedicated scoped identity adapter. Current baseline rejects guest runtime paths without that adapter; this change does not enable unrestricted runtime execution.
- MCP document/deck edits return suggestion id/status when staged; document tool text explicitly says accepted content is unchanged. Pending suggestions neither enter accepted Yjs content, revision, checkpoints, export nor accepted change history.
- Document proposals validate with the real core on a disposable replica and retain guarded operations. Acceptance replays guards against the current room, rechecks current blob policy and active comment anchors, and commits only the resulting delta. Unrelated human work remains. Invalidated target guards become terminal conflicts, requiring a fresh proposal.
- Deck proposals use the actual DeckSceneAdapter/core observations to prepare a selective delta without committing it. The prepared delta and preview persist. Acceptance requires exactly the same accepted room revision; any intervening edit/restore produces an explicit conflict. This deliberately conservative policy works across restart without fabricating opaque core observations or overwriting a snapshot. Blob/embed policy is rechecked by existing commitDeck validation; bounded accepted embed retention is unchanged.
- Accepted content, status, selective origin/revert data and checkpoint provenance persist in the same room transaction. Rejection updates only the suggestion. Checkpoint retries retain existing trusted frozen provenance. Raw agent socket writes and noncanonical agent snapshot fallback are disabled, closing paths which cannot stage guarded suggestions.
- Mounted member document/deck collaboration sheets share `Suggestions`: exposed mode checkbox, attribution/status, expandable inert-text preview and individual accept/reject controls. Existing mobile sheets retain this panel. Human guest editor operations remain direct.
