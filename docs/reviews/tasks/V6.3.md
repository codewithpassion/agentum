# V6.3 review

## Scope note

The Dockerfiles and `apps/computer/scripts/test-desktop-image.sh` came in with V6.2. V6.3 added `.github/workflows/computer.yml` (`workflow_dispatch` only, lowercased owner in the image names, `latest` and commit tags) and the README "Docker" section in `apps/computer/README.md`.

Local checks: both images build, `scripts/test-desktop-image.sh` passes (screenshot colour test included), `bun run check && bun run test && bun run build` pass. Nothing was published to ghcr.

## Verdicts

- Round 1 (bc007ee): not clean. One must-fix: the README recommended `--code-stdin` for a detached container, which exits on empty stdin.
- Round 2 (d4321cf, fix only): clean.

## Nits left

- Workflow passes no `VERSION` build arg, so published binaries report `0.0.0-docker`.
- Workflow sets no `platforms:`, so only amd64 is published although the base images are multi-arch.
- Actions are pinned by tag, not commit sha, as in `ci.yml`.
- README commands set no `--hostname`, so the computer enrols under a random container hostname.
- `test-desktop-image.sh` does not run the exact documented flag set (`--cap-drop ALL`, `no-new-privileges`, `--shm-size`).
- Two README lines run past the usual wrap width, and the seccomp download wording is clumsy.

## Ideas beyond scope

- Publish `seccomp.json` inside the desktop image or as a release asset so ghcr users need no checkout.
- Add a `--name` example so a container enrols with a readable name.
