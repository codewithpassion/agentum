## Nits left

- `managed-poller-core.ts` `kick`: a kick that lands while an `alarm` handler waits on `step` is overwritten by the handler's closing `setAlarm`, and a `next === null` result drops it. The window is narrow. V1.11 should know when it relies on `resume` cutting the wait short.
- `machine-runs.ts` wait route ignores the `:runId` path segment. A request id from another run of the same machine is served, because the service checks machine and workspace only.
- `machine-runs.ts` create route drops the daemon's `display.summary` and `display.toolName`. The service rebuilds the summary, and nothing checks that `display.toolName` matches `toolName`.
- `MS_PER_SECOND` sits between the status constants in `machine-runs.ts`.
- No test covers an answer arriving during a long poll.
