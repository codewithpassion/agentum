# V1.16 review: Pi durability end-to-end check

## Cause

`bun run e2e:pi-durability` failed with the model answering `"echo: "`. The app was wrong, not the check or the faux model. pi-durable writes a system entry that removes and re-declares every tool when the tool order wanted at prompt time differs from the order replayed from the transcript. That entry landed after the user message or the interrupted tool result, so the scripted model, which reads the last message, saw no prompt.

Two places changed the order:

- `installEnvironmentTools` uninstalled `web_fetch` and `run_script` before reinstalling them, which moved them behind the connector and skill tools on every run start (since C.15 and C.17).
- The `PiRun` harness callback installed the connector tools before the environment tools, the reverse of a fresh start, so every eviction reordered them.

The fix keeps a staying extension in place and installs the environment before the connectors. In production the old code also re-declared 45 tools on every run, which invalidates the prompt cache.

The check itself is unchanged. A unit test in `environment-tools.test.ts` pins the in-place reinstall.

## Rounds

Round 1 at fe73969: clean.

## Nits left

- A connector added in a later run of a session lands after the skill tools, while a rebuild after eviction puts all connectors before them. The first prompt after that eviction gets a remove-all entry (`pi-run.ts`, `#installTools` and the harness callback).
- A session whose agent switches environment between runs appends the library or VM extension at the end, and a rebuild puts it near the front (`environment-tools.ts`, `pi-run.ts` `#selectEnvironment`).
- No test pins "fresh install order equals rebuilt order" at the `PiRun` level.
- `pi-run-faux.ts` reads only the last message, so any legitimate mid-session system patch makes it answer `"echo: "`.

## Ideas beyond the scope

- Fix the install order in code (environment, connectors, skills) and make it independent of history, with the install sequence in one pure function that the harness callback and the start path share, so `bun test` can cover it.
- Add an e2e assertion that no entry with `toolsRemoved` follows an eviction, then let the faux model read the last non-system message.
