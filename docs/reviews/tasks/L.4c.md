## API and factory composition

`@repo/services/live-artifacts/factory` exports `createLiveArtifactsWithAsk(deps)`. Pass all core dependencies except `ask`, plus the real `RunsService` as `runs`, and required `presence` and `resolveMember` ports. The factory constructs `createLiveAskService` first and passes its real `startComment` implementation to core/comments as `LiveAskPort`. There is no circular initialization, late mutable service reference, optional ask dependency, or no-op production fallback. Alternatively construct `createLiveAskService` yourself, then `createLiveArtifactsService({ ...coreDeps, ask: asks })`.

L.7 should build RunsService first, then this factory, put the resulting service in its request services, and mount `createLiveArtifactsRouter(ctx => ctx.services.liveArtifacts)` from `apps/web/src/server/trpc/live-artifacts-router.ts`. This slice deliberately changes neither `compose.ts`, the root router, bindings, room implementation, engine, nor guest authentication.

Required trusted ports:

- `presence({ workspaceId, artifactId }, authenticatedMember)` reads that sender's current authorized awareness and returns `{ where?, present }`. Bind selection/location to that authenticated sender, resolve participant identities/names/roles against current admission, and return the full authorized roster including agents. Do not copy raw client awareness claims into this port. A selection ask is refused without a current server-resolved selection. The browser input accepts no presence, selection, author, name, role, roster, workspace or session override.
- `identity(member)` resolves the member's safe directory name; the core access layer supplies the current DB-derived artifact role. `buildSpeakerEnvelope` receives authenticated actor, this identity/role, trusted room metadata, and the person's words. Artifact id/title/kind and comment thread are derived from authorized persisted records. Rechecking access after room/directory IO prevents an earlier editor role from being used after downgrade. Every queued run keeps its own actor and `onBehalfOfUserId` and already serialized envelope.
- `resolveMember(scope, originalUserId)` returns a freshly authenticated/current workspace member principal with current admin and credential restrictions, or null. The durable processor verifies workspace/user matches and rechecks current artifact rights. It never reconstructs a privileged principal from an outbox role snapshot. Revoked users and failed deliveries remain pending and cannot start new work.

Member methods added to the full service:

- `ask(principal, { artifactId, text, via: 'artifact_thread' | 'ask_agent', agentId? })` starts one run with `runs.startRun`. Only explicit authenticated members with commenter/editor/owner rights may ask. Agents must be active in the same workspace; the current workspace run authorization applies. Viewer/read-only credentials cannot start work. Missing/hidden artifacts use `not_found`.
- `selectAgent(principal, { artifactId, agentId })` selects a runnable agent without starting a run. It creates the shared session if needed; further switches preserve its id and transcript. Initial default is handed-to agent, then creating agent. Once selected, the session stores the current choice. A member-created artifact with neither default requires selection first.
- `session(principal, { artifactId })` rereads current access, including viewer access, and returns the shared session's public record or null before it exists. No machine runtime reference is exposed.
- `retryCommentAsk(principal, { artifactId, threadId, commentId })` retries only the original member author's addressed, persisted comment with its dispatch intent. It rereads body/thread/workspace/author rather than trusting retry text. Another author's or another artifact's identifiers are refused.

The router factory exposes these plus all core/comments/changes member methods: createDocument, convertDoc, join, checkpoint, restore, setAudience, remove, invalidateAccess, comment, threads, resolve, answered, recordChange, changes and revertChange. Every input is strict and bounded. Checkpoint transports bytes as a JSON integer array and validates/transforms them to Uint8Array before the service call. Admission, startComment and system recovery processors are infrastructure APIs, never browser routes. No guest route/start is mounted or enabled.

## Shared session, continuation and run rights

The previous uniqueness tuple included agentId. Migration `0028_chemical_sinister_six.sql` adds `sessions_artifact_unique`, a partial unique index on workspaceId/externalKey for origin artifact. Non-artifact sessions keep their existing key and actor rules. Concurrent first asks with different agents race on this real DB constraint and reuse the winning session. Key and trusted-id lookup allow the selected agent to change only for artifact sessions, with current artifact authorization on direct and continuation starts; explicit artifact continuations must match the supplied artifact key. Artifact sessions are never actor-private.

The session's agentId is the current selection; each run keeps its actual selected agent and asker. System and machine claims serialize by session as well as agent, preserving order across switches. Queue continuation/expiry checks account for both. Switching agents clears incompatible machine/runtime continuation references; an older agent's completion cannot overwrite the newly selected agent's runtime reference. Session visibility permits a run's existing artifact-session association while still enforcing current asking-user membership. Reads/waits and private/same-workspace checks remain in force. Core edit rights in an artifact-session run are capped by its current asking member's role, so a commenter ask cannot gain document edit rights merely through the agent. The changes module's session-parent check accommodates this shared-session association; controller CAS finalization and original-room-actor handling remain intact.

## Durable addressed-comment handoff

Migration `0028_chemical_sinister_six.sql` also adds only `artifact_ask_dispatches`, with unique commentId, unique workspace/author/caller requestId, and pending index. No guest tables, existing table rebuilds or event triggers are changed. Generated snapshot and journal accompany it. A parallel guest migration may need numbering/meta reconciliation by the controller; this branch does not modify guest schemas.

`comment(..., { toAgent: true, requestId, ... })` requires a nonblank stable caller requestId. Thread/comment/event/dispatch intent commit in the SAME atomic transaction before any dispatch. Ordinary comments/replies create no dispatch intent and start no run. An external retry submits the same original requestId/body/artifact and receives the original comment, even after a lost response. A reused key with different body/artifact conflicts. Concurrent identical requests produce one thread/comment/event/intent.

`startComment` loads and validates the stored addressed comment and original author, uses persisted body and `requestId = 'live-comment:' + commentId` with RunsService's unique workspace request index, then acknowledges the outbox only after a durable run exists. A crash before dispatch, run failure, lost run response or failed acknowledgement leaves the intent pending. A replay reads the original run and acknowledges it without dispatching another run, including after service recreation and agent-selection changes. Successful runs awaiting an answer are not mistaken for undelivered work; inbox state is separate from delivery state.

L.7 must durably schedule/drain `retryDispatches({ kind: 'system' }, { limit?, cursor? })`, not rely solely on best-effort waitUntil. It returns `{ attempted, completed, next? }`, default 50/max 100. Follow `next` within a processing sweep, then restart without a cursor on the next sweep; failed early rows do not starve later work. Each attempt resolves the original current member and independently leaves failures pending. RunsService's existing durable queued-run processor covers a crash after run commit but before runtime dispatch. Room awareness still comes through the trusted current port on a previously undispatched retry. Port errors propagate on direct asks/comments; processor failures are represented by attempted versus completed and retained pending rows.

## Independent review — 2026-10-27

Reviewed merged implementation `4aeb361b` (checkout `d51145ccd38e9c2030b168e21bc18230b5287f74`; no differences in the reviewed service, run, session, DB or router paths). Verdict: **changes required before relying on artifact-session run authorization**.

### High — an artifact-session run can edit another private artifact using the agent's rights

`packages/services/src/live-artifacts/access.ts` applies the asker's current role only when the target is the session's own artifact (or the run has `scopeArtifactId`). For any other target, `runRole` falls through to `agentCanSee`/`agentCanUpdate`, which authorize a private artifact made by or handed to the agent without checking the asking user's access. Member artifact runs do not set `scopeArtifactId`. This lets a commenter on artifact A cause the same run to read or edit private artifact B that the commenter cannot open, if B was handed to the agent. It also bypasses the commenter's edit ceiling on B. This is a service authorization issue, not dependent on guest enablement or router mounting.

Reproducer: with the migrated SQLite test harness and actual RunsService, create two private documents owned by `u1`, grant `u2` commenter on A only, hand B to `a1`, and ask on A as `u2` using `a1`. `session(u2, B)` returns `not_found`, but `checkpoint` on B as the resulting run principal succeeds. A temporary test executed this sequence successfully (1 pass); it was removed after the probe. Apply the current asking member's authorization and role ceiling to every live-artifact target reached by an artifact-session run, or enforce an explicitly intended scope that prevents this path, and test private and workspace targets, revocation and downgrade. Preserve separately intended ordinary non-artifact run policy.
