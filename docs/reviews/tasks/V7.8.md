# V7.8 review: Q&A board pages

## Verdicts

Round 1, commit 7fb2555: clean, no must-fix.

After the verdict I fixed the first nit below (a second "Show older" click while a page loads), in 799f184.

## Choices that differ from the task text

- The list route is `qa.index.tsx`, not `qa.tsx`. With TanStack flat routes `qa.tsx` would be the layout parent of `qa.$questionId.tsx` and would need an Outlet. `nav-registry.test.ts` still resolves `/qa` through the first file-name segment.
- The map's Q&A link lives in the inspector's `OutputBody`, next to the open count on the tile, the way an agent node reaches its profile. The tile itself is not a link.
- The Q&A node reads "N open" from `qa.openCount` (V7.3 left it on the 7-day count). The wire label still shows the 7-day count.
- "Show older" paging on the board is beyond the written scope. The service already returns `nextCursor`, so it was cheap.
- Components were written fresh on shadcn and tRPC. master-control was used for layout and behaviour only, and attachments are left out.

## Nits left

- The board polls its first page only. Older pages keep the cursor they started from, so when new questions arrive, the ones pushed off the first page show in neither list until the board remounts. On Open, older pages can still show a question that has since been answered (`qa-board.tsx`).
- "All questions" on the question page goes to `/qa` with the Open filter.
- After asking, the board refreshes but does not open the new question, and on the Answered filter the new question does not show.
- Closing the ask dialog without sending keeps the last error for the next open.
- "Close question" acts on one click and no UI reopens a question.
- The map inspector's "Last 7 days" row counts wire items while the tile reads "N open", with no note on the difference.
- A question card preview shows raw Markdown for an agent's question (the first line, unrendered).
- The sidebar badge follows the 10 second desk poll, so it lags a few seconds after accept or close.

## Beyond the scope

- A per-question answer count on the list card needs a service read.
- Reopening a closed question needs a service method.
- Filter by author or by agent (`qa.list` already takes `author`).
