## API and composition

`createLiveArtifactsService` now composes `comments.ts`, `changes.ts` and `access-lifecycle.ts` with the existing core authorization functions. Every public data operation authenticates a principal and reads current artifact access. Only user/run principals are supported here; guest authentication is later work.

New mandatory dependencies, exported from `@repo/services/live-artifacts/ports` (also type-exported by the service):

- `anchors: LiveAnchorPort`: `resolve(scope, anchor)` returns `{ anchor, quote }` against current room state. Relative document positions and deck slide/element anchors use the existing protocol schema. A new anchor must match the artifact kind, resolve, have a nonempty quote within 4096 bytes, and cannot claim to be detached. Stored positions are resolved again on reads; room failure yields the original valid anchor with `detached: true`, never a guessed text offset. Corrupt stored JSON is handled safely. `guardAgentSnapshot(scope, { snapshot, runId })` must refuse an agent checkpoint that deletes anchored words. Agent checkpoints call it before codec/blob/DB persistence. The actual room must enforce this guard atomically with its live edit; checkpoint validation cannot repair an unsafe operation already broadcast by a room.
- `ask: LiveAskPort`: `startComment(principal, { workspaceId, artifactId, threadId, commentId, text }) -> { runId }`. Only a human's explicitly `toAgent` new thread calls this, after its comment/event commit. Replies, ordinary comments, resolving and marking answered never start runs. L.4c must implement current role/agent/run/session policy and deduplicate dispatch using `commentId`; an ask-port error propagates and leaves the addressed comment persisted in the inbox for recovery. There is no fake ask, synthetic session or no-op default here.
- `changes: LiveChangePort`: `revert(scope, { changeId, runId, toolCallId, revFrom, revTo, byParticipant }) -> { revision }`. The room must perform semantic undo scoped to that change's origin, preserving later human edits and rejecting anchored-word deletion. `changeId` is the required room idempotency key: if room success is followed by DB failure, retry must return the same successful result without undoing twice. The service requires a safe integer revision beyond `revTo` before writing any success audit.

`scope` is always `{ workspaceId, artifactId }`. None of these ports has an optional or no-op production default. Tests provide explicit recording/failing implementations; they do not claim to implement Yjs.

Methods:

- `comment(principal, { artifactId, body, anchor?, threadId?, toAgent? })` returns the persisted comment. Bodies are nonblank and at most 4096 UTF-8 bytes. Threads cap at 1000 per artifact, comments at 100 per thread. Conditional inserts enforce caps in the atomic commit, including competing last-slot callers; failed commits leave no false comment event. Replies must belong to the exact authorized artifact/workspace and cannot replace the thread anchor/addressing.
- `threads(principal, { artifactId, cursor?, limit?, inbox? })` returns `{ items, next? }`, ascending opaque ULID cursor, default 50 and maximum 100 threads. Each thread includes at most 100 comments. `inbox: true` selects addressed, unanswered, unresolved threads. Reads include both document and deck artifacts.
- `resolve(principal, { threadId })` requires a human commenter/editor/owner, persists resolver/time and `artifact.comment_resolved`. Runs cannot resolve human threads. Repeat sequential resolves are harmless.
- `answered(principal, { threadId })` requires a currently authorized run, an addressed thread, and a persisted undeleted reply by that run in the same thread/workspace. It sets only `answeredAt`; it never changes resolved state or starts a run.
- `recordChange(principal, { artifactId, toolCallId, summary, revFrom, revTo })` requires an editing run whose stored run/agent/session parents pass the existing same-workspace checks. Summary is nonblank and bounded to 4096 bytes; revisions must be safe nonnegative integers and advance. The stored row carries the authenticated run and timestamp. Call after the real room operation commits; this is audit recording, not a room edit implementation.
- `changes(principal, { artifactId, cursor?, limit? })` returns `{ items, next? }`, newest-first opaque cursor, default 50/max 100. Rows include run, tool call, summary, revisions, time and revert audit.
- `revertChange(principal, { changeId })` requires a human editor/owner and validates the stored change, artifact, run, agent and session in the caller's workspace. It calls the room operation before atomically recording `revertedAt`, `revertedBy` and `artifact.agent_change_reverted` with the returned revision. A failed room call, invalid confirmation or DB failure cannot produce a success audit. Sequential retries of already audited changes return without another room operation.

Viewer/read-only credentials cannot comment or mutate. Named role downgrade/revocation/expiry is reread through the shared core authorization. Commenters can reply/resolve but cannot revert document edits. Other-workspace or other-artifact parent IDs cannot bypass authorization.

## Review High findings 1/2: durable access and admission

Migration `0027_lyrical_shaman.sql` adds only `artifact_room_invalidations`, its foreign keys and pending index; its generated snapshot/journal are committed. It does not recreate existing tables or touch event triggers. Migration-backed schema tests include the new table.

Live `remove` and `setAudience` now commit the artifact mutation, ordinary artifact event and invalidation row in **one atomic DB write**, then attempt room refresh. These live wrappers perform their writes directly so the outbox cannot be separated from the mutation by a crash. Static publishing and blob quota code are untouched. A refresh/acknowledgement error propagates after the committed mutation and leaves the row pending. The mutation event describes committed DB state, not successful socket delivery, and is not repeated by retries.

`retryInvalidations({ kind: "system" }, { limit?, cursor? })` is a trusted infrastructure operation, never a user/guest router operation. It reads up to 100 pending rows (default 50), retries each independently, and acknowledges only successful refreshes. It returns `{ attempted, completed, next? }`. Follow `next` through a processing sweep and restart without a cursor on the next sweep, so failing earlier deliveries cannot starve later entries. It reads artifact rows directly with a workspace match, including soft-deleted rows; it never relies on `findArtifact`, which hides deleted artifacts. Delivery is at least once. `rooms.refresh` must therefore idempotently close/downgrade affected sockets after rechecking current access, including rooms for deleted artifacts. A successful refresh followed by acknowledgement failure safely repeats refresh.

L.7 must install a durable scheduled/queue processing adapter that repeatedly drains pending invalidations, retries failures, and observes `attempted/completed`; a best-effort `waitUntil` alone is insufficient. Admission continues to recheck DB rights while delivery is pending. Membership mutation adapters must include `roomInvalidationStatement(deps, scope, participantId?)` from `@repo/services/live-artifacts/access-lifecycle` in the **same atomic write** as their grant mutation, then trigger processing. Calling the convenience `invalidateAccess` only after an unrelated grant transaction does not provide crash-atomic membership invalidation.

`LiveAdmissionPort.admit(principal, { artifactId, ticket })` is implemented by the service. It checks ticket signature, room/workspace, expiry and participant identity, then rereads current artifact/run/grant authorization. If current role differs from the signed role (including downgrade), admission is refused; callers must obtain a fresh ticket. Revoked/private/deleted artifacts refuse old tickets even if their cryptographic expiry has not passed.

L.3/L.7 must pass a **freshly authenticated principal**, including current workspace membership/admin status and credential read-only restrictions, rather than rebuilding a privileged principal from ticket claims. Invoke admission inside the serialized room admission/refresh boundary immediately before atomically consuming `jti` and attaching the socket; use a fresh ticket and current check for renewal. Signature verification alone never authorizes a connection. Actual ticket single-use storage, socket closures/expiry and real semantic room behavior remain L.3/L.7 integration work.

## Independent review — 2026-10-27

Reviewed merged HEAD `f0687e34` (including L.4b `7879f38a`, L.Q and controller fixes). Verdict: **changes required**. The room and socket implementation is L.3; this review does not claim that its semantics are implemented or tested here.

### Must fix

1. **High — addressed comments can be committed without ever starting a run.** `packages/services/src/live-artifacts/comments.ts:304` commits the thread, comment and event, then `:324` invokes `ask.startComment`. A crash between them, or a rejected/ambiguous dispatch, leaves a persisted request with no durable dispatch work. Retrying `comment` creates a different comment ID, so deduplication by the original ID cannot prevent duplicate requests after an ambiguous success. An unanswered inbox is not a dispatch queue: it also contains successfully dispatched but not yet answered work and no recovery processor is specified. Persist dispatch intent atomically with the comment and event, with a stable idempotency key and a durable retry/acknowledgement protocol; ensure an external retry can refer to the original request. Test crash before dispatch, failure, ambiguous success and replay. L.4c may supply the processor, but this atomic handoff must be in place before the addressed-comment path is accepted.

2. **Medium — concurrent reverts duplicate and misattribute the audit.** `packages/services/src/live-artifacts/changes.ts:151` checks a stale read, and `:174` unconditionally updates and inserts an event. Two callers can both enter the idempotent room operation and both commit events; the second overwrites `revertedBy`, even if the room attributed the actual undo to the first. A migrated SQLite probe held both room calls at a barrier and observed two revert events for one change. Atomically claim/finalize the audit once, condition event insertion on the winning state transition, and carry the room's original actor and revision across retries. Test concurrent callers with different actors as well as failure after room success. The same stale-read pattern in `packages/services/src/live-artifacts/comments.ts:343` permits duplicate resolve events and overwriting the resolver; make that transition and its event conditional too.

### Integration gates and boundary assessment

- L.4a High 1 is addressed at the service boundary for live audience/delete: the mutation, event and outbox row are atomic; retry sees soft-deleted artifacts and acknowledges only after refresh. It is **not end-to-end resolved** until L.7 installs a durable recurring processor, wires every membership mutation into the same transaction via `roomInvalidationStatement`, and proves eventual close/downgrade after crashes and acknowledgement failures. A best-effort call alone is insufficient. L.4a High 2 is addressed at the service boundary by `admit` re-reading access and comparing the signed role, but remains **an integration gate**: L.7 must obtain a fresh authenticated principal with current membership/admin and credential restrictions, and L.3 must serialize admission and refresh, consume the ticket once and enforce expiry/renewal. Test revoke, downgrade and delete between issue and admission, and interleave admission with mutation/refresh. These explicit mandatory contracts are sufficient to defer the socket implementation to L.3/L.7, not to claim the end-to-end findings closed.
- Revert must implement semantic undo scoped to one change, preserving later human edits and anchors; its room idempotency result must survive room restart and DB failure. Restore similarly needs durable reconciliation of room success with failed checkpoint/audit, preserving provenance. Agent edit recording occurs after the room edit (`changes.ts:41`): L.3/L.7 must make that handoff recoverable and idempotent so a crash or retry neither loses nor duplicates history.
- Anchors are resolved through the room port and agent checkpoints invoke its guard; the actual operation must guard atomically before broadcast. Addressed-only dispatch, run inability to resolve, role ceilings, parent workspace checks, and read-only credentials/runs were inspected and exercised by the focused tests. Real room, codec, and fresh-principal behavior remain integration tests, not evidence supplied by mocks.
- L.Q's quota statement remains in the live persistence transaction (`service.ts:453`); the merged static/live and live/live competing-write tests passed. Migration 0027 only adds the outbox table/index and does not rebuild `events`; migrated schema/foreign-key tests and event immutability trigger tests passed.
