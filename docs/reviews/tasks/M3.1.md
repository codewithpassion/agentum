# M3.1 review

## Verdicts

Round 0, commit 7dba177: not clean. One must-fix (a concurrent re-paste for one owner reported success for a value that was not stored), many nits.

Fix round 1, commit c0344c6: clean, with two nits.

## Decisions

- Migration 0006 adds `connectors`, `credentials` and `agent_connectors`. `connectors` has no unique index on url, as the design says. `credentials` is unique on (connector, owner kind, owner), so a user-owned and an agent-owned header credential coexist and a second paste for one owner replaces the value and bumps `version`.
- The SSRF guard is control-plane's `safe-url.ts`, copied once with `.home.arpa` added. Agentum's `url.ts` wraps it and keeps `canonicalizeConnectorUrl`. There is no loopback exception: tests reach the stub through an injected `fetch` that maps a public-looking host to it.
- Agentum's `mcp.ts` is copied with a `header` option (name and value), `redirect: "manual"` so a redirect cannot get past the guard, and a `Fetcher` type. `health.ts` and `usability.ts` were not copied because nothing calls them yet.
- Adding a connector probes it. A 401 whose challenge carries `resource_metadata` makes it `oauth` (discovery and connecting are M3.2), any other 401 or 403 makes it `header` with header name `Authorization` unless given, and a good answer makes it `none`. An unreachable server is refused and nothing is stored.
- A pasted value is probed with the connector's header before it is stored, so a wrong value is refused and a good one refreshes the tool list. The value is encrypted with `SECRETS_KEY`, bound to workspace, table, row and field. Every read selects `credentialColumns`, which has no `secret`. A paste logs `credential.created` with ids only.
- Pasting as an agent takes an `agentId` of an active agent in the workspace. The Connectors page pastes as yourself only. The agent page offers both.
- Connectors are managed from a signed-in session only. A user sees their own user-owned credential and every agent-owned one.
- `createConnectorsService` also takes `clock`, `events` and `secretsKey`, beyond the `{ db, atomic, fetch }` in the task. `SECRETS_KEY` is read only when a credential is stored.
- `scripts/dev/stub-mcp.ts` flags: `--fail-once` invalidates the configured token on the first authorised request and only a token from `POST /token` works afterwards. `--count-token-calls` prints and serves the `/token` call count. `--sleep` delays `tools/call`.

## Checks

`bun run check && bun run test && bun run build` pass, and the grep for drizzle in `apps/web/dist/client` finds nothing. `packages/services/src/connectors.test.ts` covers the four cases in the task file (probe lists echo, a private IP URL is refused with no request made, the header value is in no response, event or stored plaintext, user-owned and agent-owned credentials coexist). `apps/web/src/server/trpc/connectors-router.test.ts` checks the no-leak case through the real router. Live, against `vite dev` on port 3217 after `wrangler d1 migrations apply DB --local` (0006 applied): dev login, the Connectors nav entry and page rendered, and adding `https://10.0.0.5/mcp` showed "That URL is not allowed: the host is a private IPv4 address." The stub could not be added there, because the guard refuses loopback by design.

## Nits left

- `setCredential` writes the fenced credential update and the tool-list refresh as two writes. If the refresh fails after the update, the caller sees an error for a value that was stored. Running the refresh first would avoid it.
- Redaction of a pasted value from a server's error text is an exact match on the whole value.
- `includes("resource_metadata")` is a substring match on the whole challenge. M3.2 replaces it with discovery.
- `mcp.ts` keeps unused copied leftovers (the `token` option, a comment about the OAuth ladder). `isSafeUrl` and `safeFetch` are exported and unused.
- The `url.ts` comment on exposure says only a metadata GET and a token POST leave the Worker. M3.3's proxy forwards tool calls.
- `credentials` has no `workspace_id` index.
- Stub: requests refused with 401 are not recorded in `calls`, and `--fail-once` trips on the first authorised request, so a paste against it is refused. M3.3's tests must seed the credential row directly.
- UI: `notice` on the Connectors page is never cleared, floating promises in two handlers, `errorMessage` copied into three files, no `<form>` so Enter does not submit, the agent tab shows raw `needs_auth` and a different badge variant than the page, an empty table head and an untruncated URL there, and the paste dialog always suggests `Bearer abc123`.

## Ideas beyond the scope

- Revoke a credential and delete a connector. The design has `credential.revoked`, and M3.3's tests need a revoked row.
- A "Test connection" action that re-probes and refreshes the tool list.
- A form element in the dialogs, and one shared `errorMessage` helper.
