# V6.7 review

Take-over requests on the waiting model. Implemented in Codex (4a81def, b5af217), fixed by the dispatcher (4971acf).

## Verdicts

Round 1 at b5af217: not clean, two must-fix.
- The takeover cancelled text said the run was ending. It now says the person cancelled (`outcomeText` in `packages/protocol/src/requests.ts`).
- Managed `deliverAnswers` skipped cancelled rows, so a person's cancel never reached a managed session. It now delivers a cancelled takeover row, with a test.

Round 2 at 4971acf: clean.

## Nits left

- `take` checks the request is pending and then writes `computer.taken` in a separate step, so a hand-back or expiry in between logs `computer.taken` after the close.
- Nothing stops a second person taking an already taken computer, and the holder is not stored on the row. Hand-back and cancel work for any user who can see the request.
- `handBack` resumes the runtime inside `requests.answer` before it releases the lease and writes `computer.handed_back`. If `release` throws, the event is never written.
- Expiry and the run-ending cancel release no lease and write no `computer.handed_back`.
- `requests.cancel` accepts any kind at the requests layer (the takeover service restricts it), records no `answeredBy`, and says "Already answered" on a conflict.
- The `open` fallback error now always says a takeover is pending, including for an approval or question insert that finds no winner.
- The hand-back note has no length cap, here or in `takeoverAnswerSchema`.
- `TakeoverCard` in `request-card.tsx` calls `getTrpc()` itself, and Hand back and Cancel are enabled before anyone takes over.
- Tests cover a second request on the same run, not on two runs of one agent, and do not check the run returns to `running` after settle.
- No test shows a takeover cancelled because the run ended is never delivered to a managed session.

## Beyond scope

- `requestPart` in `packages/protocol/src/thread.ts` drops takeover rows, so a takeover card is missing from the session chat thread.
- `packages/services/src/tasks/receipt.ts` labels a takeover step "Approval required", and `status-band.ts` shows "Waiting for an answer" without the reason.
- Slack takeover cards are skipped on purpose.

## Steps for Dom

None. V6.10 passes the relay lease into `createTakeoverService` (`lease.take`, `lease.release`) and should release it on expiry and on a run-ending cancel. V6.12 and V6.13 open the request with `SYSTEM_PRINCIPAL` through `requests.open({ kind: "takeover", reason, runId, toolUseId })`.
