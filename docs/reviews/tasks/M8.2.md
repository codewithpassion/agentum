## What changed

Outage rule: managed runs get a 10 minute lease (`MANAGED_LEASE_MS`, `managed/types.ts`), the same approach as C.4's `CLOUD_LEASE_MS`. The managed claim and both of its heartbeats use it. A session token is valid while the run's lease is, so the token survives the outage too, and the reaper needs no change. The poller's alarm still heartbeats every poll, and the minute tick's `rearm` wakes a poller that came back. An outage longer than 10 minutes still ends the run `interrupted`.

Cleanup: `RuntimeAdapter` has a new optional hook, `abandon(run)`. `reapExpiredLeases` and the unclaimed-run expiry in `sweepQueuedRuns` call it through `abandonEnded` after the run is ended and its event is written. A throw is logged and does not stop the job. The managed runtime's hook is `managed.abandon`, wired in `compose.ts`, which interrupts the Anthropic session, drops the vault and closes the `managed_sessions` row only while the run is still the session's `currentRunId`. It is called directly, not through the poller, because the poller may be what is down.

## Tests

`managed.test.ts`, block "a poller outage and the reaper": a reaped run sends the interrupt and closes the session, a reaped run that is no longer the session's current run leaves it alone, a poller down for 120 s ends `done`, an outage past the lease still ends `interrupted`, and the sweep failing a waiting run leaves the running run's session alone. `runs.test.ts`: the reaper and the sweep call `abandon`, a live lease does not, and a throwing hook does not stop the reaper.

## Nits left

1. `managed.test.ts:1245`: "an outage longer than the lease still ends the run" repeats the setup and assertions of the first test in the block. It names the bound, so it stays.
2. `managed/types.ts:26`: `MANAGED_LEASE_MS` is a runtime constant in a types module. Cloud keeps its constant in `cloud/lease.ts`.
3. `managed.test.ts:734`: older tests fake the reaper by setting the status by hand and leaving the session open. The real reaper now closes the session, so they cover a failed cleanup, and their names do not say that.
4. `runs/types.ts`: `abandon` takes `(run)` while `cancel` takes `(db, run, deps)`. Two hook shapes on one interface.
5. `runs.ts` (`reapExpiredLeases`): after the reaper ends a managed run it does not offer the session's next queued run. The 60 s sweep does. Same as before this task.
6. `runs.ts` (`abandonEnded`): the runtime is found from the agent's current `runtime`. A run left live when its agent was switched off `managed` is never cleaned up. Cancel has the same gap.

## Ideas beyond the scope

- Nits 3 and 5 are one change: a reaped managed run offers the next run of its session at once, and the old by-hand tests say what they cover.
- The kill test in C.4 (`scripts/e2e/cloud-outage.ts`) has no managed twin. A live check needs a real Anthropic key and a tunnel.
