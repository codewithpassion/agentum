# V6.6 review

## Verdicts

- Round 1 (445cfeb): clean. The reviewer found no must-fix items. It re-ran check, test and build, and probed `validateUrl` with about 30 SSRF inputs (octal, hex and decimal IPv4, mapped IPv6, userinfo, odd schemes), all refused.

## Decisions

- No Browser Run binding is added here. The `BROWSER` binding goes into `wrangler.jsonc` in V6.11, in all three places (top level, `env.staging`, `env.staging.previews`).
- Every test uses a fake `BrowserDriver`. No live Browser Run call was made.
- Actions are run-only. A principal from another workspace or agent, or a user principal, is refused before the driver is touched.
- Events carry only `{action, host, outcome}`.

## Nits left

- `packages/db/src/shared.ts:351`: `BrowserActionPayload` still says `{ action; url? }`. It should become `{ action; host; outcome }`. Outside the services lane.
- `rules.ts:44`: the IPv4 guard allows 192.0.0.0/24, 192.0.2.0/24, 198.18.0.0/15, multicast and 240.0.0.0/4.
- `rules.ts:64`: single-label hosts (`http://intranet/`) pass, and so do public names that resolve to 127.0.0.1.
- `service.ts:165`: the landing URL after a redirect is not re-validated.
- `service.ts:67`: the run's status is not checked.
- `service.ts:181`: an error from writing the error event hides the original error.
- `service.ts:183`: a `ForbiddenError` from `library.write` is reworded as "browser unavailable".
- `service.ts:153`: a relaunch does not reset `currentUrl`.
- `service.ts:140`: two concurrent first calls both launch a session.
- `service.ts:240`: a type-narrowing check duplicates the earlier run-kind check.
- `service.test.ts:178`: the relaunch test does not check the stored session id or the `updatedAt` refresh.
- `index.ts`: a re-export barrel, which the task scope asks for although HANDOVER says no barrel files.

## Ideas beyond scope

- Refuse single-label hostnames and the remaining reserved IPv4 ranges.
- Re-check the final URL after navigation and mark the action as blocked when it lands on a private host.
- Serialise first-launch per agent with a unique-insert or a lock.
