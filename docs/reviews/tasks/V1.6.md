# V1.6 review

## Verdicts

Round 1 at 34b5c79: not clean. One must-fix: the chat never fell back to polling when the stream route refused the connection for good (401, 404, 500), because only `MAX_FAILURES` errors in a row triggered it and a closed EventSource does not retry.

Round 2 at 0c238d9 (the fix, checked on its own): clean. The fallback now also triggers on `readyState === EventSource.CLOSED`.

## Nits left

- `use-session-stream.ts`: if the first transcript fetch fails, no stream opens, no poll starts and the focus retry is not registered. The chat shows the error and stays stale until the session changes. Fix: `setMode("poll")` when the first load returns null.
- `use-session-stream.ts`: the doc comment names only `MAX_FAILURES` as the poll trigger, not a refused stream.
- `use-session-stream.ts`: a failed fetch sets `error` even after a newer fetch replaced it, and leaves `needsRefetch` true, so the refetch effect does not run again.
- `use-session-stream.ts`: `Date.now()` is read during render for `shouldPoll`, which stays fresh only through the chat's 15 s clock.
- `stream-logic.ts`: `applyTranscript` keeps the delta of an active run even when the fetched transcript already holds that run's stored assistant message (a truncated >64 KB message). The duplicate lasts until the next delta or the end of the run.
- `stream-logic.ts`: `applyTranscript` replaces `latestRun` with the fetched one, so a reload that started before a `run.started` frame can show "Queued" again until the next status event.
- `stream-logic.ts`: a late delta for an active run whose stored message already arrived shows a second copy. Nothing publishes deltas yet.
- `chat-logic.ts`: `type Entry = ChatEntry` is a plain alias.

## Beyond the scope

- `sessions/session-transcript.tsx` still polls every 1.5 s. Adding `waiting` to `isRunActive` makes it poll for as long as a run waits for an answer, which can be hours. It could use `useSessionStream` too.
- A fake runtime that emits tool calls and deltas would let the browser check cover live text and tool cards. The current one answers in one event.
