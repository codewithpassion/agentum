## Addressed human comments

The existing rotating `POST /api/guest/artifacts/:id/comment` now accepts explicit `toAgent: true` plus stable `requestId` for a new thread, body and optional canonical anchor. The additive checkbox lives only in `components/guests/comments.tsx`; it does not replace the Ask composer, selection flush, shared SSE or suggestion review. A pending addressed comment persists its immutable payload/request ID across a same-tab reload under workspace+guest+artifact identity. It shares the existing signout-clearing namespace and requires explicit discard before changing a submitted retry. Old/unmounted acknowledgements cannot erase a replacement. Viewer roles have no composer. Replies cannot change addressing or anchor. Ordinary comments, replies and resolution never start runs.

The route renews the cookie first and passes that new credential. `createGuestAddressedComment` resolves current role/anchor, uses an actor/artifact/request-specific run key, and supplies trusted `alongside` statements to the existing `startForGuest` transaction. The human thread/comment, comment-created event, immutable reply binding, normal run/provenance/shared-session rows and cap guard all commit together. There is no comment-then-dispatch gap, saved credential, principal fabricated for a guest, background member-delegation fallback or non-idempotent resend. A crash before commit leaves none of these rows; after commit the queued run/sweep/alarm is the durable dispatch. Retrying returns the same run/comment/thread without another charge. Reusing the request ID with a different body is refused. A cap refusal rolls back the comment and binding along with the run.

Migration **0032_lovely_lake** adds `guest_comment_runs` (the exact original thread/comment binding) and `guest_comment_effects` (unique run/call receipt, fingerprint and result identifiers). It was generated with Drizzle and includes its snapshot/journal. No preceding migration was changed. No other lane used this migration number.

## Scoped agent comments and answers

The dedicated production MCP mount now registers receipt-backed `document_comment` for documents and `deck_comment`/`deck_comments` for decks, in addition to existing scoped tools. Both commenter and editor runs can comment; commenter runs still cannot obtain edit/write tools. The ordinary non-idempotent live comment port is not a fallback: registration requires the explicit comment port, and ordinary live service comment/answered methods deny stored guest scope even if a caller omits that scope from its principal. General creation, handoff, resolution and unrelated artifact tools remain absent/refused.

The dedicated comment service checks current exact provenance, artifact and role before work, in its conditional write, and before returning results (including replay). The SQL guard requires a running run with a live lease and current guest grant/session/workspace switch. It enforces thread/artifact/workspace ownership and quotas. One Atomic transaction commits the comment, optional answered update, audit event and unique receipt. Stable `${runId}:${turn}` IDs survive tool replay; changed payload under an existing ID is refused. A crash after the room/service effect but before executor acknowledgement replays the result instead of adding a comment. Anchored new document comments resolve through the current scoped room; deck comments may start an unanchored thread. Agents cannot address a new thread back to an agent.

On final completion, the executor reads the persisted original thread binding and posts the answer there before completing the run. Answer chunks are UTF-8 bounded to the existing 4096-byte comment limit; stable per-run chunk IDs make a partially acknowledged completion resumable. Only the last chunk marks the addressed thread answered. Empty answers refuse. No agent path writes resolvedAt or resolvedBy, and the human Resolve action remains available after an answer. Current role/grant loss stops the effect even when its receipt or dispatch was previously persisted. Agent-origin content edits still use trusted forceSuggestions ancestry and room staging; comment capability does not grant direct content mutation.

## Configured runtime coverage and exact readiness

The restricted adapter is now independent of the selected agent's ordinary execution runtime:

| Selected agent configuration | Guest execution |
| --- | --- |
| cloud/native/VM-backed agent | Dedicated GuestRun inference; no ordinary PiRun/VM session |
| machine/daemon native or container agent | Dedicated GuestRun inference; no machine claim, process, subscription credential, home or daemon |
| managed agent | Dedicated GuestRun inference; no managed remote agent/session, private instructions, files or tools |

All persisted production runtime values (`cloud`, `machine`, `managed`) are supported through the existing configured provider/model abstraction. The development `fake` runtime is not a production guest capability. This is not removal of native-runtime refusals: ordinary machine/managed/VM paths still reject guest scope. The guest's runtime never inherits private agent instructions/runtimeConfig, library, connectors, shell, files, native tools or general network capabilities. Only bounded inference and the exact scoped MCP registry are model-facing.

Readiness requires the dedicated runner, signing/base URL/live infrastructure, active current selected workspace agent, a supported configured model and its actual configured workspace provider key. Anthropic models use ManagedKeys; OpenRouter models use ModelKeys, just as the existing inference abstraction does. Aliases such as sonnet resolve to the supported model catalogue. No model substitution or key generation occurs. Unknown model/provider combinations and missing keys refuse **before** the cap/start transaction. A daemon's local subscription/OAuth login is not a portable workspace inference credential: agents relying only on that login remain unavailable until a supported workspace provider credential is configured. That external configuration/provider validation is an acceptance gate, not a fake implementation or permission to expose native sessions. Supporting a nonportable subscription without a workspace API credential would require a separately reviewed inference-only broker; no such path is silently enabled here.

The actual model leaf uses the existing provider abstraction. Fixture keys and model completions exist only in the explicit local fixture subclass; production has no fake inference switch. No external provider call, credential request/change or real send was used.
