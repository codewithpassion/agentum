## Routing rule request body, checked against Cloudflare

`createEmailRoutingPort` sends `POST /zones/<zone>/email/routing/rules` with `actions: [{ type: "worker", value: [<worker>] }]`, `matchers: [{ type: "literal", field: "to", value: <address> }]`, `enabled: true` and `name`. This is the shape Wrangler 4.151.1 builds for its own `addresses` feature (`ruleShapeForTarget` in its bundle), and it matches the API reference for the create call: `type` is `drop`, `forward` or `worker`, `value` is an array limited to one entry, a literal matcher takes `field: "to"`, and `name`, `enabled` and `priority` are optional. No rule was created. The V5.7 body needs no change.

Limits from the reference: a matcher `value` is at most 90 characters, a rule `name` at most 256 (`harbourmaster:<address>` stays under that), and the list takes `page` and `per_page` with `per_page` between 5 and 50 (`PAGE_SIZE` is 50, at the ceiling). `result_info.total_pages` is documented, so the short-page fallback in `findRule` is defensive only.

The zone holds eight rules, all `forward` to Dom's addresses, none named `harbourmaster:`: `fluentsea@`, `clerk@`, `pr-stoneflow@`, `re-insidemotivation@`, `bluecrab-org@`, `cf-stoneflow@`, `ccau@`, `supatesta@`. The catch-all is disabled with action drop. So `findRule("research@...")` finds nothing and `createRule` makes the first managed rule, and `findRule` would refuse any of those eight addresses as "Address in use outside Harbourmaster". The 200-rule limit leaves room.

## Not done, and why: everything that needs the token

Mailbox status reaches `active` only through `route()` in `packages/services/src/mail/index.ts`, which needs a created rule. `hasActiveMailbox` (`packages/services/src/mail/agent.ts`) reads only rows with status `active`, and `routes/mcp.ts` turns the `mail` tool group on from it. So with no token no agent has a mail tool, and outbound mail cannot be tested either. The controller's note expected outbound to work without the token. It does not. I did not create throwaway agents or touch remote D1 to fake an active row.

These wait on the token:

- Provisioning to `active`: the Retry on Researcher (or a new agent) creates the rule and flips the chip to active.
- Outbound through the `EMAIL` binding, and whether Cloudflare keeps our own `Message-ID` header and what `result.messageId` is (V5.6 open question).
- Approval of an outside send in Needs you, Allow once, Deny, and the thread showing in the Mail tab, the desk strip and the task view.
- Bounce of an approved send to an address that does not exist, shown on the task's band. This also answers whether a bounce arrives as mail or needs a Queue (V5.2 idea).
- Inbound: Gmail to the agent starts a task in a new session, a Gmail reply continues the same session and task, mail to an unknown address bounces at SMTP time.
- Whether a throwing `email()` handler makes the sender retry (V5.7).
- Whether the sha256 dedupe catches a redelivery when Cloudflare stamps new `Received` headers (V5.6).
- Mail between two staging agents (V5.16 stores it and starts no run).
- Teardown: archive the throwaway agents and delete their `harbourmaster:` rules with `wrangler email routing rules delete`.

The Gmail legs also need Dom's inbox. Use another staging agent's address as the recipient for the legs that do not.
