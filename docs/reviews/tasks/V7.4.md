## Nits left

- `triggers.ts`: `requireLive` takes a boolean `movable` flag that swaps its query, with one dead `if (!summary)` and a doubled `revokedAt` check. A separate helper for `reassign` would read better.
- `triggers.ts` imports `findMapTrigger` from `@repo/db/map`, so a core service depends on the map's query module.
- `triggers.reassign` writes no trigger change event of its own. Only `map.edited` records the move. The task refinements allow this.
- `reassign` neither checks the row count nor uses `.returning()`, so a trigger revoked between the check and the update is a silent no-op that still logs `map.edited`.
- `edited()` re-runs the principal check that `writer()` already did.
- `map.edited` is appended after the underlying write, not in the same `atomic`, as the underlying services do for their own events.
- `savePositions([])` appends a `map.edited` event with `count: 0`.
- Some refusal tests use bare `.rejects.toThrow()` with no message.
- Unplug of a computer reads then detaches in two steps, so a concurrent plug could be detached.
- The position key regex lets invisible format characters (Unicode `Cf`) through in library keys. Harmless.

## Ideas beyond scope
