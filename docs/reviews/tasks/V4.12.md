Round 1 at 2c1855c: clean, no must-fix. Codex wrote the service, the Needs you source and the router. The dispatcher ran `bun run check`, `bun run test` and `bun run build`, all green, and the client bundle has no `drizzle`.

## Nits left

- `suggestions.ts`: `list` and `get` accept run principals and do not check library read scope. Latent, because tRPC only admits users.
- `suggestions.ts`: the decide update matches on id only, with no status guard, so a racing reject and replacement could overwrite each other.
- `suggestions.ts`: replaced rows are read outside the batch, so a concurrent suggest can be closed without its own decided event.
- `suggestions.ts`: a replacement is stored as `rejected` with `decidedBy` null. Only `replacedBy` in the event payload tells it apart from a person's reject.
- `suggestions.ts`: the blob is written before the batch, so a failed batch leaves an orphan, and replaced or rejected suggestions never delete their blobs.
- `suggestions.ts`: on a legacy unversioned page a concurrent seed can make the insert fail on the foreign key.
- `suggestions.ts`: when the latest version is a delete, accept sends no `ifEtag`.
- `suggestions.ts`: `list` runs one history query per open row and can write status updates, an N+1 on a read endpoint.
- `suggestions.ts`: a redundant `refresh(row)` in `decide`.
- `wiki-router.ts`: `list` and `get` return the raw row, including `blobKey`.
- `desk.ts`: the desk reads `wikiSuggestions` directly, so it never runs the stale check, and a stale suggestion shows as a plain card.
- `desk.ts`: the Needs you card carries no base or proposed text. The UI fetches them through `wiki.suggestions.get`.

## Beyond the scope
