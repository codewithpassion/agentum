## Component entry points and exact integration contract

Import `DeckRuntimeGate` from `components/live-decks/runtime-gate` and pass one of:

```ts
{ state: "loading", message?: string }
{ state: "unavailable", message: string }
{ state: "ready", ports: DeckEditorPorts }
```

`DeckEditor` is also exported from `deck-editor.tsx` for an already prepared component host. There is no production fake provider or default successful upload/history/comment/ask/presentation implementation. The executable fixture is isolated under `fixtures/` and is never imported by a product route.

`DeckEditorPorts` is exported from `ports.ts`. Its required fields are:

- `deck: Deck`: a **trusted local replica**, constructed with `richTextCodec` from `@repo/live-deck/rich-text`. Bootstrap untrusted persisted/network bytes using `Deck.applyUpdate`/`restore` on an empty document, rather than applying them before construction. The host owns Deck/provider lifetime and destroys/replaces them when the room epoch or artifact changes.
- `role: "owner" | "editor" | "commenter" | "viewer"`: reactive, room-authorized role. Scene and rich-text editing require owner/editor, `provider.state === "synced"`, and an initialized shared theme. Downgrade/disconnect/rejection disables scene controls and removes editable Tiptap views. Comment/ask are unavailable to viewers. Presentation broadcast controls require an editing role and synchronized provider; loss of permission stops local broadcasting and requests spotlight release.
- `provider: { state: "connecting" | "synced" | "disconnected" | "rejected"; publishPresence(location): void }`. The location contains optional `slideId`, `selection: string[]`, and optional `pointer: {x,y}`. The callback **replaces ephemeral location**, including clearing an undefined pointer. It must publish through the actual room awareness transport. Pointer publication is throttled to at most 20 Hz. The host rerenders ports on provider/role changes; these props are not a transport implementation.
- `participants: readonly DeckParticipant[]`, `selfId: string`. Participant identity (`id`, `name`, `kind`, `color`) and location must already have been authenticated/validated by the room. Kinds are member/guest/agent, with optional slideId, selection, pointer and agent status. The component never accepts a client-supplied identity override.
- `ownsBlob(path): boolean`: synchronous current-artifact membership, also supplied when constructing the Deck. Prefix matching alone is insufficient. The UI refuses to render or insert an unowned image.
- `upload(file: File): Promise<{path: string}>`: actual upload/storage/ownership callback. Result paths must satisfy the core `/files/...` grammar. Membership must be visible to both ownership callbacks before the promise resolves. Role/provider and slide existence are checked again on completion; errors are surfaced. There is no optimistic successful insertion for a failed upload.
- `history(): Promise<void>`: open the actual checkpoint/version UI and implement restore in the host. This leaf invokes the callback and displays errors; it does not invent local checkpoint success.
- `comment(where): Promise<void>` and `ask(where): Promise<void>`, where **`{slideId: string, slideNumber: number, elementIds: string[]}`** uses a one-based current slide number and filters deleted selection IDs. The host maps this component selection into the platform comment/conversation envelope and derives the speaker from the authenticated session.
- `presentToEveryone(position: {slideId: string, build: number} | null): Promise<void>`: broadcast the actual current slide/build, or release presentation with null. `build` is the count of completed/started build steps (zero means before the first step). The room must authorize the presenter and validate/clamp positions against the current deck. Return failures as rejected promises.
- Optional **trusted incoming** `presentation?: {slideId: string, build: number} | null`: room spotlight state, updated for each slide/build. Participants can leave follow, exit presentation without being reopened by the next update, and explicitly follow again. This is a separate channel from ordinary pointer/selection awareness.

The runtime gate refuses a ready deck without shared theme initialization. On authoritative deck creation, **call `deck.setTheme({colors: {}, fonts: {}, sizes: {}})` once before distributing the initial checkpoint or allowing replicas to write** (or seed a real theme there). Existing initialized decks need no initialization. Do not independently create the nested theme maps on each replica. This is required because concurrent first calls to `setTheme` on an absent theme create competing root-map values; the core currently has no special first-map merge operation. Once initialized and shared, independent token edits merge per key; the tests exercise this.

## Implemented behavior

- Fractional-order slide strip and all-slides grid; add, duplicate with fresh descendant IDs, delete, and earlier/later reordering. Presence initials appear on each participant's current slide thumbnail.
- React DOM scenes for shared rich text, rectangle/ellipse/triangle/line shapes, owned images, table cells, the bounded icon picker and selectable SVG connectors. Connectors follow endpoint anchors through parent translation/rotation. Stable element IDs provide matching DOM nodes for magic transitions. Agent HTML is never inserted with `innerHTML`.
- Scene selection (including Shift multi-select and a layer selector for overlapped elements), direct pointer movement/resize/rotation, numeric geometry, six alignments, grouping/ungrouping, group resize and duplicate/delete. Group membership preserves pinned coordinates; ungroup accounts for parent rotation. Pointer gestures form one local scene undo item. Remote changes and Tiptap transactions do not enter the scene undo stack.
- Pinned and flow positioning, flex/grid root layout, direction, gap, padding, tracks, and per-element flex/grid properties. Per-key fill, border, typography, opacity, alignment and shared theme controls. Numeric/text inspector drafts commit on blur/Enter so intermediate invalid CSS/geometry is not written.
- Tiptap binds to the **existing** attached text/cell Y.XmlFragments. It uses the actual shared document extensions and disables generated IDs that would rewrite existing fragment content. A pre-publication transaction filter validates proposed ProseMirror content with the accepted production codec; document-only blocks, unsupported marks/attrs and unsafe links are refused. Marks, lists/tasks, links, text colors and own text undo/redo are available. Scene updates preserve untouched text/cell identities and concurrent human text edits.
- Table cells mount Tiptap when opened, rather than mounting thousands of editors up front. Existing empty cells render as empty DOM. New tables contain valid empty paragraphs. Missing cells allocate a valid empty paragraph through a role-checked command before binding. Explicit last-row/last-column deletion removes the affected cells and changes dimensions together; ordinary dimension changes retain the core's refusal to discard occupied cells.
- Notes edit the existing Y.Text with a minimal prefix/suffix splice and validate XML legality before mutation. Concurrent note characters are not replaced wholesale.
- Presentation supports none/fade/push/magic transitions, all seven in/out effects, build ordering, click/withPrevious/afterPrevious, separate entrance/exit events, native fullscreen, Right/Space/Left/Home/End/F/Escape, notes and next-slide presenter view, and typed present-to-everyone updates. CSS magic transitions reuse matching element nodes and geometry. Reduced-motion preferences shorten animations.
- Trusted pointers with names and interpolated positions, remote selection outlines/name labels, strip avatars, pointer hiding, participant kind/status, and follow until local selection/navigation/scroll. Narrow/mobile editor layouts retain the same controls.

## Core mismatch found and bounded workaround

With the actual production codec, calling `cellFragment` for an unallocated cell currently calls `setCell(..., [])` and fails validation (`Invalid content for node doc: <>`). The component never uses that failing allocation path: new/explicitly opened missing cells are initialized as `<p></p>` through `setCell` and then bound to the attached fragment. Existing fragments are never replaced to attach an editor. Core and codec were left unchanged. The room/tool owners should separately resolve or document the core empty-cell allocation contract; this does not require a production success stub in the component.

## Remaining integration gates

1. Route/frame selection for deck artifacts must mount `DeckRuntimeGate` with real ports, responsive product chrome and authenticated context. No document route or component was edited here.
2. The real deck room/provider must perform ticket authorization, serialized core admission **before live-document application**, persistence/broadcast of accepted original bytes, ephemeral trusted awareness, role refresh/expiry, initialization of shared theme maps, checkpoint/history wiring, and full replica replacement after rejected optimistic updates. A synchronized server snapshot must not be merged into a client retaining rejected structs. Host cleanup must clear departed awareness and release any presenter lease on disconnect/unmount; the server owns lease expiry/revocation.
3. Own undo is local CRDT undo, not permission to bypass room admission: undo-generated updates must cross the same authority validation/authorization boundary as every other client update. Structural conflicts after intervening remote deletion can require authority rejection and replica rebuilding. A fresh room epoch/replacement starts new local undo history.
4. Services and upload ownership must bind returned file paths to this artifact and supply the same current ownership policy to Deck and UI. Version history/restore must use actual persisted checkpoints.
5. The platform comment/ask/agent tools must map `elementIds` into the authoritative deck `where` envelope (`slideId`, one-based slide number and selected element IDs), derive speaker rights from the session, and run read/write tools on the synchronized room authority. No MCP/service/tool code was changed.
6. Production spotlight must authorize a presenter and relay slide **and build**, support leave/rejoin and release on revocation/disconnect. The component callback and incoming state do not implement this server channel.
7. Authenticated two-profile live-room browser checks, staging deployment, maximum-size/performance acceptance, persistence/reconnect/rejected-branch rebuild and product-level R2.1–R2.8 acceptance remain with the integration/controller lanes. This leaf includes executable component evidence, not those service guarantees.

## Independent review — 27 October 2026

Verdict: **changes required for the component leaf**. Reviewed merged main `2e4ac249`, including `e2db6189`, `fffc410b` and handoff `d72459f9`, against CLAUDE.md, LD.3, PRD §5 and R2.1–R2.8, and the accepted LD.0/LD.2 core and codec contracts. Findings below are component defects, independent of the separate room and route integration work.

1. **High — an in-flight presentation start can survive a role/provider downgrade or exit.** In `presentation.tsx`, clicking Present to everyone invokes the async port and sets `broadcast` only when it resolves. The downgrade effect releases only when `broadcast` is already true. Reproduce with a deferred `presentToEveryone(position)`: click Present to everyone, change the reactive role to viewer or provider to disconnected while the promise is pending, then resolve it. The completion sets `broadcast` true after revocation; the effect subsequently requests release, but there is an interval in which the stale start succeeds, and if the component was closed/unmounted before resolution there is no mounted effect to request release at all. Similarly, Exit while the start is pending sees `broadcast === false` and does not release. Concurrent clicks can also send overlapping starts/releases out of order. The host must enforce authorization and lease expiry, but the documented component promise to stop and request release on downgrade/exit requires handling pending starts and late completions as well. Exercise deferred promises, downgrade, disconnect, exit and reordered completion with a real component fixture.

2. **Medium — a following participant can drift from the presenter's build.** `DeckPresentation` schedules `afterPrevious` locally for every instance, including a spotlight follower, and keyboard/Next navigation also calls local `navigate` without leaving follow or waiting for a new trusted presentation position. Reproduce with an incoming spotlight on a slide whose next step is `afterPrevious`: hold the incoming `{slideId, build}` unchanged; after the slide duration the follower advances its own build. Right/Space also advances independently while the control still says Leave presenter. The incoming effect runs only when its prop changes, so the follower remains divergent until another update. This breaks the component's claimed follow behavior and R2.6 even if a real room correctly relays every presenter position. Followers need to derive their position from the trusted spotlight while following, with an explicit leave policy for local navigation.

The actual React scenes use keyed DOM elements and validated scene values; text and opened cells bind attached fragments through the shared Tiptap schema and codec filter. Scene commands use a local Yjs origin and per-key core methods, with role/provider checks; image insertion rechecks current permission and artifact ownership after upload. The initialization gate requires an already shared theme, and the missing-cell workaround allocates a valid paragraph through the core. These observations and the tests below do not establish all limit, simultaneous gesture, ownership revocation, timing, or lifecycle cases. In particular the two findings are code-path reproductions; deferred-port and spotlight adversarial browser probes were not run in this review.
