# L.7 — Production live document wiring

Phase 1 production composition mounts `liveArtifacts` through `createLiveArtifactsRouter`, installs DOM-free content, room RPC, shared ask, comment anchor and MCP document adapters, and exports the real hibernating room with an in-process `ARTIFACT_ROOM_SERVICE` adapter. There is no remote service binding with that name. `ARTIFACT_ROOM` and `LIVE_ARTIFACT_MAINTENANCE` SQLite Durable Objects are bound in default, staging and preview environments with migration v8. Guest execution and deck runtime registration remain disabled in this phase.

## Browser contracts

All three routes authenticate the current caller and authorize artifact access through services. Responses are private/no-store. Images additionally require same-origin requests and current write permission.

- `GET /api/live-artifacts/:artifactId/policy` returns `{ownBlobUrls:string[],agentChanges:{id:string,name:string,start:RelativePosition,end:RelativePosition,text:string}[]}`. Image URLs are verified against that artifact's persisted ownership manifest. Agent ranges are surviving character IDs from persisted accepted room updates, with trusted origin identity; replacement with identical human text does not inherit attribution.
- `POST /api/live-artifacts/:artifactId/images`, multipart field `file`, returns HTTP 201 `{url:string,alt:string}`. Validated raster bytes persist through the files service, then artifact ownership commits before acknowledgement. The upload limit is 8 MiB. Other documents cannot adopt the URL merely because they share a workspace.
- `GET /api/live-artifacts/:artifactId/markdown` returns `{filename:string,markdown:string}` from the latest published checkpoint, rather than an unsaved browser draft.

`liveArtifacts.restore` accepts optional `requestId` for retry identity. Existing artifact versions supply history. The root router carries inferred types without a client root-router cast.

## Authorization and durability

The pre-Clerk room route requires a real authenticated initial request as well as a signed ticket. It forwards the credential request to admission; ticket claims never become a fabricated principal. The room persists opaque private references and refreshes real bearer authorization or Clerk session status, expiry and current organisation membership/admin. Original run lease, API key revocation, read-only and source/target run restrictions remain enforced. Namespace IDs derive from the exact workspace/artifact tuple, with immutable scope checks inside the object.

Document static mutation paths delegate access changes and restore through live services; generic static document updates are refused. Access mutations fence and drain the room before the database commit. Atomic invalidation rows are acknowledged only after room refresh. The durable maintenance object repeatedly sweeps invalidations and comment dispatches every two seconds, re-arms before work, paginates, and provides a checkpoint fallback tick. Active socket rooms independently refresh authorization every two seconds. This does not depend on request `waitUntil` or a minute cron for the five-second invalidation gate.

Room checkpoint identity is also the version identity. Persisted state equality prevents an unrelated snapshot claiming a retry ID. Versions, artifact pointer, origins/change reconciliation, quota and checkpoint event publish atomically; failed publication retains the frozen room save. Restore publication retains original actor and source-version provenance. Published HTML copies verified image assets into version-owned files. Read history is chunked through room storage, with bounded retained metadata and bytes.

MCP document tools use the shared runtime registration and approvals, real service creation and room edits, guarded operation translation and error mapping. JSON-RPC call identity produces stable run change IDs and detects differing replay payloads. Presence heartbeats clear in `finally`; ask selections use canonical normalized room cursors, and blur clears selection. Comments use room-resolved relative anchors.

## Independent production review — 2026-10-27

**Verdict: changes requested.** Reviewed production wiring through `1bb3da36` (including `b729aadf`; the reviewed live-artifact implementation is unchanged in this checkout). This is an independent bounded review, not browser or staging acceptance.

### High — a long checkpoint outage can strand the only durable save

`production-room.ts` stores the checkpoint actor credential with a 15-minute expiry (`storeCredential` and `registerActor`). The room's `save` callback resolves `checkpointActor`, or the original restore actor, and refuses to publish when that credential expires or ceases to authorize. A failed publication leaves the frozen checkpoint pending, but neither the room alarm nor `retryCheckpoints` refreshes that credential: both retry the same save. Thus, if D1/R2 is unavailable past the credential lifetime and the editor has left, recovering storage alone does not publish the pending snapshot; no new request is guaranteed to arrive. A restore additionally selects its original actor reference. The room state survives, but version history, persisted Markdown and downstream readers can remain stale indefinitely. Preserve trusted publication authority for an already accepted frozen room checkpoint while retaining original provenance and scope, or provide another durable recovery mechanism that does not require a live user credential. Test an outage beyond credential expiry, restart, recovery without another request, and restore provenance. This finding follows the production code path; the existing real-worker failure/restart fixture recovers before credential expiry and does not reproduce the elapsed-time case.

## Controller recovery remediation

Accepted room actor provenance is persisted separately from short-lived admission credentials. Each frozen checkpoint binds that provenance durably before publication. Only the internal system service capability can publish using this stored actor; it grants no connection, new edit or restore authority. Publication still validates artifact/workspace/type, refuses deleted artifacts, validates state and own images, enforces quota and stable checkpoint identity, and retains restore source/original actor checks. Ordinary calls still require current access.

The real production workerd regression fails D1 publication after R2 writes, ages every stored credential to 16 minutes before the test clock, restarts, then observes only D1 while the alarm recovers the frozen checkpoint. No authenticated room request refreshes credentials during recovery. It passes, including exactly one published version. This deterministic expiry transition avoids a 15-minute wall-clock wait. Service regressions cover loss of current actor rights, internal-only recovery, workspace mismatch, original restore author and one restore event, and refusal to resurrect deleted artifacts. Full authenticated app and staging gates remain unchanged.

## Independent bounded recovery recheck — 2026-10-27

Reviewed main `d983f853` with merged document client `8b06aadb`. **Verdict: changes requested.**

### Medium — checkpoint provenance is not frozen atomically with the checkpoint

`ArtifactRoom.saveCheckpoint` commits the frozen snapshot and `pending` in a synchronous storage transaction, then calls the production `save` adapter. The adapter only afterwards reads the mutable `checkpointActor` (or `actor:<restore participant>`) and writes `checkpointPublication:<checkpointId>`. A crash or storage failure between these steps leaves a durable pending checkpoint without a receipt. Before its retry, another authorized editor can update `checkpointActor` through authorization or `registerActor`; the retry then permanently attributes the older frozen checkpoint to that later actor. For restores, the participant check limits substitution, but the actor reference can still be replaced before receipt creation. Freeze the accepted provenance in the same durable transaction as the pending snapshot, and cover interruption at that boundary followed by another actor and retry. This is an inferred crash-window finding from the code, not a reproduced runtime crash at that precise instruction.

The ordinary failed-publication path does persist a principal-only receipt keyed by checkpoint ID before external publication, so the existing outage test exercises retry after that receipt exists. The service accepts this bypass only when its caller is system; it checks document/workspace and deletion, validates restore participant and source artifact, and uses the existing checkpoint persistence/idempotency checks. New room operations still resolve current credentials and authorization. The system service capability itself trusts its internal caller to supply accepted provenance; the receipt boundary is therefore essential.
