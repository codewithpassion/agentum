# M5.2 review

## Verdicts

Round 0, commit b0761c1: clean. No must-fix. Ten nits, listed below. No fix round was needed.

## What was built

- Slack tab on the agent page: the steps a person follows, a Download manifest button, a form for the bot token and signing secret, and the list of the agent's Slack apps with Revoke. Checked in a browser on `vite dev` (port 3641): the tab renders, the manifest download raises no error, and a made-up token comes back from the real slack.com as "Slack did not accept that bot token (invalid_auth)".
- `@repo/services/slack-apps` (`slack-apps.ts`, test in `slack-apps.test.ts` with a fake Slack API): `manifest`, `paste`, `list`, `revoke`, session principals only. A `SlackAppSummary` has no secret field, and `slack-apps-router.test.ts` checks that no tRPC output (paste, list, revoke, manifest) contains the token, the signing secret or the stored ciphertext.
- Paste checks the token with `auth.test` (workspace and bot user) and `bots.info` (app id, needs `users:read`), so the form asks for two values only. Both secrets are stored with `slackSecretBinding` and an event `slack.app_installed` lands in the same atomic write. A second paste for the same agent and Slack workspace replaces the secrets and brings a revoked app back (same row, same id); an app id that belongs to another agent is a `conflict`.
- Revoke sets `revoked`, deletes the bot token and writes `slack.app_revoked`. The signing secret stays as ciphertext in the row (the column is NOT NULL), which an app that is not `installed` never reads. Revoke does not call Slack, so the app stays installed in Slack until the person removes it.
- Manifest (`slack/manifest.ts`, copied from Ariadne and cut): scopes from `reuse.html` (`app_mentions:read`, `chat:write`, `channels:history`, `groups:history`, `im:history`, `files:read`, `files:write`, `users:read`, `users:read.email`), events `app_mention` and `message.im` only, `features.agent_view` with the description from the agent name (max 300), Messages tab on, interactivity off, token rotation off. `message.channels`, `message.groups` and `app_home_opened` are not subscribed, because the M5.1 receiver ignores them. `suggested_prompts` is left out (optional in Slack's manifest reference). The bot display name is a slug of the agent name, since Slack allows only `a-z 0-9 - _ .` there. The event URL is `PUBLIC_BASE_URL/api/slack/events`; the manifest refuses to build when `PUBLIC_BASE_URL` is empty.
- Carried from M3.3: `events.onAppend(listener)` runs after `append`. The composition root registers the Slack gateway's `notifyNeedsAuth`, which sends one `chat.postEphemeral` with the Connect link to the person who must connect, once per run and connector, only for a run whose reply target is a Slack thread. The check named in the task is `apps/web/src/server/needs-auth-slack.test.ts` (real composed services, appends the event, asserts one ephemeral to the owner with the path), with unit tests in `gateway.test.ts` and `events.test.ts`. The person is the credential owner for a user login and the run's requester for an agent credential, because an agent has no Slack identity.
- New event types `slack.app_installed` and `slack.app_revoked` (no migration, the column is plain text).
- A worker wrote the manifest, the client methods, the events hook, the gateway method and the UI. The dispatcher wrote the service, the router, the compose wiring and the router and needs-auth tests.

## Nits left

- Each `authorize()` in `slack-apps.ts` builds its resource from the caller's own workspace, so it cannot fail; isolation rests on the `where` clauses, which are tested. This is how the other services are written too.
- A revoked row keeps its `app_id`, so the same Slack app cannot be moved to another agent, and the conflict message ("already connected to an agent") reads wrongly for a revoked app. No test covers it.
- The needs-auth dedupe counts earlier `connector.needs_auth` events, not notices that were sent. If the first notice fails (Slack error, no identity link yet) or the first event had no Connect path, later events for that connector are never notified. It also keys on connector only, so a user-login notice hides a later agent-credential one.
- The listener runs inside the proxy request and the post retries up to three times. A Slack outage can delay the agent's `needs_auth` answer by up to about 30 seconds.
- A Connect link from the `needs_auth` error that the agent repeats in its reply makes the requester see two ephemerals (one from the gateway's reply path, one from this).
- No test pastes an agent from another workspace, or the same Slack app from two workspaces.
- "A refusal from Slack does not echo the pasted token" in `slack-apps.test.ts` cannot fail as written.
- Revoke is one click with no confirmation, and it deletes the bot token.
