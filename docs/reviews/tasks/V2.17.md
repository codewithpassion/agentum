# V2.17 review

The `/sessions` hydration mismatch (React error 418) came from `sessionTitle`, which formatted the creation time in the local zone while the server renders in UTC. A dev build with a session that had an empty title reproduced it: the server text read `23:30` and the browser `10:30`.

## Fix

- `sessions-logic.ts`: the fallback title formats in UTC and ends with "UTC". This also covers the agent sessions tab.
- `receipt.tsx`: the step time on `/tasks/<id>` uses the local zone and the page renders from loader data, so it now shows after mount (`nowMs` is set).
- `session-list.tsx`: the relative time reads the clock, so its `<time>` element has `suppressHydrationWarning`.
- `/desk` and `/agents` already wait for mount or load client-side. Dev builds of `/sessions`, `/agents/<id>`, `/desk` and `/agents` showed no hydration error after the fix.

## Rounds

1. Must-fix: the SSR'd `formatDistanceToNow` on `/sessions` could still mismatch at a bucket boundary. Fixed in 9a3c39f.
2. Clean.

## Nits left

- With `suppressHydrationWarning` the server's relative text stays until the next render at a bucket boundary. Harmless.
- Fallback titles now show UTC where they showed local time.

## Ideas beyond the scope

- The same server-rendered `formatDistanceToNow` pattern sits in `settings.api-keys.tsx`, `settings.machines.tsx`, `secrets-table.tsx`, `routine-table.tsx`, `triggers/format.ts` and the inbox lists. Any of them fed by loader data can mismatch at a bucket boundary. A shared relative-time component driven by `useNowMs` would fix them together.
- `footer.tsx` renders `new Date().getFullYear()`, which differs between server and browser in the first hours of 1 January in a zone ahead of UTC.
