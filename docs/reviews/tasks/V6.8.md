## Nits left

- `slack/requests.ts` `canInteract` lets a `hm_req:<id>:cancel` action through for approval and question rows too, and `requests.cancel` does not check the kind. A forged action id from a linked Slack user could cancel such a request. Limiting cancel to `row.kind === "takeover"` closes it.
- The Cancel action calls the generic `requests.cancel`, not `takeover.cancel`. Behaviour is the same, since `takeover.onEvent` releases the lease on `request.cancelled`.
- When the person who handed back has no Slack identity link in that team, the card shows the raw Clerk user id.
- The "Open screen" link button carries an action id (`hm_req:<id>:screen`), so each click sends an interaction that is parsed and dropped. A non-`hm_req` id would skip the parse.
