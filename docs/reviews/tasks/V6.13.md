- The managed `desktopScreenshot` calls the relay as `{ kind: "agent" }` with no agent id, because its port signature takes only the machine id. The relay accepts it. `pi-run.ts` passes the run's agent id.
- `requests.open` conflicts ("A takeover is already pending", "Agent has no computer") are thrown inside `request_human_takeover`, so the model gets an error with no text. The managed path answers with the message.
- `computerInstructions` names `computer_exec` and its siblings, but a PiRun lists them with the server key prefix (`harbourmaster_computer_exec`).
- In the Linux VM the section holds both the VM guidance and the computer paragraph's "never do the user's work in another sandbox", with no sentence linking them.
