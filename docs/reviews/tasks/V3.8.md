## What changed

- `pi-run-core.ts`: `runsInVm` is false for a dry run, so `#selectEnvironment` in `pi-run.ts` never stores `VM_KEY` for one.
- `pi-run-dry-run.ts` (new): `isReadOnlyCall`, `summaryOf` (masks, then cuts), `skippedText`, the `ask_user` answer.
- `pi-run-gate.ts`: `beforeTool` checks for a dry run before `isRuled`. Non-read-only calls are blocked with "Skipped in dry run: ..." and recorded through `runs.recordDryRunSkip`. `ask_user` gets a fixed answer and opens no question.
- `pi-run-mcp.ts`: `ToolOrigin.readOnly` from `annotations.readOnlyHint`.
- `pi-run.ts`: stores `DRY_RUN_KEY` per run and passes `isDryRun`, `maskerOf` and `recordSkip` to the gate.

- A replayed `beforeTool` after an eviction can log the same `run.dry_run_skipped` twice. The event has no idempotency key.
