## Decisions

- `api_keys` already existed from M0.1, so this task adds no migration. The principal resolver now returns `apiKey: { id, access }` on a user principal that came from a key.
- Keys are managed from a signed-in session only. A key cannot create, list or revoke keys.
- A read-only key cannot start a run. The rule is in `deriveSubject`, so it holds on every bearer route, not just `/mcp`.
- `/mcp` accepts user principals (keys) and run principals (run tokens). Machine and trigger tokens get 403. Clerk OAuth tokens get 401 until M2.2 supplies `verifyClerkOAuthToken`.
- A run token reads sessions and runs of its own agent, and the runs it started. UI sessions are visible only for the user the run acts for.
- A run cannot message an agent that is a `running` ancestor of it, itself included. Ancestors that are not `running` do not count.
- A `requestId` returns the first run only to the same agent, actor, parent run and person. Anyone else gets a conflict.
- Clerk membership answers are cached for 60 seconds in module scope (`apps/web/src/server/mcp/clerk-membership.ts`), because the resolver is built per request.
- `search_sessions` is a LIKE over the raw payload JSON of `message.*` events, with the query JSON-escaped and LIKE-escaped. Payloads moved to R2 are not searched.

## Nits left

- `search_sessions` also matches JSON key names such as `text`, and SQLite LIKE is case-insensitive for ASCII only while the passage cut is case-insensitive for Unicode.
- `sessions.transcript` queries before it calls `authorize()`. The query is already limited to the caller's workspace.
- The busy-ancestor walk also refuses through a finished middle run (A running, B done, C to A).
- `api-keys.create` writes the row and the event in two statements, not through `atomic`. Revoking logs no event, because there is no `api_key.revoked` type.
- The resolver's own 60 second membership cache in `workspaces.ts` never hits on `/mcp` (built per request) and duplicates the module cache. Its comment is stale.
- The membership cache never evicts expired entries, and the Clerk check reads one page of 100 memberships.
- A malformed `PUBLIC_BASE_URL` makes `/mcp` answer 500, and the hostname check runs after authentication.
- `ports.ts` repeats the title truncation of `sessions.ts`.
- No test isolates the `parentRunId` comparison of the requestId check, or a trigger retry. No test pins that `clerkOrgMemberCheck` returns one cached function.

## Ideas beyond the scope

- FTS for `search_sessions`, as the task says for later.
- A cursor or page size on `list_sessions` and `search_sessions`.
- `api_key.revoked` event and a key expiry date.

## Steps for Dom

- Staging and previews have `PUBLIC_BASE_URL` empty in `wrangler.jsonc`, so `/mcp` refuses every host there until O.1 fills it in.
- On a deployment, set `RUN_TOKEN_KEY` and `CLERK_SECRET_KEY` as Worker secrets (`/mcp` answers 503 without them). Keys only work for users who are members of an org in `ALLOWED_ORG_IDS`.
- The manual check: create a write key on `/settings/api-keys`, then `claude mcp add --transport http harbourmaster http://localhost:3000/mcp --header "Authorization: Bearer hm_key_..."` and ask Claude Code to message the agent.
