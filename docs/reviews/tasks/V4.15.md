## What changed

The library page refetches every 5 s while the tab is visible, and on focus (`use-library-refresh.ts`). There is no library stream in the browser (Refinements 2026-10-26), so this is polling. The tick reads the listing directly and keeps the old one on failure. The open file is reread on each tick: a clean editor takes the new text, an editor with unsaved edits shows the existing "changed since you opened it" notice with Reload.

`library-history-panel.tsx` lists versions (version, author, time, op), compares any two text versions with `lineDiff` (new in `library-logic.ts`, tested for insert, delete, change and edge cases) and restores one after a confirm. It shows only for library files, not for the skill editor, which passes its own `io`.

`library-move-dialog.tsx` is the Rename and Move dialog, opened from icon buttons on each list row. It checks the target with `library.stat` first and shows "<path> already exists." before calling `library.move`. The route follows a moved file or folder (`remapPath`), so the open panel and the current folder keep pointing at the item.

Browser check on a local dev server: upload, edit and save gave two versions; compare showed the line diff; restore of v1 wrote v3 with the old text; move into a folder and rename of that folder kept the history (v4 and v5 are move versions) and the open file followed the new URL; renaming onto an existing folder showed the error; a second browser session saw an upload and an edit from the first within 5 s without reloading; a save made after a refresh tick stayed saved; a dirty draft survived a tick.

## Nits left

- `library.tsx`: overlapping list polls have no ordering, so a slow older poll can show the older listing until the next tick.
- `library.tsx`: user actions still use `router.invalidate()`, so a loader failure on one of them shows the error view.
- `library-file-panel.tsx`: a Reload or restore read in flight while the user saves can resolve afterwards with the pre-save text.
- `library-history-panel.tsx`: after a restore the history refetch depends on the file reread succeeding.
- `library-history-panel.tsx`: the author column shows the raw user or agent id, not a name. There is no id-to-name lookup in the library router.
- `library-history-panel.tsx`: raw checkbox input instead of the shadcn checkbox.
- `library-history-panel.tsx`: restore sends no `ifEtag`, so it overwrites a change made after the history was fetched.
- `library-move-dialog.tsx`: the stat check and the move are two calls. The server lets a file overwrite a file, so a change between them is overwritten silently.
- `library-move-dialog.tsx`: in Move mode a folder path that exists fails with "already exists" and does not move the item into it.
- `library-logic.ts`: `lineDiff` allocates an n by m table over the changed middle, so two large versions with edits at both ends are slow. `library.compare` exists on the server and is unused.
- `library-file-panel.tsx`: a file deleted elsewhere stays open until the user closes it.
- `use-library-refresh.ts` repeats the timer and visibility logic of `usePolledQuery` in the inbox.

## Ideas beyond scope

- A real library event stream for the browser (library events carry `runId` and no `sessionId`), which would replace the polling.
- Show author names by resolving user and agent ids.
- A server-side `library.move` mode that moves into an existing folder.
