# V1.1 review

## Verdicts

Round 1, commit a9cd101: clean. `bun run check`, `bun run test`, `bun run build`, `bun run tasks` and the bundle grep for `drizzle` all passed. drizzle-kit reported no schema changes against migration 0013.

## Nits left

- `bun.lock` carries unrelated churn: root `@types/bun` moved from 1.4.3 to 1.4.4, with nested 1.4.3 copies in several packages. Only the `@repo/db` line for protocol belongs to this task.
- `createRequestBodySchema` does not tie `kind` to `display`, so an approval body with a question display passes. V1.9 checks the pairing, or splits the schema on `kind`.
- `toolName` and `toolKey` accept empty strings, while `toolUseId` needs at least one character.
- `questionAnswerSchema.answers` has no cap on entry count or string length.
- The new "Waiting for you" label in `sessions-logic.ts` and the `waiting` entry in `log-logic.ts` have no test. The label differs from the "Waiting for an answer" wording V1.6 plans for `statusLine`.
- The log's cancel button now shows on waiting runs, but `cancelRun` accepts them only once V1.2 lands.
- `@repo/protocol` now depends on `@repo/db` (browser safe, no cycle) to share the request constants.

## Ideas beyond the scope

- `statusLine` in `chat/chat-logic.ts` shows a waiting run as "Interrupted" and `isRunActive` lacks `waiting`. Both are V1.6's.
- The service-side `ACTIVE` and `STARTING` run status lists belong to V1.2.
- Split `createRequestBodySchema` into approval and question variants in V1.9 so the pairing is type-checked.
