## What was built

Migration 0021 adds `qa_questions`, `qa_answers`, `skill_sources` (keyed by `skill_id`, index on `checked_at`) and `map_positions` (primary key `(workspace_id, node_key)`), plus `skill_versions.source_commit_sha` and the index `events_workspace_type_created_idx`. `accepted_answer_id` has no foreign key, as the task says. `@repo/db/shared` gains the Q&A statuses, author kinds and limits, the skill source providers, the map node, port and wire types with `MapGraph`, and the events `qa.asked`, `qa.answered`, `qa.accepted`, `qa.closed`, `skill.update_available` and `map.edited` with id-only payload shapes. `@repo/protocol/skills` gains `githubSkillSourceSchema` (rules from trueforge, GitHub only) and the `GithubSkillFetcher` and `FetchedSkillTree` port types. `qa.asked` and `qa.answered` join `STREAM_EVENT_TYPES` and stay out of the desk stream.

Choices the task left open. `skill_sources.path` is nullable, null meaning the repository root. `map.edited` carries `action` as `"moved" | "reset"` (`MAP_EDIT_ACTIONS`), which V7.5 may extend. `FetchedSkillTree` also carries `commitSha`. `fetchTree` takes `path` as `string | undefined`.

## Nits left

- The ref regex, as in trueforge, allows `main..dev` and a leading `-`. Harmless through the GitHub API, but a ref must never reach a `git` command.
- The `LIKE '%__new_%'` check in `schema.test.ts` cannot fail (`_` is a wildcard, and drizzle renames its temp tables back). The trigger-count assertion is the one that holds. The earlier test at line 143 has the same pattern.
- `qa_answers.workspace_id` and `skill_sources.workspace_id` foreign keys have no refusal test.
