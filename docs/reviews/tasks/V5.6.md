## Decisions

- Cutoffs for the hour, day and 7-day windows are computed in TypeScript from an injectable clock and compared as ISO strings. The decision suggested `strftime`, but that cannot be tested at a fixed time. The boundary tests are deterministic.
- The migration runner goes through drizzle, one statement per entry, in `db.transaction`. No second SQL adapter is needed. Bookkeeping table is `mailbox_migrations`.
- Stored body is the text part when the mail has one, else the HTML (`body_is_html`). Agents read text, and stripping tags flattens paragraphs. The thread view returns `html` only for HTML-only mail.
- Addresses in the thread view carry no display names. Names stay in `raw_headers` for inbound mail.
- Thread resolution: stored `message_id` or `thread_id` matches `References` and `In-Reply-To`, then subject and exact participants within 7 days (threads whose id is a bare row id are skipped, as in the inbox), then `References[0]` or `In-Reply-To`, then the row's own id. A thread the agent starts is named by its RFC `Message-ID`.
- `insertInbound` relies on the unique index (`ON CONFLICT DO NOTHING`) and then reads the winner, so a second delivery that races the first counts as a duplicate. `storeInbound` in the port looks the key up first so a duplicate writes no files.
- The send flow passes our own `Message-ID` header. The inbox did not. If Cloudflare rejects it, every send fails on staging and the fix is one line in `buildSendMessage`.
- `postal-mime` is not added. Parsing belongs to the V5.7 handler, which hands `InboundMessage` to the port.
- `bun.lock` was edited by hand: a plain `bun install` bumped about 300 unrelated lines (`latest` ranges). `bun install --frozen-lockfile` passes.
- Wrangler change is the DO binding and `v6` only. `send_email` (`EMAIL`), `MAIL_DOMAIN`, `MAIL_ZONE_ID`, `MAIL_WORKER_NAME` and `.env.example` stay in V5.7.

## Nits left

- `outgoingRow` applies `capBody` to outgoing bodies, so a held draft over 1 MB is sent truncated on release.
- `draftOf` rebuilds `html` only when the stored body is HTML, so a held draft that had both parts is released with generated HTML.
- `release` reads, sends and moves without a guard. Two concurrent releases both send, and a failure after the send resends on retry. V5.5 must guard it through the D1 message status.
- `sendNew` sends before it records, so a failed `createEmail` leaves a delivered mail the rate limit never counts.
- Inbound `subject`, `to`, `cc` and `raw_headers` have no size cap. A huge header could push a row past the 2 MB SQLite limit. The `date` header is not kept because `InboundMessage` has no date field.
- `./test-db` is a public export and imports `bun:sqlite`. Only tests use it.
- The Durable Object's `emails` rows are never deleted by the port. `deleteEmail` exists but nothing calls it, and file bytes are not removed.

## Ideas beyond the scope

- V5.9's Mail sheet gets `html` only for HTML-only mail. If it wants HTML for every mail, store both parts (two columns, each capped at 512 KB).
- A `MailboxClient` adapter over `DurableObjectStub<MailboxDO>` goes in V5.7. A type test there should pin that the stub satisfies the client.
