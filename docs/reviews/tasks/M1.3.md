# M1.3 review

## Verdicts

Round 0, commit 2f1c5ad: must-fix. `RUN_TOKEN_KEY` and `SECRETS_KEY` were missing from `apps/web/.env.example`, so a CI-style typecheck failed. A repeated `complete { status: "aborted" }` was accepted, but the check says once.

Round 1, commit 0ad7ee8: must-fix. The fix made a service test fail, because `runs.test.ts` still expected a repeated aborted call to succeed.

Round 2, commit a88c609: clean. Check, test and build pass from a CI-style checkout.

The live check also passed by hand: `fake-daemon.ts --echo` enrolled against a local dev server, took the offer for a run sent from the agent page, claimed it, and the page showed "Echo: ping from M1.3" with the run done.

## Nits left

- `packages/services/src/runs/machine-claim.ts`: if `announceStarted` or the reads after the write throw, the run is `running` but the daemon never gets the token. A re-claim answers 409 and the reaper interrupts the run after 90 seconds.
- `packages/services/src/runs/machine-claim.ts`: the claim does not check the agent's `status`, so a machine can claim a run of an archived agent.
- `packages/services/src/runs.ts`: `startRun` returns `status: "queued"` although the machine dispatch has already marked the row `offered`.
- `packages/services/src/runs.ts`: the heartbeat 409 message uses the status read before the write, so after a race with the reaper it can say "Run is running, not running".
- `packages/services/src/runs.ts`: the events 409 check reads the status and then writes, so a batch racing the reaper can be stored after the run is interrupted. Same as in M0.
- `apps/web/src/server/routes/machine-runs.ts`: the `/mcp` URL comes from the request origin, not `PUBLIC_BASE_URL`. Behind a proxy it follows the host the daemon dialled.
- `apps/web/src/server/routes/runs-machine.test.ts`: the resolver is shown refusing the token only after the lease has also passed, so the test cannot tell the `status = running` fence from the `lease_until` fence.

## Ideas beyond the scope

- Daemon retries: a repeated `aborted` now answers 409, so the M1.2 and M1.4 daemon should treat 409 on `aborted` as done.
- `/mcp` does not exist yet (M2.1). The platform entry in `mcpServers` points at it already.
- Connector entries join `mcpServers` when M3 lands.
