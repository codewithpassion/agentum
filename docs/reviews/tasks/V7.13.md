## Findings, each a new task

1. "Ask before Run a shell command" does nothing for a Cloudflare isolate agent. Its shell is the MCP tool `harbourmaster/bash` (the library script sandbox, `SCRIPT_WRITE`), so the gate computes the key `harbourmaster/bash`, while the switch writes the rule `bash`. With the switch on, `date` and `echo done` ran with no card, while "Ask before Write a file" did gate. A script there can write library files, so the write switch can also be bypassed. The platform MCP `bash` tool is offered to every runtime, so a VM or machine agent can also call it past its own switches, and `harbourmaster/library_write` sits outside the `write` rule too. Fix: have the profile's shell and write switches cover the platform tools on every runtime, and say in the profile what each switch covers.
2. A machine agent's `Read` of the file a person had just edited came back as "The user doesn't want to take this action right now" with no approval card, and the run ended `done` a moment later. It happened once, straight after a background `sleep 60` finished and a library edit landed in the same minute. A fresh task reading the same file worked. Not reproduced. Worth a look at what aborts a Claude Code turn when the daemon syncs a file in and a background command ends.
3. The draft step for `v713-machine` put the rules into the Does text as a second "Rules:" block, so the profile showed the rules twice. `v713-walk` did not. Draft prompt quirk.
4. The Machines page has no Revoke button. A revoke went through the `machines.revoke` call from the browser. V6.16 did the same.
