# V7.12 review

Q&A ports, GitHub fetcher and the skills update tick. Branch task/V7.12-qa-skill-wiring.

## Verdicts

Round 1 (36464da, Opus): clean, nothing must-fix. `bun run check`, `bun run test` and `bun run build` pass, and the client bundle has no `drizzle`.

The dispatcher wrote the code itself in one pass instead of starting Haiku workers: the units shared tests and one `compose.ts`, so briefs would have cost more than the edits.

Log notes from V7.9 and V7.11 are done. The V7.7 note is done too, because it was small.

- `github-skill-source.ts` maps HTTP 422 to a "could not find that ref" not-found error.
- `compose.ts` bridges the adapter's `resolveCommit`/`fetchTree` to the store's `resolve`/`tree` (`compose-github.test.ts`).
- `qa_list` takes a `cursor` and its text names the next cursor.

Other choices: `GITHUB_TOKEN` is optional (an empty value reads as unset) and goes to the skills store only. `routes/mcp.ts` passes `qa: true` for every principal. The browser tools are off when the run's agent has `runtimeConfig.browser === false` (`resolveRunBrowser` in `mcp/ports.ts`). The tick job runs `checkUpdates` with a batch of 2 when the UTC minute is a multiple of 5.

## Nits left

- `routes/mcp.ts:386-388`: a run's MCP request reads the agent twice, in `resolveRunComputer` and `resolveRunBrowser`. One lookup could serve both.
- `resolveRunBrowser` and `resolveRunComputer` raise `not_found` for the whole request if the agent was deleted mid-run. `resolveRunComputer` already did.
- `packages/services/src/skills-store/github.ts:82`: `createGithubSkillFetcher` in services is dead code now that `compose.ts` uses the app adapter. It predates this task.
- The tick job ignores the `failures` that `checkUpdates` returns, so a skill whose check keeps failing is visible only in its stamped `checked_at`.

## Beyond scope

- Other V7.9 nits (decompressed-bytes cap, odd filenames outside the selected folder) are still open.
