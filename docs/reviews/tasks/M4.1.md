# M4.1 review

## Verdicts

Round 0, commit 39f7a51: clean. No must-fix, eight nits.

## Decisions

- Migration 0009 drops and recreates `triggers`. SQLite cannot add NOT NULL columns without a default, and nothing could mint a trigger token before this task, so the M0.1 stub held no rows. No table references `triggers`.
- A trigger has `kind` (only `http` so far), `name`, `token_hash`, `token_prefix` (`hm_trg_` plus four characters, for the list), `created_by`, `last_fired_at` and `revoked_at`. A revoked row stays. M4.2 adds routine columns and will have to loosen `token_hash`.
- Ids are `trg_<ulid>`. `findTriggerByToken` in `@repo/services/workspaces` skips revoked rows and serves both the principal resolver and `services.triggers.authenticate`.
- `POST /api/triggers/:id`: 401 for a missing, malformed, unknown or revoked token (checked before the body is read), 403 for a valid token on another trigger's id, 400 naming the first bad field, 413 over 512 KB. Without `waitMs` the answer is always 202 with the run id. With `waitMs` it is 200 with `{ runId, sessionId, status, result, error }` when the run ends in time, else 202. `waitMs` is capped at 120000 (`WAIT_MAX_MS`).
- `requestId` is stored as `trigger:<triggerId>:<requestId>`, so two triggers can use the same id and a replay returns the same run. The same prefix shape is what M4.2 uses for routine occurrences.
- `trigger.fired` is written once per run (a replay does not write it again), with the trigger as actor and `{ triggerId, requestId }` as payload.
- A trigger-started run has `on_behalf_of_user_id` null and actor kind `trigger`, from `deriveSubject`.

## Checks

`bun run check && bun run test && bun run build` pass, and the grep for drizzle in `apps/web/dist/client` finds nothing. Live, against `vite dev` on port 3417 with a fresh local D1: dev login, created a trigger on `/triggers` for the seeded fake agent, then curl: `{"text":"ping","waitMs":5000}` gave 200 with `Echo: ping`; the same `requestId` twice gave 202 with one run id and one run row; a bad token gave 401; the token on another id gave 403; an empty text gave 400 naming `text`. After Revoke in the UI the token gave 401. The local D1 showed `on_behalf_of_user_id` null, one `trigger.fired` event per run, and `last_fired_at` set. The agent page Triggers tab opens and offers Create trigger.

## Nits left

- A trigger revoked between `authenticate` and `fire` gets 403, not 401. Only a race.
- The `trigger.fired` write is separate from the run insert, and the already-announced check is not atomic. Two concurrent replays could write it twice, and a failed write on a call without `requestId` leaves a run without the event.
- `last_fired_at` moves on a replayed `requestId` too.
- The route uses `services.triggers.authenticate` instead of `createPrincipalResolver`, as the machine routes do. CLAUDE.md names the resolver for trigger routes.
- Firing a trigger whose agent is archived gives 404 "Agent not found", and the UI still lists the trigger as active.
- `triggers.revoke` input has no `.max(200)` on `triggerId`.
- Escape or a click outside the secret dialog closes it without a warning.
- No index on `triggers.workspace_id` or `agent_id`.

## Ideas beyond the scope

- Disable or hide triggers of an archived agent.
- Rate limit per trigger, and a `last_fired_at` write that skips replays.
- A `curl` snippet on the agent tab row for an existing trigger (the token cannot be shown again, so this would need a rotate action).
