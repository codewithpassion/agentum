# V6.5 review: computer and browser MCP tools through ports

Takeover is not an MCP tool here. `request_human_takeover` stays a waiting runtime tool (`REQUEST_TAKEOVER_TOOL`) that V6.12 and V6.13 register, and `ComputerPort` has no `requestTakeover`.

## Rounds

Round 1 (b412a90): must-fix. `ComputerPort.readFile` took no byte limit, and agentum's output and paths tests were not ported.

Round 2 (97c4426): clean. Both fixed. `readFile` takes `maxBytes` and the read and edit tools pass `MAX_READ_BYTES`. The ported tests are in `packages/mcp/src/tools/computer-support.test.ts`. The edit tool also checks size before content, and the dead `!old_string` branch is gone.

## Nits left

- `computer_edit_file` is a read then a write over two port calls, not atomic, and limited to 256 KB. Agentum's backend edit was atomic and allowed 1 MB.
- `offline`, `timeout`, `desktop_busy` and `human_in_control` all map to `ToolError` code `conflict`, so `structuredContent.code` hides the real failure type.
- `computer_exec` uses `WRITE_CREATE` and `computer_write_file` uses `WRITE_UPDATE`, both with `destructiveHint: false`, though a command or an overwrite can destroy data.
- `desktop_input` reports `applied` from the input length and ignores the port's `applied`.
- `ComputerPort.screenshot` is unused inside `@repo/mcp`. It exists for V6.12 and V6.13.
- `BrowserPort.screenshot` returns a `url` that nothing says must be absolute. The V6.11 adapter must make it absolute.
- `readOnly` callers lose the computer and browser read tools. Automation and skill tools filter down to their read tools instead.
- `browser.ts` imports `jsonPayload` and `portValue` from `./computer`. They fit a shared file better.
- `ACTIVITY_STREAM_MAX_BYTES` and `byteLength` in `computer-support.ts` are exported but unused outside the file.
- `computerInstructions` dropped agentum's "# Your computer" heading and the computer's name, and the exec description lost the home-directory path note.

## Ideas beyond scope

- An atomic edit method on `ComputerPort` (compare and swap) for V6.11.
- A distinct `ToolErrorCode` for transport failures.
