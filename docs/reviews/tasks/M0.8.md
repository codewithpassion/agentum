## Nits left

- `docs/HANDOVER.md:61` still says services take `{ db, atomic, ... }`, while `CLAUDE.md` now says `{ db, ... }` plus the infra a service needs.
- `CLAUDE.md` mixes hard-wrapped and long lines in the Bun section.
- `ci.yml` does not pin the Bun version. `bun-version-file: package.json` would match `packageManager`.
- `packages/db/README.md` and `CLAUDE.md` describe `@repo/db/<module>` query functions, but `packages/db` exports none yet. Services query the schema directly.
- The docs describe the bearer-authenticated routes (`/mcp`, machine, Slack, trigger, file) in the present tense, but those lane routes are not built yet. `composed` is set only for `/api/*` in `server.ts`, so a route mounted at `/mcp` needs its own middleware to read it.
- `agents.ts` and `runs` append events after their `atomic` write, outside it. The docs say rows that must land together use `atomic`, which these appends do not.
- `.github/workflows/preview.yml` triggers on `pull_request`, against the GitHub rule in `docs/workflow.md`. Nobody opens PRs, so it never runs.

## Beyond the scope

- The task check says a planted `import "drizzle-orm"` fails the bundle grep. A bare import is tree-shaken (`drizzle-orm` is `sideEffects: false`), so the grep passes. An import whose value is used, such as `sql`, fails it. The check should say so. `docs/tasks/` belongs to the controller, so it is not edited here.
