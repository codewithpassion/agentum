# M1.5 review

## Verdicts

Round 1, commit 5b9b8f0: must-fix, three items. Send was not gated on an interrupted run, Retry had no in-flight guard, and switching tabs dropped the `session` search param.

Round 2, commit 0a09f22 (fixes only): clean after 1 fix round.

## Decisions

- The task's `sessions.transcript` did not exist, so the task adds a sessions service (`@repo/services/sessions`) with `list` and `transcript`, and the tRPC router `sessions`. `transcript` returns the message and tool events, the session and the latest run with its input text, so the chat polls one call.
- A `ui` session is visible only to the user who opened it. Sessions of other origins (slack, mcp, trigger) are visible to every workspace member.
- Chat sessions use `runs.start` with origin `ui`. The first message has no key, and the session's own id is its key afterwards. The `session` search param on the agent page carries the open session, and the Sessions tab opens one in the Chat tab.
- Send is blocked, like Retry, while the latest run is interrupted until `process_ended_at` is set or ten minutes have passed. The server does not enforce this gate.
- Runtime is read only when editing an agent, because the update schema has no runtime field. The runtime select offers `fake` in dev builds only.
- The enrol dialog shows `harbourmaster enroll <code> --server <origin>`, the command from M1.2's scope.

## Checks

`bun run check && bun run test && bun run build` pass, and `! grep -rl drizzle apps/web/dist/client` holds. The dev login link was not clicked because the browser session was already signed in as the dev user.

## Nits left

- `chat.tsx`: if the first transcript load fails, Send stays disabled until the page is reloaded.
- `chat.tsx`: the hint under an interrupted run mentions Retry only, not why Send is disabled.
- `chat.tsx`: polling of an interrupted run can run up to 15 seconds past the ten-minute mark, because `nowMs` ticks every 15 seconds.
- `chat.tsx`: Retry resends only the input text, not input files. The UI has no attachments yet (M1.6).
- `chat-logic.ts`: the ten-minute window compares the browser clock with server timestamps.
- `sessions.ts`: `transcript` queries the session before `authorize()`, though the query is workspace-filtered. The list is ordered by `createdAt`, not `lastRunAt`. It loads full run rows for 50 sessions. Non-ui visibility compares `actorId` only.
- `agent-form.tsx` and `settings.tsx`: an agent on a revoked machine shows "Choose a machine" while the form still holds the revoked id.
- `enroll-dialog.tsx`: the "Copied" reset timeout is not cleared on unmount.

## Ideas beyond the scope

- Enforce the interrupted-run gate in `startRun`, so a script cannot start a second process on the same session.
- Show the machine name on the agent page and the machine's agents on the Machines page.
- A revoke button on the Machines page (the `machines.revoke` procedure exists).
- Cap `events.transcript` and page it, since the chat re-reads the whole transcript every 1.5 seconds.
