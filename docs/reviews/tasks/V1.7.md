# V1.7 review

Branch task/V1.7-slack-request-cards. Implemented by Codex, reviewed by Opus.

## Verdicts

Round 1 (8e0bfa3): must-fix. Three items.
- Choice button `value` held the full question and choice, over Slack's 2000 character cap.
- Modal `private_metadata` held all questions, over Slack's 3000 character cap.
- One choice button settled a request that had several questions, leaving the rest unasked.

Round 2 (6a19abe, fix commit): clean.
- Buttons and the modal carry indices only. `parseInteraction(payload, questions?)` takes the stored request's questions as a second argument and answers `questions_required` without them.
- Choice buttons appear only when the request has exactly one single-select question. Every other shape goes through the modal, where single-choice questions get `radio_buttons`.
- Fallback text is escaped, `modal_required` returns the identity and `trigger_id`, and an empty modal answer is `invalid`.

## Differences from the task file

The task file says `parseInteraction(payload)`, buttons for any single-choice question, and checkboxes only for multi-select. The code differs on all three, for the reasons above. V1.13 must load the stored request after `questions_required` or `modal_required` and parse again with its questions.

## Nits left

- `settledCard` fallback text adds `status` (with the caller's `by`) unescaped.
- `questions_required` carries no identity, so V1.13 loads the request by id before checking app and team.
- A stale `choice:q:i` action does not check that the request has one question. The card never emits one, and the request service should check answer completeness.
- A whitespace-only free text counts as an answer.
- An empty modal submission is a generic `invalid`, so V1.13 cannot return a field-level `response_action: errors`.
- A multi-question card repeats the same "Answer" button under every question.
- A lone single-choice question gets buttons only, with no way to give free text from Slack.
- Dead `clicked ? "foreign" : "invalid"` branch in `parseAction`.
- `cut` after escaping can split an entity (`&amp;am…`).
- No test for a radio with nothing selected or a multi-select with nothing ticked.
- Multi-select answers join with ", ", ambiguous when a choice contains a comma (protocol shape).
- `settledCard` keeps the "Expires" line.

## Ideas beyond scope

- A shared helper for the request service to check that an answer covers every question.
- Return `response_action: errors` from the modal handler for an empty answer.
