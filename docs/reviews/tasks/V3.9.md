# V3.9 review

## Verdict

Round 1 (bbc31c1): clean. No must-fix findings. `bun run check`, `bun run test` and `bun run build` pass, and the client bundle has no drizzle.

## What changed

`registerTools` gates once. With a `dryRun` option set, a tool whose `readOnlyHint` is not true calls `record` and answers "Skipped in dry run: would <action> <summary>" without calling its port. A recorder failure becomes the generic error result. The MCP route passes the option only for a run principal with `dryRun` set, and the recorder calls `services.runs.recordDryRunSkip`. The library `bash` tool is gated like a write tool, and its skipped text says cloud runs read the library with Pi's `read` tool instead. `run-tokens.ts` needed no change.

## Nits left

- `register.ts` imports the `ServerOptions` type from `server.ts`, which imports `registerTools` back. The cycle is type-only.
- The action text comes from the lower-cased tool title, so some skips read awkwardly, for example "would enable or pause routine {...}".
- The route test covers the dry-run case only. Existing route tests cover a normal run token.
- The skipped text repeats the raw input, while the stored event is masked by the runs service. The caller supplied that input.

## Beyond scope

A per-tool action phrase on `ToolDefinition` would give cleaner skip text. It repeats across 20 tools, so it needs its own task if wanted.
