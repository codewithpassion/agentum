# V1.12 review

Verdict: clean after 1 fix round.

Round 1 reviewed 78df4fa and found three must-fix items: an answer that failed the protocol was retried forever (status 0), the gate's retries had no limit so a hook could outlast its timeout and let the tool run, and an `always_allow` answer did not stop the gate asking again in the same run. Round 2 reviewed the fix commit b26049a and found nothing must-fix.

## Spike

Under bypassPermissions with the real SDK 0.2.119 and `claude` 2.1.310: a PreToolUse hook that awaits 70 s with a matcher `timeout` of 300 still decides the call (allow and deny). A deny reason reaches the model. AskUserQuestion is not offered unless the query has a `canUseTool`; with one set (and bypassPermissions kept), the hook runs first and `updatedInput` with `answers` plus `allow` returns the answers to the model, and `canUseTool` is not called. So the gate is the hook, plus a `canUseTool` that allows at once. Scripts and logs are in `tmp/V1.12/`. The finding is at the top of `apps/daemon/src/approvals.ts`.

## Nits left

- `approvals.ts` question branch: the log line and the `?? REASONS.unavailable` fallback for a question answered with an approval answer never run, because `outcomeText("question", ...)` throws and `decide` catches it. The result is still a deny. The test for it passes through the catch.
- `MAX_RETRIES` comment: the loop allows 11 failures (first try plus 10 retries), and "about five minutes" counts only the backoff. The worst case with the 30 s request timeout is about 10 minutes.
- `key.includes("/")` in the approval summary relies on only MCP keys containing a slash. `@repo/protocol` does not state that.
- No delay between pending polls: a Worker that answered `pending` at once would be polled in a tight loop.
- The default `sleepUnlessAborted` has no test, and most executor gate tests call the hook after the run finished.

## Ideas beyond scope

- The platform could say in the claim which tool keys an `always_allow` answer turned to allow mid-run, so two runs of one agent agree. Today only the run that was asked stops asking.
- A shared helper for "is this a retryable RunApiError" would serve the gate and the event batcher.
