## Fixes made

1. Tool keys follow the artifact's maker (`grants.ts`, `service.ts`, test in `grants.test.ts`). `checkManifest` named tools by the calling agent's connectors while `recordVersionGrants` and the call path use the maker's. A second agent handed an app could not update it ("Unknown tool shop/list_orders"). Update and restore now check against the artifact's maker, new artifacts against the caller as before.
2. A manager can open a proposed version, as a restricted viewer (`shares.ts`, `artifact-frame.tsx`, the viewer route, tests in `shares.test.ts`). The viewer said "Version not found" for a proposed version, so a person pressed Promote without seeing the page. The owner or an admin can now open it; anyone else, and a rejected version for everyone, still gets not found. Review round 1 found that a plain member token would run the unreviewed server part with the manager's storage rights, so a proposed version opens with a `test` token (reads the shared area, writes nothing, calls no tool) and the frame answers none of the page's tool and storage calls: `artifacts.open` returns `preview: true` for a proposed version (an optional field added to its output) and both the viewer route and the thread card pass it to the frame, since the thread card shows exactly the version an agent just published. Checked locally: the proposed v4 of "Client intake" renders, and its form submit answers "forbidden: this viewer cannot write the shared area". On staging the preview of "B10 Client intake" v2 rendered the new heading, but that was deployed before this change, with a member token.
3. `artifact_test` with no version opens the latest version that is not rejected, like `artifact_promote` (`mcp/artifact-ports.ts`, test in `artifact-ports.test.ts`). For an app with no live version it answered "Artifact not found", which every agent hits right after `artifact_create`.
4. Connecting a connector with OAuth caches its tool list (`connector-oauth.ts`, test in `connector-oauth.test.ts`). OAuth connectors kept an empty tool list for ever (staging's "The-Brain" has none), and artifact grants read that cache, so no tool of an OAuth connector could be granted. Not deployed to staging: this commit came after the deploy. See steps for Dom.
5. 40 px tap targets on phones for the hand-to dialog (rows and close button) and the grant approval card's Approve and Reject (`hand-to-dialog.tsx`, `grant-approval-card.tsx`).
6. `vite.config.ts` sets `server.cors: false`. In dev, Vite answered CORS preflights itself and refused the `null` origin of a sandboxed frame, so any POST from an app page to `api/*` failed ("No 'Access-Control-Allow-Origin' header") and never reached the Worker. B.8 drove the gateway with curl and Miniflare, which send no browser preflight, so it did not see it. Dev only: the deployed Worker answers OPTIONS itself.

## Findings, not fixed

1. A copied `apps/web/.env.local` carries `PUBLIC_BASE_URL` of another worktree's port. The cloud run's MCP client then fails with "Network connection lost" and the run hangs in `running`. Set it to the dev server's own port. Whoever sets up a worktree next hits it.
2. Local dev harness: a second message in the same session to the scripted `faux` model answers "echo:" with an empty prompt. Start a new session (new `externalKey`) per scripted call.
3. The share dialog lists `harbourmaster.json` under "Data files", and "Created by" in the link list shows the raw user id (A.14 noted the id).
4. An app that declares hosts fails its own `artifact_test` when its page calls `/api/*` on load (403, "This link cannot use the app's server"). That is B.8's rule for test tokens, and it means an agent cannot see the server part work before it asks for approval. The page also cannot be previewed end to end by the owner until the hosts are approved.
5. The live dashboard fixture shows an error for link viewers because it writes the viewer area before reading the tool, and the frame refuses that area for links. B.1's proposal was to allow it for live links; B.7 chose to refuse in the frame. Decide which one is meant.
6. `artifact_test`'s text snapshot is taken before the page's fetch finishes (A.11's finding 5): the Haiku and Sonnet runs on staging both noticed an empty "Submissions" list and had to say they had not confirmed it.
7. On staging the first `artifact_create` of "B10 Client intake" failed once with "index.html is missing" (the task folder had not synced), and worked on the agent's retry.
8. The flood guard (30 a minute per link token) is lower than the service's 60 a minute per link, so with exact counting the 60 is never reached, and calls the guard refuses write no row (R2.13 and R2.14). Raise the binding, count in the service, or write a row for guard refusals.
9. Not run: a second member's own call (R2.5 "each member"), a non-owner creating a live link, `granted_by` leaving the org, the 1,000 a day limit, the 20 MB cap, Safari.
