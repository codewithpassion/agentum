# V1.13 review

Branch task/V1.13-slack-answer-surface. Built by Haiku workers under a Sonnet dispatcher, reviewed by Opus.

## Verdicts

Round 1 (ec03cb3): clean. No must-fix. Signature and team are checked before any payload field is trusted, the named request is scoped to the app's workspace and agent, the identity link and session visibility are checked (through `requests.outcome`) before an answer or a modal, and the route acks before any Slack call.

## What was built

- Manifest sets `interactivity` on with `request_url` at `/api/slack/interactions`. The Slack tab says installed apps must paste the new manifest.
- `slack/requests.ts`: `onEvent` posts the card on `request.opened` (thread of a Slack run, otherwise a DM to `on_behalf_of_user_id` with a linked Slack identity and an installed app) and stores `slack_message` as `{ appId, channel, ts }`, with `appId` Slack's `api_app_id`. It settles the card on `request.answered`, `request.expired` and `request.cancelled`. `interact` verifies and reads a click or modal submission, then returns an `after` job.
- `SlackClient` gained `updateMessage` (`chat.update`), `openView` (`views.open`) and `blocks` on `postMessage`.
- Route `POST /api/slack/interactions`; `slackRequests` in `Services` and `compose.ts`.

## Nits left

- Fallback `text` is escaped twice: the card builders escape it and `postMessage` / `updateMessage` escape it again, so `&` shows as `&amp;` in notification previews. Blocks are fine.
- A refused interaction (bad signature, wrong team) is not recorded as `slack.event_refused`, unlike `/events`.
- No test for a correctly signed payload whose `team.id` differs from the app's team.
- `principalOf` repeats `findLink` from `slack.ts`.
- A modal submission that fails to parse (a choice question with neither text nor a choice) closes the modal with nothing answered. `response_action: "errors"` would keep it open.
- A failed `views.open` (such as an expired `trigger_id`) is logged and the person sees nothing.
- The settled card does not name who answered (`by` is not passed).
- If the agent row is gone, `cardOf` throws and the card is not settled (logged).
- Without `defer` (Pi run requests, the cron path, SSR contexts) the Slack calls run inline with retries, up to a few seconds. `notifyNeedsAuth` has the same exposure.
- The Slack tab notice mentions Allow and Deny only, but question buttons and the modal need interactivity too.

## Ideas beyond scope

- Pass the answerer's name to `settledCard` (`by`) using `linkedPeople`.
- Return a field-level error from the modal handler for an empty answer (V1.7 idea too).
- Share one `findLink` between `slack.ts` and `slack/requests.ts`.

## Steps for Dom

- Paste the updated manifest (interactivity on, request URL `<origin>/api/slack/interactions`) into each agent's Slack app: App Manifest on api.slack.com/apps, save, and approve the change if Slack asks. Without it Slack sends no clicks.
- Live check on staging: start a run from Slack that needs an approval, confirm the buttons appear in the thread, click Deny, and confirm the web card shows the denial (the web wording "Denied in Slack" is V1.14).
