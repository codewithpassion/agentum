## Nits left

- A file-level grant equal to `path` leaves `<path>.conflict-<runId>` outside the run's scope. Checking `canWriteAt` on `conflictPath` as well would close it.
- `recordConflict` does not check that the copy exists. A row for a missing copy cannot be resolved, because `resolveConflict` reads and removes the copy and throws `not_found`, so it stays in Needs you.
- A run without write scope gets `invalid` (400), not `ForbiddenError`.
- Write scope is checked only at record time, not again at resolution.
- A copy overwritten by a move closes with resolution `moved`, and the test does not assert that value.
- No route-level test for a refused mismatched `conflictPath`.
- `recordConflict` does not dedupe, so a daemon retry opens a second row. Resolving one closes both.
- `remove` takes a loosely typed positional `resolution` string.
- `resolveConflict` repeats the `choice` runtime check that the type and zod enum already give.
- The conflict card title is only `path`. It names neither the copy that keep-library deletes nor the agent.
- keep-agent is two atomic batches (write, then remove). If the remove fails, the row stays open and a retry writes another version.
- The Needs you provider test sits in `desk.test.ts`, not `library-conflicts.test.ts`.
