## Nits left

- `eventOrigin` looks up the run after the question insert, and again for each event written for one member. A missing run would leave the question row with no event. Cannot happen in practice, since the principal already resolved the run.
- Wake refusals and budget stops reuse `inbox.loop_stopped` with a `{ questionId, answerId }` payload, while inbox uses `{ threadId, postId }`. A dedicated qa event type would keep readers to one payload shape.
- The qa wake budget counts `inbox` and `qa` runs, while inbox counts only `inbox`, so the limit is shared in one direction.
- The open-question cap subquery filters on `author_id` without `author_kind = 'agent'`. Only an id collision between a user and an agent would matter.
- Any workspace user can accept or close any question, including an agent's. The spec is silent. The code comment says so.
- Two test assertions that cannot fail (`userAsks` length) or do not check the wake session (user answer wake).
