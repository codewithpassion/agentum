## What changed

`scripts/codex-task.sh <worktree> <brief file> <log dir>` runs `codex exec` with `--dangerously-bypass-approvals-and-sandbox`, `-C <worktree>`, model `gpt-6.1-sol` and medium reasoning effort. The brief comes in on stdin, JSONL events go to `<log dir>/codex.jsonl`, the final answer to `<log dir>/last-message.md`, and `timeout` stops the job after 90 minutes. It prints one line with the exit code, whether the usage limit was hit and the last-message path. `CODEX_TASK_TIMEOUT` overrides the limit, which is how the 1-minute test ran. The script resolves the worktree with `realpath`, so `..` and symlinks cannot get out, and refuses anything that is not under `/home/roboto/devel/harbourmaster-wt/` or has no `.git` file. `docs/HANDOVER.md` "Session setup notes" says how Codex runs and why the sandbox is off. The stale "nobody has verified" line about Codex is gone.

## Nits left

1. `mkdir -p` and `realpath` for the log dir have no failure check, so an unwritable log dir prints `codex exit=1` instead of a refusal.
2. The log dir is created before the worktree check, so a refused run leaves an empty directory.
3. Nothing stops the log dir from being inside the worktree, where Codex could commit the logs.
4. Any linked worktree under `harbourmaster-wt/` passes, including one from another repo.
5. The usage-limit grep covers the whole JSONL, so a command that prints `docs/workflow.md` could report `usage_limit=yes` falsely. The exact ChatGPT message is not known yet, so the match stays loose.
6. The first 1-minute loop run was killed by hand (exit 143) because it started with the default limit. The 124 result came from the second run, whose output went to the terminal and not to a file.
7. The smoke brief is a trimmed Codex template.
