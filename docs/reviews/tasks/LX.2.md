## Delivered behavior

`POST /api/live-artifacts/:artifactId/export/:format` accepts `docx`, `pptx` or `pdf`. Documents support Word/PDF; decks support PowerPoint/PDF. The route is mounted in the real Worker entry point and `composeWith` constructs `liveExports` from the actual live service, rooms and file services. Production composition supplies `exportPrintPDF(env.BROWSER)` through the existing Browser Run infrastructure. There is no unwired-port handoff or new deployment configuration dependency beyond the added rate-limit binding.

The route authenticates through `authenticateRoomRequest`, requires a member/user principal, applies CSRF protection and the export rate guard, and replays the original request credential throughout generation. Run/system identities are refused; guests are never cast into a Principal. Owner, editor, commenter and viewer access follows `createLiveAccess`, including current workspace, audience, member grants, expiry, deletion and credential restrictions. Access and credential checks run before capture, around asset retrieval, after generation and immediately before returning bytes. The final check is a delivery authorization point, not a promise that already-delivered bytes can be recalled after a later revocation.

Capture uses `rooms.snapshot` → the existing room's serialized `authoritativeSnapshot`. It exports accepted room state at the reported revision, without applying a client update, checkpointing, restoring, overwriting local edits or changing permission. In-flight local edits can be absent, as the UI explicitly explains. No client supplies a snapshot, rendering HTML, asset URL or network destination.

Own assets come from the current artifact's server-side inventory. Only exact canonical `/files/<opaque-id>` paths are accepted. The engine receives a copied allowlist; every actual read rechecks current access and inventory, preflights real file metadata through `files.describe`, retrieves through authorized `files.download`, and caps the stream before joining chunks. Ownership is checked again after retrieval and for all used paths before delivery. Files from another workspace cannot satisfy retrieval. No public-file HTTP request, signed public URL, arbitrary URL fetch or redirect-following fallback is used. The accepted engine still enforces PNG MIME/signature, complete stream validation and its image/aggregate budgets. JPEG, SVG, GIF and other unsupported inputs remain explicit export refusals; no silent missing-image success or normalization service was introduced.

Responses are binary with the correct Office/PDF MIME, an ASCII-safe title-derived `Content-Disposition` filename, `private, no-store`, `nosniff`, accepted revision, and bounded URI-encoded structured warning metadata. Refusals, authorization endings, timeouts, unavailability and unexpected failures return structured errors; infrastructure details are not exposed.

Both real member pages mount the shared export controls. Preparing a file keeps the editor mounted. A review dialog shows the accepted revision and every format warning before its explicit download button creates the browser download. Cancel discards the prepared result. Ownership/media restrictions and Office/font/interactive-content limitations remain visible even when no engine warning is emitted. Failures are confined to the export controls. Disconnect/unmount cancels the request and clears a prepared download; object URLs are released after use.

## PDF execution and bounds

`browser-run.ts` remains the single production import point for `@cloudflare/playwright`. Export launches a dedicated ephemeral browser, never an agent's persistent session. Its page disables JavaScript and service workers; all network routes are aborted. Only the accepted engine's static HTML, embedded validated PNGs and generated geometry reach `setContent`. Printing uses print media, CSS page sizes, print backgrounds and no browser headers/footers. The browser closes on success, content/print failure, cancellation and acquisition finishing after cancellation. Failed page creation also closes the acquired browser. The original request signal and the service deadline cancel ongoing work; the composition root's existing `defer`/`waitUntil` retains pending cleanup after a deadline response.

Bounds: six admitted exports per minute per workspace/member key, in each rate limiter's enforcement location; a 45-second service deadline (test injection can only shorten it); 15-second content loading and 20-second PDF operation timeouts; 4096 inventory entries; 4096 streamed chunks per asset; 5,000,000 bytes per asset; engine aggregate image/reference budgets of 20,000,000 bytes; 16,000,000-byte checkpoint; 24,000,000-byte print HTML; 32,000,000-byte final output; 24,000 encoded warning-header characters. Existing engine projection, dimensions, decoded pixels and shared schema limits also apply. The Browser Run binding and compatibility date/`nodejs_compat` already existed in production, staging and previews. `EXPORT_LIMIT` is now declared in all three, with separate namespace IDs 2012/2013/2014. No schema or migration was added.

These are admission/output/deadline guards, not a hard memory reservation or globally serialized job queue. A JavaScript deadline cannot preempt synchronous authority decoding or Office library work; intermediate allocations precede some final bounds. Cloudflare rate limiting is not a global cross-location concurrency lease. Production worst-case quota qualification remains a release gate below.

Primary references retrieved 27 October 2026: [Cloudflare Playwright/Browser Run](https://developers.cloudflare.com/browser-run/playwright/) and [Workers best practices](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/). Checked the pinned Playwright 1.3.5 declarations, installed Wrangler schema/help and generated Worker binding/runtime declarations. No external paid browser session was launched.
