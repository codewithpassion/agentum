## What changed

- The Slack gateway takes `library` (`read`) and `taskFiles`. At delivery it lists the run's task folder as the run's user (`via: "slack"`), keeps the files that have a `library_versions` row with this run's id, and uploads them through `library.read` as the run. A file outside the folder, or one a person added to it, is not posted.
- The old limits stay: one file in memory at a time, the 20 s upload budget, and a failed file named in the `slack.delivered` event. The size cap is `MAX_FILE_BYTES` (50 MB), checked against the folder listing before the read.
- Whether to defer the delivery now depends on the folder listing, not on `message.fileIds`. A run with no user, or a listing that fails, posts the text and records `task files: <reason>` in the event.
- `completeRun` no longer writes `outputFileIds` or puts it in `run.finished`. It still checks the ids a runtime reports and passes them on to the reply gateway, so the inbox keeps its attachments. Slack ignores them.
- `stripAttachmentMarkers` stays for old text.
