# M0.3 review

## Verdicts

Round 1, commit 5b6b877: clean, no must-fix. Zero fix rounds.

## Nits left as they are

- `payload_ref` stores only the blob key. The sha256 and byte count that `capPayload` computes are dropped, so nothing checks blob integrity on read.
- `events/payload.ts` keeps a copied comment about a `payloads/<yyyy>/<mm>/<dd>/<client_id>/...` key. The service uses `payloads/<workspaceId>/<eventId>.json`.
- `transcript(sessionId)` takes no workspace id, as the task specifies. The caller must check the session's workspace first. It also has no limit.
- `transcript` could use `inArray` over the known `message.*` and `tool.*` types instead of `LIKE`.
- `query` orders by id while the only workspace index is `(workspace_id, created_at)`, so SQLite may sort in memory.
- `toRecord` parses `type` and `actor_kind` strictly, so one row with a type dropped from `EVENT_TYPES` makes a whole read throw.
- A payload is parsed three times per append (input, after redaction, inside `capPayload`).
- `EventInput` types `payload` as `unknown`, because the schema pipes through a transform.
- `append` calls `new Date()` directly. M0.4 specifies an injected clock for runs.
- The `hm_` token pattern in `redact.ts` is anchored to a whole string and has no `.`. Check it against the real run token format once M0.5 settles it.

## Ideas beyond the scope

- A size ceiling on blob payloads. Depth and node limits exist, but a payload has no byte limit.
- Order and cursor `query` by a covering index if workspace feeds grow.

## Steps for Dom

None for M0.3. The events service is not in `apps/web/src/server/trpc/context.ts` or the add-clerk template copy. That needs an R2 bucket binding (top level, `env.staging`, `env.staging.previews`), so M0.7 should wire it with an R2 adapter for `blobs`.
