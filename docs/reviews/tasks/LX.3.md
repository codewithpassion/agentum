## Implementation

The authenticated `/a/$artifactId` page and dashboard route now mounts `ElementAskViewer`, the existing sandboxed `ArtifactFrame`, an agent selector and the real shared agent transcript. The injected bridge offers an element picker only when the member frame enables it; link and proposed-version frames do not. Picking intercepts the click, records the artifact-relative HTML file, structural CSS selector, tag, bounded rendered text and HTML, and outlines the element with a separate overlay. The picker checks connectivity, the full original element HTML and selector/context again before sending; DOM changes require a new selection. Escape clears it. The overlay never edits artifact DOM content. Desktop and mobile have a usable picker and separately scrollable transcript.

The request uses the existing nonce/window-source/MessagePort bridge and `ui/message`, then the mounted viewer's typed `liveArtifacts.askElement` procedure. Artifact and version identifiers come from the host frame's opened content URL, not the iframe message. Strict schemas reject submitted workspace, speaker, role, session, roster and other authority fields. The service checks current workspace membership, preserves the authenticated credential restrictions, intersects current admin membership, resolves effective artifact role, verifies published current version/artifact ownership and HTML file membership, and rechecks the version after identity resolution. Hidden targets, viewers/read-only credentials, unavailable agents, old versions and missing files refuse the request. The actual RunsService persists a member actor, on-behalf-of member and artifact-origin session; the normal member tool model is preserved, and guest execution is not enabled. DOM context is explicitly marked `untrusted_artifact_dom` under `where.pageElement`, with trusted artifact/version provenance outside it. Shared-session model instructions identify this metadata as data rather than instructions or speaker authority. Stable request IDs return the existing authorized run after retry; editing a question generates a new request ID, and the field is locked while sending.

Document and deck comment/reply composers now offer “Mention member by email”. The server resolves a verified address through the existing Clerk email-member lookup and uncached current membership check, verifies artifact access, and inserts an explicit `@[Name](member:user_id)` token. Ordinary `@words` and agent mentions remain separate. Readers see the member label. Parsing deduplicates recipients, caps fanout at ten, and suppresses self-mentions. A direct caller can submit a token but cannot bypass the same current recipient checks at delivery.

Unique per-comment/per-member delivery intent commits atomically with the comment, thread and audit event. The guest/schema owner supplied standalone migration `0031_large_nightmare.sql` and `artifactMentionDeliveries` in commit `6ff7a4c6`; this checkout cherry-picked it as `5108aa36`, plus controller inventory fix `24d93e20` as `f5399f92`. This lane generated no schema. The outbox stores no address or message body.

Production `LiveInfra.mentions` uses the configured EMAIL binding and existing mail domain, with a separate escaped plain-text/HTML mention template. The durable live-maintenance alarm processes `retryMentions`. Every attempt joins comment → thread → artifact with workspace equality, reloads current stored body/title, checks deletion and intended member ID, and resolves current verified primary address, membership and artifact access. Directory/transport failures remain retryable; removed/inaccessible recipients are suppressed. Email excerpts are limited to 500 characters and titles to 120; links stay on the configured application origin and identify the artifact/comment thread. The diagnostic delivery header contains the stable intent ID.

## Delivery semantics

Claims conditionally increment persisted attempts while `attempts < 5`, with a fresh UUID lease token and a 60-second lease. Concurrent workers cannot claim the same live lease. Ownership/expiry is checked before sending and acknowledging, and acknowledgement matches the exact token, so an old worker cannot complete a newer attempt. Completed intents are never resent. At five claims, automatic retries stop and the pending row remains available for operational inspection; there is no unbounded retry or automatic reset.

External email delivery is bounded at-least-once attempt processing, **not exactly-once email**. The EMAIL adapter has no verified provider-side idempotency guarantee. A successful send followed by a lost acknowledgement/crash can cause another email after lease expiry. Tests deliberately demonstrate that ambiguity using the same stable delivery ID. An intent can also exhaust its five attempts without a confirmed delivery. The `completedAt` marker covers both successful sends and suppressed recipients; it is not an SMTP delivery receipt.
