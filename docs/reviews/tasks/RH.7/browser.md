# RH.7 browser walkthrough (local)

Verdict: PASS on local. All eight flows work at 1280x800 and 390x844, and the wall's state sort matches `sortCards` on real data in all four states. During the flows the console showed no app errors and no request failed (4xx/5xx). The only console errors came from a test setup problem, and I list them under "Things to know". Staging was not run (local only, per the brief).

Run on 2026-11-20 against `task/RH.7-roster-e2e` at a35052b2. `vite dev` ran on port 5217 with a clean `.wrangler`. I signed in with dev login, desktop and phone each in their own agent-browser profile. The question in flow 6 was raised by a real agent, not seeded: a drafted agent on the Cloud (Pi) runtime called its `ask_user` tool with the workspace Anthropic key.

At 390 px, `scrollWidth` was 390 on every page I visited: `/home`, `/agents/new`, `/agents/<id>` and all seven room tabs, `/threads/<id>`, and `/desk?item=<id>`. No page overflows. At 1280 px every page was 1280 as well, including the `/settings/*` pages.

## Findings

1. small-fix: The room header ignores the agent's stored avatar. The home card draws the stored avatar (for example "L" on green for Lunch Planner, and "L" on green for Long-Form Blog Writer). The room header and the builder's draft card draw initials and a colour taken from the name ("LP" violet, "LB" red). One agent shows two different avatars. Files: `apps/web/src/components/agent/room/room-header.tsx` (`agentInitials`, `agentTileColour`) and `apps/web/src/components/agent/builder/draft-card.tsx`. Compare `desktop-2c.png` with `desktop-3.png`, and `desktop-5b.png` with `desktop-8.png`.
2. small-fix: A card's job line is cut at 80 characters in the middle of a word, with no ellipsis. Standup Helper reads `Starts each conversation by asking a single question: "What did you finish yeste`, and Long-Form Blog Writer reads `... on any topic it is given` with its full stop missing. The first sentence is not found either when it ends in `?"`, because the split wants whitespace straight after the punctuation. File: `packages/services/src/roster.ts` (`jobLineFor`, `JOB_LINE_MAX_CHARS`). `desktop-7a.png`.
3. small-fix: A card whose owner is not a workspace member shows the label "Owner" with nothing after it. The seeded Fake echo (created by `seed-script`) shows this. In real use it would happen to any agent whose owner has left. Hide the line when `ownerName` is empty. File: `apps/web/src/components/roster/agent-card.tsx`. `desktop-7a.png`.
4. larger: Times show in different zones on different surfaces. Chat and task times are the UTC `HH:MM` of the ISO string (`slice(11, 16)` in `components/thread/task-thread.tsx`, `components/task/thread-runs.tsx`, `components/task/task-page.tsx` and `components/requests/request-card-logic.ts`). So at 20:13 Sydney time the chat said 09:13. The desk pane's "How it got here" uses the browser's zone ("Nov 20, 8:13 PM"), and the card's status line uses the workspace zone (UTC by default). It needs one rule for which zone the app shows.
5. larger (low): The Find command dialog's screen-reader heading ("Find" / "Find an agent, a page or a setting") is rendered on every page while the dialog is closed, because shadcn's `CommandDialog` puts its sr-only `DialogHeader` outside `DialogContent`. Screen readers hear a stray "Find" heading. The file is shadcn output (`components/ui/command.tsx`), so the fix is a wrapper or a re-generated component, not a hand edit.

## Things to know

- `apps/web/.env.local` sets `PUBLIC_BASE_URL=http://localhost:3917` (it belongs to the Pi durability e2e). On any other port, a Cloud (Pi) run never starts. The Worker log repeats "PiRun: MCP server harbourmaster did not list its tools Network connection lost", and the UI shows "Working" with an empty log until `START_TIMEOUT_MS` (2 min). The MCP URL is fixed into the run when it is created, so restarting the server does not rescue that run. Cancel it and start a new conversation. Workaround for a re-run: start vite with `CLOUDFLARE_INCLUDE_PROCESS_ENV=true PUBLIC_BASE_URL=http://localhost:<port>`. Those console lines, and a burst of `net::ERR_CONNECTION_REFUSED` while I restarted the server, are the only console errors in this run, and none of them come from the app. `tmp/RH.7/dev-1.log` is the first server's log.
- Anthropic cloud (managed) is the builder's default runtime, and it cannot run on local without a public tunnel. Pick "Cloud" in the draft's "Runs on" to get a real model reply locally.
- The agent-raised question works like this: tell a Cloud agent "use your ask_user tool to ask me X, with A and B as choices". It calls `ask_user`, which opens a `question` request through `pi-run-gate.ts`, and the request shows in Needs you within a few seconds.
- At 390 px the TanStack Devtools button (dev builds only) sits over the thread composer's Send button, so a click on Send times out. Use Ctrl+Enter in the composer.
- `wait --load networkidle` never settles, because the page polls. agent-browser's `network requests` shows no status codes, so I read failed requests from `performance` entries (`responseStatus >= 400`). The script is `tmp/RH.7/check.js`, and `tmp/RH.7/roster.js` reads `roster.list` through the signed-in session.
- The local database now holds the workspace Anthropic key, four agents (Lunch Planner, Standup Helper, Long-Form Blog Writer, Fake echo) and one open Standup Helper question ("Is tomorrow's standup at 9 or at 10?"). Delete `apps/web/.wrangler` for a clean slate.
