# V1.10 review

Cloud runs gate tool calls and ask questions in Pi.

## Verdicts

- Round 1 (b847a7b): must-fix, one finding. A run older than its run token (12 h, `RUN_TOKEN_MAX_AGE_MS`) is no longer heartbeated, but a question may wait 24 h (`QUESTION_TTL_MS`). A run that waits past 12 h therefore loses its lease and is interrupted, and the reaper then cancels its open request. This limit is older than V1.10, which is only the first task to let a run wait that long. It is not fixed in code: the run ends cleanly and the card is cancelled, and a run with an expired token could not call MCP tools after an answer anyway. It needs Dom's decision, see below.
- Round 2 (e91fea3, fix commit only): clean.

## Design note

The gate is a `beforeTool` hook of Pi's tool task, which the task file allows. The hook runs before the tool records its intent, so a task cut short while the hook waits starts over from the hook after an eviction. The hook finds its request by tool call id and waits again, or goes on at once when the request is closed. The tool then runs under its own replay policy. A wrapper plus a nested call was not used: a wrapped tool has one replay policy, and the wait needs "safe" while the inner tool keeps its own. The hook also covers MCP tools installed later. `bun run e2e:pi-durability` has a new case that kills the server while a run waits, answers after the restart, and checks the tool ran once.

## Nits left

- The lease beat clears the rule cache (20 s) so the 30 s `RULE_CACHE_MS` never fires while a run is active. Correct, at most one D1 read per tool key per beat.
- `scripts/e2e/pi-durability.test.ts` hardcodes `dev_gated`, and `pi-durability.ts` imports a constant from `apps/web/src/server`.
- A D1 failure in the rule read or in `open` blocks the call, so a short D1 outage blocks tools that have no rule too (fail closed).
- The e2e harness answers through a local requests service, so the RPC wake path (`durableRunnerPort.answered` to `PiRun.requestAnswered`) is only unit tested (`pi-run-port.test.ts`). The beat path is the one the suite exercises. The staging check exercises the RPC.
