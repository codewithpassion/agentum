## What changed

- `apps/web/src/server/mcp/library-ports.ts` wires `library_list`, `library_read`, `library_write`, `library_versions`, `wiki_read` and `wiki_suggest_edit` to the library, wiki and wiki suggestions services. Each is a thin call under `guarded`, so the services' `authorize` and path rules apply. `ports.ts` spreads it in and the six "not wired yet" stubs are gone. `compose.ts` already built the wiki service, link index and suggestions (V4.11, V4.12), so it needed no change.
- `packages/services/src/managed/skills-sync.ts` now caps a new Anthropic skill's display title at 64 characters. Found on staging: the built-in `library-transfer` skill id carries the workspace id, so its title was 82 characters, Anthropic answered 400, and every managed run on staging failed with "Anthropic could not be reached: Anthropic answered 400" (sk-check-managed included). I found it by reproducing the upload against the real Skills API ("display_title must be at most 64 characters long"). This is a V4.22 regression. It needs a redeploy.

## Findings

- A conflict that keeps changing leaves one card per sync. While the agent kept writing, the daemon recorded the same conflict three times (5 s apart) and Needs you showed three identical cards. Resolving one cleared all three. Harmless but noisy. `library.recordConflict` could skip the row when an open one exists for the same path, conflict path and run.
- The agent's local write to a read-only path succeeds on its disk and fails silently from the agent's point of view. Both agents said so in their report. The daemon logs the refusal, and nothing tells the agent.

## Nits left

- `library-ports.test.ts:110` asserts only `isError` on the out-of-scope write, not the `forbidden` code.
- `skills-sync.test.ts:85` checks the title length only. An exact title would pin that the id survives the cut.
- The cut drops the readable `library-transfer` name from the built-in skill's title (cosmetic).
- `.slice` counts UTF-16 units, so a non-ASCII skill name could be cut mid-character, if skill names allow that.
- `wiki.page` (`packages/services/src/wiki/service.ts:155`) reads every backlinking page as the caller. An agent whose grants cover only part of `wiki/` would get `not_found` from `wiki_read` when one backlink is unreadable.
- The Log in the task file has no entry from this branch (the controller owns it).

## Ideas beyond the scope

- Cap the title in a single place for user skills as well. A user skill with a name over 23 characters hit the same limit before this fix.
