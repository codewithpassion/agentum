## Nits left

- `fromBase64Url` accepts non-canonical base64url, so a signature has a few other strings that also verify (`crypto.ts`, used by `run-tokens.ts`). Matters only if something later keys on the token string, such as a revocation list or a rate-limit key. Key on the claims or on a hash of the decoded bytes instead, or reject non-canonical input then.
- `lease_until` is compared as text with `now.toISOString()`. The M1 claim and heartbeat code must write `toISOString()` format. The column has no format comment. A SQLite `datetime()` value would refuse tokens, silently.
- No length cap on a token before the split, decode and HMAC. The HTTP layer should cap header size.
- `atob` ignores whitespace inside a key, so the key check is looser than its message says.
- No test for the 60 s clock-skew boundary.
- `toBase64Url`, `fromBase64Url` and `constantTimeEqual` are public. `constantTimeEqual` is exported only for its test.
- The README export table lists the main functions, not every export.
- `CryptoError.code` has one value, kept for parity with flightdex's `CoreError`.
- `verifyRunToken` is a plain function, not a `{ db, atomic }` factory. M0.1 wires it into the resolver.
