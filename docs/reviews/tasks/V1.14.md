## Nits left

- `stream-logic.ts`: the stored-prefix check for late deltas can drop the first deltas of a new message that starts with the same words as the previous one, and `finishedKeys` only grows during a session.
- `applyPending` never settles a request that left the pending list. In poll mode a card answered in Slack keeps its buttons until someone clicks, and the click then shows the conflict line.
- A card past its expiry time keeps its buttons, and a click shows "Already answered somewhere else" rather than "Expired".
- If the follow-up `requests.pending` fetch fails, `needsRequests` stays set and is not retried. The pending fetch also runs after the transcript fetch, so a failure hides the transcript too.
- Question inputs are keyed by question text, so two questions with the same text share state.
- `isConflict` duplicates `components/library/library-logic.ts`.
- The card uses native `<details>`, and the rules input uses a `<datalist>`, instead of Collapsible and Combobox. `transcript-view.tsx` already uses `<details>`.
- `mcp-servers.ts` has an unreachable `?? connector.id` fallback, and `server-keys.ts` has no test of its own.

## Beyond the scope

- Request cards are not in the transcript endpoint, so a settled card disappears on reload. Returning `request.*` events from `sessions.transcript` would keep them.
- Answerer names: the card only knows the current user's name, other users show as "a teammate".
