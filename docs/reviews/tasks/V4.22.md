# V4.22 review: managed sandbox library transfer

## Verdict per round

Round 1, commit 2449e79: clean, after 0 fix rounds. The reviewer ran `bun run check`, `bun run test`, `bun run build` and the dist/client drizzle grep, all passing.

## What was built

- `/api/session/library/*` (list, stat, file GET/PUT/DELETE, conflicts, and `GET run`) in `apps/web/src/server/routes/run-library.ts`. It takes `hm_run_` or `hm_ses_` tokens through `verifyAgentToken`, checks no run id, and answers 401 once the run ends. `/api/runs/:id/library/*` is unchanged.
- `managed/service.ts` adds a `HM_LIBRARY_TOKEN` environment variable credential (the session token, limited to the Worker host) when `libraryTransfer: { helper }` is passed. `compose.ts` passes the bundled helper.
- `managed/library-transfer.ts`: a built-in `library-transfer` skill (SKILL.md plus `scripts/library.js`) added to each managed agent's skills with a per-workspace skill id and a content-hash version, and the prompt text that says when to run `pull` and `push`.
- The helper, `packages/library-sync/src/transfer*.ts`: `pull <path>...` and `push [<path>...]` over the session routes, with `--url`, `--dir`, `HM_LIBRARY_TOKEN`. `bun run bundle` in `packages/library-sync` writes `transfer-bundle.generated.ts` (about 14 KB); a test fails when it is stale.
- An end-to-end test in `run-library.test.ts` runs the helper against the real routes with a session token.

## Nits left

- A credential is counted and created even when the agent is at the 20-skill cap and gets no skill (`service.ts`). An agent with exactly 20 credentials now fails its run.
- An agent skill named `library-transfer` hides the built-in, and the guidance still points at `scripts/library.js`.
- `sessionRoute` repeats the key import of `runPrincipal` in `files.ts`.
- No session-route test for another workspace's or another agent's paths. The access rules are the library service's, tested elsewhere.
- `a/./b` paths pass the helper's check. Disk writes follow links inside the sandbox's own folder. The bundle hash ignores `scripts/bundle-transfer.ts`. Push never prints the "refused" line (a read-only path fails with HTTP 403).

## Ideas beyond the scope

- A live watcher on top of the helper, with the announce or long-poll route the spike suggests.
- Mounting the bundle through the Files API `resources` field instead of the Skills API.
- Pass `dryRun` through the session principal if dry runs ever restrict library writes (run tokens do not today either).
