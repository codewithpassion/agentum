## Decisions

Relay: one Durable Object, not two. `MachineRelay` (`idFromName(machineId)`) holds every socket of one machine, tagged `daemon`, `computer` or `viewer`. That gives one machine identity and one presence, and one `revoke` closes every socket. The viewer hub pumps frames from the computer socket, so it needs that socket in the same object. It adds no DO class and so no wrangler migration. The daemon keeps its JSON frames (`packages/protocol/src/machine.ts`, `relay-core.ts`). The computer socket speaks frozen v1 in a separate core module that V6.9 adds. V6.9 also writes the decision comment at the top of `relay.ts`, because V4.6 edits that file in the worker lane. To reverse it later: a second class `ComputerRelay` would need a wrangler DO migration, and the viewer hub would have to reach the computer socket across objects. Decide that only if one object's single-threaded loop becomes the bottleneck for a machine's frames.

Computer-only machine: `machines.credential_hash` stays NOT NULL. V6.2 or V6.9 fills it with the SHA-256 of 32 random bytes nobody is shown, so no bearer token hashes to it. This is a comment on the column, nothing in this task writes it. Computer credentials go in `machine_credentials`, with the `hm_mach_` prefix, so `enrollResponseSchema` is unchanged.

Added beyond the scope text: `workspace_id` (NOT NULL, FK) on `machine_credentials` and `browser_sessions`, because the repo test requires it on every table (agentum's `browser_sessions` had none). `browser_sessions.agent_id` is a FK with `ON DELETE CASCADE`. `computer_status` is `online | offline` and null when a machine has no computer role (`COMPUTER_STATUSES`).

`requestRecord` (`packages/services/src/requests/records.ts`) throws on a takeover row. Widening `REQUEST_KINDS` otherwise widened `RequestRecord.kind` through desk and web code, and the task keeps `NeedsYouItem.kind` as it is until V6.7. No code opens a takeover row before V6.5 and V6.7, so a takeover here is a bug. V6.7 removes the guard and teaches `describe` in `desk.ts`, `openInputSchema` and the web consumers about the takeover display.

## Nits left

- The fixture test compares parsed JSON, not bytes, because zod emits keys in schema order. It still catches a dropped or extra field.
- `computer.exec` and `browser.action` get no token redaction in `packages/services/src/events.ts` (only `tool.call` and `tool.result` do). The V6 task that writes them should add them to that set, since `command` and `url` can hold a token.
- `machine_credentials` has no primary key and no index on `machine_id`.
- Nothing checks that `machine_credentials.workspace_id` matches its machine's workspace, or rejects an enrol token with role `agent_host` and a `machine_id`. That is the repo's existing pattern.
- Nothing records that a machine holds the `agent_host` role, so a computer-only machine looks like an offline daemon host. Run dispatch and machine pickers (V6.2, V6.9) need a way to tell them apart, for example `credential_hash` matching a known marker or a column.
- The ported helpers `classifyClientFrame`, the `parse*Result` functions, `describeAge` and `offlineMessage` have no direct tests here. In agentum they are covered through `relay.test.ts` and `remote-client.test.ts`, which arrive with V6.9.
