# M0.1 Workspace, principal, authz, task review

## Verdicts

Round 1, commit 29e19d5: clean, no must-fix. 97 services tests, 8 db tests and 11 web tests pass, typecheck and Biome clean. The reviewer found the four bearer prefixes, the `system` kind, the 60 s membership cache, `authorize()` in the events reads, `workspaceProcedure` and the `me` router test all in place. The browser check passed: dev login lands on `/`, the Clerk session has the dev org active, and `/api/trpc/me` returns `{ userId, workspaceId }`. Fix rounds: 0.

## Decisions

- `api_keys` and `triggers` are stub tables in migration 0003, because the resolver has to read `hm_key_` and `hm_trg_` tokens now. M2.1 builds on `api_keys` (its "first migration" is already there) and M4.1 replaces `triggers`.
- `verifyClerkOAuthToken` is injected and returns `{ userId, workspaceId }`. M2.2 supplies the workspace from its approved `oauth_clients` row.
- The 60 s `isOrgMember` cache lives inside `createPrincipalResolver`. The caller must build the resolver once per isolate, not per request, or the cache does nothing.
- The events service reads (`transcript`, `query`, `readPayload`) take the principal first and call `authorize()`. `append` is unchanged.
- No bearer route uses the resolver yet. M2.1 wires it and supplies the real `isOrgMember` (a Clerk Backend API call).
- `ALLOWED_ORG_IDS` is an env var (comma separated). It is not in `wrangler.jsonc`.

## Nits left

- `ALLOWED_ORG_IDS` is not on the generated `Env` type on a clean checkout, because `wrangler types` emits it only from the uncommitted `.env.local`. `tsc --noEmit` in `apps/web` then fails (same already for `DEV_LOGIN_EMAIL` and `CLERK_SECRET_KEY` in `server.ts`). M0.8 (CI) will hit it. Fix with `vars` in `wrangler.jsonc` or a hand-written `env.d.ts`.
- `readPayload` authorizes on `event.workspaceId` from the record the caller passes, then fetches `event.payloadRef` unchecked. Not live today, since records come from the service's own reads. Checking the `payloads/<workspaceId>/` prefix would close it (`events.ts`).
- `lookupApiKey` drops `api_keys.access`. The `user` principal has no field for it. M2.1 needs one.
- The `triggers` stub has no revoked column.
- The membership cache never evicts expired entries (`workspaces.ts`).
- `principal.test.ts` does not assert that a disallowed org never calls `isOrgMember`.
- `sessionPrincipal` never passes a name, so a workspace is named after its Clerk org id.
- Every tRPC request with an org claim runs an insert-or-ignore and a select on `workspaces`.
- Nothing maps `ForbiddenError` to tRPC `FORBIDDEN`. A cross-workspace attempt through a router would show as a 500 until one does.
- `/api/dev-login` and `create-dev-user` take the user's first org membership. A dev user in several orgs gets an arbitrary one.
- `/dev-login` for an already signed-in user redirects without `setActive`, and a rejected `setActive` leaves the page spinning.

## Ideas beyond the scope

- A real `isOrgMember` in `apps/web` (Clerk Backend API, `organizations.getOrganizationMembershipList` filtered by user) when M2.1 wires the resolver.
- Put the workspace name from Clerk (`organization.name`) on first create.
- Skip the workspace lookup for public procedures.
