# M1.1 review

## Verdicts

Round 1, commit 81ab57e: clean. No must-fix findings. No fix rounds.

## Decisions

- `hello.agents` carries agent ULIDs, the same ids as `offer.agentId` and `claim.agent.id`. It is informational: the relay offers runs by the agents assigned to the machine in D1 (`agents.machine_id`), so a daemon cannot ask for runs of another machine. The M0.6 fixture now uses ULIDs.
- `machine_enroll_tokens` gained `created_by` (migration 0005, an additive change to C1). The enrol call carries only the code, so the user who minted it is the only source for `machines.enrolled_by`. `single_user` comes from the enrol body.
- `enrollRequestSchema` and `enrollResponseSchema` joined `@repo/protocol/machine`, with fixtures.
- Runs with `pending_files` are left out of the offers on `hello`. They cannot be claimed yet, and the sweep offers them once the files are in.
- The machine runtime adapter is registered in `compose` now. Its dispatch offers through the Durable Object stub and its cancel sends `cancel`. M1.3 adds marking the run `offered`.
- The task's "fake-runtime agent assigned to the machine" is a machine-runtime agent. The agents service refuses a `machineId` on a fake agent, and the fake runtime finishes runs inline.
- The relay logic is in `apps/web/src/server/relay-core.ts` (tested with fake sockets and storage); `relay.ts` holds the Durable Object class.
- The connect route replaces `/api/machines/ping-do`, which is removed together with the DO `ping()`.
- tRPC `machines.createEnrollToken`, `machines.list` and `machines.revoke` exist so revoke is reachable. M1.5 builds the UI on them.

## Checks

`bun run check && bun run test && bun run build` pass. The live check ran against `vite dev`: enrol code, fake daemon enrols and prints `hello_ack`, `machines.ts` shows online, `kill -9` shows offline with a `machine.offline` event, queued runs started while it was stopped are offered oldest first on reconnect, a second connection closes the first with 1012, a run started through tRPC while connected is offered at once through the stub, and revoke closes the socket with 4401 and the credential is refused afterwards.

## Nits left

- `packages/services/src/machines.ts` `enroll` spends the code and inserts the machine as two writes outside `atomic`. A crash between them burns the code.
- `machines.ts` `markOnline` uses two updates, and `revoke` reads the status before its conditional update, so the `machine.offline` event can be doubled or missed in a race.
- `enroll` does not check `allowedOrgIds`. `authenticate` does, so a code from a disallowed workspace only makes a dead row.
- `list` accepts any non-system principal. Only the router calls it.
- `pendingOffers` offers queued runs of archived agents.
- `machines/runtime.ts` `cancel` does not catch a relay error the way `dispatch` does, so `cancelRun` can throw after the run is cancelled.
- `enrollRequestSchema` repeats the service's `enrollInputSchema` and hardcodes the `hm_` prefixes.
- `relay-core.ts` `connect` closes the old sockets before the new one is accepted.
- `UPGRADE_REQUIRED` and the 101 status are defined twice (`routes/machines.ts`, `relay.ts`).
- `packages/services/README.md` has no rows for the machines modules.
- `relay-port.ts` has no test.
- `relay.test.ts` imports `@repo/db/schema/*` from `apps/web`, as `tick.test.ts` and `router.test.ts` already do.
- `scripts/dev/seed-fake-agent.ts` was moved onto the new shared `scripts/dev/local.ts`.
