## Verdict

Clean. There are 0 must-fix findings and 5 nits.

The CI steps pass in the review worktree. `bun install --frozen-lockfile`, `bun run check`, `bun run test` and `bun run build` all exit 0 (logs `r2-*.log` in this folder). Services ran 2517 tests, web 2696, mailbox 136 and mcp 296, all passing. `apps/web/dist/client` contains no `drizzle`.

Round 1 finding 1 is resolved by V5.13. `DO_MAX_BOUND_PARAMS = 100` sits in `packages/mailbox/src/store.ts`. Attachment inserts chunk at 14 rows (7 columns each), `findThreadByIds` queries 49 ids per chunk (2n + 1 parameters) and keeps the newest match across chunks, and `attachmentsOf` chunks at 100. `testMailboxDb({ maxBoundParams })` throws above the limit through drizzle's logger, and under it the tests store 20 attachments, resolve a 120-id `References` header and read a 150-message thread with attachments. The optional `safeFilename` cap (255 bytes, UTF-8 safe) and the DEL replacement are in.

Round 1 finding 2 is resolved by V5.14. `mailProvisionLabel` gives Retry for `failed`, Try again for `provisioning` and Set up mail for an active agent with an address and no mailbox row. A draft agent gets nothing. `MailProvisionButton` calls `mailbox.provision` from the status line, the header and the Channels row. There is no services change. `profile-logic.test.ts` covers every case the check lists, and the task review records the browser check.

Round 1 finding 3 is resolved by V5.15. `startInbound` looks up the thread's session. When that session is not the thread's own `mail:<mailboxId>:<threadId>` session, it passes it as the trusted `StartRunOptions.sessionId`, which is not in `startRunInputSchema`. `findSessionById` scopes the session to the same agent and workspace. The thread's `session_id` is then left as it is. `requestId: mail:<id>` is kept. The test covers the ui session, the redelivery, `threadForTask` for both runs and the single session row.

Round 1 finding 4 is resolved by V5.16, in the form the controller accepted. Mail from an address of the workspace is stored, indexed and emits `mail.received`, and starts no run. Auto-submitted and list mail are still dropped before anything is stored, and outside mail still starts a run.

No other commit in the range breaks a V5 rule. The range adds migration 0022 (an index on `library_versions`, V4.26) and changes the MCP route for the browser and Q&A flags (V7.12, V7.17). Neither touches mail tables, mail bindings or mail tool gating.

The nits in `docs/reviews/tasks/V5.13.md` to `V5.16.md` stand and are not repeated here. Round 1 nits 5 to 31 also stand.
