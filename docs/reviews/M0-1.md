## Must-fix tasks

**Redact real run tokens.** Scope: `packages/services/src/events/redact.ts` only. Let `HARBOURMASTER_TOKEN` match the `hm_run_<base64url>.<base64url>` shape (allow one `.`), keep the other prefixes as they are. Check: in `packages/services/src/events.test.ts`, append an event whose payload is `{ output: await signRunToken(key, claims) }` under a non-secret key and assert the stored row's payload is `{ output: "[redacted]" }`; `bun run test` passes.

**Give the C4 events body a seq.** Scope: `packages/protocol/src/machine.ts` `runEventInputSchema` gains `seq: z.int().min(1)`, `fixtures/events-request.json` gets seqs 1..3, and the service and protocol share one meaning (the daemon numbers events per run from 1). Alternatively drop `seq` from the service and assign it server-side, but then say how a resent batch is deduped. Check: a test in `packages/services` parses `packages/protocol/fixtures/events-request.json` with `eventsRequestSchema` and passes `.events` to `ingestRunEvents` twice, asserting one stored copy and `lastSeq` 3; `bun test packages/protocol` still passes with an unknown field failing.

**Bind output files to their run.** Scope: `packages/services/src/runs.ts` `completeRun` and `runs/queries.ts` `requireFiles`: output `fileIds` must belong to the run (`files.run_id = run.id`, same workspace). Check: a `runs.test.ts` case where a claimed run completes with a file id uploaded by another user (or another run) gets `not_found`, the run stays `running`, and no gateway call happens; the existing completion tests still pass.
