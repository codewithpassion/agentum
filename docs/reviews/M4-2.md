## Verdict

Clean. Nothing is must-fix. There are four nits.

Round 1's must-fix is resolved. `sweepQueuedRuns` now first fails every run still `queued` or `offered` more than `UNCLAIMED_EXPIRY_MS` (one hour) after `created_at`, with the error "Never claimed" and a `run.failed` event (`packages/services/src/runs.ts:82`, `1095-1135`, `1151`). This is what Dom chose. The write is conditional on the starting statuses, in the same way as the reaper. The offer query now skips runs past the cut-off, so the two steps never compete for the same rows, and it keeps its `swept_at` order and its batch of 100. Settlement already counts `failed` as an error, so a routine on a dead machine now switches itself off about 65 minutes after its first slot. The tests cover each part of the check. The backlog test runs at 200 and 3,000 simulated minutes, and the peak stays under 100 with the same pass count both times. The routine test shows the routine switching off after five "Never claimed" runs, between 60 and 70 minutes. The claim test shows a run claimed at minute 59 surviving the sweep at minute 61. The M4.4 task review reports that the backlog, expiry and routine tests fail without the change. I did not repeat that.

M4 as a whole now meets the build plan's M4 section. M4.1 and M4.2 are unchanged since round 1, where they met their scope and checks. The starvation chain from round 1 is closed. The sweep's backlog is bounded by the age limit times the firing rate, and settlement can no longer stall behind a run that never ends.

`bun install --frozen-lockfile`, `bun run check`, `bun run test` and `bun run build` pass at f8939f6. The test run had 709 services tests, 336 web tests and 265 daemon tests, all passing. `apps/web/dist/client` has no `drizzle`. The log is `checks-r2.log` next to this file.

Round 1 nits 2, 3, 4, 5, 7 and 8 are unchanged and not repeated here. Nit 6 is a little worse and is listed again as finding 3.

| 1 | nit | Turning a routine off, whether by hand or after five errors, leaves the routine's unclaimed runs in the queue.
