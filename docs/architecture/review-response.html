Review response

Two reviews of the first draft arrived on 16 October 2026: a blind review (review-blind.md: 3 blockers, 13 major, 20 minor) and an adversarial Codex review (review-codex.md: 6 high, 2 medium). This page lists every blocker, high, major and medium with the decision and where the pages changed. Minors are grouped at the end. Reuse-related findings were checked against source before acceptance; the checks are noted in the summary column.

The round 1 rows record what the first revision did. Round 2 (below) replaced some of those mechanisms: the rotating run token, mcpServers passed to query(), "one D1 batch", and agent paths under ~/.harbourmaster. Where the two disagree, the round 2 rows and the overview are current.

What changed in shape: three build lanes instead of ten; only the three boundary-crossing contracts freeze at M0; Managed Agents is out of v1 by default behind a new open question; the credential subject is a per-run on_behalf_of_user_id chain instead of the direct actor; run tokens never touch disk; an expired lease interrupts a run instead of re-running it; Slack and routines admit work durably before acknowledging; channel watch, agent env secrets and the daemon release pipeline moved to Deferred with their seams.

Round 2

A fresh blind review (review-blind-r2.md: 2 blockers, 9 major, 11 minor) and a second Codex pass (review-codex-r2.md: 5 high, 3 medium, 2 low, from inlined text without repo access). Claims about the Agent SDK, drizzle and Ariadne's test shim were checked against source before acceptance: setMcpServers sends mcp_set_servers over the control channel while --mcp-config goes on argv (sdk.mjs, sdk.d.ts 0.2.119); batch exists only on drizzle's D1 driver and transaction on the SQLite drivers (drizzle-orm 0.44.7 typings in this repo); ariadne/apps/web/bunfig.toml preloads a cloudflare:workers shim.

What changed in shape: one run token for the life of the run, delivered through setMcpServers() on the SDK control channel, validated server-side against the running row and its lease; an atomic write port in @repo/db so "in one atomic write" is a real call on both drivers; Claude Code runs as a separate hm-agent Unix user; queued runs are the dispatch source, with the relay offering on hello and a sweep job re-offering; one running run per agent enforced in the claim predicate; a refresh lease before any token-endpoint call; actor removed from StartRunInput and derived from the principal, with trusted context passed to gateways; Connect links are signed-in Harbourmaster pages bound to the initiator; only the nine foundation tables and the tool names freeze at M0; the manifest API is optional; UI pages belong to the lane that owns the service.
