Build plan

Milestone 0 is serial: the foundation contracts as code with tests, the wiring and the UI shell split so later work does not collide, and a run that goes end to end on a fake runtime. After it, three coordinated lanes run in parallel, which is what one to three people can use. Milestone 1 is the walking skeleton and the first thing Dom can use. Every task ends in a check someone can run, and the checks include the failure cases the reviews asked for. Sizes are rough: S under a day, M one to three days, L more. Revised twice after review; the review response lists what moved.

Contracts

Seven contracts exist as code with tests by the end of M0. What freezes at M0 is the part that crosses a process or network boundary, and only the part the skeleton needs. Feature tables and tool input schemas arrive with their milestones through the serial migration queue. The unfrozen contracts may change until the M1 gate, with every change announced to the other lanes.

Composition has one owner: apps/web/src/server/compose.ts, under the Runtime lane, builds every service with its dependencies and hands them to the tRPC context, the route groups and the tick. Every other lane adds one factory call there. Schema rule after M0: one serial queue of small migration PRs. A lane that needs a table or column opens that PR first, the others rebase and rerun bun run generate. Nobody merges two migrations/meta journals.

Two kinds of check. Contract tests in M0 run on bun:sqlite with injected fakes (a fake clock, a fake blob store, a fake Clerk verifier) and need no Worker. Route integration tests from M1 on run the Hono apps with the cloudflare:workers shim and name their prerequisites. The build order is the dependency order, so no check runs before the thing it checks exists.
